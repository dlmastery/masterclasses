An unmatched route ends the branch with only a log line

How do you branch in an ADK 2.0 Workflow, and what happens to an unmatched route?
A function yields Event(route=...); a dict edge maps routes to nodes.An unmatched route ends the branch with a log warning only: no error, no reply.Fix: a Literal output_schema, and DEFAULT_ROUTE, the edge taken when no other route matches.
Why let the LLM classify but let code make the routing decision?
A plain function is unit-testable without a model call."p1 always pages on-call" stays deterministic. Routing and review calls use 32-44% of multi-agent tokens (2610.21411).
Two branches both end with an output. What happens?
The run fails: a workflow allows one terminal output.A terminal node has no outgoing edge.Fix: side branches emit Event(message=...), or add a JoinNode before one final node.

  routes = [l for l in node_input.labels if l != "outage"]

from pydantic import BaseModel
MAX_ROUNDS = 3
class Review(BaseModel):
  grade: Literal["compliant", "needs_fix"]
  feedback: str
def brief(node_input: str):
  yield Event(state={"brief": node_input, "feedback": "", "round": 0})
write_copy = Agent(name="write_copy", output_key="draft",
  instruction="Write a 2-sentence ad for: {brief}. Fix: {feedback?}")
review_copy = Agent(name="review_copy", output_key="review",
  output_schema=Review,
  instruction="Must say 'Capital at risk.' Grade this ad: {draft}")
def gate(ctx: Context, node_input: Review):
  if node_input.grade == "compliant":
    yield Event(route="done")
  elif ctx.state["round"] >= MAX_ROUNDS:
    yield Event(route="escalate")
  else:
    yield Event(state={"feedback": node_input.feedback}, route="retry")
# publish and escalate get draft from ctx.state["draft"] by name
def publish(draft: str): yield Event(message=f"PUBLISHED: {draft}")
def escalate(draft: str): yield Event(message=f"To Legal: {draft}")
root_agent = Workflow(name="copy_review", edges=[
  ("START", brief, write_copy, review_copy, gate),
  (gate, {"retry": write_copy, "done": publish, "escalate": escalate})])

from google.adk import Event, Workflow
from google.adk.workflow import node
def split_lines(node_input: str):

@node(rerun_on_resume=True)
def manager_gate(ctx: Context, order_id: str, amount: float):

Show the script and the output, and ask why the same session id s1 works at 10:02 and is gone at 10:04. The hint is line 8: --min-instances=1 sets a floor, not a ceiling, so Cloud Run adds instances under load and replaces them on every new revision. The answer is line 6: sqlite:///./sessions.db is a file on one container's disk, so each new instance has its own empty file and a recycled instance takes its file with it. Some requests still reach instance A and work, which is why it looks random; Cloud Run session affinity is best effort and does not survive a new revision, so it only hides the bug. A run request that lands on instance B starts an empty conversation, which is what the user sees. No flag at all gives the same failure in memory, as the deploy Q&A showed. Fix it with one shared store: agentengine://ID for managed Agent Runtime sessions, or a managed Postgres URL with google-adk[db] (for Cloud SQL, also connect the service to the instance). Analogy: a bank where each teller keeps your file in a desk drawer, so a new teller has never heard of you.
