A graph is an agent.

Blog ADK for Go 2.0: build agent workflows as a graph (2026-06-30) Docs Welcome to ADK 2.0
Start with the one-sentence answer to the interview question "What is ADK 2.0?": it is a graph-based Workflow Runtime, and agents, tools and functions are all nodes, because BaseAgent now subclasses BaseNode. Follow the token. On the billing route, plain functions do the data-determined steps, and a RequestInput node waits for a human. On the general route, one Agent works alone inside a bounded LLM island. Google gives the reason in "Why we built ADK 2.0" (Google Developers Blog, 2026-07-01): "For production-grade reliability, you need full deterministic control over your application flow." Analogy: the graph is the railway track and the switches. The model is the driver who reads the signals at each station. Likely question: "Is this only LangGraph again?" Answer: explicit edges are a shared idea. In ADK, node input and output are typed, the graph is validated when you construct it, and HITL pause and resume come from the session event log. The node colours match the adk web graph view: amber RUNNING, violet WAITING, green COMPLETED.

Graph workflows

“Workflows separate execution routing from language processing.”

Blog Why we built ADK 2.0 · Google Developers Blog · 2026-07-01

Codelab ADK 2 Orchestration: Graph, Collaborative & Dynamic Workflows Repo cuppibla/adk2-tutorial · tested on google-adk 2.3.0 and 2.0.0b1
This chapter teaches the three ways to compose work in ADK 2.0. The small graph comes from the codelab "Marathon Race Day Coach": a function fetches the conditions, a function router picks HOT or COLD, and only then does an agent run. Press once: the deterministic edges draw. Press again: the router fires one branch, and the other branch stays dark. Press a third time: the three styles appear. Graph-based is a declarative edge list, dynamic is plain Python with ctx.run_node, and collaborative is a coordinator with sub-agent modes. Analogy: a railway. Code lays the tracks and sets the switches; the model drives the train between stations. Likely question: "Is this just LangGraph?" The idea is similar, but in ADK every agent, tool and function is the same BaseNode type, and you can follow the whole chapter in the codelab (about 50 minutes).

A chain tuple wires nodes, and each return value becomes the next node's input

agent.py · adk.dev/graphs “Get started”

from google.adk import Agent, Event, Workflow
from pydantic import BaseModel

city_generator_agent = Agent(name="city_generator_agent",
    model="gemini-flash-latest",
    instruction="Return the name of a random city. "
                "Return only the name, nothing else.")

class CityTime(BaseModel):
    time_info: str  # time information
    city: str       # city name
def lookup_time_function(node_input: str):
    return CityTime(time_info="10:10 AM", city=node_input)

city_report_agent = Agent(name="city_report_agent",
    model="gemini-flash-latest", input_schema=CityTime,
    instruction="It is {CityTime.time_info} in {CityTime.city} right now.")
def completed_message_function(node_input: str):
    return Event(message=f"{node_input}\n WORKFLOW COMPLETED.")

root_agent = Workflow(name="root_agent", edges=[
    ("START", city_generator_agent, lookup_time_function,
     city_report_agent, completed_message_function)])

Every node runs the same three phases

  1. Validate node_input against input_schema. Dicts are coerced into the model.
  2. Run the user logic: a function, an Agent, a BaseTool or a nested Workflow.
  3. Normalize each yield: None is dropped, an Event passes, a RequestInput becomes an interrupt, any other value becomes Event(output=value).

Four Event fields carry the run

outputData for the next node. Only one per node run.
messageContent that the user sees.
stateA delta that the session saves.
routeThe branch to take (next slide).

The hand-off is the return value. You do not need session state for it.

Workflow(...) checks 10 rules at construction

  • Unique node names. Reuse one instance to loop back.
  • START is present, with no incoming edges and no routes.
  • Every node is reachable. No unconditional cycles.
  • output_schema equals the successor's input_schema (often from type hints).
  • An LlmAgent(mode='chat') only directly after START.

The check is structural, not behavioural.

from google.adk import START raises ImportError. Import START from google.adk.workflow. The string "START" works in chain tuples, but not in Edge(...).
Two terminal nodes that both output fail the run with WorkflowConfigurationError. The engine cannot choose the workflow output. Put a JoinNode before the end.
A node is any NodeLike: a function (auto-wrapped in FunctionNode), an Agent (usually mode='single_turn'), a tool, a Workflow, or the START sentinel __START__, which never executes.

Read the tuple left to right: START, then four nodes. Each press highlights one tuple element, draws its edge, and moves the payload. Step 1: the generator agent returns a plain string, "Kyoto". Step 2: a plain Python function receives that string as node_input and returns a Pydantic CityTime object. Step 3: the report agent declares input_schema=CityTime, so ADK validates the object and fills the {CityTime.city} placeholders. Step 4: the last function returns an Event with a message, which goes to the user, not to a next node. Steps 5 and 6 show the construction-time checks and the two most common errors. Analogy: a Unix pipe. Each stage reads stdin and writes stdout; you do not need a shared file between stages. Likely question: "Why not keep output_key and session state?" You can, but node_input keeps each node's context small and typed, and the schema check catches mismatches before the first run.

Durable execution and human-in-the-loop

Long runs must pause for people, survive crashes and retry safely.

“any node can pause the graph and ask a human a question”

Blog ADK for Go 2.0: build agent workflows as a graph · Google Developers Blog, 2026-06-30
RequestInput resume by replay RetryConfig
This chapter is about runs that do not finish in one go. A run can stop for three reasons: it waits for a person, the process crashes, or a call fails for a short time. Step 1 shows the pause: the approve node becomes WAITING and the invocation ends. Step 2 shows the crash: on resume, ADK replays the session log and runs the failed node again. Step 3 shows the retry: RetryConfig runs a node again with backoff when it raises an exception. Analogy: a bank transfer form that you can save, that survives a power cut, and that tries the line again when it is busy. Likely question: "Is this the same as Temporal?" Answer: the idea is the same (journal each step and replay it), but ADK keeps the journal in the session event log.

Context engineering, memory and skills

Context is a compiled view over a richer stateful system.

Google Developers Blog Hangfei Lin, Architecting efficient context-aware multi-agent framework for production (2025-12-04)

The goal is "the smallest possible set of high-signal tokens that maximize the likelihood of some desired outcome."

Anthropic Engineering Effective context engineering for AI agents (2025-09-29)
This chapter is about what the model sees on each call, and what the agent keeps between calls. Press once: the green stack is the session, the full event log and the ground truth. Press again: a funnel compiles that stack into one small working context for one model call. Analogy: the session is the source code, and the working context is the compiled binary for a single run; you never ship the whole repository to the CPU. Then read the Anthropic line: the target is the smallest high-signal set of tokens, not the biggest window. Likely student question: "Gemini has a 1M-token window, so why compile at all?" Because quality, cost and latency all get worse as the input grows; the next slide shows the evidence.
