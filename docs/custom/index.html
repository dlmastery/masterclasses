Prompt, retrieve, tune or reinforce. Each rung up the ladder costs more data, more money and more platform risk.

This chapter answers one question: which lever do I pull first? The ladder on the right goes from the cheapest lever, prompt and context, to the most expensive, reinforcement learning. Blue rungs change only the tokens in the window; coral rungs change the weights. The amber bars show that cost, data needs and platform risk grow with each rung. Knowledge failures go to retrieval; behavior failures go to weights

“RAG only solves our in-context learning issues”

Doc OpenAI, Optimizing LLM accuracy Paper Ovadia et al. 2023 Paper Gekhman et al. 2024 Paper Balaguer et al. 2024

Knowledge → retrieval

Missing, stale or private facts. Use prompting and RAG.

Ovadia 2023: “RAG consistently outperforms” unsupervised fine-tuning for knowledge injection.

Gekhman 2024: models learn new facts slowly. Once they learn them, hallucination rises linearly.

Behavior → weights

Format, tone, style and consistent reasoning. Use fine-tuning, preference tuning or RL.

Balaguer 2024 (agriculture): fine-tuning gave +6 p.p. RAG added +5 p.p. on top. The two levers combine.

Do not add retrieval to a style task. In the Icelandic case BLEU fell from 87 to 83. Classify the failure before you pick the tool.
This is the OpenAI two-axis frame. The x-axis is context optimization: what the model knows. The y-axis is LLM optimization: how the model behaves. Walk the path: start with a prompt, add RAG for missing facts, fine-tune for behavior, and combine both only when the eval shows both failures. Analogy: RAG gives the model an open book; fine-tuning trains its handwriting. The Icelandic case is the key number: fine-tuning took GPT-4 from 62 to 87 BLEU, and RAG then pulled it down to 83, because grammar correction is a behavior task. Interview: choosing a customization lever

Your support bot quotes the wrong refund policy and also sounds too formal. What do you change?
knowledge behavior
These are two failures. The policy is knowledge: put it in retrieval, so it stays fresh, citable and permissioned. The tone is behavior: fix it with the prompt first, then SFT or DPO on preferred replies. Build a 20+ case eval before you start. RAG can hurt a behavior task: in the OpenAI Icelandic case BLEU fell from 87 to 83.
When is long context better than RAG?
cost
When the KB is under ~200k tokens (about 500 pages) and stable. Use prompt caching to cut the per-call cost. Watch for context rot: recall drops as the window fills. Move to RAG when the corpus grows, changes often or needs per-user ACLs.
Why not fine-tune your product catalogue into the weights?
knowledge
Models learn new facts slowly, and hallucination rises once they learn them (Gekhman, EMNLP 2024). The facts go stale, and each update needs a new training run. The tuned weights also die with the base model. Keep the catalogue in retrieval and tune only the behavior.
Your vendor retires the base model you tuned. What survives?
platform risk
The data, the data contract, the grader, the eval set and the pinned recipe survive. The checkpoint does not. OpenAI ft-o4-mini shut down on 2026-10-23. Teams with portable recipes re-tune on Vertex AI, Bedrock or open models, then re-run the same eval to prove parity.

Supervised fine-tuning teaches format, style and skills from examples

SFT minimizes the cross-entropy of the target tokens. The data and the mask decide what the model learns.

Fine-tuning is “the most reliable way to enforce a specific output format”.

Blog Own your AI · Google Developers Blog · 2025-10-08
This chapter is about supervised fine-tuning, the most common way to change model weights. Point at the token strip: the grey tokens are context, and only the coral tokens add to the loss. That is the whole idea of SFT: next-token cross-entropy, but only on the tokens you choose. An analogy: SFT is a copy-writing exercise where the teacher grades only the answer lines, never the question lines. The quote is from Google's "Own your AI" post: fine-tuning is the most reliable way to force a format. A likely student question: "If prompting already works, why fine-tune?" Answer: for a format, a tone or a narrow skill that prompting cannot make consistent, or to make a small model do the job of a big one.

SFT learns only from unmasked tokens, so the chat template and the mask define the task

Objective

L = −Σt log pθ(yt | y<t)

The sum skips tokens with label −100 (the ignore index).

Data quality beats size: LIMA used 1,000 curated examples.

Chat template

A Jinja template adds role markers and special tokens. SFTTrainer applies it to conversational data: messages, or prompt + completion; tool_calls and images also work.

Loss mask in TRL v1.16.0

  • completion_only_loss=None (default): prompt-completion data gets loss on the completion only.
  • assistant_only_loss=True: loss on assistant turns only. The template needs {% generation %} … {% endgeneration %}.
  • TRL patches known families (Qwen3). Vision data: since v1.15.0.
A train/serve template mismatch fails silently. For a base model such as Qwen/Qwen2.5-1.5B, set eos_token="<|im_end|>". If not, the model never learns to stop.

Packing

  • packing=True; max_length (default 1024) sets the row length.
  • packing_strategy: "bfd" (default, best-fit decreasing), "bfd_split", "wrapped".
  • padding_free=True (FlashAttention): no attention across examples.
Doc TRL SFT Trainer Paper LIMA 2305.11206
Start with the data: one conversation in the messages format. Step 1: the chat template turns it into tokens with role markers. Step 2: with assistant_only_loss, every system and user token gets label minus 100, so it adds no loss. Step 3: the loss bars appear only above the assistant tokens; the model learns to write answers, not questions. Step 4: the end-of-turn token must be inside the loss, or the model never learns to stop. Step 5: packing puts several short examples into one row; best-fit decreasing removes the padding, and padding-free attention keeps the examples separate. Analogy: packing is loading boxes into a van biggest-first. Likely question: "Does packing leak attention between examples?" Not with padding_free and FlashAttention, because the position ids restart for each example.

The grey square is one frozen weight matrix W with d equal to 4096. Step 1: LoRA adds two thin matrices, B and A, and trains only them; watch the trainable share as the rank moves from 4 to 64 and back to 16. At r = 16 it is 2·d·r over d squared, about 0.78% of the layer. Step 2: rsLoRA changes the scale from alpha over r to alpha over the square root of r, so high ranks keep a useful update size. Step 3: the variants. QLoRA keeps the base in 4-bit NF4, DoRA splits magnitude and direction, PiSSA starts from the top singular vectors. Step 4: the practical evidence from LoRA Without Regret: all layers, about 10 times the learning rate. Analogy: the base model is a printed book, and LoRA is a thin transparent overlay you can swap. Likely question: "Why does LoRA need a higher learning rate?" Because B starts at zero and the update is scaled down, so the same step size moves the output less.

Limit forgetting with adapters, merging and on-policy distillation

Why a fine-tuned model forgets

Mitigations, cheapest first

  1. Use PEFT. Keep the adapter separate and hot-swappable.
  2. Lower the LR. Train 1–3 epochs. Stop early on held-out general benchmarks.
  3. Watch the loss: below 0.2 usually means overfitting. Scale an over-fit adapter by α × 0.5 (Unsloth).
  4. Merge back toward the base model.

Real example: SmolLM3

A linear merge of 0.9 × the APO soup + 0.1 × a mid-training checkpoint recovered the long-context RULER scores.

Distillation

  • Off-policy: SFT on teacher outputs, as in the DeepSeek-R1-Distill Qwen and Llama students.
  • On-policy (GKD, 2306.13649): the student writes, and the teacher scores every token. This removes the train/inference mismatch.
  • TRL DistillationTrainer, stable since v1.10.0 (2026-08-13): beta 0.0 = forward KL, 0.5 = JSD, 1.0 = reverse KL (default). Teacher and student must share a vocabulary. Tool-result tokens are masked.
Doc TRL Distillation Trainer Paper On-Policy Distillation (GKD)
Catastrophic forgetting is the price of specialization. Step 1: the plot has target-task accuracy on the x-axis and general accuracy on the y-axis; the list shows the usual causes. Step 2: full fine-tuning moves far right but drops a lot; LoRA moves right with a smaller drop. The mitigations are in cost order, so try the cheap ones first. Step 3: merging pulls the full-FT point back toward the base; SmolLM3 used a 0.9 to 0.1 linear merge to win back long-context scores. The plot is illustrative, not measured. Step 4: TIES in three moves: trim the small deltas, elect a sign per weight, and average only the values that agree. Step 5: distillation. On-policy distillation lets the student make its own mistakes and get a grade on every token. Analogy: off-policy is copying the teacher's homework; on-policy is the teacher marking your own homework line by line. Likely question: "Why does TIES elect a sign?" Because a plus and a minus delta on the same weight cancel when averaged, and both tasks lose.

Interview: supervised fine-tuning

After SFT the model never stops generating. Why?
The EOS token or the chat template is wrong, so the stop token never got a loss. Set eos_token (for example "<|im_end|>" on a Qwen2.5 base). Use the same template in training and serving. Check the mask: the end-of-turn token must be unmasked.
LoRA or full fine-tuning for 20k support conversations?
LoRA on all linear layers, MLP included, with a LR about 10× the full-FT LR (LoRA Without Regret). On small and medium SFT sets it matches full FT. Use full FT only when the data exceeds the adapter capacity, for example large continued pretraining.
How do you measure and limit forgetting?
Track held-out general benchmarks next to the target metric each epoch. Stop early. Keep the adapters separate. Mix in general data. Merge toward the base with TIES, DARE or a linear merge, as SmolLM3 did to recover long-context scores.
Explain where QLoRA saves memory.
The base stays frozen in 4-bit NF4 with double quantization. Only the small LoRA matrices train, and paged optimizers absorb memory spikes. QLoRA fine-tuned a 65B model on one 48 GB GPU. Full FT with AdamW needs about 16 bytes per parameter.

Question 3 tests measurement discipline: you cannot limit forgetting that you do not measure. Read the loss from the inside out. The first log-ratio measures how much more likely the chosen answer is under the policy than under the reference; the second does the same for the rejected answer; beta scales the gap and acts as the strength of the implicit KL constraint. There is no reward model and no sampling: it is a binary classifier on pairs. GRPO drops the critic and scores each answer against its own group

  1. Sample a group of G answers for each prompt. TRL default: num_generations=8.
  2. A rule scores each answer: 1 if the final answer matches, else 0. R1 uses accuracy, format (think tags) and language-consistency rewards.
  3. Ai = (ri − mean(r)) / std(r). The group mean is the baseline. Then apply a PPO-style clipped ratio, with an optional KL term.
  4. No value model: about half the memory of PPO. No neural RM either: DeepSeek says neural RMs “are susceptible to reward hacking during large-scale RL”.
  5. R1-Zero is pure RL on the base model. AIME 2024 pass@1 rises from 15.6% to 77.9%, and to 86.7% with self-consistency (paper v2).

Cost of the RL stage: about US$294K on 648 H800 GPUs, base model not included (Nature supplementary). The Register argues the true cost is far higher.

Build the group live. One prompt gives eight answers; a program marks three of them correct. The mean reward is 0.375, so each correct answer gets a positive advantage and each wrong answer a negative one, after division by the group standard deviation. That group baseline replaces the critic, so the value model leaves memory. Analogy: grading on a curve inside one class; you do not need a model of how hard the exam is, because the classmates show it. Then show what this did at scale: DeepSeek-R1-Zero went from 15.6% to 77.9% on AIME 2024 with only rule rewards, and the model started to write "Wait" and re-check its work. Likely question: "What happens if all eight answers are wrong?" Answer: every advantage is zero, so the prompt gives no gradient; DAPO drops such prompts on the next slide.

DAPO and Dr. GRPO fix entropy collapse and length bias, and TRL ships them as defaults

1 · Clip-Higher

Set εlow 0.2 and εhigh 0.28. Rare tokens can gain probability. It “avoids entropy collapse”.

2 · Dynamic sampling

Drop prompts with group accuracy 0 or 1. They give zero advantage and zero gradient.

3 · Token-level loss

Average the loss over all tokens in the batch, not per sample. Long answers keep their weight.

4 · Overlong shaping

Apply a soft length penalty. Max length 16,384 tokens, with a 4,096-token cache before it.

5 · Dr. GRPO: length bias

GRPO “artificially increases response length”, mostly for wrong answers. Fix: divide by a constant, drop the std term.

Interview: reinforcement learning for LLMs

Why does GRPO not need a critic, and what does that cost?
The mean and std of the rewards of G sampled answers act as the baseline. You save the value model, about half the memory of PPO. But you generate G completions per prompt, and groups with all-0 or all-1 rewards give no gradient. DAPO dynamic sampling drops them.
Reward goes up, but human-rated quality goes down. What happened?
Overoptimization or reward hacking (Gao et al.). Read samples. Look for length inflation or edited tests. Add hidden tests, stop at the gold peak, use KL or early stopping, and rotate the judges. Trust a held-out gold signal, not the proxy.
DPO chosen log-probs fall during training. Is it a bug?
Not necessarily. DPO mostly suppresses the rejected completions (TRL docs), so the margin can grow while both log-probs fall. Watch rewards/margins and an eval. Add an SFT term (MPO) to anchor the chosen responses.
You have 2,000 prompts and a unit-test harness. Which method?
RLVR with a GRPO-family loss: TRL default dapo, beta=0, dynamic sampling. Run the tests in a sandbox and decontaminate the eval. Start from an SFT checkpoint of 1.5B or larger. Expect the reward to rise only after about 300 steps.

Interview: retrieval-augmented generation

Retrieval recall@20 is high, but the answers are still wrong. Where do you look?
Look past retrieval. Check context packing and order, and rerank to a small top-n (3–20). Find conflicting chunks. Run faithfulness checks on the generator. If the model uses distractors, train it RAFT-style with distractor documents.
How do you evaluate a RAG system?
Score the two halves apart: recall@k on labeled question–chunk pairs, then faithfulness and answer correctness. Mix real queries with a synthetic set. Verify the set (closed-book leak test, humans check 5–10%). Report per slice.
When does agentic RAG not pay off?
On single-hop lookups with tight latency budgets. The loop costs 2–10x more LLM calls and more latency. Use it for multi-hop or ambiguous questions. Keep a one-shot pipeline for simple lookups.
How do you choose the chunk size?
Start at about 512 tokens with 100 overlap. Add a contextual header to each chunk. Tune on retrieval recall with a labeled set, not by eye. In Anthropic’s test, contextual embeddings + BM25 + reranking cut top-20 failures by 67%.

Measure agreement before you scale labeling, and accept an LLM only when it agrees like a human

Cohen's κ: two raters, corrected for chance

κ = (po − pe) / (1 − pe)
po
5/7 = 0.714
pe
15/49 = 0.306
κ = (0.714 − 0.306) / (1 − 0.306) = 0.588

po is the observed agreement. pe comes from the label shares of each rater. The quadratic-weighted κ on the same data is 0.800, because it gives partial credit on ordinal scales. Kappa paradox: with skewed classes pe is high, so κ is low while raw agreement is high. Report both.

Krippendorff's α = 1 − Do / De

Observed over expected disagreement. It accepts any number of raters, missing ratings (grey cells), and nominal to ratio levels. Use it for crowd and LLM + human panels. Fleiss' κ needs a fixed number of raters per item.

Loop: guidelines → pilot 50–200 items with 3+ raters → α per label → adjudicate → revise → repeat until α ≥ 0.8 → scale with 5–10% overlap items. Low agreement can be signal on subjective tasks: keep soft or per-annotator labels.

Hybrid LLM + human labeling recipe

  1. Humans label a gold set of 200–500 items with high agreement.
  2. The LLM labels the same items. Compare LLM–human α with human–human α. Accept the LLM only if the two are close.
  3. Reduce known biases: swap the answer order, use a fixed label set, set temperature 0, use several judges and vote.
  4. Send low-confidence and disagreeing items to humans.
  5. Run cleanlab on the merged labels. Re-audit 2–5% of the LLM labels each week.
