01

Pick the lever first

Classify the failure first.

This chapter follows two assistants, an insurance-claims assistant and a refund assistant, and drills the first decision in every customization interview: which lever do you pull? Start with only the failure from a real trace. Click 1: a wrong refund clause is knowledge, so it goes to retrieval, where it stays fresh, cited and permissioned. Click 2: a reply that sounds too formal is behavior, so you start with the cheapest fix, the prompt. Click 3: you climb to SFT (supervised fine-tuning) or DPO (direct preference optimization) only when the eval still fails after the prompt fix. For goals a program can check, like a payout amount, the base model's pass rate on a probe decides between SFT and RFT (reinforcement fine-tuning). pass@k is the share of prompts where at least 1 of k sampled answers is correct. If pass@8 is 0, there is nothing for RFT to reinforce, so SFT comes first; if pass@1 is already above 95%, RFT adds little. We prove this rule on the training-lever slide and debug a broken probe on the last slide. Analogy: you do not send an employee to a training course because the policy binder is out of date. Likely question: "What if the failure is both?" Then it is two failures with two fixes, which is the first question on the next slide.

def all_evidence_recall(rows, k=20):
    ok = [set(r["required"]) <= set(r["retrieved"][:k])
          for r in rows]
    return sum(ok) / len(rows)

rows = [{"required": ["c12", "c40"],
         "retrieved": ["c12", "c7", "c3"]}]

Ask the question and wait. First fix the metric words, because candidates mix them up. Hit rate at k counts a question as a hit when any one required chunk is in the top k. Recall at k is the share of all required chunks that are in the top k. All-evidence recall counts a question only when every required chunk is in the top k. In the diagram the claim needs two facts, the deductible and the flood exclusion; the top 20 holds only the deductible. So hit@20 is 1, recall@20 is 0.5, and all-evidence recall is 0, and the generator cannot answer correctly however good it is. Click 2 shows the three numbers and the five-line function: label the required chunk ids per question, then test that the required set is a subset of the top k. Click 3: arXiv 2610.26951 found that similarity retrieval finds any relevant chunk far more reliably than all required chunks, so answer-only evals hide grounding failures. The base model's pass rate picks SFT, RFT or distillation

SFT or reinforcement fine-tuning (RFT) for claim payouts?
Probe the base model first. RFT learns only from rollouts that pass, so it needs pass@8 > 0. Start with 100-200 examples. Reward = the grader's score in [0, 1]. pass@k uses the same grader. GRPO is the RL algorithm Bedrock RFT uses.
A strong teacher model exists. RL or distillation?
Try on-policy distillation first: the student writes, the teacher scores each student token. It costs about 10x less compute. Needs the teacher's per-token logprobs: an open-weight teacher with the same tokenizer.

First the words: the reward is the grader's score between 0 and 1, and pass@k is the share of prompts where at least 1 of k sampled answers gets full marks from the same grader. Click 1: RFT learns only from contrast between rollouts. If the base model never gets a payout right, pass@8 is 0, every reward is 0 and there is nothing to reinforce, so SFT comes first. A recent paper, arXiv 2610.18011, adds that distillation on failure-only prompts declined in all 8 configurations, so keep prompts where the student is sometimes right. import json, re

def grade(sample: dict, item: dict) -> float:
    m = re.search(r"\{.*\}", sample["output_text"], re.S)
    try:
        out = json.loads(m.group(0))
        amount = float(out["refund_amount"])
    except (AttributeError, KeyError, TypeError, ValueError):
        return 0.0                         # no usable JSON
    if out.get("decision") != item["gold_decision"]:
        return 0.0                         # wrong decision
    return 1.0 if abs(amount - item["gold_amount"]) <= 0.01 else 0.5

def is_correct(text, gold):              # the payout must be in \boxed{N}
    m = re.findall(r"\\boxed\{([\d.,]+)\}", text)
    return bool(m) and abs(float(m[-1].replace(",", "")) - float(gold)) < 0.01

          for out, r in zip(outs, ds)]

pass_n = sum(k > 0 for k in solved) / len(ds)

Show the script and its output, and ask: "Do you trust this verdict?" The rule in the script is right: RFT needs at least one correct answer among several attempts, so pass@8 of zero normally means SFT first. The probe is wrong. The grader expects the final payout inside \boxed{}, because the claims prompts ask for that format, the same convention the RL trainer's accuracy reward reads. Click 1, bug 1: 48 tokens is too short for the model to reason and then write the boxed payout, so every one of the 1,600 rollouts is cut off and scored wrong. The 48 probably came from a short-answer default. Set the cap from the length of correct reference answers, for example the 95th percentile plus a margin; here that gives 384. Click 2, bug 2: the script never reads finish_reason, so a cut-off answer looks the same as a wrong answer. Count the "length" stops and trust pass@k only when fewer than 10% are cut. The same signal in GRPO training is completions/clipped_ratio. Click 3: with the fix, truncation drops to 3% and pass@8 rises to 0.64, so the decision flips to RFT. The chapter is about the bugs that do not raise an error. The animation shows the two ideas we drill. First, the loss mask on a chat transcript: system and user tokens get label -100, which is PyTorch's ignore_index, so they get no loss; only the assistant tokens, including the end-of-turn token, get loss. Second, LoRA: the weight W stays frozen, and LoRA learns a low-rank update B times A that is added to W. B is d by r, A is r by k, and r is 16 here. B starts at zero, so at step 0 the model equals the base model, and only B and A receive gradients. An analogy: SFT is a teacher who grades only the answer lines of an exam, never the question lines. The template and mask checks run on a laptop CPU; the training runs need one GPU with at least 12 GB. A likely question: "Why must the end-of-turn token be inside the trained span?" A DPO loss stuck at ln 2 means the policy never moved

A DPO-LoRA run on Nemotron-Nano-9B-v2 finishes 25/25 steps. Loss is 0.6931 at every step. Why?
DPO loss = −log σ(β · margin). The margin compares policy and reference log-ratios. At step 0 the margin is 0, so the loss is ln 2 = 0.6931. A flat ln 2 means the margin never changed.
Reported cause: PEFT's default targets match attention projections only. That is 4 of 56 layers. PEFT raises only when nothing matches (#3658).

import re
BOX_RE = re.compile(r"\boxed\{([^{}]*)\}")

def _is_correct(text, gold):
    m = BOX_RE.findall(text)
    return bool(m) and abs(float(m[-1]) - float(gold)) < 0.01

def gated_brevity_reward(completions, completion_ids, solution,
        trainer_state=None, log_metric=None,
        target_tokens=120, warmup_steps=50, **kwargs):
    ramp = min(1.0, trainer_state.global_step / warmup_steps)
    out, gated = [], 0
    for c, ids, gold in zip(completions, completion_ids, solution):
        if not _is_correct(c[0]["content"], gold):
            out.append(0.0); gated += 1; continue
        out.append(ramp * max(0.0, 1 - len(ids) / (2 * target_tokens)))
    log_metric("brevity/gated_frac", gated / len(out))
    log_metric("brevity/ramp", ramp)
    return out

def n_eff(err):  # err[j, i] = 1 if judge j is wrong on item i
