import pathlib
from pandera.errors import SchemaErrors
from claims_contract import ClaimsContract   # step 1
from nightly_batch import batch     # the 4 rows, as strings

try:
    ClaimsContract.validate(batch, lazy=True)   # collect ALL
except SchemaErrors as exc:
    fc = exc.failure_cases
    print(f"{len(fc)} failure cases")
    print(fc[["column", "check", "index", "failure_case"]]
          .to_string(index=False))
    bad_rows = set(fc["index"].dropna().astype(int))
    clean = batch.drop(index=list(bad_rows))
    print("quarantined rows:", sorted(bad_rows),
          "| clean rows kept:", len(clean))
    q = pathlib.Path("quarantine"); q.mkdir(exist_ok=True)
    fc.to_csv(q / "failure_cases.csv", index=False)
    batch.loc[sorted(bad_rows)].to_csv(q / "rows.csv", index=False)

This is step 2 of Lab 6: lab6_quarantine.py imports the contract from step 1, the same way the training job does, and runs it on the nightly batch. With lazy=True pandera collects all 12 failure cases into one DataFrame; without it the run stops at the first problem, the duplicate claim_id. Six of the twelve lines come from one row-wise rule, because a dataframe_check reports every column of the failing row; adjuster_note is null in row 3, and the captured report lists only the other 6 columns. So count bad rows, not lines. unique=True flags both copies of CLM-000102, so this code quarantines rows 1, 2 and 3 and keeps only row 0; if you want one copy, dedupe upstream with drop_duplicates("claim_id", keep="first") before validate. The report and the bad rows go to quarantine/ as CSV, so nothing disappears silently. Analogy: a customs desk that writes up every problem in the suitcase, not only the first one. Likely question: why not drop_invalid_rows? You can set Config.drop_invalid_rows = True with lazy=True, and pandera returns only the valid rows; still write the dropped rows and failure_cases to quarantine. When upstream adds a column, strict=True fails with COLUMN_NOT_IN_SCHEMA: add the column in ClaimsContract v2, or set strict="filter" on purpose, and alert on new failure types, not on failure counts.
