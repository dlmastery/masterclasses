“Fundamentally, evaluations are experiments.”

Paper Evan Miller, Adding Error Bars to Evals (arXiv 2411.00640)

An eval is an experiment: design it like a dataset and report it with error bars

The eval set decides what ships, so it needs more care than the training set.

error analysis golden sets slice metrics paired bootstrap LLM-as-judge calibration cost-sensitive thresholds
This chapter treats the eval set as a dataset product. It is also the experiment that decides what ships. The animation shows the main idea: one score of 84 percent is not a result. It needs a confidence interval, and it needs a split by slice, because one slice can sit far below the average. Analogy: a doctor does not report "the average patient is fine"; she reads each patient's chart and states how sure the test is. Step 1 lists the tools of this chapter. Step 2 places the eval set in the same lifecycle as training data, with one change: error analysis feeds new failure modes back into design. A likely student question: "Why more care than the training set?" Because a noisy training example costs a little accuracy, but a wrong eval number can ship a regression to every user.
