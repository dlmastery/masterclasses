Select sets, not samples: set quotas, drop each example's self-vote

loo_select.py · simplified sketch, not the authors' code
import numpy as np
def loo_select(G, k):
    """G: (n, d) per-example gradients for one candidate batch."""
    gram = G @ G.T
    np.fill_diagonal(gram, 0.0)              # drop self-credit
    score = gram.sum(1) / (len(G) - 1)       # agreement with the others
    return np.argsort(-score)[:k]

Every Batch Is Its Own Validation Set: Leave-One-Out Gradient Matching

In-sample gradient matching rewards each example's own noise (the Gram diagonal). Dropping it beats full-batch training by +2.3 (Llama-3.1-8B) and +2.4 (Qwen2.5-7B). Injected label noise is picked at under 1/5 of its base rate.
Zero the diagonal of any gradient-similarity selector. Same lesson as out-of-sample pred_probs for cleanlab (chapter 9).

Lab 6 picked claims one by one, by margin; these papers say to pick sets. One idea links these three papers: the value of a training set is not the sum of the scores of its examples. LOOM explains why gradient-matching selectors pick noisy examples: each row of the Gram matrix includes the example's dot product with itself, and a noisy example has a large gradient, so it votes for itself; watch the two red rows sit on top, then sink when the diagonal is set to zero. The toy matrix is schematic; the numbers on the card, plus 2.3 and plus 2.4 over full-batch training and noise picked at under a fifth of its base rate, are the paper's. Analogy: a committee where each member may vote for their own proposal; remove the self-vote and the loudest member stops winning. Mixture-then-Select says the same at the domain level, set quotas before you rank, and the diversity benchmark tells you which number to report per release. Likely question: do I need per-example gradients? Yes, at least projected ones, which is the main cost the authors list.
