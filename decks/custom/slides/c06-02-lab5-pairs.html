# dpo_support.py - DPO + LoRA for support-reply tone (TRL 1.16.0)
from datasets import Dataset, concatenate_datasets, load_dataset
from peft import LoraConfig
from trl import DPOConfig, DPOTrainer

def turn(q, r): return [{"role": "user", "content": q}, {"role": "assistant", "content": r}]

PAIRS = [  # (customer message, on-brand reply, off-brand reply) - from QA-reviewed tickets
    ("My package is 5 days late.",
     "Sorry about the delay. Your parcel is at the Leeds depot and arrives tomorrow; I added a $5 credit.",
     "Shipping delays happen. Please wait."),
    ("I was charged twice!",
     "You're right, I see two charges of $49.99. I refunded the duplicate; it shows in 3-5 business days.",
     "Contact your bank about card issues."),
    ("Your app deleted my notes.",
     "I'm sorry. Notes stay in Trash for 30 days: Settings > Trash > Restore. Want me to restore them now?",
     "We don't delete user data. You probably did it yourself."),
]
support = Dataset.from_list([{"chosen": turn(q, c), "rejected": turn(q, r)} for q, c, r in PAIRS] * 100)
uf = (load_dataset("trl-lib/ultrafeedback_binarized", split="train[:3000]")
      .select_columns(["chosen", "rejected"]))
train = concatenate_datasets([uf, support.cast(uf.features)]).shuffle(seed=0)
split = train.train_test_split(test_size=0.05, seed=0)
print(split.num_rows, split["train"].column_names)

This is the data half of Lab 5: we turn three QA-reviewed tickets into DPO pairs. Each row has a chosen and a rejected conversation with the same user turn, and TRL extracts the shared prompt for us, so we do not need a prompt column. We repeat the three seeds 100 times so the brand signal is about 9% of the data, and we mix in 3,000 UltraFeedback pairs so the model does not forget how to answer everything else; the cast call is there because concatenate_datasets needs identical features. Analogy: three model answers from the QA lead, pinned beside a big pile of general examples. Likely question: "Are three seeds enough?" For a demo yes, but in production you want hundreds of reviewed pairs, and you must audit the labels, because a paper from 18 October 2026 shows that flipped preference labels can steer DPO toward an attacker's target.
