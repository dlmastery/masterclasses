Run the script and keep the log with tee. The numbers here are illustrative and the runtime depends on your GPU, but the keys are real: TRL logs entropy, mean_token_accuracy and num_tokens next to the loss. Token accuracy is teacher-forced: the model sees the gold prefix and we check only the next token, so it is not the same as a generated answer. Click 2: with eval_strategy epoch we get one eval per epoch, and eval_packing follows packing, so eval loss uses the same token layout as training; set eval_packing=False if you want per-example numbers. Loss falls from 1.912 and token accuracy rises to about 0.85. Click 3: save_model writes only the adapter: 10.1 million parameters times 4 bytes, because PEFT keeps adapter weights in fp32, so about 40 MB next to a 1.2 GB bf16 base. Think of the adapter as a patch file, not a new program. A likely question: "Can I ship the checkpoint with the lowest eval_loss?" Answer: no, choose on a generated task metric, as the last slide of this chapter shows. Next: step 4 merges this adapter into the base and proves the merge kept behaviour.
