"""Lab 9 - Acme HR policy assistant: synthesize a RAG eval set with ragas, then verify it."""
import collections, difflib, glob, hashlib, json, os

from langchain_core.documents import Document
from langchain_openai import ChatOpenAI
from openai import OpenAI
from ragas.embeddings import OpenAIEmbeddings
from ragas.llms import LangchainLLMWrapper
from ragas.testset import TestsetGenerator

client = OpenAI()   # reads OPENAI_API_KEY
JUDGE = os.environ["JUDGE_MODEL"]   # used by the checks in step 2
docs = [Document(page_content=open(p, encoding="utf-8").read(), metadata={"source": p})
        for p in sorted(glob.glob("hr_policies/*.md"))]   # pto.md, ...

generator = TestsetGenerator(
    llm=LangchainLLMWrapper(ChatOpenAI(model=os.environ["GEN_MODEL"])),
    embedding_model=OpenAIEmbeddings(client=client))
rows = generator.generate_with_langchain_docs(docs, testset_size=40).to_list()
print(len(rows), sorted(rows[0]))

This is step 1 of Lab 9: we turn the Acme HR policies into 40 synthetic question, answer and context rows with the ragas 0.4.3 TestsetGenerator. Step 1: each markdown policy becomes one LangChain Document with its source path; keep each policy above 500 tokens, because ragas bins documents by length and rejects very short ones. Step 2: the generator gets an LLM through LangchainLLMWrapper and an embedding model; inside, it builds a knowledge graph, with headline and entity extractors on each document and relationship edges between related documents such as PTO and parental leave. Step 3: the default mix is half single-hop specific, a quarter multi-hop abstract and a quarter multi-hop specific, and each row carries user_input, reference_contexts, reference, persona and query style; the deprecation warning is expected because the 0.4.3 docs still use the wrapper. Analogy: the generator is a new hire who writes exam questions from the handbook, and like any first draft, the next slide checks every question before anyone uses it. The JUDGE_MODEL variable is read here but used in step 2. Likely question: "Why does multi-hop fail on my two documents?" Because multi-hop synthesizers need relationships between documents; with one or two unrelated files there are none, so you get "Cannot form clusters".
