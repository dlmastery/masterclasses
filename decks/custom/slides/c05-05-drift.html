drift.py · Evidently 0.7.23

from sklearn import datasets
from evidently import Report
from evidently.presets import DataDriftPreset
from evidently.metrics import ValueDrift

iris = datasets.load_iris(as_frame=True).frame
report = Report([
    DataDriftPreset(method="psi", drift_share=0.7),
    ValueDrift(column="sepal length (cm)", method="ks"),
], include_tests=True)
my_eval = report.run(iris.iloc[:60], iris.iloc[60:])  # cur, ref
my_eval.save_html("drift.html")

Drift is a comparison between a reference window and a current window, column by column. Step 1: the descriptor here is prompt length in 10 bins; the current week moves to the right. Step 2: PSI adds one term per bin, (a minus e) times the log of a over e; the bins in the tails contribute most, and the total is 0.226, which the credit-risk convention calls a moderate shift. These cut-offs are an industry habit, not a standard. Step 3: the same data as two cumulative curves; KS is the largest vertical gap, 0.19 here. With a large n, the KS p-value is tiny even for a shift nobody cares about, so Evidently uses distances such as Wasserstein above 1000 rows. Step 4: the defaults table; know it for interviews. Step 5 and 6: the code sets PSI for all columns and KS for one column, and runs current against reference. For LLM and RAG data, compute descriptors first and run these tests on the descriptors. Analogy: a p-value with a million rows is a smoke alarm that goes off when you make toast. Likely question: "Which threshold do I alert on?" Tie the alert to a slice metric that drops, not only to the statistic.
