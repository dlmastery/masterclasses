from peft import LoraConfig
from trl import GRPOConfig, GRPOTrainer
from trl.rewards import accuracy_reward, get_soft_overlong_punishment
from claims_data import claims_dataset
train = claims_dataset(2000, seed=7)
heldout = claims_dataset(64, seed=99)          # different seed = disjoint-ish eval prompts
lora = LoraConfig(r=16, lora_alpha=32, target_modules="all-linear", task_type="CAUSAL_LM")
args = GRPOConfig(
    output_dir="qwen-claims-grpo",
    model_init_kwargs={"dtype": "bfloat16"},   # TRL default is float32 for string model ids
    learning_rate=1e-5,                        # LoRA: ~10x the 1e-6 full-FT GRPO default
    per_device_train_batch_size=8,
    gradient_accumulation_steps=4,             # 32 completions per step = 4 prompts x 8
    num_generations=8,
    max_completion_length=256,
    mask_truncated_completions=True,           # DAPO: do not learn from cut-off answers
    loss_type="dapo", beta=0.0,                # the TRL defaults, written out on purpose
    reward_weights=[1.0, 0.5],
    max_steps=300, logging_steps=5, save_steps=100,
    eval_strategy="steps", eval_steps=50, per_device_eval_batch_size=8,
    log_completions=True, num_completions_to_print=2,
    report_to="trackio",
)
trainer = GRPOTrainer(
    model="Qwen/Qwen2.5-0.5B-Instruct",
    reward_funcs=[accuracy_reward,
                  get_soft_overlong_punishment(max_completion_len=256, soft_punish_cache=64)],
    args=args, train_dataset=train, eval_dataset=heldout, peft_config=lora,
)
trainer.train()
trainer.save_model()

1 GPU: 8 x 4 = 32 completions = 4 claims x 8. TRL raises unless this divides by num_generations. Two GPUs: 64.
accuracy_reward (math-verify) reads only LaTeX answers, \boxed{} first, and scores each one 1.0 or 0.0 against solution.
Penalty: 0 up to 192 tokens, then linear to -1 at 256. Cut-off answers leave the loss.
beta=0.0: no reference model, no kl metric. Lab 4 step 5 turns KL on.

This is the full training script for the Acme claims payout calculator: Qwen2.5-0.5B-Instruct with a LoRA adapter, trained by GRPO in TRL 1.16.0. Step 1: one optimizer step uses 8 per device times 4 accumulation steps, which is 32 completions, that is 4 claims with 8 answers each; TRL raises an error unless this number divides by num_generations, because the advantage is computed inside each group of 8. Step 2: accuracy_reward uses math-verify and accepts only LaTeX answers, so the system prompt asks for \boxed{}; when the gold answer cannot be parsed the reward is None and the row is skipped, not scored 0. Step 3: the soft overlong penalty is 0 up to 192 tokens and falls linearly to -1 at 256, and mask_truncated_completions removes answers that hit the cap from the loss. Step 4: loss_type dapo and beta 0.0 are the defaults, so no reference model is loaded and there is no kl metric. Analogy: the 8 answers per claim are 8 students on the same exam question, and only the differences between them give a learning signal. Likely question: why is the learning rate 1e-5? Because a LoRA adapter has few parameters, it usually needs about 10 times the 1e-6 full fine-tuning default.
