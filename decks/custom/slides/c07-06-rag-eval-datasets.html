Build RAG test sets from a knowledge graph, then verify them before they count as gold

Doc Testset Generation for RAG Doc RAGAS rag_eval

1 · Documents become graph nodes

RAGAS 0.4.3 loads each document as a node of a KnowledgeGraph.

2 · Transforms add structure

default_transforms and apply_transforms add summaries, entities, embeddings and relationships. Docs example: 10 nodes become 48 nodes with 605 relationships. The graph gives scenarios. Each scenario gives a query.

3 · Synthesizers write the queries

Default mix: 50% single-hop specific, 25% multi-hop abstract, 25% multi-hop specific. Each row has four columns:

user_input reference_contexts reference synthesizer_name
0LLMContextRecall
0Faithfulness
0FactualCorrectness (docs example)
make_testset.py · condensed from the RAGAS docs

import openai
from langchain_community.document_loaders import DirectoryLoader
from langchain_openai import ChatOpenAI
from ragas.embeddings import OpenAIEmbeddings
from ragas.llms import LangchainLLMWrapper
from ragas.testset import TestsetGenerator
docs = DirectoryLoader("Sample_Docs_Markdown/", glob="**/*.md").load()
llm = LangchainLLMWrapper(ChatOpenAI(model="gpt-4o"))
embeddings = OpenAIEmbeddings(client=openai.OpenAI())
generator = TestsetGenerator(llm=llm, embedding_model=embeddings)
dataset = generator.generate_with_langchain_docs(docs, testset_size=10)
dataset.to_pandas()
# user_input, reference_contexts, reference, synthesizer_name
  1. Check that each reference is supported by its contexts (faithfulness judge).
  2. Drop questions that the model answers without retrieval. closed-book leak test
  3. Have humans spot-check 5–10% of the items.
  4. Rebalance single-hop vs multi-hop to match real, PII-scrubbed query logs.
  5. Version the set. Never train on it.
A RAG system needs a test set before it needs a better retriever, and most teams do not have labeled questions. RAGAS builds one from your own documents: each document becomes a node, transforms add summaries, entities, embeddings and similarity edges, and the graph gives multi-hop scenarios that a flat list of chunks cannot give. Step 3 shows the default query mix and the four output columns; the three numbers are the docs example scores, not a benchmark. Step 5 is the part that most teams skip: a synthetic question only counts as gold after a faithfulness check, a closed-book leak test, a human spot-check and a rebalance to real traffic. Analogy: an exam written by the textbook author; check that the answers are in the book, and drop the questions anyone can answer without it. Likely question: "Why remove questions the model answers closed-book?" Because they test the model's memory, not your retrieval, so they inflate the RAG score.
