model = PeftModel.from_pretrained(base, ADAPTER).eval()
FIELDS = ["loss_type", "severity", "needs_adjuster", "policy_section"]
def generate(msgs):
    enc = tok.apply_chat_template(msgs, add_generation_prompt=True,
                                  return_tensors="pt", return_dict=True).to(model.device)
    with torch.no_grad():
        out = model.generate(**enc, max_new_tokens=96, do_sample=False)
    return tok.decode(out[0, enc["input_ids"].shape[1]:], skip_special_tokens=True)
def score():
    valid, hits = 0, dict.fromkeys(FIELDS, 0)
    for ex in test:
        gold = json.loads(ex["completion"][0]["content"])
        try:
            pred = json.loads(generate(ex["prompt"]))
        except json.JSONDecodeError:      # prose after the JSON: invalid
            continue
        if isinstance(pred, dict):
            valid += 1
            for f in FIELDS:
                hits[f] += pred.get(f) == gold[f]
    n = len(test)
    return {"json_valid": valid / n, **{f"acc_{f}": hits[f] / n for f in FIELDS}}
with model.disable_adapter():          # BEFORE: same weights, LoRA off
    before = score()
after = score()                        # AFTER: same weights, LoRA on
for k in before:
    print(f"{k:20s} base={before[k]:.3f} tuned={after[k]:.3f}"
          f" delta={after[k] - before[k]:+.3f}")

This is the honest test: one model object, the same 4-bit NF4 weights, and the adapter switched off for the "before" run with disable_adapter. Walk the code in order. First, generation is greedy: Qwen3-4B-Instruct-2507 ships a generation_config that samples, with temperature 0.7 and top_p 0.8, so do_sample=False makes the metric reproducible, and we decode only the new tokens so the prompt never reaches json.loads. Second, a JSONDecodeError on the base model is expected, because it adds prose after the JSON, and that row counts as invalid. Third, disable_adapter gives the "before" scores on the same weights, so quantization noise is identical in both arms. Fourth, the "after" run gives the delta, and all four keys, including the free-text policy_section, are scored. The numbers are illustrative on 200 notes. With n=200 and a score near 0.6, the 95% interval is about plus or minus 0.07 (normal approximation), so a delta of 0.38 is far outside the noise; chapter 11 adds proper intervals and a slice table. Also run a general-capability regression on both arms, because forgetting is the main SFT cost; the forgetting slide (NB-LoRA) shows how large it can be. If the adapter fails to load with "Target modules ... not found in the base model", the adapter was trained on a different base: load the base named in adapter_config.json. Likely question: "Why not compare against the base loaded separately in bf16?" Because then you also measure quantization, and you cannot tell which change moved the score.
