QLoRA and honest before/after evaluation

QLoRA, then prove it

A 4B model fits a 16 GB GPU in NF4. The adapter counts only when the same weights score better with it on.

Qwen3-4B · NF4 · LoRA r=16
This chapter is Lab 2: the Acme claims desk wants free-text adjuster notes turned into strict JSON with four keys: loss_type, severity, needs_adjuster and policy_section. The picture shows the plan. The bf16 weights use 16 bits per weight, about 8.1 GB for 4.06 billion parameters. We load the same weights in 4-bit NF4, about 2.3 GB (not exactly a quarter, because some parts such as the quantization constants are extra), so the frozen base fits a 16 GB GPU. Beside it sits the LoRA adapter: a small folder with adapter_model.safetensors and adapter_config.json that loads on top of the base, and that we can switch on and off. Then comes the honest part: we score the same quantized weights twice, once with the adapter off and once with it on, so quantization noise is identical in both arms. Analogy: a clinical trial where the control group takes the same pill without the active ingredient. Likely question: "Why not compare against the bf16 base?" Because then you measure quantization and the adapter together, and you cannot tell which one moved the number.
