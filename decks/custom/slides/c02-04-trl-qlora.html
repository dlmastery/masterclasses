TRL v1.16 puts QLoRA, packing and assistant-only loss in one SFTConfig

sft_qlora.py · TRL v1.16.0 (from the TRL SFT docs, combined)

from datasets import load_dataset
from peft import LoraConfig
from transformers import BitsAndBytesConfig
from trl import SFTConfig, SFTTrainer

args = SFTConfig(
    output_dir="qwen3-sft",
    max_length=2048,
    packing=True, packing_strategy="bfd",   # padding-free BFD packing
    assistant_only_loss=True,                # mask user/system tokens
    learning_rate=1e-4,                      # adapters -> higher LR
)
trainer = SFTTrainer(
    model="Qwen/Qwen3-0.6B",
    args=args,
    train_dataset=load_dataset("trl-lib/Capybara", split="train"),
    peft_config=LoraConfig(r=16, lora_alpha=32, target_modules="all-linear"),
    quantization_config=BitsAndBytesConfig(load_in_4bit=True,
                                           bnb_4bit_quant_type="nf4"),  # QLoRA
)
trainer.train()

This is the full SFT recipe in about twenty lines, current for TRL v1.16.0. Step 1: packing with best-fit decreasing; recent releases also made the LM head cheaper, with 1.2 to 1.7 times throughput from chunked cross-entropy. Step 2: assistant_only_loss gives the mask from the previous slide. Step 3: the peft_config and the quantization_config together make QLoRA: a 4-bit NF4 base and trainable LoRA matrices. Step 4: the default SFTConfig learning rate is 2e-5, which is right for full fine-tuning, but adapters want about 1e-4. Step 5: many tutorials, including the Google Cloud Run codelab, still use the pre-1.0 argument names; in TRL 1.x they move into SFTConfig and the tokenizer becomes processing_class. Pin trl and peft, and run a ten-step smoke test after each upgrade. Analogy: SFTConfig is the recipe card, and SFTTrainer is the kitchen. Likely question: "Why does my old notebook fail with an unexpected keyword?" Because of this API drift; pin trl and move the arguments.
