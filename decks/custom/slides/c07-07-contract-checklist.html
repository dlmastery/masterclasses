Best practices

Dataset design rules: contract, hash, version, and check every rank

1 · Gate the rows

  • Contract class in the producer repo. The training job imports it: two gates.
  • lazy=True; alert on new failure types. One full report.
  • Check label ranges yourself. ClassLabel accepts 5 for 3 classes.

2 · Pin the bytes

  • Own sha256 per shard; pin revision=. 4.8.5 stopped checksums.
  • Assert per-rank sample ids are disjoint. Concat dropped the split.
  • Empty-doc filter first. Curator filters hit ZeroDivisionError.

3 · Write the rules down

  • Taxonomy and split rule in the contract. Coverage becomes a test.
  • Audit labels from the export or API. The UI grid can show blanks.
  • No silent dedupe or quarantine. Log (row, rule, value).
  • No mixed MinHash schemes. datasketch 2.0: affine32, not legacy.

build_passport.py
import hashlib, pathlib
from datasets import load_dataset
# datasets 4.8.5 no longer records checksums (#8590)
shards = pathlib.Path("claims_data/training_table").glob("*.parquet")
sha = {p.name: hashlib.sha256(p.read_bytes()).hexdigest()
       for p in shards}
REV = "<commit sha>"                     # never "main"
ds = load_dataset("acme/claims-fraud", revision=REV, split="train")
# ClassLabel skips the range check if the dtype matches (#8596)
n = ds.features["label"].num_classes
bad = ds.filter(lambda r: not 0 <= r["label"] < n)
assert len(bad) == 0, f"{len(bad)} labels outside 0..{n - 1}"
passport = {"contract": "ClaimsContract v2", "revision": REV,
            "sha256": sha, "label_range": [0, n - 1],
            "taxonomy": ["auto", "home", "travel", "health"],
            "split_rule": "group by policy_id"}
This slide closes the chapter: it turns Lab 6 into rules. Read these ten rules as a pre-flight list for any training table, such as the Acme fraud-model training table, not as theory: each one comes from a bug we saw in Lab 6 or in an open issue. The first group gates the rows: one contract class that the producer and the training job both import, lazy validation so the data owner gets one full report, and an explicit label-range check because datasets ClassLabel accepts label 5 for three classes when the Arrow dtype already matches. The second group pins the bytes: datasets 4.8.5 stopped recording checksums with no release note, so hash the Parquet shards yourself and pin the commit with revision. The passport card on the right fills one pair of fields per group, and its values are illustrative; it is the same dict that the last lines of the code write. Think of it like a passport for a traveller: no stamp, no boarding the training job. A likely question: "Why assert disjoint sample ids per rank?" Because concatenate_datasets on iterable datasets dropped the split_dataset_by_node split, so every rank trained on all the data and nothing failed.
