import torch
from peft import LoraConfig
from trl import SFTConfig, SFTTrainer
from common import refund_splits  # Bitext rows, category == "REFUND"
# 2,992 rows: get_refund · track_refund · check_refund_policy
ds = refund_splits()                # messages, random 95/5 split
args = SFTConfig(output_dir="qwen3-0.6b-refund-lora",
    model_init_kwargs={"dtype": torch.bfloat16,     # else float32
        "attn_implementation": "kernels-community/flash-attn2"},
    assistant_only_loss=True, max_length=1024,
    packing=True, packing_strategy="bfd",           # padding-free
    per_device_train_batch_size=8, gradient_accumulation_steps=2,
    learning_rate=2e-4, num_train_epochs=2,
    warmup_steps=0.03,                              # float = ratio
    eval_strategy="epoch", save_strategy="epoch",   # keep every ckpt:
    load_best_model_at_end=False,                   # pick by task metric
    logging_steps=10, report_to="none", seed=42)
peft_config = LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05,
    target_modules="all-linear", task_type="CAUSAL_LM")
trainer = SFTTrainer(model="Qwen/Qwen3-0.6B", args=args,
    train_dataset=ds["train"], eval_dataset=ds["test"],
    peft_config=peft_config)
trainer.model.print_trainable_parameters()

This is the whole training call for the Acme refunds assistant: the 2,992 Bitext REFUND rows over three intents, Qwen3-0.6B and one LoRA config. The data helper in common.py filters category REFUND, maps each row to system, user and assistant messages, and makes a random 95/5 split. Walk the four bands. One: set dtype to bf16, because TRL loads a string model id in float32, which doubles the weight memory. Two: assistant-only loss plus BFD packing switches on padding-free batches, which need FlashAttention, so we load the kernels-community flash-attn2 kernel; that needs an Ampere or newer GPU such as an L4 or A10G. Three: a learning rate of 2e-4, about ten times the full fine-tuning default of 2e-5, and a float warmup_steps below 1 is a ratio. Four: target_modules all-linear; without it PEFT trains only q_proj and v_proj, 2,293,760 parameters instead of 10,092,544. We save one checkpoint per epoch and do not load the best one by eval_loss, because the last slide of this chapter picks the checkpoint by generated output. Think of LoRA targets like the gears you allow a mechanic to adjust: give access to two and the car still drives, but not well. A likely question: "Is a random split enough?" No: Bitext has many paraphrases of each request, so a random split puts near-copies on both sides; keep a separate set of new phrasings for the final check.
