gemma4_router.py · router: request → {category, intent} JSON · REFUND → Lab 1
from unsloth import FastModel        # import unsloth FIRST: it patches trl
from unsloth.chat_templates import get_chat_template, train_on_responses_only
import json
from datasets import load_dataset
from trl import SFTConfig, SFTTrainer
model, tokenizer = FastModel.from_pretrained("unsloth/gemma-4-E2B-it",
    max_seq_length=1024, load_in_4bit=True)   # Unsloth kwarg, not SFTConfig
model = FastModel.get_peft_model(model, finetune_vision_layers=False,
    finetune_language_layers=True, finetune_attention_modules=True,
    finetune_mlp_modules=True, r=16, lora_alpha=16, lora_dropout=0)
tokenizer = get_chat_template(tokenizer, chat_template="gemma-4")
SYSTEM = "Classify the customer ticket. Reply with JSON only."
def to_text(r):
    label = json.dumps({"category": r["category"], "intent": r["intent"]})
    convo = [{"role": "system", "content": SYSTEM},
             {"role": "user", "content": r["instruction"]},
             {"role": "assistant", "content": label}]
    return {"text": tokenizer.apply_chat_template(convo, tokenize=False)}
raw = load_dataset("bitext/Bitext-customer-support-llm-chatbot-training-dataset",
                   split="train").shuffle(seed=3407).select(range(6000))
trainer = SFTTrainer(model=model, processing_class=tokenizer,
    train_dataset=raw.map(to_text, remove_columns=raw.column_names),
    args=SFTConfig(dataset_text_field="text", max_steps=200, learning_rate=2e-4,
        per_device_train_batch_size=2, gradient_accumulation_steps=4))
trainer = train_on_responses_only(trainer,
    instruction_part="<|turn>user\n", response_part="<|turn>model\n")
trainer.train()
model.save_pretrained_gguf("gemma4-router-gguf", tokenizer, quantization_method="Q8_0")
Acme now wants a small router in front of the refunds assistant: it labels each request with category and intent as JSON over the 27 Bitext intents, on a free T4 with Gemma 4 E2B. A REFUND label sends the request to the Lab 1 adapter. Start on the left: the plain TRL path fails at once, because assistant_only_loss needs a training-compatible chat template, and TRL 1.16 patches Gemma and Gemma 3 but not Gemma 4. Click 1: Unsloth. Import unsloth first so it can patch trl and transformers. max_seq_length is Unsloth's own loader argument, not the TRL SFTConfig field we renamed earlier. With r=16 about 25 million of 5.1 billion total parameters train; E2B means about 2 billion effective parameters. The data map builds one text field per row with the gemma-4 template. Click 2: Gemma 4 uses turn markers that differ from Gemma 3, so old tutorial markers match nothing. Click 3: train_on_responses_only gives every user token the label minus 100, so only the JSON label trains. We pass instruction_part and response_part explicitly, because auto-detection can fail with "Could not auto-detect chat template structure - pass instruction_part and response_part." Think of the mask as a highlighter: the model reads the whole page but is graded only on the highlighted answer. Click 4: export a Q8_0 GGUF, one of the three formats Unsloth supports for Gemma 4 today, and probe three prompts with llama.cpp's llama-cli. Click 5: a GGUF export from a raw PeftModel wrapper silently ships the base model (unsloth issue 11698), so load the adapter with FastModel before export.
