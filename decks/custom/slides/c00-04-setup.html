Native Windows: use .venv\Scripts\activate for the CPU labs. Run the GPU and RL labs in WSL2 or Colab.
Analogy: this is the kitchen before the first recipe; every lab cooks with the same pinned tools, so the outputs on the slides match yours. Click 1: one virtual environment with the pinned versions that every lab uses. On Linux, WSL2 or Colab the activate command is ". .venv/bin/activate". Click 2: prove the GPU works before Lab 1. A plain pip install can give a CPU-only torch wheel; then the first line prints False and training is very slow. Reinstall torch from the pytorch.org selector for your CUDA version. The second line must print the trl version that the labs use, 1.16.0. Click 3, hardware. Lab 1 (Qwen3-0.6B LoRA) needs about 12 GB; Lab 2 (Qwen3-4B in 4-bit QLoRA) fits 16 GB with batch size 2. A T4 runs both, but it has no bf16, so set bf16=False and fp16=True. Labs 4 and 5 (GRPO and DPO) need a 16–24 GB card such as an L4 or A10G. Labs 3 and 6–10 run on a CPU. Click 4, keys. Lab 3 tests its reward functions offline first; only its last two steps call the OpenAI grader API and Vertex AI RFT. Lab 9 calls an OpenAI model to generate and judge HR questions. Vertex AI also needs "gcloud auth application-default login". On native Windows, the RL labs run slowly (math-verify falls back to multiprocessing timeouts), so use WSL2 or Colab. Data: Lab 1 downloads the Bitext customer-support dataset from Hugging Face (bitext/Bitext-customer-support-llm-chatbot-training-dataset, 2,992 REFUND rows). Each lab's first slide lists its own files and data. Likely question: "Can I use free Colab?" Yes for Labs 1–2 on a T4 with fp16. Labs 4–5 need a 16–24 GB card.
