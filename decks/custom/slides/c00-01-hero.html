Code-first course: every lab solves one Acme business problem, with pinned library versions. Analogy: the base model is a new hire that everyone can rent. Weights = training the hire (habits, format, judgment). Context = handing them the current policy binder with each question. The data loop = the QA team that keeps the training material and the exam honest. Click 0: one base model, the same for everyone. Your data is the only thing you own. Click 1, weights. SFT (supervised fine-tuning) = train on example input and answer pairs. LoRA = train small adapter matrices instead of all weights. GRPO = sample a group of answers, score each one with a reward function, and push toward the better ones. DPO (direct preference optimization) = learn from chosen versus rejected pairs; it uses no reward function. Labs 1–2 are SFT, Labs 3–4 are GRPO rewards, Lab 5 is DPO. Click 2, context. RAG (retrieval-augmented generation) = retrieve documents into the prompt at query time; the weights do not change. Rule: facts that change go to context; behaviour, format and decisions go to weights. Lab 9 builds and checks the eval set for the HR policy RAG assistant. Click 3, the data loop that feeds all three: contract = schema checks on each incoming row (Lab 6, the start of the loop); label = humans add answers (Lab 6); synthesize, dedup, verify = generate new examples, remove near-duplicates and test leaks, reject wrong items (Lab 9); eval = score on held-out cases (Lab 10); drift = watch production data change, which starts the next round (Labs 7–8). Likely question: "Do I need to train at all?" Not always. Chapter 01 shows how to decide before you spend GPU hours.
