Gotcha label-noise tooling · cleanlab 2.9.0 · captured runs

cleanlab hung 77 times on Windows; flagged labels are not delete lists

1 · the run never ends
SymptomRuntimeError: An attempt has been made to start a new process before the current process has finished its bootstrapping phase. Printed 77 times, then hung. Killed after 100 s. CauseDefault n_jobs=None starts one process per physical core. Windows and macOS spawn re-import a script that has no if __name__ == "__main__": guard. Fixn_jobs=1 or the guard. The docstring: "Windows users may see a speed-up with n_jobs=1" (filter.py:177).
2 · the input format
SymptomValueError: Labels cannot be strings, they must be zero-indexed integers corresponding to class indices. / Values in pred_probs must be between 0 and 1. CauseThe vendor CSV holds "billing". The model gave raw scores, not probabilities. Fixnp.searchsorted(classes, string_labels) with sorted classes. Use predict_proba or a softmax.
3 · cleaning made the model worse
SymptomThe team deleted every flagged row. The retrained model did not improve. EvidencearXiv 2609.25487 (21 Sep 2026): 870,514 Google Play apps, 3 detectors agreed on 7,598. Removal did not help; loss grew with the number removed. Overlap-only model: AUC 0.2518. FixSend flagged rows to review. Delete only after a human decision, especially when the label is a proxy.

import numpy as np
from cleanlab.filter import find_label_issues
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_val_predict
from sklearn.pipeline import make_pipeline
from tickets import make_tickets

def main():
    texts, y, classes = make_tickets(3_000, seed=1)     # classes = sorted names
    string_labels = np.array(classes)[y]                 # what a vendor CSV holds
    labels = np.searchsorted(classes, string_labels)     # "billing" -> 0: ints 0..K-1
    model = make_pipeline(TfidfVectorizer(ngram_range=(1, 2), min_df=2),
                          LogisticRegression(max_iter=2_000))
    cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
    pred_probs = cross_val_predict(model, texts, labels, cv=cv, method="predict_proba")
    ranked = find_label_issues(labels=labels, pred_probs=pred_probs,
                               return_indices_ranked_by="self_confidence", n_jobs=1)
    return ranked[:200]                                  # a review queue, not a delete list

if __name__ == "__main__":                               # spawn re-imports this module
    print(main())
Three things go wrong when you take Lab 8's cleanlab step to a real laptop and a real vendor file. First, on Windows the default n_jobs=None starts one process per physical core; without a main guard each spawned process re-imports the script, and our captured run printed the bootstrapping RuntimeError 77 times and then hung until we killed it at 100 seconds, so set n_jobs=1 or add the guard. Second, cleanlab wants integer labels 0 to K-1 in sorted class order and real probabilities, so encode the vendor's strings with searchsorted and use predict_proba, not raw scores. Third, and most important: the Google Play study 2609.25487 found that deleting the apps that three detectors agreed on did not improve the model, and loss grew as more were removed, so a flagged list is a review queue, not a delete list. Analogy: a metal detector tells you where to dig; it does not tell you to tear up the whole beach. Likely question: when is auto-delete fine? Only after a reviewed sample shows the flags are almost all real errors and the label is the true target, not a proxy like "app was removed".
