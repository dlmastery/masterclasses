# l = mean token logprob of y under pi_ref(.|x) (request only)
def calif_reward(r_ver, l, l0, l1, alpha=0.5):
    if l0 > l1:                       # degenerate band
        return r_ver if l <= l1 else 0.0
    if l < l0:  return r_ver          # quality-risk region: no bonus
    if l <= l1: return r_ver + (alpha if r_ver > 0 else 0.0)  # desired region
    return 0.0                        # likelihood-inflation region
Lines 5–7: below l0, r_ver only. From l0 to l1, add α. Above l1, score 0.

Three October papers say the same thing: how a verifier fails matters more than how often. The survey of 58 studies finds that false positives the policy can learn cause plateaus or collapse, and the top panel shows why: one false positive keeps an all-wrong group for training, and one false negative drops a useful mixed group. The side-effect paper is our route_ticket risk: a check that looks only at the returned queue passes a run that also writes a file, so add an assertion for globals and files. CaLIF is the format-reward version: plain IF-RLVR satisfied constraints while quality fell from 4.51 to 2.96, and a likelihood band under the reference policy kept quality at 4.59; think of a speed limit with a minimum as well as a maximum. A likely question is what l0 and l1 are: before RL, sample one answer with the constraint and one without, and score both under the reference policy with the request only. Chapter 5 takes these tested rewards into a full GRPO run with a verifier.
