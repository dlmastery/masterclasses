refunds_sft/vertex_sft.py · same rows, split and SYSTEM as Lab 1
import os, time
from google import genai
from google.genai import types
from common import SYSTEM
from to_gemini_jsonl import upload_lab1_split  # Lab 1 split -> JSONL
BUCKET = os.environ["TUNING_BUCKET"]           # gs://my-project-tuning
upload_lab1_split(BUCKET)   # refund_train.jsonl, refund_val.jsonl in GCS
client = genai.Client(http_options=types.HttpOptions(api_version="v1beta1"))
job = client.tunings.tune(
    base_model="gemini-3.5-flash",
    training_dataset=types.TuningDataset(gcs_uri=f"{BUCKET}/refund_train.jsonl"),
    config=types.CreateTuningJobConfig(
        tuned_model_display_name="refund-agent-v1", epoch_count=3,
        validation_dataset=types.TuningValidationDataset(
            gcs_uri=f"{BUCKET}/refund_val.jsonl"),
        adapter_size=types.AdapterSize.ADAPTER_SIZE_FOUR))
while not job.has_ended:             # property: state in JOB_STATES_ENDED
    time.sleep(60)
    job = client.tunings.get(name=job.name)
resp = client.models.generate_content(model=job.tuned_model.endpoint,
    contents="I was charged twice for order {{Order Number}}, refund one",
    config=types.GenerateContentConfig(system_instruction=SYSTEM,
        thinking_config=types.ThinkingConfig(
            thinking_level=types.ThinkingLevel.MINIMAL)))
print(job.state, resp.text)

These are the same 2,992 refund rows, the same train and test split and the same system prompt as Lab 1, but now Google runs the training. Set up once: application-default login, enable the Vertex AI API, create a bucket in the us multi-region, and export the project, the location us, the enterprise flag and the bucket. Click 1: a small helper in the repo, to_gemini_jsonl.py, writes each Lab 1 row as one Gemini SFT line, with a systemInstruction and user and model parts, and copies the train and validation files to Cloud Storage. Click 2: client.tunings.tune on gemini-3.5-flash with adapter size four and three epochs; the adapter size sets how many adapter parameters train, like the LoRA rank, and Gemini 3.5 Flash allows 1, 2, 4, 8 or 16. Click 3: poll until the job ends. The location must be the us or eu multi-region, not us-central1, or the job fails. Then read tuning_data_stats: you pay for training tokens times epochs, so truncated or dropped examples cost money and quality at the same time. Click 4: call the tuned endpoint with the same system instruction as training and thinking level MINIMAL, because the model learned from data with no thinking. Think of it as sending laundry out instead of buying a washing machine: no hardware, but you accept their sizes, their queue and no guarantee. Two more gotchas: a raw string in training_dataset raises a pydantic ValidationError, and a second concurrent job hits the global quota of one. A likely question: "When should I pick the open-weights path?" When you need the weights, control of the loss mask, multi-LoRA serving or an SLA, which managed SFT does not give: it is not a Covered Service.
