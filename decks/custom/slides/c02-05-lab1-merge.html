Merge the adapter, then assert the argmax did not change

refunds_sft/step4_merge_and_verify.py · peft 0.21.2 · transformers 5.20.2
import torch
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer
from common import refund_splits
BASE, ADAPTER = "Qwen/Qwen3-0.6B", "qwen3-0.6b-refund-lora/final"
tok = AutoTokenizer.from_pretrained(BASE)
# Merge into a bf16 (16-bit) base, never a 4-bit base.
base = AutoModelForCausalLM.from_pretrained(BASE, dtype=torch.bfloat16)
peft_model = PeftModel.from_pretrained(base, ADAPTER).eval()
test = refund_splits()["test"].select(range(20))   # 20 held-out rows
encs = [tok.apply_chat_template(r["messages"][:2],   # SYSTEM + user
            add_generation_prompt=True, enable_thinking=False,
            return_tensors="pt", return_dict=True) for r in test]
with torch.no_grad():
    ref = [peft_model(**e).logits.float() for e in encs]
merged = peft_model.merge_and_unload(safe_merge=True)  # returns the model
with torch.no_grad():
    new = [merged(**e).logits.float() for e in encs]
diff = max((a - b).abs().max().item() for a, b in zip(ref, new))
same = all(torch.equal(a.argmax(-1), b.argmax(-1)) for a, b in zip(ref, new))
print(f"max |logit diff| = {diff:.4f}  same argmax, 20 prompts: {same}")
assert same, "merge changed the argmax - do not ship"
merged.save_pretrained("qwen3-0.6b-refund-merged")  # ~1.2 GB, no peft
tok.save_pretrained("qwen3-0.6b-refund-merged")

This is step 4 of the refunds lab: we fold the 40 MB adapter into the bf16 base and prove that behaviour did not change. Load the base in bf16, because merging into 4-bit bitsandbytes layers re-quantizes, and PEFT warns: "Merge lora module to 4-bit linear may get different generations due to rounding errors." Call merge_and_unload on the PeftModel and use its return value, which is the plain transformers model with merged weights; if you call it on the base model you get "AttributeError: 'Qwen3ForCausalLM' object has no attribute 'merge_and_unload'". safe_merge=True checks the merged weights for NaNs. The prompts use the same system prompt and the same empty think block as training, on 20 held-out rows. The gate is the argmax at every prompt position: bf16 re-rounds W plus B times A times alpha over r, with alpha 32 and rank 16, so a scale of 2; logits move by about 0.06, which is one bf16 rounding step for values near 10, but the top token must stay the same. Think of it as re-typesetting a contract: the font can shift a pixel, but every word must be the same. A likely question: why not assert exact equality? Because it fails on harmless rounding, and the deployment decision is the token the model picks. The merged folder is about 1.2 GB and loads without peft.
