Chapter 02

SFT with TRL and LoRA

Train only on assistant tokens, train all linear layers, and prove the merge kept behaviour. Step 1 runs on a CPU; steps 2–5 need one GPU.

Qwen3-0.6B + LoRA r=16 trl 1.16.0 Docs TRL SFT Trainer
This chapter builds one thing end to end: the Acme refunds assistant. We take the 2,992 REFUND rows of the Bitext customer-support dataset (split into train and eval later), train Qwen3-0.6B with LoRA, merge it, prove the merge kept behaviour, and serve it. Watch the loop: the grey user tokens get label -100, which is PyTorch's ignore_index, so cross-entropy skips them; only the coral assistant tokens are in the loss. That gradient updates only the small B and A matrices, so the new weight is W plus B times A, and the base W stays frozen. The 1.67% is for rank 16 on all linear layers; other settings give other numbers. Analogy: the base model is a printed textbook, and LoRA is a thin set of sticky notes you can peel off or print in. Likely question: "Why not train the user tokens too?" Because then the model learns to write customer complaints, not refund answers. After the open-weights path we use the same data on managed Gemini tuning and on Gemma 4 with Unsloth. Next: Lab 1 starts on a laptop CPU, by printing the loss mask before any GPU time.
