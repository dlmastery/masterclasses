Rewards you can unit-test

A reward function is code. Test it with a known hack before it meets a GPU.

Acme refunds desk: refund-decision agent gold labels from the policy engine one reward: TRL 1.16.0 · OpenAI graders · Vertex Gemini RFT unit tests: Python 3.11+, CPU, no packages Docs TRL GRPO Trainer
This chapter is Lab 3: the Acme refunds desk has an agent that answers with an answer block holding decision, refund_amount and reason, and the policy engine of record gives the gold labels. We write the reward once as plain Python, unit-test it on a CPU with hand-written completions, and then run the same logic in TRL GRPO, as an OpenAI python grader, and as a Vertex Gemini RFT reward. Watch the loop: the good answer scores 1.0, but the hack and the broken answer must score 0.0, and only then does the CI check go green. Analogy: you test a smoke detector with test smoke before you trust it to guard the building. Likely question: "Why test a reward at all, it is ten lines?" Because our first draft of this exact reward paid 0.5 to a schema-less hack, and GRPO amplifies any cheap partial credit it finds.
