Interview: retrieval-augmented generation

Retrieval recall@20 is high, but the answers are still wrong. Where do you look?
Look past retrieval. Check context packing and order, and rerank to a small top-n (3–20). Find conflicting chunks. Run faithfulness checks on the generator. If the model uses distractors, train it RAFT-style with distractor documents.
How do you evaluate a RAG system?
Score retrieval and generation separately: recall@k on labeled question–chunk pairs, then faithfulness and answer correctness. Mix real queries with a synthetic set. Verify the set (closed-book leak test, humans check 5–10%). Report per slice.
When does agentic RAG not pay off?
On single-hop lookups with tight latency budgets. The loop costs 2–10x more LLM calls and more latency. Use it for multi-hop or ambiguous questions. Keep a one-shot pipeline for simple lookups.
How do you choose the chunk size?
Start at about 512 tokens with 100 overlap. Add a contextual header to each chunk. Tune on retrieval recall with a labeled set, not by eye. In Anthropic’s test, contextual embeddings + BM25 + reranking cut top-20 failures by 67%.
