Best practices

Ten SFT rules that each prevent a failure we saw in code

  • Pin versions; pass dtype.The float32 default doubles memory.
  • Prove the mask in CI.Fail on sum(mask)==0 or no stop token.
  • target_modules="all-linear"Qwen3/Llama/Gemma3 default: q, v only.
  • LR 1e-4 to 2e-4; set alpha.Three tools, three defaults (below).
  • QLoRA: nf4; merge into bf16.Default is fp4; 4-bit merges drift.
  • Select checkpoints on the task.Beats NLL by 0.71-0.85 pp; gate on adapter on/off.
  • Do not SFT new facts.Hallucination rises (2608.30987); use RAG.
  • Same think block in train and serve.Vertex: thinking_level MINIMAL.
  • Serve with multi-LoRA.Merge only for GGUF or edge.
  • Managed: check the limits.us/eu, 5,000 val cap, no SLA.
assistant_only_loss: loss on replies only. Lab 1 proves it.
all-linear, and set alpha: the defaults differ by tool.
warmup_steps: 0.03 is a ratio. warmup_ratio raises TypeError in v5.

Each rule on this slide maps to a bug we hit in the labs, so read it as a pre-flight list, not as theory. The first five protect the training run: pin the stack, prove the mask in CI, target all linear layers, set alpha yourself, and use nf4 explicitly because the transformers default is fp4. The next five protect the release: pick checkpoints on the task metric, keep facts in RAG, keep one think-block convention, serve adapters with multi-LoRA, and read the managed-tuning limits. The table is the reason for rule four: TRL CLI, PEFT and Unsloth ship different alpha defaults, so "r=16" gives an update scale of 2.0, 0.5 or 1.0 depending on the tool. Think of it like a recipe that says "one cup" when three kitchens use three cup sizes. A likely question: "Why not just pick the lowest eval loss?" Answer: the lowest-loss checkpoint is often not the best task score, which is why Lab 2 gates on the adapter off/on delta, and 2609.36569 shows generation-based selection beats NLL selection.
