QLoRA in one trainer call: NF4, double quant, paged 8-bit Adam

lab3_qlora_claims.py · trl 1.16.0 · transformers 5.20.2 · bitsandbytes 0.50.2
import torch
from datasets import load_dataset
from peft import LoraConfig
from transformers import BitsAndBytesConfig
from trl import SFTConfig, SFTTrainer
DT = torch.bfloat16 if torch.cuda.is_bf16_supported() else torch.float16  # T4: fp16
PREC = {"bf16": DT == torch.bfloat16, "fp16": DT == torch.float16}   # SFTConfig flags
print("dtype:", DT)
ds = load_dataset("json", data_files={"train": "claims_train.jsonl",
                                      "validation": "claims_val.jsonl"})
bnb = BitsAndBytesConfig(load_in_4bit=True,
    bnb_4bit_quant_type="nf4",              # default is "fp4": always set nf4
    bnb_4bit_use_double_quant=True,         # quantize the quantization constants too
    bnb_4bit_compute_dtype=DT)
args = SFTConfig(
    output_dir="qwen3-4b-claims-qlora", model_init_kwargs={"dtype": DT},
    **PREC, max_length=1024, learning_rate=1e-4, num_train_epochs=3,
    per_device_train_batch_size=4, gradient_accumulation_steps=4,  # T4: batch 2
    optim="paged_adamw_8bit",               # QLoRA paged optimizer
    eval_strategy="epoch", save_strategy="epoch", logging_steps=10, report_to="none")
trainer = SFTTrainer(
    model="Qwen/Qwen3-4B-Instruct-2507", args=args,
    train_dataset=ds["train"], eval_dataset=ds["validation"],
    quantization_config=bnb,                # trainer argument only
    peft_config=LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05,
                           target_modules="all-linear", task_type="CAUSAL_LM"))
trainer.model.print_trainable_parameters()  # step 3 checks this number
trainer.train()
trainer.save_model("qwen3-4b-claims-qlora/final")

Set nf4 and double quant. BitsAndBytesConfig defaults to fp4; the TRL CLI defaults to nf4.
Pass quantization_config to SFTTrainer only. Setting it in model_init_kwargs too raises ValueError. TRL places the model on the GPU and sets the adapter dtype.
paged_adamw_8bit keeps 8-bit Adam states. It pages them to CPU RAM only when GPU memory runs out.
T4 has no bf16. DT and PREC switch the dtype, the compute dtype and the bf16/fp16 flags together.

This is the complete QLoRA script for the Acme claims extractor: Qwen3-4B-Instruct-2507 in 4-bit, LoRA r=16 on all linear layers, and one SFTTrainer call. First band: set nf4 and double quant yourself, because BitsAndBytesConfig defaults to fp4 without double quant, while the TRL CLI defaults to nf4, so a script and a CLI run called "QLoRA" can differ. Second band: give quantization_config to the trainer only; TRL moves it into model_init_kwargs, so setting it there as well raises a ValueError, and TRL also places the model on the GPU and casts the adapter, so you need neither device_map nor prepare_model_for_kbit_training. Third band: the paged 8-bit Adam keeps small optimizer states; paging to CPU RAM happens only when a memory spike would otherwise cause an out-of-memory error, so at normal settings the states stay on the GPU. Fourth band: a T4 has no bf16, and SFTConfig defaults to bf16=True, so the DT line switches the model dtype, the compute dtype and the bf16/fp16 flags in one place; on a T4 also use batch size 2. Think of NF4 as a zip file of the weights that is decompressed one layer at a time for each matrix multiply. Likely question: "How long does it take?" Read train_runtime at the end of the log; it depends on the GPU and on the number of rows, so measure it on your data.
