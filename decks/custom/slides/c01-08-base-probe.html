import json
from openai import OpenAI      # any OpenAI-compatible server, e.g. vLLM
from grade import grade        # refunds/grade.py, the portable grader

client, MODEL = OpenAI(), "Qwen/Qwen3-4B-Instruct-2507"
rows = [json.loads(l) for l in open("eval_set.jsonl")]   # 20-50 prompts
passes = solved = 0
for row in rows:
    r = client.chat.completions.create(model=MODEL, messages=row["messages"],
                                       temperature=1.0, n=8)
    s = [grade({"output_text": c.message.content}, row) for c in r.choices]
    passes += sum(x == 1.0 for x in s)
    solved += any(x == 1.0 for x in s)
print(f"pass rate {passes / (8 * len(rows)):.2f}")
print(f"pass@8 > 0 on {solved}/{len(rows)} prompts")

This is check 3 as code. The probe samples the Acme base model 8 times per eval prompt at temperature 1.0, scores every sample with the same grade() function we keep portable, and counts two numbers. The pass rate is the share of samples that score a full 1.0; pass@8 greater than zero means at least one of the 8 samples is fully correct for that prompt. The tree is the decision. If the reward is always 0, RL has no signal: do SFT first. If the reward is already above 95%, Bedrock says RFT might be unnecessary: ship the prompt. Otherwise RFT is in range; GRPO, the usual RFT algorithm, compares the samples in a group, so it needs some passes and some fails. On the right, 4 of the 20 to 50 eval prompts are shown; the dots are illustrative: 13 of 32 samples pass, so the pass rate is 0.41, and every prompt has at least one pass. Analogy: a coach tests whether the athlete can do the move at least sometimes before planning drills. Likely question: "why temperature 1.0?" With low temperature all 8 samples are the same answer, so the probe and GRPO both see no variety. Next: chapter 2 takes the format failure to SFT with TRL and LoRA in Lab 1.
