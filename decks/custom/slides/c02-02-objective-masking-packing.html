SFT learns only from unmasked tokens, so the chat template and the mask define the task

Objective

L = −Σt log pθ(yt | y<t)

The sum skips tokens with label −100 (the ignore index).

Data quality beats size: LIMA used 1,000 curated examples.

Chat template

A Jinja template adds role markers and special tokens. SFTTrainer applies it to conversational data: messages, or prompt + completion; tool_calls and images also work.

Loss mask in TRL v1.16.0

  • completion_only_loss=None (default): prompt-completion data gets loss on the completion only.
  • assistant_only_loss=True: loss on assistant turns only. The template needs {% generation %} … {% endgeneration %}.
  • TRL patches known families (Qwen3). Vision data: since v1.15.0.
A train/serve template mismatch fails silently. For a base model such as Qwen/Qwen2.5-1.5B, set eos_token="<|im_end|>". If not, the model never learns to stop.

Packing

  • packing=True; max_length (default 1024) sets the row length.
  • packing_strategy: "bfd" (default, best-fit decreasing), "bfd_split", "wrapped".
  • padding_free=True (FlashAttention): no attention across examples.
Doc TRL SFT Trainer Paper LIMA 2305.11206
Start with the data: one conversation in the messages format. Step 1: the chat template turns it into tokens with role markers. Step 2: with assistant_only_loss, every system and user token gets label minus 100, so it adds no loss. Step 3: the loss bars appear only above the assistant tokens; the model learns to write answers, not questions. Step 4: the end-of-turn token must be inside the loss, or the model never learns to stop. Step 5: packing puts several short examples into one row; best-fit decreasing removes the padding, and padding-free attention keeps the examples separate. Analogy: packing is loading boxes into a van biggest-first. Likely question: "Does packing leak attention between examples?" Not with padding_free and FlashAttention, because the position ids restart for each example.
