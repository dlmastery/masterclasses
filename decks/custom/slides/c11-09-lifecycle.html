This slide joins the whole deck into one loop that we run again for every release. Each step moves the release token to the next stage and shows the number that the lab produced there: the pandera contract found 12 failures, the verifier kept 29 of 40 synthetic questions, margin sampling needed about 300 labels to match random sampling's 900, GroupKFold dropped the leaky 0.886 to an honest 0.602, the judge had kappa 0.58 against humans, and cleanlab flagged 223 of 225 flipped labels. At step 7 the token reaches the quality card from Lab 10, and the card already carries the hash of the eval file; add the model version and the train-set hash as two more fields, so every number traces back to its inputs. Analogy: it is a flight checklist, you run every item before every take-off, not only on the first flight. Likely question: "Do we rerun all stages for a small model change?" Yes, but most stages are cheap scripts with exit codes, so the loop costs minutes; only labelling needs new human time, and only for the new or thin slices.
