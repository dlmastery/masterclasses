# lab2_rows.py - gate the claims rows before any GPU time
import json, sys
from datasets import load_dataset
KEYS = {"loss_type", "severity", "needs_adjuster", "policy_section"}
ds = load_dataset("json", data_files={"train": "claims_train.jsonl",
                                      "validation": "claims_val.jsonl"})
print(list(ds), ds["train"].column_names)   # prompt, completion

def bad_row(r):                              # wrong keys or broken JSON
    try:
        return set(json.loads(r["completion"][0]["content"])) != KEYS
    except json.JSONDecodeError:
        return True

bad = [(s, i) for s in ds for i, r in enumerate(ds[s]) if bad_row(r)]
if bad:
    sys.exit(f"{len(bad)} bad rows, first: {bad[:5]}")
print("bad rows: 0")

One row has two columns. prompt holds the system and user turns. completion holds the JSON answer.
Prompt tokens get label -100, the ignore index of PyTorch cross-entropy. They add zero loss. TRL does this when both columns exist.
assistant_only_loss needs {% generation %} marks in the chat template. TRL adds them for Qwen3, not for Gemma 4. Prompt-completion rows need no marks.
The gate exits on a bad row, so no GPU time is lost. claims_test.jsonl never trains and never picks a checkpoint.
Lab 2 starts with the data, because the row format decides what the model learns. Each JSONL row has two columns: prompt, with the system and user turns, and completion, with the assistant's JSON answer. Export the three files from the claims system in this format; the test file has 200 rows and stays locked away for step 4. When both columns exist, TRL's completion_only_loss defaults to True, so every prompt token gets label -100, which is the ignore index of PyTorch cross-entropy, and only the JSON is in the loss. Note on the diagram: the words stay readable, they only stop counting. assistant_only_loss does the same job for conversational rows, but it needs generation marks in the chat template; TRL patches Qwen3, which is why Lab 1 can use it, but it does not patch Gemma 4, which then raises "The chat template is not training-compatible". Prompt-completion rows avoid that question for any model. Do not add a formatting_func: TRL raises "A formatting function was provided while completion_only_loss=True, which is incompatible." Analogy: an exam sheet where the question is printed and only the answer box is graded. Likely question: "What does the gate catch?"
