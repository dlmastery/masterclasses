1 · The regex never matches
Symptombrevity/gated_frac stays 1.0. The brevity reward is 0 for every sample. CauseIn a raw regex, \b is a word boundary. The pattern needs "oxed" after a boundary. On real text: []. Fixr"\\boxed\{([^{}]*)\}" gives ['8500'].
2 · The self-test passed anyway
SymptomThe CPU self-test printed the expected rewards. CauseThe test strings were not raw. \b became a backspace (\x08), and the broken pattern matches after it. FixRaw test strings: r"...so \boxed{8500}".
3 · The prompt was garbled
SymptomThe policy is told to answer in a strange format. accuracy_reward needs \boxed. CauseSYSTEM was not raw. The prompt held \x08oxed{number} (checked with repr). FixSYSTEM = r"..." and print(repr(SYSTEM)) in CI.

This bug is real: the verifier found it in our own Lab 4 code before the deck shipped. In a raw regex, backslash-b means a word boundary, so the pattern looks for "oxed" right after a boundary and never matches a real \boxed{8500}; every answer looked wrong, so the gated brevity reward paid zero. The self-test still passed, because the test strings were not raw, and Python turned backslash-b into a backspace character that the broken pattern happily matched after. The same escape also garbled the system prompt, so the model was asked for a format that accuracy_reward cannot read. Analogy: you tested the lock with a key cut from the same wrong template. Likely question: "How do I catch this class of bug?" Run every reward on a few real completions from the base model, and print repr() of every prompt string in CI.
