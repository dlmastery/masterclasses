Gotcha MCP install

Two loud MCP failures: a missing extra and a renamed SDK

1 · the import fails SymptomImportError: cannot import name 'McpToolset' from 'google.adk.tools.mcp_tool' Causemcp is not installed. ADK logs the real error only at debug level. Fixpip install "google-adk[mcp]==2.13.0"
2 · v1 server code on mcp 2.3.0 SymptomNo module named 'mcp.server.fastmcp'. This is mcp 2.x, where FastMCP was renamed to MCPServer ... CauseFastMCP is now MCPServer. host and port moved to run(). FixThe diff below, or pin mcp<2.
claims_agent/handbook_server.py · mcp 1.x → 2.x
# mcp 1.x: fails on mcp 2.3.0
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("claims-handbook-server", port=3000)
# mcp 2.x: the name changed, and host and port go to run()
from mcp.server.mcpserver import MCPServer
mcp = MCPServer("claims-handbook-server")
mcp.run(transport="streamable-http", host="127.0.0.1", port=3000)
Docs MCP SDK v2 migration
These two failures are loud, but their messages point the wrong way. Step 1: in google-adk 2.13.0, mcp is an optional extra. Without it, importing McpToolset fails with an ImportError that names McpToolset, because tools/mcp_tool/__init__.py catches the real ImportError and logs it only at debug level. Install google-adk with the mcp extra. Step 2: old tutorials use FastMCP. The mcp 2.x SDK renamed it to MCPServer, and mcp 2.3.0 raises a ModuleNotFoundError whose text tells you so; if you pass port to the constructor, you get a TypeError about an unexpected keyword argument. Step 3: the fix is a three-line diff. Step 4: in 2.x, the constructor takes only the name, and host and port go to run(). If you cannot migrate yet, pin mcp below 2. Think of a shop that moved to a new address: the old sign says "closed", but the shop is open around the corner. A likely question: "Does ADK need mcp 2.x?" No, ADK accepts mcp from 1.24 up to 3, so the server code decides the version you pin.
