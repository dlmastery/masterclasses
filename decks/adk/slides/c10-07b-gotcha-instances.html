Each agent_engine deploy without an id makes a new instance

SymptomTwo instances exist. The client still talks to the old one. CauseWithout --agent_engine_id, every deploy creates a new instance. A failed update deletes only a newly created one. FixPass --agent_engine_id on every update.
labs/adk/c10-acme-hr/ship.sh · excerpt
adk deploy agent_engine --project=$PROJECT --region=$REGION \
  --agent_engine_id=$AGENT_ENGINE_ID hr_agent
The second default is on Agent Runtime. Press once: CI runs adk deploy agent_engine three times without an instance id; each run creates a new instance, so we end with three instances while the HR web client still talks to instance 1 on revision 1. Press again: the cause is in cli_deploy.py: without --agent_engine_id, every deploy creates a new instance, and if an update fails, only a newly created instance is deleted, so the old ones stay and keep billing. Press again: pass --agent_engine_id on every update and the deploy updates instance 1 in place; the client gets revision 3 at the same address. Analogy: the instance id is a house number; without it the mover builds a new house each time instead of furnishing the one you live in. Likely question: "How do I clean up the extra instances?" Delete them in the console or with the Agent Platform SDK, and put the id in your CI variables so it cannot be forgotten.
