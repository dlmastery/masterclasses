The second rules slide is structure, plus two things you never do. Step 1: at most one terminal output, so end nodes yield only a message, or you add a JoinNode before one final node; Lab 3.3 works because page_oncall emits only a message. Use single_turn or task nodes in graphs, and chat only right after START. Step 2: keep topology and prompts in YAML and logic and schemas in Python; the diagram shows who reviews what: PM and legal read the YAML diff, CI runs pytest on agent.py, and the loader reads both from your repo. Step 3, the Never card: never build or load YAML from user input, because name: references import Python objects, and never swallow exceptions inside a node with a broad except, because the engine then cannot see the failure; Chapter 5 shows the retries and human-in-the-loop that this breaks. Analogy: the YAML is a signed blueprint; you would not let a visitor hand the builders a new one. A likely question: "Can the Visual Builder write YAML safely?" Its endpoints accept only .yaml files, reject paths with .. and block keys like args, but treat any generated YAML as code and review it.
