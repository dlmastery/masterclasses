class RefundCase(BaseModel):
  order_id: str
  amount: float
  days_since_delivery: int
  eligible: bool

def parse_request(node_input: str) -> str:       # -> "A-1001"
  return next(t for t in node_input.split()
              if t.upper().startswith("A-")).upper()

def check_policy(ctx: Context, node_input: str) -> RefundCase:
  order = ORDERS[node_input]
  eligible = order["days_since_delivery"] <= 30   # 30-day policy
  ctx.state["refund_case"] = {"order_id": node_input, **order,
                              "eligible": eligible}
  return RefundCase(order_id=node_input, eligible=eligible, **order)

Here are the two function nodes of the refund chain; the full file is labs/adk/c03-refund-flow/refund_flow/agent.py. A plain Python function becomes a FunctionNode, and its type hints become its input and output schemas. Step 1: parse_request returns the string "A-1001", and the edge hands it to check_policy as node_input. Step 2: check_policy returns a typed RefundCase. Because both ends of that edge declare a type, the Workflow checks that they match when you build it. The **order spread works because RefundCase ignores the extra category key. Step 3: check_policy also writes refund_case into ctx.state; that write goes into the event's state_delta, and the next slide's prompt reads it. Think of the edge as the conveyor belt and state as the noticeboard: the belt carries one item to the next station, and the noticeboard is for facts every station may read. A likely question: "Why both return and write state?" The return value is typed and checked; the state key is what a prompt template can read.
