Fan-out runs branches in parallel, and a JoinNode waits for every one of them

  • A tuple of nodes inside a chain is a parallel fan-out.
  • JoinNode sets _requires_all_predecessors → True. It emits one dict keyed by predecessor node name.
  • Compact form: (START, (word_count, shout), join, report). Then report reads node_input['shout'] and node_input['word_count'].
  • Without a join, the successor runs once per predecessor (sample multi_triggers).
  • Map over a runtime list: @node(parallel_worker=True) or Agent(..., parallel_worker=True). One run per item. The next node gets a list.
  • max_parallel_workers caps the per-item concurrency. Here it is 2: two run, two wait.
  • Codelab level L4a sizes the fan-out at runtime. Level L2a uses a fixed tuple and a JoinNode.

Workflow(max_concurrency=2) caps graph-scheduled nodes only. ctx.run_node children are exempt: “throttling them would cause deadlock”.

0–1model calls per level, codelab L0–L2b
5–30model calls per run, L4b fan-out

Fixes: 2.8 counts START as a satisfied join predecessor. 2.13 makes a JoinNode in a loop wait for each iteration's predecessors.

from google.adk import Event, Workflow
from google.adk.workflow import JoinNode, node
def make_uppercase(node_input: str): return node_input.upper()
def count_characters(node_input: str): return len(node_input)
def reverse_string(node_input: str): return node_input[::-1]
join_node = JoinNode(name="join_for_results")
async def aggregate(node_input: dict):
    yield Event(message=f"Upper: {node_input['make_uppercase']} | "
                        f"Len: {node_input['count_characters']} | "
                        f"Rev: {node_input['reverse_string']}")

root_agent = Workflow(name="root_agent", edges=[(
    "START", (make_uppercase, count_characters, reverse_string),
    join_node, aggregate)])

@node(parallel_worker=True)          # map: one run per list item
def make_upper_case(node_input: str):
    yield node_input.upper()
Pitfall: two parallel branches that write the same state key race. Give each branch its own key, or pass data through node outputs into the join. Interview angle: parallelism multiplies token cost, so justify it with latency or with independent sources.
Step 1 is the barrier. The three functions start together and finish at different times: 1.0, 1.8 and 2.6 seconds in the animation. Each output waits at the JoinNode gate, and the gate opens only when the last one arrives. Step 2: the gate emits one dict keyed by predecessor node name, and aggregate reads the three keys. Step 3 is the other parallel tool, parallel_worker: the list size is known only at run time, and a cap of two workers makes two items wait. Step 4 covers the concurrency caps and the cost: the codelab's simple levels make 0 to 1 model calls, the recursive fan-out makes 5 to 30. Analogy: a restaurant pass. The waiter takes the table's plates only when every dish of the order is ready. Likely question: "What happens if one branch fails?" The failure shows up downstream at the join, away from its cause, so the docs say to put a RetryConfig on any branch node that can fail.
