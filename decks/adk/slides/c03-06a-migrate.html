Port SequentialAgent to a Workflow with one chain tuple

labs/adk/c03-migrate-sequential/v2/support_desk/agent.py
from google.adk import Agent, Workflow
from support_desk.tools import lookup_order   # same tool as 1.x

intake = Agent(name="intake_agent", mode="single_turn",
               model="gemini-3.5-flash", tools=[lookup_order],
               instruction="Look up the order, then "
                           "summarize the finding.")
synth = Agent(name="synthesizer_agent", mode="single_turn",
              model="gemini-3.5-flash",
              instruction="Write the customer reply from the "
                          "intake finding.",
              include_contents="default")   # sees upstream turns

root_agent = Workflow(name="support_workflow",
                      edges=[("START", intake, synth)])

Many teams still have 1.x pipelines, so this build step ports the Acme support pipeline. Right: the 1.x version. SequentialAgent still runs in 2.13.0 but is deprecated. Left: the 2.x version in labs/adk/c03-migrate-sequential/v2. Step 1: the Workflow with one chain tuple START, intake, synth replaces sub_agents; the lookup_order tool does not change. Step 2: Agent replaces LlmAgent, and mode="single_turn" makes each node a one-shot worker; it is also what an agent node resolves to inside a graph when you leave mode out. Step 3: include_contents="default" on the synthesizer. Inside a Workflow, single_turn nodes default to include_contents none, so without this line the second agent never sees the user's ticket. The next slide shows the exact request it gets. Analogy: moving house, the furniture (the agents and tools) stays, only the floor plan (the graph) changes. A likely question: "Can a Workflow be a sub_agent?" No: Workflow is a BaseNode, not a BaseAgent, so put it at the root.
