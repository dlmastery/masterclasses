Start adk api_server in the lab folder, the one that holds agents/, and drive it with curl from a second terminal; the full list of calls is in rest_calls.sh. Click 1: list-apps shows claims_api, because the server names each App after its folder, so name the App like its folder. Click 2: create the session with a business key, claim-77, for user u-tom, and seed state with the channel. The URL path is the hierarchy: app, then user, then session. Click 3: if you skip the create call, /run answers with HTTP 404 "Session not found: claim-77", unless you start the server with --auto_create_session. Analogy: the URL is a filing path: cabinet, drawer, folder. A likely question: "Does api_server load .env?" Yes, like adk run and adk web it reads agents/claims_api/.env.
