@node(parameter_binding="node_input")   # deterministic, no LLM
def policy_math(line: str, limit: float) -> bool:
  amount = float(line.rsplit("$", 1)[1])
  return amount <= limit

# in orchestrate, after the gather:

        v.status = "ok"

The model said FLAG for "Hotel Berlin 1 night $240", but the cap is 250 dollars a night. policy_math is a plain function node with no LLM: it takes the number after the dollar sign and compares it with the limit, so an LLM mistake on a number cannot block a valid claim. It is decorated with @node(parameter_binding="node_input"), so the keys of the dict you pass as node_input bind to the parameters line and limit. The orchestrator calls it with ctx.run_node, the same way it called the auditors, so the call is recorded and replayed on resume. 240 is at most 250, so code flips the verdict to OK with a fixed reason. The output is illustrative and wrapped to fit: two lines pass and only the wine is flagged, because alcohol is not reimbursable. The finished verdicts go to state under flagged and to the output of the node. A likely question: "Why not ask the model to double-check?" A second model call can make the same mistake; a comparison in code cannot. The codelab level L4b goes further with recursive spawning, bounded by a MAX_DEPTH check in code.
