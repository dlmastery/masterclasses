An after_tool_callback turns a wrong amount into an error

labs/adk/lab9-refund-eval/refund_agent/agent.py · excerpt
class OutcomeContractPlugin(BasePlugin):
    RECOVERY = {"lookup_order": ["escalate_to_human"]}
    def __init__(self):
        super().__init__(name="outcome_contracts")
    async def after_tool_callback(self, *, tool, tool_args,
                                  tool_context, result):
        if tool.name != "lookup_order":
            return None                  # None: keep the tool result
        if result.get("status") != "success":
            return None
        amount = result.get("amount")
        if isinstance(amount, (int, float)) and amount > 0:
            return None
        return {"status": "error", "violated": "amount > 0",
                "recovery_tools": self.RECOVERY["lookup_order"]}

Return None: ADK keeps the tool result.

The contract: a looked-up amount must be above 0.

Return a dict: it replaces the result the model sees.

Name the next tool. Without it the gain disappears.

The fix is a check in code, not a line in the prompt. A plugin's after_tool_callback runs after every tool call with the tool, its args, the context and the result. Returning None keeps the result, so every other tool and every error passes through untouched. For lookup_order with status success, the contract is simple: the amount must be a number above 0. If it is not, the callback returns a dict, and that dict replaces the result the model sees: status error, the violated contract, and recovery_tools, the next tool to call. The Outcome Monitors paper, arXiv 2608.19303, shows the receipt must name a recovery tool: on the ToolMaze tool-use benchmark success went from 10.9 to 28.1 percent, and removing the tool list removed the gain. Analogy: a smoke detector wired into the pipe, with the exit sign lit. A likely question: "Why a plugin and not an agent callback?" A plugin on the App applies to every agent and tool in the app, so one contract covers the whole refund team.
