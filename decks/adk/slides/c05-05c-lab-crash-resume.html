Docs adk.dev Resume
The last step of Lab 5B is the crash case. Try it: press Ctrl-C during attempt 2 of "resume yes", then run "python -m payouts.app continue -". The continue branch passes only the invocation id and no new message; the Runner then continues the interrupted invocation from the checkpoint events in payouts.db. That works only because the App sets ResumabilityConfig(is_resumable=True); without it, the same call fails with "ValueError: Running an agent requires a new_message or a resumable app." kyc_lookup replays and the log still has one line, and the attempt counter starts again, so pay gets its full retry budget back. The table separates the two kinds of resume that people mix up. Answering a pause sends a FunctionResponse, needs no ResumabilityConfig, and works from adk run and adk web. Continuing after a crash sends no message, needs ResumabilityConfig and your own Runner: the docs say resuming from the ADK Web UI or the CLI is not supported. Think of the checkpoint as the bookmark from the chapter opener: you go back to the page you were on, and you read that page again. A likely question: "Then why do I still need an idempotency key?" Because resume is at-least-once: a crash between the charge and the saved event re-runs pay; the retry gotcha comes back to this.
