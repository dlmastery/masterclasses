This build slide hardens the pay node from step 2. The exceptions list matches exception class names along the MRO. A timeout raises NodeTimeoutError, which is not a ConnectionError, so with only ConnectionError in the list a 2-second timeout ends the node on attempt 1; the error text is "Node 'pay' timed out after 2.0 seconds." Add the string "NodeTimeoutError" and the timeout is retried like the 503. The right side is about jitter. Our lab sets jitter=0.0, so the wait before try 2 is exactly 0.5 seconds every time, which is what you want in a test. RetryConfig() with no arguments resolves to max_attempts=5, initial_delay=1.0, max_delay=60, backoff_factor=2.0 and jitter=1.0, so the wait before try 2 lands anywhere between 0 and 2 seconds; keep jitter on in production to spread load. Think of jitter as staggering the start times of runners so they do not all hit the gateway at the same second. A likely question: "Why a string and not the class?" Both match by name; the string saves an import of an internal error class.
