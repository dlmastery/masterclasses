Two more things that do not cross an A2A boundary the way you expect. First, session state never crosses in either direction: the remote agent's output_key lands in the remote session, so triage reads None. This is by design, issue 6854, and since 2.12.0 ADK logs a warning when it drops a state-only event. Send the data in the message text or an artifact, parse the reply on the triage side, and test behind a real to_a2a server, because in one process everything appears to work. Second, issue 6461 is open: inbound A2A messages become role='user', so a peer can send confirmed true for a pending tool confirmation, adk_request_confirmation, which is how ADK asks the user to approve a tool call; the v2.8.0 guard was reverted. Keep confirmation-gated tools off agents you serve over A2A. Analogy: another department cannot read your notes, and a note from them is not a signature from your manager. A likely question: "Does a test in one process catch the state bug?" No, in-process everything works, so test behind a real to_a2a server.
