Metric: token_usage_v1, Status: NOT_EVALUATED, Score: 2843.0
$ echo "exit code: $?"

Exit 1 if any case fails or none ran. CI stops before deploy.

Before 2.13.0 it always exited 0. Old pipelines shipped red runs.

token_usage_v1 and the other efficiency metrics never pass or fail.

Step ten: run the evalset from the shell and look at the exit code, because the exit code is the only thing CI reads. We use the broken agent from the config slide, without the 500 dollar sentence: one case fails, and since 2.13.0 adk eval exits 1 when any case fails or when no case ran, so the pipeline stops before deploy. The source is cli_tools_click.py lines 1604 to 1613, and the 2.13.0 changelog lists it. Before 2.13.0 it printed the red result and still exited 0, so older pipelines deployed the failing agent; think of a smoke alarm that beeped but did not call anyone. The efficiency metrics, such as token_usage_v1, are added automatically and show NOT_EVALUATED: they report cost, they never fail a run. A likely question: "How do I rerun one case?" Append a colon and the eval id to the evalset path, for example refund.evalset.json:large_refund_escalates.
