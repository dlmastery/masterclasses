Three layers: filter hides, confirm gates, server checks.

Still step 2: some calls are allowed, but only with a human yes. Step 1: payout_needs_human is a plain function. ADK calls it with the arguments of the call, and with **kwargs one rule covers every tool of the toolset; 1,800 dollars is over the limit, so it returns True. Step 2: require_confirmation on the toolset attaches the rule to every tool it exposes. Step 3: run it. The model looks up the claim first, as the instruction says, then ADK emits adk_request_confirmation before approve_claim runs, and adk web shows a Confirm dialog. On Confirm the tool runs; on Reject the model gets "This tool call is rejected." Step 4: the rule sees the arguments the model sent, so if the model sends 999, no human is asked. That is why the server keeps its own limit. Least privilege has three layers: the filter hides, the confirmation gates, and the server checks. Think of a bank teller: big withdrawals need a manager's signature, and the vault still has its own lock. A likely question: "Where does the approval go in production?" The reply is a function response with the same id as the adk_request_confirmation call, so a Slack bot or a web form can send it.
