import logging, sys
from mcp.server.mcpserver import MCPServer
# stdout carries JSON-RPC: log to stderr only
logging.basicConfig(stream=sys.stderr, level=logging.INFO)
mcp = MCPServer("claims-server")
CLAIMS = {"CLM-1001": {"status": "open", "amount": 1800.0}}
@mcp.tool()
def get_claim(claim_id: str) -> dict:
    """Return status and amount (USD) for a claim id like CLM-1001."""
    if claim_id not in CLAIMS:
        return {"status": "error",
                "message": f"Unknown claim {claim_id}."}
    return {"status": "ok", "claim_id": claim_id, **CLAIMS[claim_id]}
# ... approve_claim and purge_claim: next slide
if __name__ == "__main__":
    mcp.run()  # transport defaults to "stdio"

This is step 1 of the Acme claims desk lab: a small MCP server with claim tools that the agent starts as a child process. The full file is labs/adk/lab6-acme-claims-desk/claims_agent/claims_server.py; the slide shows only the lines that carry the idea. Step 1, the import: mcp 2.x renamed FastMCP to MCPServer, so old tutorials fail with an import error. Step 2, logging goes to stderr, because over stdio the stdout pipe carries the JSON-RPC messages and nothing else. Step 3, the tool: the decorator turns the function into an MCP tool, and the docstring and type hints become its schema; an unknown id gives a structured error, not an exception. Step 4, mcp.run() picks stdio by default. Run the server alone with stdin closed: it starts, reads the end of its input and exits, and any import error shows in the terminal. Think of stdout as a phone line that a fax machine uses: if you say one word into it, the fax fails. A likely question: "Do I start this server myself?" No, McpToolset starts it; you run it alone only to check it imports.
