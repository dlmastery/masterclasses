Five calls in flight, a fresh session each, one dict in your process

labs/adk/c04-dor-batch/dor.py · excerpt · google-adk 2.13.0
sem = asyncio.Semaphore(5)          # PANW: "batches of five"

async def answer(q: str) -> tuple[str, str]:
  async with sem:                   # at most 5 calls in flight
    s = await runner.session_service.create_session(
        app_name="dor", user_id="dor")         # fresh session
    msg = types.Content(role="user", parts=[types.Part(text=q)])
    final = ""
    async for ev in runner.run_async(
        user_id="dor", session_id=s.id, new_message=msg):
      if ev.is_final_response() and ev.content and ev.content.parts:
        final = "".join(p.text or "" for p in ev.content.parts)
    return q, final                 # context never grows

async def build_dor(questions: list[str]) -> dict[str, str]:
  return dict(await asyncio.gather(*(answer(q) for q in questions)))

Here is the PANW pattern on google-adk 2.13.0, the full file is labs/adk/c04-dor-batch/dor.py. The orchestrator is ordinary async Python and the agent answers exactly one question per call. Semaphore(5) is PANW's batch of five: the sixth call waits until one of the five finishes, which is what the slots on the right show. Each call creates a fresh session, so no history piles up and the context never grows; that is the fix for the Out of Memory error. The loop over run_async keeps only the final response text. asyncio.gather collects every pair into one dict in your process: the document lives in your code, not in the agent's context. The animation runs all 140 questions through five slots; the answered count only rises, and in flight never goes above five. Analogy: a deli counter with five clerks and a ticket machine. A likely question: "Why not a ParallelAgent or a workflow fan-out?" You can, but for a flat list of independent questions a semaphore and gather is the smallest thing that works, and it runs the same against a deployed Agent Engine endpoint. Model ids in the lab file are pinned to gemini-3.5-flash; PANW used Gemini 2.5 Flash.
