Two frontmatter mistakes stop the refund skill from loading

skills/refund_policy/SKILL.md
# folder: skills/refund_policy/    <- snake_case
---
name: refund-policy
description: Decide refund eligibility for Acme orders.
metadata:
  adk_additional_tools: lookup_order   # a string
---
skills/refund-policy/SKILL.md
# folder: skills/refund-policy/    = name:
---
name: refund-policy        # kebab-case, max 64 chars
description: Decide refund eligibility for Acme orders.
metadata:
  adk_additional_tools:    # a YAML list
    - lookup_order
---
Error 1ValueError: Skill name 'refund-policy' does not match directory name 'refund_policy'. FixRename the folder to refund-policy/. Names are kebab-case; description ≤ 1024 chars. Error 2ValueError: adk_additional_tools must be a list of strings FixWrite a YAML list, even for one tool. Each name matches a function in additional_tools=.

Both errors come from the skill loader, before the model ever sees the skill. Error one: load_skill_from_dir compares the folder name with the frontmatter name, and raises "ValueError: Skill name 'refund-policy' does not match directory name 'refund_policy'." Names must be lowercase kebab-case unless you turn on the experimental SNAKE_CASE_SKILL_NAME feature; the name has at most 64 characters and the description at most 1024. Error two: adk_additional_tools must be a YAML list even for one tool; a plain string raises "ValueError: adk_additional_tools must be a list of strings". Each name in the list must match a function you pass in additional_tools on the SkillToolset. Analogy: a skill folder is a labelled drawer; if the label and the drawer disagree, the clerk refuses to open it. A likely question: "Why not just accept snake_case?" The Agent Skills spec uses kebab-case names so the same folder works in every runtime that reads skills.
