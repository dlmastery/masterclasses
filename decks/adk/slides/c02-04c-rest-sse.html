Same body as /run, same session claim-77, new question. Click 1: curl -N switches off output buffering, so each line shows the moment the server sends it. Click 2: /run_sse sends one data line per event while the turn runs: the tool call, the tool result, then the answer, three events, and the counter follows them. Click 3: add "streaming": true to the body and the server also sends partial text chunks, so expect more lines; your client must then join the partial text. Analogy: /run is a letter that arrives when the turn is done; /run_sse is a phone call that you hear as it happens. On Windows the single-quoted JSON breaks in PowerShell, so use Git Bash or WSL. A likely question: "Which one does a chat UI use?" /run_sse, because the user sees the tool call and the answer as they happen.
