How does the spec become a tool? Step 1: set operation_id in FastAPI, here getClaimStatus. Without it, FastAPI generates a long id from the function and path, and the tool name changes whenever the route changes. Step 2: ADK's operation parser makes one tool per operation and names it snake_case of the operationId, cut to 60 characters, so getClaimStatus becomes get_claim_status. tool_filter must use that generated name, not the operationId; if you are not sure, print [t.name for t in await claims_status.get_tools()]. Step 3: the servers entry in the spec gives the base URL, and the model calls get_claim_status with the claim id. With a wrong key, the tool returns the 401 as an execution error that the model can read. Think of the operationId as the item number on a menu: keep it stable, and the order always reaches the right dish. A likely question: "What if my API needs camelCase parameters?" Pass preserve_property_names=True; otherwise ADK converts them to snake_case.
