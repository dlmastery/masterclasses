These three bugs hit the ACME-GmbH payout after the retry lab works. The first: a node body that catches Exception and returns "error" turns the 503 into a normal output, so RetryConfig sees a successful node and the payout ends on attempt 1. The 2.0 migration guide says not to wrap node bodies in except Exception for exactly this reason. Let transient errors raise; the retry config decides what to retry. The last click is the stronger rule: never catch BaseException. ADK raises NodeInterruptedError, a BaseException, to interrupt a node, and the source says it does so "so user code cannot accidentally catch it with except Exception". A bare except or except BaseException would swallow the interrupt too. Think of a smoke alarm with a pillow on it: the fire is still there, only the alarm is quiet. A likely question: "Where do I log the error then?" Log and re-raise, or use a plugin or callback; do not return a value from the except block.
