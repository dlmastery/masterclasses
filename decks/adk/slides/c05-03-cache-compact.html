Cache the stable prefix and compact the tail

app.py · adk.dev/context/caching + /compaction

from google.adk.apps.app import App, EventsCompactionConfig
from google.adk.agents.context_cache_config import ContextCacheConfig
app = App(
    name="support_app", root_agent=root_agent,  # static_instruction first
    context_cache_config=ContextCacheConfig(          # Python 1.15+
        min_tokens=2048, ttl_seconds=600, cache_intervals=5),
    events_compaction_config=EventsCompactionConfig(  # Python 1.16+
        token_threshold=4000,    # compact when exceeded
        event_retention_size=5,  # keep the last 5 raw events
        # or sliding window: compaction_interval=3, overlap_size=1
    ),
)

Cache defaults: min_tokens=0, ttl_seconds=1800, cache_intervals=10. ADK 2.8 added Anthropic cache breakpoints. If you set both compaction modes, token-based wins. ContextFilterPlugin(num_invocations_to_keep=N) trims history before each model call.

  • Manus: "the KV-cache hit rate is the single most important metric for a production-stage AI agent." Input to output is about 100:1.
  • Keep the prefix stable. Put no second-level timestamps in it.
  • Append only. Serialize deterministically (stable JSON key order).
  • Mask tools. Do not remove them in the middle of a task.
  • Offload big results: Deep Agents write tool output over 20,000 tokens to a file and keep a path plus a 10-line preview.
A timestamp in the system instruction makes every call a cache miss. Each compaction also rewrites the prefix once, so compact rarely and in large chunks.

The bar is the context window of one model call. The hatched block on the left is the stable prefix: static_instruction and the tool definitions, which the provider caches. Step 1: events append on the right, the prefix does not change, and the meter stays on HIT; Manus measured cached input at $0.30 per million tokens against $3 uncached on Claude Sonnet, a 10x gap, and agents read about 100 tokens for each token they write. Step 2: one timestamp at the front changes every byte after it, so every call is a miss. Step 3: the tail reaches token_threshold=4000, the old events fold into one summary event, and the last five stay raw; the raw originals stay in session storage. ADK also fixed two safety bugs here: compaction no longer drops pending function calls (1.27) or HITL events (1.34), and since 2.2 the summary includes thoughts and tool calls. Analogy: the prefix is a printed letterhead; change one character in it and you must reprint the whole stack. Likely question: "Why not compact on every turn?" Each compaction rewrites the prefix once, so it costs one cache miss; compact rarely and in large chunks.
