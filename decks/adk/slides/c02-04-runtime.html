The App packages the agent; the Runner turns each yielded event into committed state

main.py · runs inside async def main()

from google.adk.apps import App
from google.adk.runners import InMemoryRunner
from google.genai import types

app = App(name="time_app", root_agent=root_agent)
runner = InMemoryRunner(app=app)
session = await runner.session_service.create_session(
    app_name="time_app", user_id="u1", state={"user:name": "Ada"})
msg = types.Content(role="user",
                    parts=[types.Part(text="Time in Paris?")])
async for event in runner.run_async(
        user_id="u1", session_id=session.id, new_message=msg):
    for call in event.get_function_calls():
        print("TOOL CALL", call.name, call.args)
    if event.is_final_response() and event.content:
        print(event.author, ":", event.content.parts[0].text)
A state change is “only guaranteed to be persisted” after the Runner processes the event that carries its state_delta.
Never edit session.state on a session fetched outside an invocation: it “will likely NOT be saved”.

The App is the deployable unit: it holds the root node and the app-wide settings for plugins, compaction, context caching and resumability, and it scopes app: state. The Runner takes keyword-only arguments, and only session_service is required; in 2.0 you can also pass node= to run any node or Workflow directly. Walk the code with the steps: create_session seeds user:name, run_async yields events, and each event's state_delta is committed by the Runner before your loop sees it. Analogy: the Runner is a bank clerk, and a transfer counts only after the clerk stamps the slip, not when you write it. At the end of the invocation the temp: key is gone, but the user: keys stay. Likely question: "Which session service in production?" DatabaseSessionService or VertexAiSessionService; InMemorySessionService loses everything on restart and, since 2.9, raises SessionNotFoundError for unknown sessions.
