arXiv 2609.35381 · MCP error messages written for developers
An error message is a prompt: the model reads it and tries to do what it says. arXiv 2609.35381 (2026-09-28) audited 3,001 errors from 150 popular MCP servers; 949 of them prescribe a next step, and 62 of 67 credential steps ask for a terminal command, a config change or a web page, which a tool-only agent cannot do. Step 1 shows that style on our own server: "Run claims-cli login". With a terminal step, mean recovery from an expired credential was 45%. Step 2: add a login tool and name it the way the model sees it: with tool_name_prefix="claims" that is claims_login, and login must also go into tool_filter. Naming a login tool lifted recovery to 84%. Step 3: for rate limits, "Wait before retrying." gave 6% recovery, and naming the call to repeat gave 88%. The study used five OpenAI models on BFCL-style tasks, so treat the numbers as direction, not as a guarantee for Gemini. Think of a note on a locked door: "Ask reception for a key" helps a person, but a robot needs "press button 2". A likely question: "Why not just retry in code?" Do both: back off in code for 429s, and still tell the model which call to repeat.
