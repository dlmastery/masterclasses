Production on Google Cloud and open challenges

AgentOps ships tool-using agents as versioned artefacts: code, prompt, tools, model and config. Trajectory-aware evals gate each release. Traces and cost and latency SLOs operate it, and production failures become new tests.

“a subcategory of GenAIOps that focuses on the efficient operationalization of Agents”

This chapter takes the agent from a laptop to production on Google Cloud. Read the definition aloud: AgentOps versions code, prompt, tools, model and config together, because a change to any one of them changes the trajectory. Step 1 shows Google's own definition from the Agents Companion whitepaper: AgentOps is a subcategory of GenAIOps. Step 2 lights two shortcut arcs: rollback goes from Observe straight back to Deploy, and "traces become tests" sends every production failure into the eval set, which the Agent Quality whitepaper calls the flywheel. Analogy: an airline does not only fly planes; it logs every incident, and each incident becomes a new item on the pre-flight checklist. Likely student question: "How is this different from MLOps?" MLOps versions models and data; AgentOps must also version prompts and tool schemas, grade whole trajectories and govern side effects with identity, guardrails and human approval.
