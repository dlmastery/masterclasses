Step eight: the body of refund_policy_score. It scores each invocation, meaning each turn, with its own PerInvocationResult and status. If no invocations ran, it returns an empty EvaluationResult, which ADK reports as NOT_EVALUATED; never turn "nothing ran" into a pass. The overall score is the minimum, so one bad turn fails a three-turn chat, and the function sets overall_eval_status explicitly: a metric that returns only a score is reported as not passed, as the custom_metric sample README warns. Analogy: a chain is as strong as its weakest link, so the case score is the weakest turn. A likely question: "Why min and not the mean?" Because the rule is absolute: one refund of 820 dollars is one too many, and a mean of 0.67 would hide it behind a threshold.
