plan_and_execute.py · sketch from documented primitives

@node(rerun_on_resume=True)
async def plan_and_execute(ctx: Context, goal: str):
    # planner_agent: output_schema=Plan(steps: list[str])
    plan = await ctx.run_node(planner_agent, goal)
    results = []
    for step in plan.steps:
        out = await ctx.run_node(executor_agent, step)
        results.append(out)
    return await ctx.run_node(synthesizer_agent,
        {"goal": goal, "results": results})

Long-horizon harness (Anthropic, 2025-11-26)

Session 1 writes init.sh, claude-progress.txt, a JSON list of 200+ features (all passes:false) and a first commit. Each later session reads the progress file and the git log, runs a smoke test, builds ONE feature, tests it end to end, flips passes and commits. Why JSON: the model is "less likely to overwrite it".

The same harness in ADK 2.0

  • Planner node, then a dynamic @node loop over the feature list
  • A verifier node after each feature
  • ResumabilityConfig and rerun_on_resume for durability
  • AgentEngineSandboxCodeExecutor: no network, 100 MB I/O, 14-day state
  • Agent Runtime: long-running operations up to 7 days
  • adk deploy --trigger_sources pubsub,eventarc for ambient agents
A plain tool loop gives a shallow agent: it plans badly and drifts on long tasks. Deep agents move state out of the prompt into files and a todo list, and move exploration into subagents. Press once: the initializer session writes the harness files, including a feature list where every feature fails. Press three times: each new session starts with an empty context, reads the files, runs a smoke test, finishes exactly one feature, turns one red dot green and commits. The last press maps this to ADK 2.0: a planner node, a dynamic loop, a sandbox and resume. Analogy: shift workers in a factory read the shift log, finish one job and write the log for the next shift. Interview question: "How do you keep a 6-hour agent on track?" Keep progress outside the context, do one feature per session, run a smoke test first, use a separate evaluator, and checkpoint every step.
