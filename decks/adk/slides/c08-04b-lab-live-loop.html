# ... runner + create_session("call-1"): see the lab file
q = LiveRequestQueue()                    # one queue per call
q.send_content(types.Content(role="user", parts=[
    types.Part(text="What's my balance on account A-3310?")]))
pcm = bytearray()
try:
    async for ev in runner.run_live(user_id="cust-42",
            session_id="call-1", live_request_queue=q,
            run_config=cfg):
        t = ev.output_transcription
        if t and t.text: print("agent:", t.text)
        for p in (ev.content.parts if ev.content else []):
            if p.inline_data: pcm += p.inline_data.data
        if ev.turn_complete: break
finally: q.close()
save_wav(bytes(pcm))

This is the live loop. Before it, the lab file builds the Runner and creates session "call-1", because run_live needs an existing session; without it you get "ValueError: Session not found". Press once: a LiveRequestQueue is the phone line for one call; send_content puts the text question on it, as a stand-in for the microphone; a real call streams 16 kHz PCM chunks with send_realtime. Press again: runner.run_live is an async generator; the Live model hears the question and calls get_balance. Press again: each event can carry transcript text and audio bytes; we print the text, collect the PCM and break on turn_complete. Press again: close the queue in finally, because a closed queue cannot be reused, and save 153,600 bytes, which is 3.2 seconds at 24 kHz, as answer.wav. Think of LiveRequestQueue as a phone line you hang up with close(), so you dial a new one for every call. A likely question: "Can I guard what the caller says?" Model callbacks run in live mode in 2.13, but a before_model_callback sees only the transcript, after the model already heard the audio. For a mic in the browser, run adk web --no-reload; Windows needs --no-reload.
