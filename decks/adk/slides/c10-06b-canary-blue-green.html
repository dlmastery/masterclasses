The canary on the last slide uses Cloud Run revisions; Agent Runtime does not give you that. Press once: the research found no traffic-splitting or revision-rollback feature for Agent Runtime, so do not look for a percentage slider. Press again: deploy a second Agent Runtime resource for the new version and run the evals against it while the old one stays live. Press again: the client switches to the new resource id; to roll back, it switches back, so keep the old resource until the new one has soaked. Press again: two rules from production. Anthropic's 2026-04-23 postmortem added soak periods and gradual rollout for every system-prompt change. And never shadow-test a candidate that has live write tools: a shadow call to an HR or refund write tool is a real write, so stub those tools. Analogy: blue/green is two stages in one theatre; the audience walks to the second stage only when it is ready. Likely question: "How does the client switch?" Keep the resource id in config, not in code, so the switch is a config change.
