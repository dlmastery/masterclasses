ADK 2.0 replaced the agent tree with a graph engine and kept the 1.x features as its base

The docs call 2.0 the move “from a hierarchical agent executor to a graph-based execution engine”. “Agents, Tools, and Functions are evaluated as individual nodes within a workflow graph.”

In Python, BaseAgent subclasses BaseNode. One runtime runs every node.

  • 1.x: a root LlmAgent holds sub_agents. The model picks the next agent with transfer_to_agent.
  • 2.0: code owns the edges. START, function nodes and routers sit between the agents. A return value is the next node's input.

my_agent/agent.py · README quickstart

from google.adk import Agent, Workflow

generate_fruit_agent = Agent(
    name="generate_fruit_agent",
    instruction="Return the name of a random fruit. "
                "Return only the name.",
)
generate_benefit_agent = Agent(
    name="generate_benefit_agent",
    instruction="Tell me a health benefit about "
                "the specified fruit.",
)
root_agent = Workflow(
    name="root_agent",
    edges=[("START", generate_fruit_agent,
            generate_benefit_agent)],
)

Start with the 1.x picture: a root LlmAgent with sub_agents, where the model decides each handoff with transfer_to_agent. Press once more and the same boxes become nodes in a Workflow graph. Code now owns every edge, and the agents keep only the judgment inside their node. Analogy: 1.x is a manager who improvises who works next; 2.0 is a written process map where people still do the thinking at each station. The timeline makes one point: App, plugins, caching, compaction and resume all shipped in 1.x and are now the base of the graph engine. Version 2.12 also made the first model request about 40% faster in long sessions. Likely question: "Must I migrate now?" No. Pin google-adk~=1.0, which is still patched, and plan the move with the breaking-change list on the last slide of this chapter.
