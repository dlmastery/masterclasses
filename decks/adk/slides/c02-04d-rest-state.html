Last call of step 3: GET the session. The response holds the state and the events; this slide shows the state. Click 1: turn 1, the /run call, invoked lookup_policy once, and the AuditPlugin wrote the first audit_log entry before the tool ran. Click 2: turn 2, the /run_sse call, invoked it again, so there is a second entry: one entry per tool call, in every agent of the App, without any change to the agent. Click 3: these are the same FastAPI routes that adk deploy cloud_run serves, so put authentication in front of them in production; anyone who can GET a session can read its state. Analogy: the audit log is the visitor book at the security desk. Hand-off: this session remembers one chat; the next slide makes Tom known in every new session.
