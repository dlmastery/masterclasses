Least privilege for MCP tools: five checks for every toolset

  • tool_filter on every toolset. New server tools need a review.
  • tool_name_prefix per server. Merged namespaces raise tool hallucination.
  • require_confirmation on money, delete and send. The server checks too.
  • Identity in headers via header_provider. Never in the prompt.
  • A default tenant when user:tenant is missing. Fail closed.

This slide and the next are the review list for every toolset the Acme claims desk mounts. Each check maps to one line of the final agent.py on the right. Check 1: tool_filter on every toolset, so a tool the server team adds needs a code review before the model can call it. Check 2: one prefix per server, because merged namespaces are where tool hallucination is worst (arXiv 2609.19425 collected 322 real cases across 10 models). Check 3: require_confirmation on money, delete and send tools, while the server keeps its own authorisation, because other MCP clients can call it. Check 4: identity travels in headers from header_provider, never in the prompt. Check 5, a don't: never fall back to a default tenant when user:tenant is missing; raise instead, so one broker never sees another broker's data. Think of a building pass: the badge lists the doors you may open, and each door still has its own lock. A likely question: "Is the prefix only cosmetic?" No, it also stops two servers that both expose search from colliding on one name.
