HrGuardPlugin redacts SSNs and refuses other employees' bands

labs/adk/c10-acme-hr/hr_agent/agent.py · excerpt
SSN = re.compile(r"\b\d{3}-\d{2}-\d{4}\b")

class HrGuardPlugin(BasePlugin):       # __init__: name="hr_guard"
    async def before_model_callback(self, *, callback_context,
                                    llm_request):
        for content in llm_request.contents or []:
            for part in content.parts or []:
                if part.text and SSN.search(part.text):
                    part.text = SSN.sub("[REDACTED-SSN]", part.text)
        return None                    # None = continue
    async def before_tool_callback(self, *, tool, tool_args,
                                   tool_context):
        caller = tool_context.state.get("employee_id")
        if (tool.name == "get_salary_band"
                and tool_args.get("employee_id") != caller):
            return {"status": "error", "error_message":
                    "You can only view your own salary band."}

Rewrite each SSN in place, then return None: the model call goes on.

A returned dict replaces the tool result. The tool never runs.

Plugin hooks are keyword-only, and the name is tool_args.

Our own HrGuardPlugin is the outer ring: plain, deterministic code that runs before the model and before every tool. Press once: before_model_callback walks every part of the request and rewrites any SSN to REDACTED-SSN in place; returning None means "continue", so the model still runs, only on clean text. Press again: before_tool_callback compares the employee id in the tool arguments with the caller's id in session state; a returned dict replaces the tool result, so get_salary_band never runs for E-2002. Press again: the illustrative output shows the error dict and the polite reply. Plugin hooks are keyword-only and the argument is tool_args; an agent-level before_tool_callback gets args instead, which is a common copy-paste bug.
