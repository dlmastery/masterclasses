async def main(text: str) -> None:
    # ... runner = Runner(app=app, session_service=sessions, ...)
    sid, uid = "claim-77", "u-tom"
    old = await sessions.get_session(app_name="claims_api",
                                     user_id=uid, session_id=sid)
    delta = None if old else {"claim_id": sid}  # seed once
    msg = types.UserContent(parts=[types.Part(text=text)])
    async for ev in runner.run_async(
            user_id=uid, session_id=sid,
            new_message=msg, state_delta=delta):
        if ev.is_final_response() and ev.content and ev.content.parts:
            print(f"[{ev.author}] {ev.content.parts[0].text}")
    s = await sessions.get_session(app_name="claims_api",
                                   user_id=uid, session_id=sid)
    print(f"(events stored: {len(s.events)})")

Run the script twice, as two processes. Both open the same file.

Seed claim_id on first contact only. Later runs find the session.

Process 1 stores 2 events: the message and the reply.

Process 2 loads them, answers, and adds 2 more.

The main function of claims_followup.py, run as two separate processes. Click 1: get_session tells first contact from a returning session; the script seeds claim_id only on first contact, because a delta on every run would write the same value in a new event each turn. The same id is stored as claim_id, so there is one key for the claim. Click 2: process 1 sends "My car is a 2024 Civic." and stores 2 events, the user message and the reply. Click 3: process 2 asks "Which car did I say I have?"; it loads claim-77 from the file, answers with the Civic, and the count goes to 4. Analogy: each run adds two pages to the same claim folder. A likely question: "Can adk web open this file?" Yes: adk web --session_service_uri sqlite:///claims_sessions.db opens the same store.
