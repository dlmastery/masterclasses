05

Durable execution and HITL

Build Acme refund approvals that wait days for a manager, and payouts that survive a pause or a crash without paying twice.

Docs adk.dev Human input Docs adk.dev Resume
This chapter builds two Acme jobs that run longer than one process. Lab 5A: a refund over $500 stops at a manager_gate node and waits, maybe for days, until a manager answers from a later shell command; the answer can approve, reject or ask for a revised draft. Lab 5B: a payout to ACME-GmbH retries a flaky gateway, pauses for an analyst, and a new process continues from the SQLite session and replays the finished nodes instead of running them again. Three APIs carry the chapter: RequestInput waits for a human, RetryConfig retries a flaky call, and ResumabilityConfig continues an interrupted run. Think of a checkpoint like a bookmark in a long book: you do not reread the chapters you finished, but you do reread the page you were on, so that page must be safe to read twice. That is why the ResumabilityConfig docstring says "Tool call to resume needs to be idempotent". A likely question: "Is resume exactly-once?" No, it is at-least-once, so every payment and refund carries an idempotency key. All code is in labs/adk/lab5a-refund-approval and labs/adk/lab5b-payouts-durable, tested against google-adk 2.13.0 source.
