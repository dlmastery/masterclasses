Answering a pause is a new turn. It needs no ResumabilityConfig.

Step 5 closes Lab 5A with the type trap. adk run sends every reply as {"result": text}, and the engine JSON-parses string results when it can. So the word approve stays a str, 42 becomes an int, and true becomes a bool, and ManagerDecision.model_validate rejects all three with a ValidationError. Only a JSON object becomes a dict, and only a dict becomes a ManagerDecision. The docs say response_schema "does not reshape the reply": the reply must already be in that format. The last click shows the quoting for each shell: cmd needs the inner quotes escaped, and Windows PowerShell 5.1 needs the escaped form inside single quotes. It also separates two ideas people mix up: answering a HITL pause is a new turn and works from adk run with no ResumabilityConfig; ResumabilityConfig is for continuing an interrupted or crashed invocation from your own Runner code, which Lab 5B shows. Think of the schema as a form with boxes: a sticky note that says "approve" does not fill the boxes. A likely question: "Can I accept plain text anyway?" Yes, parse the str yourself; the HITL gotcha slide shows how.
