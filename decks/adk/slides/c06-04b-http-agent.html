from google.adk.tools.mcp_tool import StreamableHTTPConnectionParams
handbook_tools = McpToolset(
    connection_params=StreamableHTTPConnectionParams(
        url="http://127.0.0.1:3000/mcp",  # path defaults to /mcp
        timeout=5.0,                      # connect, default 5.0 s
        sse_read_timeout=300.0),          # streamed reads, 300 s
    tool_filter=["search_policy", "list_topics"],
    tool_name_prefix="handbook",          # handbook_search_policy
)
root_agent = LlmAgent(
    name="claims_desk", model="gemini-3.5-flash",
    instruction=("You help Acme claims adjusters. ... "
                 "Answer coverage only from handbook_search_policy."),
    tools=[claims_tools, handbook_tools],
)

Still step 3: claims_desk mounts the handbook server as a second toolset. Step 1: StreamableHTTPConnectionParams points at the /mcp endpoint; the connect timeout defaults to 5 seconds and streamed reads may wait up to 300 seconds. Step 2: the same filter and prefix as in step 2 of the lab, so the model sees handbook_search_policy and handbook_list_topics, and the two servers cannot collide on a name. Step 3: the agent now has two toolsets, and the instruction keeps coverage answers on the handbook tool, so the model does not answer from its own memory. The output shows one call through the session and the answer. Think of the prefix as a department name on each phone extension. A likely question: "Do I still start claims_server.py myself?" No, McpToolset starts it over stdio; only the handbook server needs its own terminal. Next, each broker's identity travels to this server.
