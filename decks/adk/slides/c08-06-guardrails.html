LLMs are unable to reliably distinguish the importance of instructions based on where they came from.

Lethal trifecta (Willison, 2025-06-16): private data + untrusted content + external communication = exfiltration. Rule of Two (Meta, 2025-10-31): one session gets at most two of [A], [B], [C].

Detection alone fails, so change the architecture

CaMeL (Google, Google DeepMind, ETH Zurich): a privileged LLM writes a program from the trusted query, a tool-less quarantined LLM parses untrusted data, an interpreter tracks provenance. In ADK a Workflow is plan-then-execute: the LLM classifies, code decides what runs.

callbacks.py · deterministic guard outside the model

def limit_refunds(tool, args, tool_context):
    if tool.name == "refund" and args.get("amount", 0) > 500:
        return {"error": "Refunds > $500 need human approval."}
    return None  # None = let the tool run
agent = Agent(..., before_tool_callback=limit_refunds)
app.py · adk.dev/integrations/model-armor (ADK 2.8+)

from google.adk.integrations.model_armor import (
    ModelArmorConfig, ModelArmorPlugin)
app = App(name="model_armor_demo", root_agent=agent, plugins=[
    ModelArmorPlugin(config=ModelArmorConfig(
        prompt_template_name="projects/my-project/locations/"
            "us-central1/templates/my-prompt-template",
        response_template_name="projects/my-project/locations/"
            "us-central1/templates/my-response-template",
    ))])

ModelArmorPlugin screens prompts and responses and fails closed by default. The templates must be in the same region. Agent Gateway adds egress allow and deny rules.

Know the limits. Model Armor screens one turn at a time. It does not decode Base64 and does not read audio or video. Documents stop at 4 MB. The console Model Armor settings in Gemini Enterprise do not protect ADK agents: configure it in code.
  • ADK hardening: 2.8 fences relayed agent output so it can not pose as instructions. 2.9: A2A needs https for non-loopback agent cards. 2.11: ToolCallIntegrityPlugin.
  • Supply chain: LiteLLM 1.82.7 and 1.82.8 on PyPI held unauthorized code. Pin and hash every dependency.

Open with the honest premise: no filter stops every injection, so we design for the day one gets through. Step 0 shows the three Rule-of-Two properties as circles. Step 1: an injected email enters through untrusted input, reaches private data and leaves through an external action; the stats show why detection alone is not the answer, because adaptive attacks broke twelve published defences. Step 2: remove external action for this session and the same attack has no way out; then CaMeL and plan-then-execute show how architecture, not a classifier, gives the guarantee. Step 3: if the task truly needs all three, a human approval sits in the overlap, and the callback shows a deterministic limit that the model can not argue with. Step 4: the defence rings; each attack stops at a different ring, from UI escaping outside to Agent Identity inside, and the Model Armor code shows the plugin layer. Step 5: release hardening, the LiteLLM supply-chain incident and the codelab that builds Model Armor, Agent Identity and a conditional IAM grant to one dataset. Analogy: a bank does not trust that no robber enters; it uses a vault, time locks and two-person rules so a robber inside still gets little. Likely question: "Is Model Armor enough?" No: it is one ring, it screens one turn at a time, and the console setting does not cover ADK agents.
