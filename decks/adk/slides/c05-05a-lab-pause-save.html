  if cmd == "start":

    msg = types.Content(role="user", parts=[types.Part(text=arg)])
    inv = None
  # ... "resume" and "continue": next slides

Step 4 of Lab 5B is the first half of the driver, main(). Process 1 is "start": it creates the session s1 in payouts.db and sends the payee name as the first message. run_async streams events; kyc_lookup runs and writes its one log line, then analyst_review yields a RequestInput. That event carries long_running_tool_ids, which is how a driver sees a pause. The driver writes the invocation id and the interrupt id to pending.json and the loop ends, so the interpreter exits with nothing left in memory. Everything the next process needs is now on disk: the session in SQLite and the two ids in a small file. Think of pending.json as the claim ticket you get when you leave a coat: the coat stays in the building, you keep only the number. A likely question: "Why save the invocation id too?" The resume call passes it so the Runner continues that invocation; the interrupt id alone names the question, not the run. For a fresh run, delete payouts.db, pending.json and side_effects.log, because start creates s1 again.
