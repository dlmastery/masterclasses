Bound the shape: every loop and fan-out gets a hard limit

  • Fan out only independent checks. Each one reads the original claim.
  • Give every loop MAX_ROUNDS and an escalate exit.
  • Keep the orchestrator thin. Put side effects in child nodes.
labs/adk/c04-copy-review/copy_review/agent.py · excerpt
MAX_ROUNDS = 3

def gate(ctx: Context, node_input: Review):
  ctx.state["round"] = ctx.state["round"] + 1
  if node_input.grade == "compliant":
    yield Event(route="done")
  elif ctx.state["round"] >= MAX_ROUNDS:
    yield Event(route="escalate")
  else:
    yield Event(state={"feedback": node_input.feedback},
                route="retry")

root_agent = Workflow(name="copy_review", edges=[
    ("START", brief, write_copy, review_copy, gate),
    (gate, {"retry": write_copy, "done": publish,
            "escalate": escalate})])
The second rule bounds the shape you picked. Fan out only checks that are independent, and let each branch read the original claim, not a rewrite from another branch; the paper on flat topologies showed why. Give every loop a hard MAX_ROUNDS and a second exit, escalate, so a reviewer that never says compliant ends in a person's queue, not in a runaway bill; the gate on the right is the whole mechanism, and the round count lives in state, so it survives a resume and shows up in evals. Keep the orchestrator thin: it re-runs from the top on every resume, while child nodes started with ctx.run_node are replayed from history, so database writes and emails belong in children. Analogy: every loop is a meeting with a fixed end time and a named person who decides if it runs over. A likely question: "How do I pick MAX_ROUNDS?" Measure rounds-to-compliant on your eval set with the @ counter from the trace, and set the bound a little above what almost every case needs.
