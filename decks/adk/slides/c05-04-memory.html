from google.adk.tools import preload_memory

async def auto_save(callback_context):
    await callback_context.add_session_to_memory()

agent = Agent(
    model=MODEL, name="Generic_QA_Agent",
    instruction="Answer the user's questions",
    tools=[preload_memory],          # search every turn
    after_agent_callback=auto_save,  # you write memory
)

preload_memory searches on every turn: predictable, but it costs tokens and latency. load_memory is a tool, so the model searches only when it decides.

Three words first, from the Agent Platform Sessions docs: a session is the chronological events of one interaction, state is temporary data for this conversation, and memory is information that persists across sessions. Step 1: the Runner does not write memory for you; an after_agent_callback calls add_session_to_memory, and Memory Bank runs LLM extraction that keeps only information that matches a memory topic. Step 2: consolidation compares the new fact with existing memories in the same scope, {app_name, user_id}, and decides CREATE, UPDATE or DELETE; here "likes window seats" becomes revision 2, "prefers aisle seats", and a TTL will expire the trip fact. Step 3: in Session 2, preload_memory puts the fact into the new context, so the agent answers with the preference. Analogy: the session is today's meeting transcript, and Memory Bank is the short CRM note that a good assistant keeps up to date. Likely question: "Why not save the whole transcript?" Raw transcripts grow without limit and re-inject old contradictions; extraction plus consolidation keeps a small, current set of facts, and the RMM paper behind Memory Bank reports more than 10% on LongMemEval.
