Step 5 of Lab 5B is process 2, a new Python interpreter. "resume yes" reads pending.json and sends a FunctionResponse named adk_request_input with the interrupt id and response {"result": "yes"}, exactly what adk run sends. analyst_review uses the hand-off pattern, so the reply becomes its output; "yes" is not JSON, so pay receives the str "yes". The workflow scans the recorded events of the invocation and fast-forwards kyc_lookup from its stored output, so only analyst_review and pay run. pay retries twice and pays on attempt 3, and the driver prints the pay node's output; it filters on node_info.path, because a function node's events carry the workflow's name as author, not the node's. The last click is the proof: side_effects.log still has exactly one line. Think of a film editor who jumps straight to the cut point instead of shooting the first scenes again. A likely question: "Is kyc_lookup ever run twice?" Not on a clean resume; only a node that crashed before its event was saved runs again, which is why the next slide talks about idempotency.
