One print() on stdout breaks the JSON-RPC stream

claims_agent/claims_server.py
if __name__ == "__main__":
    print("server ready")         # stdout
    mcp.run()
claims_agent/claims_server.py
if __name__ == "__main__":
    logging.info("server ready")  # stderr
    mcp.run()
This is the most common stdio bug. Over stdio, stdout is not a console: it is the wire that carries JSON-RPC messages between McpToolset and the server. Step 1 shows a harmless-looking print("server ready") at startup. Step 2: that line enters the stream, the client cannot parse it as JSON-RPC, and the session dies; adk web logs "ConnectionError: Failed to create MCP session". Step 3: the fix is logging.info, because the server set up logging on stderr, and stderr goes to the terminal, not to the client. Step 4: the stream is clean again and the log line still reaches you. Think of stdout as a fax line: if you say one word into it, the fax fails. A likely question: "Does a print inside a tool break it too?" Yes, any write to stdout at any time corrupts the stream, so search the server and its libraries for print calls.
