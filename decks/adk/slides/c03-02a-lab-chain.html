This is Lab 3.1, the Acme refund desk: one refund ticket goes through four nodes in a fixed order. Step 0 is the setup box: install the pinned version, make the folder with an __init__.py that imports agent, and put the Gemini API key in .env; the full files are in labs/adk/c03-refund-flow. On Windows, create the empty files in your editor or with New-Item instead of touch. Press through the nodes: parse_request and check_policy are plain Python functions, write_reply is the only LLM call, and audit_log writes the audit line. The last press shows the green checks: the Workflow compares the schemas on every edge where both ends declare a type, when you build it, not when a ticket arrives. Think of the chain tuple as an assembly line that checks that each part fits before the line starts. A likely question: "Why not one agent with tools?" Because the order here is a business rule, and a graph makes the order a fact instead of a request to the model. Next slide: the two function nodes.
