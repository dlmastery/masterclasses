from google.adk.tools import FunctionTool
def needs_ok(amount: float, **_) -> bool:
  if amount > AUTO_APPROVE_LIMIT:
    return True
  return False                             # never fall through
FunctionTool(issue_refund, require_confirmation=needs_ok)
The third HITL bug is issue 7010, still open, about the tool-level FunctionTool predicate. ADK uses cast(bool, ...), which does nothing at run time, so a predicate that forgets its return statement returns None; None is falsy, and an 820-dollar refund runs with no prompt and no error. The fix is boring and strict: return a real bool on every path, and never fall through to the end of the function. Write the predicate of the node-level decorator from the build slide the same way. The double-star underscore parameter takes the other tool arguments, so the predicate only names the one it needs; FunctionTool passes the tool's own arguments to the predicate, so the name amount must match the tool's parameter name. Think of a door alarm with a loose wire: it does not ring, and silence looks exactly like "all clear". A likely question: "How do I catch this in CI?" Add a unit test that calls the predicate with 820 and asserts it is True, and one with 320 that asserts it is False; an assert on the type catches None.
