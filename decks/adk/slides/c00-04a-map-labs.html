This is the whole course on one page, and it runs on one company: Acme. Each lab is one Acme team with one real problem, and each card names the main ADK API the lab teaches. Start with Lab 1. The four parts are on screen; each press fills one part. Press once: Part 1, one agent: Lab 1 is the Acme refund desk with tools, a refund cap in a callback and a human check; Lab 2 returns typed output with output_schema and serves it over REST from an App. Press again: Part 2, graphs: Lab 3 routes tickets with Workflow edges, and it is the graph you saw on slides 2 to 5; Lab 4 runs parallel checks with a JoinNode and bounded loops; Lab 5 pauses for approval with RequestInput and survives a crash. Press again: Part 3: Lab 6 uses MCP servers and a REST API as tools; Lab 7 serves one agent over MCP and A2A. Last press: Part 4, production: Lab 8 caches, compacts, remembers with Memory Bank and talks over the Live API; Lab 9 blocks a bad deploy with adk eval; Lab 10 adds guardrails, deploys and ships to staff. Analogy: a metro line with ten stations through four districts. Likely question: "Do I need a cloud account?" Only for Labs 8 and 10; the next slide shows where each lab runs.
