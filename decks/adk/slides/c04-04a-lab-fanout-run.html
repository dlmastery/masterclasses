Now run the graph from the parent folder with three claims. adk run takes the query as a positional argument; leave it out and you get an interactive prompt instead. The output is marked illustrative because nothing was executed for the slide, but this graph has no LLM, so the code fixes the text. Step 1 is the point of the slide: the three checks start together, so wall time is the slowest branch, about 0.5 seconds. Step 2 draws the same checks in sequence: the 1.0 second sum. It is like three adjusters working on copies of the same file at the same time, instead of passing one file down a corridor. Step 3 gives one verdict per claim: the first is approved for 3,490 (4,200 times 0.95 is 3,990, capped at the 20,000 limit, minus the 500 deductible); the total-loss claim scores 0.82 and goes to the special investigations unit; POL-99 is not in the policy table, so it is denied. A likely question: "What if one branch is slow?" The whole fan-out waits for it, so put a timeout or retry config on any branch that calls a real service.
