from google.adk.agents.readonly_context import ReadonlyContext
def tenant_headers(ctx: ReadonlyContext) -> dict[str, str]:
    # user: state is set at login, never by the model
    tenant = ctx.state.get("user:tenant")
    if not tenant:
        raise ValueError("no user:tenant in state")  # fail closed
    return {"X-Tenant-ID": tenant}

A prompt injection cannot change a header.

This is step 4 of the Acme claims desk: several brokers share the handbook server, so each request must carry the broker's identity. A broker here is an insurance agency that uses the desk, one tenant. Step 1: tenant_headers reads user:tenant from session state. State with the user: prefix belongs to one user and lasts across that user's sessions; your login code sets it, never the model. If it is missing, raise, so a request never falls back to another tenant's data: the middle pill shows that fail-closed path. Step 2: header_provider sends the value as the X-Tenant-ID header, and ADK pools one MCP session per header identity, so two brokers never share a session. Step 3: identity travels in headers, outside the conversation, so text in a prompt or a tool result cannot switch the tenant. Think of a hotel key card: identity travels with the card, not with what the guest says at the desk. A likely question: "Can header_provider be async?" Yes, it gets a ReadonlyContext per session and may be async, for example to look up a token.
