import pathlib
from google.adk.agents import LlmAgent
from google.adk.code_executors import UnsafeLocalCodeExecutor
from google.adk.skills import load_skill_from_dir
from google.adk.tools.skill_toolset import SkillToolset
from refund_core import lookup_order    # A-300: $120, day 42
HERE = pathlib.Path(__file__).parent
skills = SkillToolset(
    skills=[load_skill_from_dir(HERE / "skills" / "refund-policy")],
    additional_tools=[lookup_order],          # supplies the function
    code_executor=UnsafeLocalCodeExecutor(),  # DEV ONLY: exec()
)
root_agent = LlmAgent(
    name="refund_skill_agent", model="gemini-3.5-flash",
    instruction="Use skills when they match the request.",
    tools=[skills])

Step 5 of the Acme refund team: agent.py turns the skill folder into tools with SkillToolset. lookup_order comes from refund_core, where the test order A-300 is a 120 dollar jacket bought 42 days ago. Focus one: load_skill_from_dir reads the folder, and the toolset gives the model four tools: list_skills returns level 1, load_skill returns the body, level 2, and load_skill_resource and run_skill_script reach level 3. Focus two: additional_tools supplies the lookup_order function, but the model sees it only after load_skill, because the frontmatter lists it in adk_additional_tools. Focus three: run_skill_script needs a code executor. UnsafeLocalCodeExecutor runs the script with exec() inside the agent process and script_timeout does not apply, so it is for a laptop only; use a container or GKE executor in production. Think of a manual on a shelf: the model reads the spine first and opens the chapter only when the question needs it. A likely question: "Why hide lookup_order until the skill loads?" A smaller tool list at the start means fewer wrong tool calls; the skill brings its own tools.
