HANDBOOK = pathlib.Path("handbook.md").read_text()

agent = Agent(
    name="handbook_agent", model="gemini-3.5-flash",
    static_instruction=types.Content(
        role="user", parts=[types.Part(text=HANDBOOK)]),
    instruction="Customer: {customer_name}. "
                "Answer only from the handbook.")

The handbook is read once. It must reach 4,096 tokens on Gemini 3.

Every request starts with the same prefix bytes: one cache key.

The customer name changes per session, so it goes after the prefix.

This is step one of Lab 8: the Acme mobile support agent sends the same long handbook on every request, so we make that handbook a stable prefix that the model can cache. Before you run it, put about 3,100 words of plan terms in handbook.md and check the size with client.models.count_tokens, because Gemini 3 needs 4,096 tokens before it caches and Gemini 2.5 needs 2,048. Walk the three focus steps: read the handbook once; pass it as static_instruction, which ADK sends first and never templates; and keep the {customer_name} placeholder in instruction, which ADK then sends as user content after the prefix, so you do not move anything by hand. The diagram shows three requests: the green prefix is byte-for-byte the same, and only the parts after it change. Think of the prefix as a binder that stays open on the desk in the same place every time. A likely question: "Why not put the customer name in the system prompt?" Because any changed byte in the prefix changes the cache key, and every turn misses. The full file is in labs/adk/c08-context-cache.
