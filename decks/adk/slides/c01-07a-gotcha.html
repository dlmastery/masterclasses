Gotcha First run · the loader

The loader needs a package name and a variable called root_agent

SymptomInvalid agent name: 'refund-agent'. Agent names must be valid Python identifiers (letters, digits, and underscores only). CauseADK imports the folder as a Python package. A hyphen breaks the import. FixUse refund_agent for the folder and for name=. Never name an agent user.
SymptomNo root_agent found for 'refund_agent'. Searched in 'refund_agent.agent.root_agent', 'refund_agent.root_agent' and 'refund_agent/root_agent.yaml'. CauseThe variable is called agent, or __init__.py lost from . import agent. FixName it root_agent (or app, Chapter 2). Keep the scaffolded __init__.py.
layout that adk run and adk web load
refund_agent/     # folder = package
  __init__.py     # from . import agent
  agent.py        # defines root_agent
  .env            # GOOGLE_API_KEY=...
Two of the three errors that stop most first runs come from the loader, before any model call. Step 1: adk run and adk web import the agent folder as a Python package, then look for a variable called root_agent. Step 2: a hyphen in the folder gives "Invalid agent name: 'refund-agent'. Agent names must be valid Python identifiers"; a hyphen in name= gives the sibling error "Found invalid agent name: `refund-agent`. Agent name must be a valid identifier...". The name user is also reserved. Step 3: "No root_agent found for 'refund_agent'" lists the three places the loader searched: agent.root_agent, the package itself and root_agent.yaml. The fix is to name the variable root_agent, or app for an App (Chapter 2), and keep from . import agent in __init__.py. Analogy: the loader is a courier with one address format; a hyphen or a different door name and the parcel comes back. Likely question: "Can I keep a hyphenated repo name?" Yes, the repo can have any name; only the agent folder must be an identifier. Next: the third error, a loop that hits the call cap.
