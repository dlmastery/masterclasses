A uuid4 interrupt id changes on every rerun, so the gate asks forever

SymptomThe manager answers. The node asks again. CauseA new id on each rerun. The lookup never matches. FixBuild the id from invocation_id + run_id.
refund_approval/agent.py · manager_gate
# not: iid = str(uuid4())
iid = f"refund_approval_{ctx.invocation_id}_{ctx.run_id}"
answer = ctx.resume_inputs.get(iid)   # found on the rerun
The first HITL bug hits the Acme refund gate after the lab works on your laptop. A rerun_on_resume node runs again after every reply, so its interrupt id must be the same on every rerun. With uuid4 the id changes each time: the answer is stored under the old id, resume_inputs.get looks under the new one, misses, and the node asks the manager again. The animation counts it: the top row asks again and again, the bottom row asks once and hits. The fix is the lab's own line: build the id from invocation_id and run_id, which stay the same on a resume and change only on a new revise pass. Think of the interrupt id as a cloakroom ticket: if you print a new ticket every time you come back, you never get your coat. A likely question: "Why not reuse one fixed string?" Reuse is supported, but the RequestInput docstring still recommends unique ids per loop pass, which the revise loop needs.
