from google.adk import Agent, Context, Event

def refund(ctx: Context, node_input: dict):
  oid = node_input["order_id"]          # from pick's output=
  ctx.state["outcome"] = f"refund queued for {oid}"
  # returns None; the edge to audit still runs

answer = Agent(
    name="answer", output_key="outcome",
    instruction="Answer in 2 sentences: {ticket}")

def audit(outcome: str):   # not node_input or ctx: read from state
  yield Event(message=f"[audit] {outcome}")

Excerpt three: how the result reaches audit. The state panel on the right is session.state for one refund run; ticket is already there because intake wrote it. Press once: refund gets the dict that pick sent with output=, and writes outcome into session.state through ctx.state. It yields nothing and returns None; that is allowed, and the edge to audit still runs when refund finishes. Press again: on the question path, answer writes the same key with output_key="outcome", so audit does not care which branch ran. Press again: the rule. audit has one parameter, outcome; it is not node_input and not ctx, so ADK looks it up in session.state by name. That is the default parameter_binding="state". Last press: a typo such as outcom, or a branch that never wrote the key, stops the run with WorkflowDataError; the fix is to match the key or give the parameter a default. Analogy: state is a shared whiteboard; refund writes on it and audit reads it. Likely question: "If both node_input and a state key exist, which one does audit get?" Only the parameter named node_input gets the edge payload; every other name comes from state.
