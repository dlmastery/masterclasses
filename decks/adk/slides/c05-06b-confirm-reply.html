Now run the decorated node from the same lab folder. The first command pauses: node confirmation is a RequestInput whose interrupt id is wf_tool_confirmation plus the node path and whose schema is ToolConfirmation. The second command answers it. Because adk run JSON-parses the reply text, you type the JSON object as the query: {"confirmed": true} becomes a dict, the node body runs once, and the refund line comes out with its idempotency key. {"confirmed": false} is a rejection: the body does not run, and the node output is {"error": "This tool call is rejected."}. A plain yes stays a string, and the node raises WorkflowDataError with the exact text on the slide. Think of the badge reader again: it reads only badges, so a spoken "yes" at the door does nothing. A likely question: "Can I make yes work?" Not with the decorator; put a small normalizer node before it, or keep the RequestInput gate and parse the string yourself.
