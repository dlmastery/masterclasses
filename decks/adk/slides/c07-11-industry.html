from google.adk.tools.tool_context import ToolContext
from refund_core import ORDERS     # stands in for the order DB (real ids: UUIDs)

def find_order(order_id: str, tool_context: ToolContext) -> dict:
    """Find an order. Returns a short handle, never the raw id."""
    if order_id not in ORDERS:
        return {"error": f"unknown order {order_id}"}
    pins = dict(tool_context.state.get("pins", {}))
    handle = next((h for h, v in pins.items() if v == order_id), f"ord_{len(pins) + 1}")
    tool_context.state["pins"] = {**pins, handle: order_id}
    return {"handle": handle, **ORDERS[order_id]}

def issue_refund(handle: str, amount: float, tool_context: ToolContext) -> dict:
    """Refund an order by its handle."""
    order_id = tool_context.state.get("pins", {}).get(handle)   # code resolves the id
    if order_id is None:
        return {"error": f"unknown handle {handle}"}
    return {"status": "ok", "order_id": order_id, "refunded": amount}

Two companies, two separate lessons. Uber's 2026-08-27 cost post reports over 3,600 agent skills, more than 30K skill executions per day, more than 70% of pull requests attributed to agents, and 9.4x growth in weekly agentic requests from February to August; the post gives the scale, and it does not say that any one agent sees all of them. Rippling, in a vendor-published LangChain case study, shows one way to keep each agent small: a semantic-layer search first finds the domain, then middleware injects one scoped skill into the subagent, and re-rankers cut context 100 to 500 times, with no baseline stated. In ADK the same move is the preselect() step from the paper slide. Rippling's second trick is variable pinning: the model never re-types a long id; it works with a handle like ord_1, and code resolves the real id from session state. In pinning.py the same order gets the same handle again, and an unknown handle returns an error dict instead of raising. Think of a coat check: you carry the ticket number, not the coat. For Acme, google/adk-recipes ships per-skill EVAL.yaml test cases with an 80% pass gate, and setup stops below it. A likely question: "Why not paste the id into the prompt?" Because long alphanumeric ids are exactly what models garble, and a wrong id on a refund is a real-money bug.
