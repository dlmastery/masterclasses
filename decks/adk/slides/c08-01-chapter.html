Context, memory and Live

This chapter builds one support agent for the Acme mobile support desk and keeps it cheap, fast and personal. The four cards are the four labs: the cache and compaction labs run on your laptop with an AI Studio API key, and Memory Bank and the Live voice lab need a Google Cloud project with billing on. The animation shows one request: the handbook prefix is cached from turn 2, Memory Bank feeds two facts about Priya into the slot after the prefix, voice turns from run_live fill the window, and when the turns reach token_threshold the oldest ones become one summary. Think of the context window as a desk: the handbook is a binder that stays open in the same place, the chat is a pile of notes that you summarise when it gets too high, and memory is the customer file you pull from the cabinet. A likely question: "Why not just use a bigger context window?" Because every turn re-sends the whole window, so turn count and the uncached part drive the cost, as the TurnCost paper after the cache lab shows.
