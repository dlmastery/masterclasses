Codelab Building Stateful and Personalized Agents with ADK
This build is a standalone FAQ agent, claims_faq_agent, under the same app_name claims_api and the same customer u-tom; the full file is labs/adk/lab2-claims-api/claims/claims_faq.py. Start with the four buckets: a key without a prefix belongs to one session, so a new chat starts without it. Click 1: create_session seeds an app: key and a user: key. Warn the room: app: keys are shared by every user of the app, so never write customer data there. Click 2: the state_delta on run_async writes the language through an event, which is the legal way to inject per-turn context such as locale or channel. Click 3: the tool writes temp:last_topic, which lives only for this turn and is trimmed before commit, and appends to user:topics_asked, which follows u-tom into every chat. Analogy: app: is the office noticeboard, user: is the customer file, unprefixed keys are the notepad for this call, and temp: is a sticky note you throw away when you hang up. A likely question: "Where does InMemorySessionService keep user: keys?" In separate app and user dicts that it merges into every session it returns.
