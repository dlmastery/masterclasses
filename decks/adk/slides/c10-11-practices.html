Best practices

Production checklist for the Contoso HR assistant, item by item

1 · Versions and release

  • Pin google-adk==2.13.0, mcp, a2a-sdk, litellm. Canary each minor. 13 minors in 5 months; 2.2.0, 2.7.0, 2.11.0 regressed.
  • Gate deploys on adk eval and a canary. Exits 1 on failure.
  • --agent_engine_id on every update. Else a new instance.

2 · Security and privacy

  • Auth in front of adk api_server. None by default.
  • Cloud Run: --no-allow-unauthenticated. Identity tokens.
  • ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false off Agent Runtime. Default: on.
  • --with_ui in production. "ADK Web is for development purposes."
  • Gemini Enterprise console Model Armor. Not for ADK agents.

3 · Operations

  • Deploy with --session_service_uri, --artifact_service_uri. Else: lost sessions.
  • Warm-up request before live traffic. Pays the import cost.
  • Cost per successful outcome; tokens per invocation. Loops show as tokens.
  • Idempotency keys on side effects. Resume is at-least-once.

This slide is the release checklist for the Contoso HR assistant, in three groups: versions and release, security and privacy, and operations. ADK shipped 13 minor releases in 5 months, and 2.2.0, 2.7.0 and 2.11.0 each brought a regression, so pin the same versions in local and deployed requirements and canary every upgrade. The two red items are traps: --with_ui puts the dev UI with access to all data in production, and the Gemini Enterprise console Model Armor settings do not protect ADK agents, so the guard must live in the agent code. Think of it like a pre-flight checklist: the pilot knows how to fly, but the list catches the step a tired person skips. A likely question is "Why track cost per successful outcome and not cost per call?" Because arXiv 2610.13092 found a cheaper, faster decision model that raised the mean cost per successful outcome in one agent.
