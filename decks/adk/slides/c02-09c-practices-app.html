Best practices Acme claims API · one App per folder

One App per folder: name it like the folder, plugins on the App

  • Name the App like its folder, with underscores: claims_api.
  • Register plugins on the App: every agent gets them.
  • Never pass plugins= to Runner: with app= it raises.

from claims_api.agent import app      # the one App, plugins included

async def main() -> None:
    sessions = SqliteSessionService(db_path="claims_sessions.db")
    runner = Runner(app=app, session_service=sessions,
                    auto_create_session=True)      # no plugins= here
Rules for the deployable unit. Click 1: name the App like its folder, because the server names each app after its folder; the folder name must be a valid Python identifier, so use underscores, not hyphens. run_claims.py imports the one App from claims_api.agent instead of building a second one; run it from the agents folder. Click 2: register plugins on the App, so every agent in the tree gets the audit and logging hooks, in adk run, adk web, adk api_server and your own Runner alike. Click 3: never pass plugins to the Runner: that argument is deprecated with the warning "The plugins argument is deprecated. Please use the app argument to provide plugins instead.", and together with app= it raises. Analogy: one building, one security desk, one address on the door. A likely question: "Can one folder hold two Apps?" The loader takes the variable named app, so keep one App per folder and split other agents into their own folders.
