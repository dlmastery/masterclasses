Without a JoinNode, decide runs once per branch

    ("START", parse_claim,

root_agent = Workflow(name="claim_checks", edges=[

Symptomdecide runs 3 times. Each run gets the output of one branch only, and it fails. CauseA successor of a fan-out is triggered once per predecessor. FixPut join_checks between the branches and decide.

This is the most common fan-in bug. Remove the JoinNode and the graph still validates, but a successor of a fan-out is triggered once per predecessor, so decide runs three times, each time with the output of a single branch. The first run gets only the damage estimate, a float, so node_input["policy_check"] fails. The official sample multi_triggers shows the same behaviour on purpose. The fix is one name in the chain: put join_checks between the tuple and decide, and decide runs once with the full dict keyed by branch name. Analogy: without the supervisor's tray, each adjuster walks into the manager's office with only their own page. A likely question: "Is running once per predecessor ever what I want?" Yes, for a node that should react to each event as it arrives, such as a logger or a notifier; for a decision that needs all inputs, you need the barrier.
