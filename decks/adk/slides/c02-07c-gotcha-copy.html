Gotcha Session state

get_session returns a copy, so write state through an event

SymptomYou set claim_status. The next get_session does not show it. Causeget_session returns a detached copy. Edits on it never reach the store. FixWrite through state_delta=, tool_context.state or callback_context.state.

This is the same claim-77 session from the SQLite slides; the script is labs/adk/lab2-claims-api/claims/mark_reviewed.py. Step 0: someone marks the claim reviewed, and the next read does not show it. Click 1: get_session returns a detached object. The in-memory service deep-copies the session, and the SQLite and Postgres services build a new object from the rows, so editing s.state changes only your copy. Click 2: state changes persist only when they travel inside an event: state_delta on run_async, tool_context.state in a tool, or callback_context.state in a callback. Here state_delta rides on a normal user turn, so the agent also replies. Click 3: read the session again and the value is there, because the event wrote it to claims_sessions.db. Analogy: get_session is a photocopy of the claim file; writing on the photocopy does not change the file in the cabinet. A likely question: "Can I write state without running the agent?" Not with these public calls; in this course every write goes through a turn, a tool or a callback.
