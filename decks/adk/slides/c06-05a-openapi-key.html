    url = f"http://127.0.0.1:8081/claims/{claim_id}"
    key = {"X-API-Key": "demo-key-123"}  # in git

labs/adk/lab6-acme-claims-desk/claims_agent/agent.py · excerpt
# imports: OpenAPIToolset, token_to_scheme_credential
SPEC_URL = "http://127.0.0.1:8081/openapi.json"
spec = httpx.get(SPEC_URL, timeout=5).json()   # at import time
auth_scheme, auth_credential = token_to_scheme_credential(
    "apikey", "header", "X-API-Key", os.environ["CLAIMS_API_KEY"])
claims_status = OpenAPIToolset(
    spec_dict=spec,
    auth_scheme=auth_scheme,
    auth_credential=auth_credential,
    tool_filter=["get_claim_status"],   # snake_case(operationId)
    allow_private_network_access=True,  # 127.0.0.1: dev only
)
# root_agent: tools=[claims_tools, handbook_tools, claims_status]
Now claims_desk gets its third tool source, the claims-status REST service from terminal 1. Step 1 shows the version to avoid: a hand-written httpx tool with the URL and the API key in the source, so the key ends up in git. The service already publishes an OpenAPI spec, so let ADK build the tool. Step 2: OpenAPIToolset reads the spec, and token_to_scheme_credential turns the key from the CLAIMS_API_KEY environment variable into the X-API-Key header. os.environ with square brackets fails at startup when the key is missing, instead of falling back to a value in the code. Step 3: tool_filter uses the generated tool name, which the next slide explains. Step 4: allow_private_network_access=True is needed only because the API runs on 127.0.0.1; the gotcha after next shows the guard it lifts. agent.py downloads the spec when it is imported, so start claims_api before adk web. Think of the spec as a menu with item numbers: the agent orders by the number, not by describing the dish. A likely question: "Where should the key live in production?" In Secret Manager or the deploy environment, never in the instruction or the code.
