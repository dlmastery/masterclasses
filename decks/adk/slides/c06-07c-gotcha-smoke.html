Gotcha MCP at runtime · the fix

A startup smoke test fails loudly when a toolset does not load

python smoke_test.py
labs/adk/lab6-acme-claims-desk/smoke_test.py
import asyncio
from claims_agent.agent import claims_tools
EXPECTED = {"get_claim", "approve_claim", "login"}
async def main() -> None:
    try:
        tools = await claims_tools.get_tools()
    except Exception as exc:  # crash, print, bad path, timeout
        raise SystemExit(f"FAIL toolset did not load: {exc!r}")
    names = {t.name.removeprefix("claims_") for t in tools}
    if names != EXPECTED:
        raise SystemExit(f"FAIL expected {EXPECTED}, got {names}")
    print("OK", sorted(names))
asyncio.run(main())
output · illustrative · two runs
$ python smoke_test.py  # print() in server
FAIL toolset did not load: ConnectionError(...)
$ python smoke_test.py  # fixed
OK ['approve_claim', 'get_claim', 'login']

Run it in CI and before each deploy. A non-zero exit stops the rollout.

The fix for the silent failure is to make it loud before traffic arrives. Step 1: the smoke test imports the same claims_tools object the agent uses and calls get_tools(), which starts the stdio server and lists its tools; any crash, stdout print, wrong path or timeout raises here, and SystemExit turns it into a non-zero exit code. Step 2: it also compares the names with the expected set, so a server that drops a tool, or a tool_filter typo, fails too. The prefix is removed before the compare. Step 3: the output shows two runs: the first with a print in the server, the second after the fix. Step 4: run it in CI and as a deploy gate. The full file is in the lab folder; it needs claims_api running, because agent.py fetches the OpenAPI spec when it is imported. Think of a pilot's pre-flight checklist: the plane can fly without it, until the day it cannot. A likely question: "Why remove the prefix before the compare?" get_tools returns the names the model sees, with the claims_ prefix, while EXPECTED uses the server's names, the same names as tool_filter.
