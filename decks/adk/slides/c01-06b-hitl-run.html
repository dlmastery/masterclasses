Issue google/adk-python #7010
Step 1: over $200 the first call does not run the tool; ADK calls request_confirmation and returns the error dict "This tool call requires confirmation, please approve or reject." adk run detects the pending long-running call and prints the [HITL confirm] prompt; y, yes, true and confirm count as yes. Step 2: anything else is a rejection, and the model reads "This tool call is rejected."; the instruction tells it to say a supervisor declined, so it does not pretend the refund went through. adk web shows a dialog instead. In your own client, watch event.long_running_tool_ids and send back a FunctionResponse with the same id and {"confirmed": true} or {"confirmed": false}. Step 3: the open issue #7010: a predicate that falls off a branch returns None, None is falsy, and the gate is skipped; always return a real bool. Analogy: the manager's key must be turned one way or the other; "no answer" must never mean yes. Likely question: "Can the approver change the amount?"
