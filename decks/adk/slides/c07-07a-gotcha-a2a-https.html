The same card bug comes back when you deploy. RemoteA2aAgent accepts plain http only on a loopback host such as localhost; for any other host it refuses the card with "Agent card URL must use https, or http on a loopback host", issue 7139. So a card that says http://refunds.example.com:8001 works nowhere. The fix is to write the public URL into the card: host is the public name, protocol https, port 443. On Cloud Run the container still listens on $PORT, which is 8080 by default, so do not try to bind 443 yourself: the card describes how callers reach you, and uvicorn describes where the process listens. The client side fetches the card from the same public https URL. Both files are in the lab's deploy folder; replace refunds.example.com with your service's host name. Analogy: the business card must show the reception desk's public number, not the extension inside the building. A likely question: "Why does localhost work with http?" Loopback traffic never leaves the machine, so the client allows it for local development.
