refund_skill_agent/skills/refund-policy/SKILL.md
---
name: refund-policy
description: Decide refund eligibility and partial-refund
  amounts for Acme orders. Use for any refund, return
  or chargeback question.
metadata:
  adk_additional_tools:
    - lookup_order
---
Step 1: Call `lookup_order` with the order id.
Step 2: Read `references/policy.md` for the return windows.
Step 3: If the order is past the full-refund window but
inside 60 days, run `scripts/prorate.py` with args
{"amount": <amount>, "days": <days_since_purchase>}.
Step 4: Answer REFUNDABLE, PARTIAL_REFUND <amount>, or
NOT_REFUNDABLE with one reason.

Step 4 of the Acme refund team: the policy that lived in the refund_agent instruction moves into an Agent Skill, which is just a folder: labs/adk/lab7-acme-refunds/refund_skill_agent/skills/refund-policy. SKILL.md has YAML frontmatter and a body. The frontmatter name and description are level 1: they are all the model sees until it decides to load the skill, so write the description as a trigger ("Use for any refund, return or chargeback question"). The metadata key adk_additional_tools lists lookup_order; it must be a YAML list, and the tool reaches the model only after the skill loads. The body is level 2: four steps that name the reference file and the script. policy.md and prorate.py are level 3: the model reads or runs them only when a step asks. Think of a binder on a shelf: the spine is level 1, the table of contents is level 2, and the appendices are level 3. A likely question: "Must the folder name match name:?" Yes, the loader raises a ValueError otherwise; the gotcha slide shows it.
