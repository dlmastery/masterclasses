The script turns the policy's 31-60 day rule into a number

python scripts/prorate.py --amount 120 --days 42 from skills/refund-policy/
skills/refund-policy/scripts/prorate.py
import argparse
p = argparse.ArgumentParser()
p.add_argument("--amount", type=float, required=True)
p.add_argument("--days", type=int, required=True)
a = p.parse_args()
share = max(0.0, (60 - a.days) / 30)    # day 30: 1.0, day 60: 0.0
print(f"{round(a.amount * min(share, 1.0), 2)}")
output
72.0      # 120 × (60 − 42) / 30 = 120 × 0.6
Level 3 of the skill: the policy file states the windows, and the script computes the partial refund. policy.md says apparel gets a full refund within 30 days, electronics within 14 days, any category gets a prorated partial refund between days 31 and 60, and nothing after 60; the chart shows the apparel line. prorate.py takes the amount and the days as long options, because run_skill_script passes the args dict as --amount and --days. The share is 60 minus days, over 30, capped at 1. Run the script by hand first, so you know the number the agent must reach: order A-300 is a 120 dollar jacket at day 42, so the share is 18 over 30, which is 0.6, and the refund is 72.0. Think of the script as a calculator stapled to the policy binder: the model decides when to use it, the code does the arithmetic. A likely question: "Why a script and not the model?" Models round and slip on arithmetic; a script gives the same answer every time and you can unit-test it.
