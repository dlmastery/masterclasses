from google.adk.events import RequestInput
def step1():  # the reply goes to the next node
  yield RequestInput(message="Enter a number:")

def handle_human_review(node_input: str):
  if node_input == "reject":
    yield Event(route="rejected")
  elif node_input == "approve":
    yield Event(route="approved")
  else:
    yield Event(state={"feedback": node_input}, route="revise")

root_agent = Workflow(name="request_input", edges=[
  ("START", process_input, draft_email,
   request_human_review, handle_human_review),
  (handle_human_review, {"revise": draft_email,
    "approved": send_email, "rejected": reject_email})])
response_schema does not reformat a free-text reply. Put an agent after the pause to normalize it.
Read the diagram from left to right. Step 1: request_human_review yields a RequestInput, and ADK sends it to the client as a functionCall with interruptId fc-1, listed in longRunningToolIds. Step 2: the node is WAITING and the invocation ends; no process waits in memory. Step 3: the human types "shorter", and the client sends a functionResponse named adk_request_input; handle_human_review gets the string and routes "revise". Step 4: the back-edge runs draft_email again, and the second pause has a new id, fc-2, at path request_human_review@2. Step 5: "approve" routes to send_email. Analogy: a paper form in an inbox tray; the office closes, and work starts again when the signed form comes back. Likely question: "Why a function call and not a special API?" Answer: every ADK client already knows how to return a FunctionResponse, so web UIs, Slack bots and A2A callers can all resume the same run.
