Sessions are keyed by app name, user id and session id. Step 1: Dana's session holds her tool calls and the answer about A-1003. Step 2: cust-li with session li-1 starts empty, so the agent says it has no earlier messages; run_debug created that session on first use. This is the isolation you want between customers. Step 3: the most common runner error is "Session not found: ", raised as SessionNotFoundError, a subclass of ValueError: the id was never created or was created under a different app_name. Fix it with create_session first, or Runner(..., auto_create_session=True). Related warning: if InMemoryRunner gets no app_name, ADK prints "App name mismatch detected" because the agent folder implies "refund_agent". Analogy: each session is a separate ticket folder; a new customer gets a new empty folder. Likely question: "Where does history live in production?" In a persistent session service, which Chapter 2 adds. Lab 1 ends here; next we move policy out of the prompt into callbacks.
