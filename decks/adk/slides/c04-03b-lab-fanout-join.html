The JoinNode hands decide one dict, keyed by branch name

# join output: {"policy_check": {...}, "fraud_score": 0.07,
#               "damage_estimate": 3990.0}
def decide(node_input: dict):
  pol, fraud = node_input["policy_check"], node_input["fraud_score"]
  est = node_input["damage_estimate"]
  payout = max(0, min(est, pol["limit"]) - pol["deductible"])
  if not pol["active"] or payout == 0:
    verdict = "DENY: policy inactive or payout 0"
  elif fraud > 0.6:
    verdict = f"REFER to SIU (fraud score {fraud:.2f})"
  else:
    verdict = f"APPROVE payout ${payout:,.2f}"
  yield Event(output=verdict, message=verdict)

Keys are the predecessor node names, which are the function names.

The branches finish at 0.2, 0.3 and 0.5 s. The join fires at 3/3.

max(0, …) stops a negative payout under the deductible.

Active policy, fraud 0.07: the claim is approved.

adk run prints only events with a message.

decide is the node after the barrier. The JoinNode emits one dict keyed by predecessor node name, and a function node's name is its function name, so the keys are policy_check, fraud_score and damage_estimate, as in the comment at the top. Step 1 shows the order in which the keys arrive: damage_estimate after 0.2 s, policy_check after 0.3 s, fraud_score after 0.5 s; the join fires only at three of three. Step 2 is the payout: the estimate of 3,990 is capped at the 20,000 limit, minus the 500 deductible, and max(0, ...) clamps it, so a claim under the deductible is denied instead of paying a negative amount. Step 3: the policy is active and the fraud score is 0.07, so the claim is approved for 3,490. Step 4: decide yields an Event with a message, because adk run prints only message content; a plain return value prints nothing. Analogy: the join is an inbox tray with three labelled slots, and decide reads the tray only when every slot is full. A likely question: "What if I rename a function?" Then the key changes too, and decide raises a KeyError; print node_input.keys() once, or name the node with @node(name=...).
