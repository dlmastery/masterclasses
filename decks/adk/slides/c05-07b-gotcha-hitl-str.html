The second HITL bug is the type trap from Lab 5A step 5, now in production. The CLI and most UIs send the reply as text, and the engine JSON-parses it when it can, so the word approve stays a string and ManagerDecision.model_validate raises a pydantic ValidationError. The docs are explicit: response_schema "does not reshape the reply"; the reply must already be in that format. The fix is to accept a string and turn it into the schema yourself, before model_validate. Be honest about the limit: this small parser covers approve and reject only, anything else becomes a reject, and it loses notes and partial amounts, so ask for JSON when you need those, or put a small LLM normalizer node after the pause. Think of it as a paper form with tick boxes: if someone writes "approve" across the top, a clerk must tick the box for them. A likely question: "Why not make every field optional?" Then a typo would approve nothing and still pass validation; a strict schema plus an explicit parser keeps the decision visible.
