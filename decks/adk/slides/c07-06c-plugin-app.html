labs/adk/lab7-acme-refunds/guarded_app.py · excerpt
from google.adk.apps import App
from refund_guard import RefundGuardPlugin
# LlmAgent, InMemoryRunner, issue_refund, M, T, ASKS: see the file
partner = LlmAgent(name="partner_refunds", model=M, tools=T,
                   description="Partner orders.")
chargebacks = LlmAgent(name="chargebacks", model=M, tools=T,
                       description="Chargebacks.")
refunds = LlmAgent(name="refunds", model=M, tools=T,
    sub_agents=[partner, chargebacks],
    instruction="Partner-store orders: transfer to partner_refunds.")
app = App(name="refund_app", root_agent=refunds,
          plugins=[RefundGuardPlugin()])
async def main():
    async with InMemoryRunner(app=app) as runner:
        await runner.run_debug(ASKS, verbose=True)

guarded_app.py builds the same three agents as the before slide, with no callback on any of them, and registers RefundGuardPlugin once with App(plugins=[...]). Focus one: the plugins list is on the App, not on an agent, so the hook runs for every agent and every tool in the App. Focus two: partner_refunds and chargebacks are sub-agents of refunds; the instruction routes partner-store orders to partner_refunds, which is exactly the path that leaked before. Focus three: InMemoryRunner takes the app, and run_debug sends both test asks. The call order is fixed: plugin callbacks run first, then agent callbacks, then the tool, and the first non-None result wins, so a plugin block is final. With adk web you can load the same class with --extra_plugins and no code change. Passing plugins to a Runner directly still works but logs "The plugins argument is deprecated. Please use the app argument to provide plugins instead." Think of a guard at the building door instead of a lock on one office. A likely question: "Do my agent callbacks still run?" Yes, after the plugins, unless a plugin already returned a result.
