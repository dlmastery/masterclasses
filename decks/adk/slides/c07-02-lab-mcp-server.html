from google.adk.tools.mcp_tool import to_mcp_server
from refund_core import refund_agent   # the shared agent

server = to_mcp_server(
    refund_agent,
    # a public hint for the MCP host, not the agent's instruction=
    instructions=("Ask about refund eligibility by order id, "
                  "e.g. 'Can A-100 be refunded?'"),
    runner=None,   # default: in-memory sessions, lost on restart
)

if __name__ == "__main__":
    server.run(transport="streamable-http",
               host="127.0.0.1", port=8090)

Step 1 of the Acme refund team: the shared refund_agent becomes one MCP tool that any MCP host can call. Walk the focus steps. First, the host sees only the agent's description, so write it as a tool contract; the policy stays in instruction, which is never exported, and the instructions argument of to_mcp_server is a different thing: a public hint that the MCP host may show its own model. Second, to_mcp_server registers exactly one tool, named after the agent, with one request string. Third, server.run serves streamable HTTP on port 8090 at /mcp, and ADK keeps one session per MCP connection, so two clients get two separate conversations and a reconnect starts a fresh one. Fourth, runner=None is the default and keeps every session in memory, so pass your own Runner before production. Think of a sealed vending machine: the label on the front is the description, and nobody sees the wiring inside. A likely question: "Is this production ready?"
