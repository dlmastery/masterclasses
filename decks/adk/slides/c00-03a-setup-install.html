Do this once before Lab 1; the same steps are in labs/adk/c00-acme-desk/README.md. Press once: check that Python is 3.11 or newer, because google-adk 2.12.0 raised the minimum and many macOS and Ubuntu LTS machines still default to an older Python; on Windows the command is python, not python3. Then make a virtual environment. Press again: activate it with the line for your OS; in cmd.exe the command is .venv\Scripts\activate.bat. Press again: pin google-adk to exactly 2.13.0. Thirteen minor releases shipped between 2.0.0 on 19 May and 2.13.0 on 23 October, and behaviour changed between them; for example, 2.10.0 stopped filling ${var} placeholders in instructions. The labs were checked against 2.13.0 only. Last press: pip show must say 2.13.0, and adk --help proves the CLI is on your PATH. The output is trimmed and illustrative; pip show prints more lines such as Summary and Location. We do not export the API key here: it goes in a .env file, which works the same on every OS. Analogy: pinning is like a recipe that names the exact flour, so every student gets the same cake. Likely question: "Can I use uv instead of pip?" Yes; pin the same version.
