from typing import Annotated
from pydantic import Field

def lookup_order(
    order_id: Annotated[str, Field(description="Order ID, e.g. A-1001")],
) -> dict:
    """Look up an order.

    Always call this before answering a refund question."""
    order = ORDERS.get(order_id.strip().upper())
    if order is None:
        return {"status": "error",
                "error_message": f"No order with ID {order_id}."}
    return {"status": "success", "order": order}

Codelab Building AI Agents with ADK: Empowering with Tools
The model never sees your Python. It sees a schema built from the signature and the docstring. Step 1: Annotated with Field(description=...) gives order_id its own description. Step 2: the whole cleaned docstring becomes the tool description, verbatim; ADK does not parse a Google-style Args: section, so per-parameter text goes in Field. The codelab says it plainly: "The LLM uses the docstring to decide when and how to call the tool." Step 3: return a dict, also for errors, so the model can read the error and recover; any non-dict value is wrapped as {'result': value}. Analogy: the docstring is the label on a drawer; the model never opens the drawer, it only reads the label. Likely question: "Where do I say when not to call the tool?" In the docstring: when to call it, what it returns, what it will not do. Next: the second tool and the agent.
