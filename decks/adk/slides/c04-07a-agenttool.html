Each built-in tool lives alone in its own LlmAgent.

AgentTool wraps an agent as a tool. Control returns to the root.

price_search holds only google_search. Pages stay in its context.

price_math runs Python in Gemini's sandbox, not on your machine.

The root reads two short results. Its context stays small.

Acme's back office wants competitor premiums. The fix for mixing built-in tools wraps each built-in in its own LlmAgent: price_search holds only google_search, price_math has a BuiltInCodeExecutor that runs in Gemini's sandbox, and the root pricing_analyst calls both through AgentTool, so control returns to the root instead of transferring away as with sub_agents. The excerpt cuts the description and instruction strings; the full text is in labs/adk/c04-pricing-analyst. AgentTool uses the subagent's description as the tool description, so write it for the root model to read. Watch the meter: each subagent fills its own context with pages and code, and only a short result travels back into a slot of the root, so the root context stays small. Analogy: the root is a manager who sends two analysts out and reads only their one-page memos. A likely question: "Why not put google_search on the root?" On Gemini 2.x the API rejects a built-in next to function tools, which is the next slide; on Gemini 3 and later you may mix them, but the context isolation is still a reason to split.
