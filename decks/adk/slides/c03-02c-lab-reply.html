write_reply = Agent(
    name="write_reply",
    model="gemini-3.5-flash",
    instruction=("You are a refunds agent. Case: {refund_case}. "
                 # ... eligible: confirm; else offer store credit
                 "Max 3 sentences."),
    output_key="reply_text",
)

def audit_log(reply_text: str):     # read from state by name
  yield Event(message=f"[audit] reply length={len(reply_text)}"
                      " chars. WORKFLOW COMPLETED.")

root_agent = Workflow(name="refund_flow", edges=[
    ("START", parse_request, check_policy, write_reply, audit_log),

The LLM node is an Agent. The other three nodes are functions.

{refund_case} reads state. output_key saves the answer as reply_text.

audit_log gets reply_text by name. yield Event(message=…) makes adk run print it.

One chain tuple: each node runs once, in this order.

The last piece of the refund chain: one Agent node and the graph itself. Step 1: the write_reply prompt reads {refund_case} from state, not the RefundCase on the edge, and output_key stores the model's answer in state as reply_text. The comment inside the instruction marks where the slide cuts the prompt; the full text is in the lab file. Step 2: audit_log has a parameter called reply_text, and parameter binding defaults to state, so the engine fills it from state by name. It yields an Event with a message because adk run prints only message events; a plain return only sets the node output. Step 3: one chain tuple wires all four nodes; "START" as a string works only inside a chain tuple. Step 4 is the run: A-1001 was delivered 12 days ago, inside the 30-day window, so the reply confirms the refund. The output is illustrative: the model text is invented, the event shape is real. A likely question: "Why yield instead of return?" Return only sets output, and the CLI prints nothing for output-only events. Next: follow the data through this run.
