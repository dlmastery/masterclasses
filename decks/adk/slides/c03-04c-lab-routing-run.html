These are the four branch nodes and the two runs of Lab 3.3. Step 1: the double-charge outage ticket runs billing. billing is an Agent and reads {ticket} from state, which intake wrote at the start. Step 2: the same run also pages on-call, because the route list holds billing and outage. page_oncall gets the output of route_ticket as node_input, a dict, and yields only a message. That is why two branches can run and the graph still has at most one terminal output: only billing ends with an output. If page_oncall returned a value, the run would stop with WorkflowConfigurationError; a gotcha slide later shows that error. Step 3: the thank-you ticket is labelled other, no key matches, and DEFAULT_ROUTE sends it to human_queue. Function nodes sign as ticket_triage, the Workflow name. The output is illustrative. A likely question: "Do the two branches run in parallel?" They are both scheduled from the same route event; do not depend on their order. Next: the same router as YAML.
