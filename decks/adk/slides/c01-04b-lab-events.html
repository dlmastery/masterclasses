    session = await runner.session_service.create_session(
        app_name=APP, user_id="cust-dana")

    async for event in runner.run_async(
            user_id="cust-dana", session_id=session.id, new_message=msg):
        for call in event.get_function_calls():
            print(f"  TOOL CALL  {call.name}({call.args})")
        for resp in event.get_function_responses():
            print(f"  TOOL RESULT {resp.name} -> {resp.response}")
        final = event.is_final_response()
        if final and event.content and event.content.parts:
            text = "".join(p.text or "" for p in event.content.parts)
            print(f"[{event.author}] {text}")

CXBench: 55.5% of runs had the right outcome with a non-compliant process.

arXiv 2610.25954 CXBench Repo google/adk-python v2.13.0 · runner_debug_example
This is the production loop. Step 1: create the session explicitly with the same app_name as the runner, then wrap the text as a types.UserContent. Step 2: run_async is the production entry point; run() is a sync wrapper that is only for local testing. Step 3: each event can carry function calls or function responses; print both, because that is your trajectory log. Step 4: is_final_response() is false while calls are pending and true for the last text event. The CXBench paper (arXiv 2610.25954) found that 55.5% of runs had the right outcome with a non-compliant process, so outcome-only checks pass bad runs. Analogy: the event stream is a flight recorder; you read it after the landing, not only the arrival time. Variation: pass abort_signal=asyncio.Event() to run_async (since 2.11.0) and set() it from a timeout task to cancel a runaway turn. Likely question: "Do I need the event loop for adk web?" No, adk web runs it for you; your own service needs it.
