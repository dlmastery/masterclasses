Agents catch loud tool errors, but miss quiet wrong values

trace · A-1001 · lookup_order returns a plausible wrong value
lookup_order(order_id="A-1001")
# -> {"status": "success", "order_id": "A-1001", "amount": -79.0}
issue_refund(order_id="A-1001", amount=-79.0, reason="damaged")
# a negative refund charges the customer; refund_policy_score passes

A 503 is loud. A well-formed −79.0 is quiet.

Agents flag the loud fault 91.3% of the time, the quiet one 58.8%.

With nothing wrong, they still raise a false alarm 26.8% of the time.

arXiv 2610.10062
This add-on starts with a failure our eval gate cannot see. When a tool says HTTP 503, agents notice; when lookup_order returns a well-formed negative amount, they often do not. The paper arXiv 2610.10062 measured it: agents flag the loud fault 91.3 percent of the time, the quiet wrong value only 58.8 percent, and with nothing wrong they still raise a false alarm 26.8 percent of the time, so the quiet case is barely above guessing. Here the harm is real: a refund of minus 79 dollars charges the customer, and our 500 dollar metric still passes it, because minus 79 is below 500. The paper also found that a prompt line telling the model to check each result did not change detection, so the next slide puts the check in code. Analogy: a gas leak has no sound; you need a detector, not a sharper ear. A likely question: "Would the trajectory metric catch this?" No: the tools and their order are correct, only a value is wrong.
