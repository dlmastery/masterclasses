No terminal for claims_server.py. McpToolset starts it over stdio.

You need three terminals, and the order matters. Step 1: terminal 1 runs the claims-status REST service on port 8081 with its API key. Step 2: terminal 2 runs the handbook MCP server on port 3000; its endpoint is /mcp. Step 3: terminal 3 runs adk api_server with the dev UI on port 8000; pick claims_agent in the app list. We use api_server instead of adk web because the tenant step creates sessions over REST; adk web is fine until then. The claims MCP server has no terminal, because McpToolset starts it as a child process over stdio. Step 4: check terminal 1 with curl before you start the agent, because agent.py downloads the OpenAPI spec when it is imported. Think of a restaurant: two suppliers deliver from outside, and one cook works inside the kitchen. On Windows, use WSL, or the cmd forms in the README. A likely question: "Why must terminals 1 and 2 start first?" agent.py fetches the spec at import, and the HTTP toolset connects when the agent first runs.
