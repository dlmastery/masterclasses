Live agents stream audio and video both ways and must handle barge-in

Voice budget: a cascaded STT → LLM → TTS pipeline takes ~1.3 s voice-to-voice. Target 1.5 s, and measure mic-to-speaker, not model TTFB.

Pitfall: the client ignores interrupted. Then buffered audio plays over the user. Flush the player. Also call close() in finally, or zombie sessions stay on your quota.
Codelab Way Back Home - Building an ADK Bi-Directional Streaming Agent Docs ADK Live and voice agents
Input16-bit PCM, 16 kHz mono, 50–100 ms chunks (100 ms = 3,200 bytes). ADK does no transcoding.
OutputPCM 24 kHz. Live models answer in audio only: response_modalities=["AUDIO"]. Text comes from transcription.
VideoJPEG frames, ~1 fps, 768×768. "There is no video codec: a video stream is a sequence of still frames."
Queuesend_content (one text turn) · send_realtime (audio, frames) · send_activity_start/end (manual VAD only) · close()
Eventspartial · turn_complete · interrupted · input/output_transcription · usage_metadata
LimitsConnection ~10 min (GoAway with timeLeft). Without compression: audio 15 min, audio + video 2 min.
Costmax_llm_calls (default 500) does not apply to run_live. Set your own budget.

server.py · adk.dev/live/custom-server (fragments)

run_config = RunConfig(
    response_modalities=["AUDIO"],
    input_audio_transcription=types.AudioTranscriptionConfig(),
    output_audio_transcription=types.AudioTranscriptionConfig(),
    session_resumption=types.SessionResumptionConfig())
live_request_queue = LiveRequestQueue()     # fresh per session
async def upstream():                       # browser -> model
    while True:
        audio_data = await websocket.receive_bytes()
        live_request_queue.send_realtime(types.Blob(
            mime_type="audio/pcm;rate=16000", data=audio_data))
async def downstream():                     # model -> browser
    async for event in runner.run_live(
            user_id=user_id, session_id=session_id,
            live_request_queue=live_request_queue,
            run_config=run_config):
        await websocket.send_text(
            event.model_dump_json(exclude_none=True, by_alias=True))
try:
    await asyncio.gather(upstream(), downstream(),
                         return_exceptions=True)
finally:
    live_request_queue.close()              # always, even on error
A live agent keeps one two-way connection open, so the user can talk while the agent talks. Step 1: two lanes run at the same time; upstream carries 16 kHz PCM mic chunks through send_realtime, downstream carries 24 kHz audio and events out of run_live. Step 2: the user speaks over the agent; the Live API sends interrupted, and the client must flush its playback buffer, or the old answer keeps playing. Step 3: the WebSocket closes after about 10 minutes; session resumption reconnects with a handle that stays valid for 2 hours, and context window compression removes the 15-minute audio and 2-minute audio-plus-video caps. Steps 4 to 6 walk the server code: run upstream and downstream as concurrent tasks, because sequential code loses interruption, and always close the queue in finally. Analogy: a phone call, not an exchange of letters. Likely question: "Why can my Live agent not return text?" Native-audio Live models answer in audio only, so you read the text from output transcription.
