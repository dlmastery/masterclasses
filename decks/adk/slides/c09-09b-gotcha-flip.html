Issue #7258 safety_v1 flip
A third silent failure: the metric itself changes meaning. safety_v1 resolved to the unversioned latest safety metric, which became safety_v3 and scores in the opposite direction, issue 7258; it is fixed in 2.10.0, but the behaviour also depends on the google-cloud-aiplatform version, so pin both. Watch the fixture table: with a sound metric, the known-good case passes and the known-bad case fails; after the flip both results invert, and only the known-bad fixture tells you. The gate script ends with exactly that: known_bad.evalset.json is a copy of the A-2040 case that expects issue_refund for 820 dollars, so a correct agent must fail it, and if adk eval exits 0 the gate stops. Analogy: you test a scale with a known weight before you trust it. A likely question: "Why does the known-bad case fail on a correct agent?" The correct agent escalates instead of refunding, so the trajectory metric does not match the expected issue_refund call.
