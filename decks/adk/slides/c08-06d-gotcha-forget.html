Gotcha Memory

adk web forgets on restart; delete_session does not forget

SymptomMemories vanish after adk web restarts. CauseWithout a URI, adk web uses InMemoryMemoryService. FixPoint it at Memory Bank. To erase, call delete_memory.
terminal · labs/adk/c08-memory-bank/
$ adk web . \
    --memory_service_uri="agentengine://$AGENT_ENGINE_ID"
Issue #7109: delete_session leaves memories
Two memory traps point in opposite directions. Press once: in the dev UI, adk web without --memory_service_uri falls back to InMemoryMemoryService, so the callback works, but every memory disappears when the server restarts; the top lane shows the restart wiping the chips. Press again: start adk web with --memory_service_uri pointing at your Agent Runtime, and the Memory Bank lane keeps the facts across restarts. Press again: the opposite trap: deleting the session does not delete memories. Issue 7109 showed that memories survive delete_session, so a forget-me request must call delete_memory, new in 2.13, in the erasure path. Think of a notebook on the desk versus a filing cabinet: the in-memory service is the notebook that goes in the bin every night, and shredding the call log does not empty the cabinet. A likely question: "Does a new session id forget the user?" No, memories are keyed by app_name and user_id, not by session.
