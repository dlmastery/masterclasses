Step 0, the before block: InMemoryRunner keeps the session in a Python dict, so when the first process exits the conversation goes with it, and the second process answers that it does not have that detail. Click 1: the fix swaps the session service. Import SqliteSessionService from google.adk.sessions.sqlite_session_service, because it is not re-exported; it needs no extra install, because aiosqlite is a core dependency. Click 2: one constructor with a file name; the file is created in the current folder, and you delete it to start fresh. The first run stores 2 events, the user message and the reply. Click 3: the Runner takes session_service=sessions and auto_create_session=True; run 2 is a new process that loads claim-77 from the file, answers with the 2024 Civic, and the count goes to 4. Analogy: the in-memory runner is a whiteboard that is wiped when the meeting ends; SQLite is the claim folder in the filing cabinet. For production, install google-adk[db] and asyncpg and use DatabaseSessionService with a postgresql+asyncpg URL; only ADK 1.28 and later can read sessions that 2.x writes, so upgrade every reader first.
