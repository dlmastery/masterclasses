async def save_to_memory(callback_context) -> None:
    await callback_context.add_session_to_memory()

agent = Agent(name="support_agent", model="gemini-3.5-flash",
    instruction="Acme support. Use remembered preferences.",
    tools=[preload_memory], after_agent_callback=save_to_memory)
memory = VertexAiMemoryBankService(
    project=os.environ["GOOGLE_CLOUD_PROJECT"],
    location=os.environ["GOOGLE_CLOUD_LOCATION"],
    agent_engine_id=os.environ["AGENT_ENGINE_ID"])
runner = Runner(agent=agent, app_name="acme_support",
    session_service=InMemorySessionService(),
    memory_service=memory, auto_create_session=True)

The callback runs after every turn and sends the session.

The service points at the bank by AGENT_ENGINE_ID.

Without memory_service, the callback raises a ValueError.

Day one: the customer, cust-42, tells Acme support once that she is on the Family 4-line plan and wants SMS only. Press once: save_to_memory is an after_agent_callback; it runs after every agent turn and calls add_session_to_memory, which sends the session so far to the memory service. Press again: VertexAiMemoryBankService points at the bank by project, location and the AGENT_ENGINE_ID from the setup slide. Press again: the Runner must get memory_service=memory, or the callback raises "Cannot add session to memory: memory service is not available"; auto_create_session=True creates session "day1" on first use. Then the two facts move into the bank; Memory Bank extracts them asynchronously on the service side. Think of it as the notes a good call-centre agent writes after a call. A likely question: "Does it store the whole chat?" It sends the session, and Memory Bank extracts and consolidates facts from it; the next slide reads them back.
