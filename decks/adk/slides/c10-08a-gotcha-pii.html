Spans copy message content unless you turn capture off

SymptomEmployee names and HR ticket text show in Cloud Trace. CauseADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS defaults to on. FixSet it to false on every target that does not do it for you.

the fix · google-adk 2.13.0
# Cloud Run: capture is on unless you say no
adk deploy cloud_run --project=$PROJECT --region=$REGION \
  --service_name=acme-hr hr_agent \
  -- --no-allow-unauthenticated \
  --set-env-vars=ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false
# Agent Runtime: --otel_to_cloud turns it off
adk deploy agent_engine --project=$PROJECT --region=$REGION \
  --agent_engine_id=$AGENT_ENGINE_ID --otel_to_cloud hr_agent
Tracing is on in the Acme HR assistant, and three telemetry defaults now work against us; this is the first. ADK copies the message content into spans unless ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS is false; the default lives in telemetry/context.py. Press once: only adk deploy agent_engine with --otel_to_cloud sets it to false for you; on Cloud Run and on GKE it stays on. Press again: on Cloud Run, pass the env var to gcloud after the double dash with --set-env-vars. Press again: on Agent Runtime, --otel_to_cloud already does it. On GKE, set the same env var in the deployment. Lab 10 step 2 set it in code with os.environ.setdefault, which also works for a script you run yourself. Analogy: a security camera that records audio by default; switch the microphone off before you mount it. Likely question: "Can I keep content for debugging?" Keep it in an access-controlled store keyed by the trace id, not in spans that the whole ops team can read.
