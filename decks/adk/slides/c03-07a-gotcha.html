class Triage(BaseModel):
  labels: list[str]          # free text: "Billing" is legal
  priority: str

def route_ticket(node_input: Triage):
  yield Event(output=node_input.model_dump(),
              route=list(node_input.labels))

# intake, classify, billing, page_oncall, how_to: Lab 3.3
root_agent = Workflow(name="ticket_triage", edges=[
    ("START", intake, classify, route_ticket),
    (route_ticket, {"billing": billing, "outage": page_oncall,
                    "how_to": how_to}),
])

The model wrote "Billing" with a capital B.

The route tries each key. None matches.

No branch runs. Nothing raises. One WARNING line.

The engine treats an unmatched route as a legal end of a branch.

Workflow graphs can fail without a sound. The code is the free-text variant in labs/adk/c03-ticket-triage/ticket_triage_freetext: labels is a plain list of strings, so the model may write "Billing" with a capital B. Step 1: route_ticket emits route=['Billing']. The token tries each key, billing, outage and how_to, and matches none. Step 2: nothing raises. The branch ends and you get one WARNING log line: "Node 'route_ticket' has conditional/DEFAULT edges but none were matched by the emitted route(s): ['Billing']. The branch will end." Step 3: this is by design: the engine treats an unmatched route as a legal end of a branch, so the fallback must be explicit. Analogy: an unmatched route is a letter with a wrong address that nobody returns. A likely question is "Why does the engine not raise?": a branch that ends is a normal thing in a graph, so it cannot tell your typo from your intent. Next slide: the two-part fix.
