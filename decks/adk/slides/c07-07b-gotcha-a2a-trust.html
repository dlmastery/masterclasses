An A2A card can list auth schemes, but the card does not enforce them. The to_a2a docstring says security_schemes "populates metadata on the card only and is not enforced at runtime by the Starlette application", so a call with no token still gets 200 OK. Step 2: put the check in front of the server: Cloud Run IAM, an API gateway, or your own middleware; now a call without a token is rejected before it reaches the agent. Steps 3 and 4: the client sends a bearer token. token_to_scheme_credential with oauth2Token returns an HTTP bearer scheme and a credential, and RemoteA2aAgent sends them on every call through auth_scheme and auth_credential. The token comes from the REFUNDS_ID_TOKEN environment variable, for example an identity token for the Cloud Run service. Analogy: a business card that says "visitors need a badge" does not lock the office door; the guard at the door does. A likely question: "Is the card itself secret?" No, the card is public on purpose, which is why it must never hold the instruction or any secret.
