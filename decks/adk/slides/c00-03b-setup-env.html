One file holds the key on every OS, so we do not export anything in the shell. The folder tree is the agent package: __init__.py contains exactly one line, from . import agent, agent.py defines root_agent, and you run adk from the parent folder. Press once: the .env file sits inside the agent folder; adk run and adk web load it automatically, so you do not call load_dotenv yourself, and each agent folder has its own .env. FALSE means "use the AI Studio key, not a Cloud project". No quotes are needed around the key. Add .env to .gitignore: committing a key is the real Monday risk. The lab folder ships acme_desk/.env.example; copy it to .env. Press again: you will see GOOGLE_GENAI_USE_VERTEXAI in older tutorials and codelabs. In google-adk 2.x that name still works but raises a DeprecationWarning (utils/env_utils.py), and GOOGLE_GENAI_USE_ENTERPRISE wins if both are set. Last press: the fix points at the line to keep. Analogy: a renamed light switch still works, but the electrician leaves a note on it. Likely question: "Should I commit .env?" No; commit .env.example and keep the key out of git.
