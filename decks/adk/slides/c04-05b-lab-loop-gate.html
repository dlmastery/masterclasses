def gate(ctx: Context, node_input: Review):
  ctx.state["round"] = ctx.state["round"] + 1
  if node_input.grade == "compliant":
    yield Event(route="done")
  elif ctx.state["round"] >= MAX_ROUNDS:   # MAX_ROUNDS = 3
    yield Event(route="escalate")
  else:
    yield Event(state={"feedback": node_input.feedback},
                route="retry")

gate is the only thing that stops the loop: a graph cycle has no max_iterations, and the docs say it plainly, "A graph cycle is not bounded automatically." Walk the steps with the counter, which only goes up. Round 1: the writer drafts, the reviewer says needs_fix, gate adds one to round and routes retry with the feedback in state. Round 2: the same write_copy object revises the draft, the reviewer says compliant, and gate routes done to publish. Step 4 is the other exit: if round 3 still fails, gate routes escalate and a person in Legal takes the draft. publish and escalate get draft and round as parameters because function parameters that are not node_input or ctx are looked up in ctx.state by name. Step 5 is the edges: the back-edge reuses the same write_copy object, and because it is routed, validation accepts the cycle. Think of a junior copywriter and a compliance officer: after three rejections the draft goes to a lawyer instead of a fourth try. A likely question: "Why count in state and not in a Python variable?" State is saved with the session, so the count survives a resume and shows up in traces and evals.
