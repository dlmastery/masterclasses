Docs Skills for ADK agents
A skill with a script needs something to run the script. Without an executor on the toolset or on the agent, run_skill_script does not crash; it returns an error dict: "Neither Environment nor CodeExecutor is configured. An environment or code executor is required to run scripts.", with error_code NO_CODE_EXECUTOR. The model then often apologises or guesses the number, which is worse than a crash. The fix is to pass code_executor or environment on the SkillToolset, not both; passing both raises a ValueError. UnsafeLocalCodeExecutor is for a laptop only: it runs exec() in your process, shares its memory, and script_timeout does not apply. In production use ContainerCodeExecutor or GkeCodeExecutor, which isolate the script. Analogy: a recipe that says "bake for 20 minutes" is useless without an oven, and you do not put the oven in the dining room. A likely question: "Why not run scripts locally in production?" Because exec() shares your process and its memory, and nothing stops a slow script.
