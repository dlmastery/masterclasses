The $500 rule lives only in the instruction text

def escalate_to_human(order_id: str, reason: str) -> dict:
    """Opens a ticket for a supervisor to approve a large refund."""
    return {"status": "success", "ticket_id": f"ESC-{order_id.upper()}"}

root_agent = Agent(
    name="refund_agent",
    model="gemini-3.5-flash",
    instruction=(
        "You handle refund requests for Acme Retail. Always call "
        "lookup_order first. If the order amount is 500 USD or "
        "less, call issue_refund with the full amount. If it is "
        "above 500 USD, never call issue_refund; call "
        "escalate_to_human instead. "
        "Tell the customer a supervisor will review it "
        "within 24 hours."),
    tools=[lookup_order, issue_refund, escalate_to_human])

The third tool opens a ticket for a human supervisor.

The limit is a sentence. A model can ignore a sentence.

Today the agent escalates A-2040. The gate must prove it on every build.

Step three: the last tool and the agent itself. escalate_to_human opens a ticket for a supervisor, and the instruction says to call it instead of issue_refund above 500 dollars. That rule lives only in text: nothing in the code stops the model from calling issue_refund with 820 dollars, so a prompt edit or a model update can break it silently. Run adk run refund_agent from the lab folder and ask about A-2040: today the agent escalates and gives ticket ESC-A-2040. The output here is illustrative. Analogy: a sign that says "do not enter" is not a lock; the eval gate is the camera that checks every night whether someone walked through. A likely question: "Which model?" gemini-3.5-flash, the 2.13.0 default; we pin it so a model update cannot move the scores without us knowing.
