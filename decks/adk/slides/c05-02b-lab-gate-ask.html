@node(rerun_on_resume=True)
def manager_gate(ctx: Context, amount: float, draft: str):
  if amount <= AUTO_APPROVE_LIMIT:
    yield Event(route="approved", state={"final_amount": amount})
    return
  iid = f"refund_approval_{ctx.invocation_id}_{ctx.run_id}"
  answer = ctx.resume_inputs.get(iid)     # None on the first run
  if answer is None:
    yield RequestInput(
        interrupt_id=iid, response_schema=ManagerDecision,
        payload={"amount": amount, "draft": draft},

Step 2 of Lab 5A opens manager_gate. Three clicks. First, the limit: a $320 refund would route straight to issue_refund, which the dashed token shows; nobody is asked. Second, the id: iid is built from invocation_id and run_id, and on the first run resume_inputs.get(iid) returns None, because nobody has answered yet. Third, the question: the node yields a RequestInput with that id, the ManagerDecision schema, and a payload with the amount and the draft, so the approval screen shows exactly what is approved. The run pauses; on the wire this is a FunctionCall named adk_request_input whose id is the interrupt id, and it is listed in event.long_running_tool_ids. Think of the interrupt id as a ticket number stapled to the form: when the form comes back, the clerk finds the answer under that number. A likely question: "Why build the id by hand and not let ADK make one?" The default is a new uuid, and on a rerun that would never match the stored answer; the gotcha slides come back to this.
