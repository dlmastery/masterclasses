intake_agent = Agent(
    name="claim_intake",
    model="gemini-3.5-flash",
    instruction=("Extract a ClaimIntake from the email. "
                 "Never guess a value."),
    output_schema=ClaimIntake,     # not generate_content_config
    output_key="claim",
)
# ...
async def main(email: str) -> None:
    runner = InMemoryRunner(agent=intake_agent, app_name="claims_api")
    await runner.run_debug(email, quiet=True)
    s = await runner.session_service.get_session(
        app_name="claims_api",
        user_id="debug_user_id", session_id="debug_session_id")
    claim = s.state["claim"]            # a dict, None fields dropped

The agent uses the ClaimIntake schema from the previous slide.

output_schema validates the reply. output_key names the state key.

run_debug makes its own session: debug_user_id, debug_session_id.

State gets a plain dict. The null incident_date is not stored.

Same file, second half: the agent and the run. Click 1: output_schema validates the model reply against ClaimIntake, and output_key names the state key, here "claim". Click 2: run_debug creates its own session with user_id "debug_user_id" and session_id "debug_session_id", which is why get_session uses those ids. Click 3: state receives a plain dict from model_dump(exclude_none=True), so the null incident_date is not in state at all; read optional keys with .get(), and call ClaimIntake.model_validate(claim) when you want the typed object back. The gotcha slide later shows the KeyError this causes. Analogy: the clerk files a copy of the form and leaves out the empty boxes. A likely question: "Why not keep the pydantic object in state?" State must be JSON-serialisable so every session service can store it, so ADK stores a dict.
