End the technical part with what nobody has solved. Step 1: METR's 50% time horizon grew from about 1 hour (Claude 3.7 Sonnet, Feb 2025) to about 12 hours (Opus 4.6, Feb 2026) and about 17 hours (Claude Mythos Preview); METR itself says measurements above 16 hours are unreliable. Step 2 adds the contrast: on OSWorld 2.0, 108 long-horizon computer tasks with a median human time of 1.6 hours, the best binary score is 20.6% (Claude Opus 4.8). Step 3: Carlini's C compiler, 16 parallel Claudes, about 100k lines of Rust for just under $20,000, worked only because the verifier was nearly perfect. Steps 4 to 6: injection needs architecture, not only classifiers; Cognition names three coordination problems; ADK resume replays the event log, and node checkpoints are written but not read yet; evals saturate and drift, and learning agents add memory poisoning. Closing line: harness complexity does not shrink as models improve; it moves, so re-test the harness with every new model. Analogy: a bridge inspector re-certifies the bridge when the traffic changes, not only when the bridge changes. Likely question: "Will a better model fix these?" It moves the problems: longer tasks need better verifiers, more memory and more cost control.
