@mcp.tool()
def approve_claim(claim_id: str, approved_amount: float) -> dict:
    """Approve a claim and pay approved_amount USD."""
    claim = CLAIMS.get(claim_id)
    if claim is None or approved_amount > claim["amount"]:  # rule
        return {"status": "error",
                "message": "Unknown claim or amount too high."}
    claim["status"] = "approved"
    return {"status": "ok", "paid": approved_amount}
@mcp.tool()
def purge_claim(claim_id: str) -> dict:
    """Permanently delete a claim record (admin role only)."""
    if os.environ.get("CLAIMS_ROLE") != "admin":  # role check
        return {"status": "error", "message": "Needs the admin role."}
    purged = CLAIMS.pop(claim_id, None) is not None
    return {"status": "ok", "purged": purged}

Step 2 hides purge_claim from the model. Other MCP clients can still call it.

The server keeps its own rules, whatever the client does. Step 1: approve_claim pays only up to the claimed amount, so 1,800 on a claim of 1,800 passes. Step 2: the same rule refuses 5,000 with a structured error that the model can read. Step 3: purge_claim refuses any caller without the admin role, so a delete needs a server-side role, not only a polite prompt. Step 4: in step 2 of the lab, tool_filter hides purge_claim from our model, but MCP clients other than ADK can still connect to this server, so the check must live here. Think of a bank vault: the teller's screen hides the vault button, and the vault door still has its own lock. A likely question: "Why not just remove purge_claim from the server?" Other clients, such as an admin console, may need it; each client filters what its own model may see, and the server enforces the role.
