One more detail of the HTTP toolset: ADK caches the tools/list answer. Step 1: tool_list_cache_ttl_seconds=300 keeps each list for five minutes, and the cache is keyed like the session pool, so each header identity, here each broker, has its own entry and its own clock. Step 2: the server team deploys a new tool. ADK does not subscribe to the tools/list_changed notification, so both caches still say "listed 2" until their entries expire. Step 3: when each clock runs out, the next call lists 3 tools, but the agent still shows 2, because tool_filter lists only the two tools we reviewed. Step 4: that is the point of the filter: a server-side change cannot widen the agent's action space without a code review. A value of 0 raises ValueError; use None to turn the cache off. Think of a restaurant menu that is reprinted every five minutes, but the waiter only offers the dishes the manager approved. A likely question: "Why did my new server tool not appear?" The cache had not expired yet, or tool_filter does not list it.
