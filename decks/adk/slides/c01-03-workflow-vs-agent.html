Start with the two definitions from Anthropic: in a workflow the code fixes the path; in an agent the model picks the path. Step 1 is the compounding-error argument: at 95% per step, a 20-step run succeeds only 0.95 to the power 20, about 36% of the time. Step 2 shows the idea of a per-step verifier: if a perfect check catches each failure and allows one retry, each step fails only 0.05 squared, and the run climbs back to about 95%. That is arithmetic under an assumption, not a benchmark. Step 3 is the ladder: climb one rung only when the eval of the lower rung fails; agents cost about 4 times the tokens of chat and multi-agent systems about 15 times. Step 4 is Google's own refund example: line 4 has one function node and one LLM node for the unstructured complaint; step 5 shows that lines 5 and 6 let code, not the model, pick the money edge. Analogy: you do not hire a project manager to run a vending machine. Likely question: "When would you not build an agent?" When the path is data-determined, has irreversible side effects or needs an audit trail.
