This is the same refund_approval agent, run as three separate processes against one session. Monday at 10:00 the customer asks for 820 dollars, the gate pauses, adk run saves the session in SQLite under refund_approval/.adk and exits with code 2, so a script can tell "paused" from "done". On Tuesday the manager answers from a brand-new process: adk run sees the open interrupt in the session and sends the reply as a FunctionResponse with the interrupt id, printing "Auto-resuming interrupt". The note routes to revise, draft_reply writes a new draft, and the gate pauses again with a new id ending in _2, because a revise pass is a new run of the node. The third process approves 700 dollars, a partial refund, and issue_refund prints the idempotency key refund-A-2040. The last click shows the link between processes: each reply is matched to the saved interrupt by its id. Think of the session as a case folder on a shelf: any clerk on any day can pick it up and continue. A likely question: "Do I need ResumabilityConfig for this?" No: answering a pause is a new turn, and the Runner finds the paused run from the response id; ResumabilityConfig is for continuing a crashed run, in Lab 5B.
