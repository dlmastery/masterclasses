MCP, OpenAPI and tool errors

Build the Acme claims desk: two MCP servers and a REST API behind least privilege, with errors written for the agent.

MCP: a JSON-RPC protocol for tool servers. ADK's McpToolset is the client.

Codelab Getting Started with MCP, ADK and A2A Docs adk.dev MCP tools
This chapter connects the Acme claims desk to three tool sources. MCP, the Model Context Protocol, is a JSON-RPC protocol that lets an agent list and call tools on a separate server; ADK's McpToolset is the client side. Over stdio the server is a child process that the agent starts, and over streamable HTTP it is a network service that many agents share. The first source is a claims MCP server over stdio, the second a claims-handbook MCP server over streamable HTTP, and the third the claims-status REST API through OpenAPIToolset. The animation shows the rule for the whole chapter: every source offers more tools than the agent needs, so tool_filter drops purge_claim before the model sees it, and a prefix (claims_, handbook_) tells the model which server each tool comes from. Think of a new adjuster on the first day: you give them the keys to the rooms they need, not the master key. We also write tool errors for the agent, because the agent can only act by calling another tool. Everything is tested on Python 3.11+, google-adk 2.13.0 and mcp 2.3.0, and you will run three processes: claims_api on port 8081, handbook_server on port 3000, and adk web. A likely question: "If I filter tools, can the server still be called directly?" Yes, by other MCP clients, so the server keeps its own checks too. The next slide sets up the lab folder.
