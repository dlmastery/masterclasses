Build Acme refund desk · before_tool: refund cap

before_tool_callback blocks a $2,000 refund before the tool runs

labs/adk/lab1-refund-guardrails/refund_agent/agent.py · excerpt
def refund_cap(tool: BaseTool, args: dict[str, Any],
               tool_context: ToolContext) -> Optional[dict]:
    cap = tool_context.state.get("app:refund_cap_usd", 1500)
    amount = args.get("amount_usd", 0)
    if tool.name == "issue_refund" and amount > cap:
        msg = f"Refunds over ${cap} are blocked by policy."
        return {"status": "error", "error_message": msg}
    return None                        # None = run the tool

root_agent = Agent(
    # ... name, model, instruction, tools as before
    before_tool_callback=refund_cap,
)

Step 1: the cap is data, read from app: state with a default of 1500, so ops can change it without a deploy. Step 2: when issue_refund asks for more than the cap, the callback returns an error dict; any non-None value from a before_tool callback skips the tool, and the model reads the dict as the tool result, so it can explain the limit to the customer. Step 3: return None to let the tool run, as the $80 refund does. Step 4: wire it with before_tool_callback=refund_cap on the Agent; the callback runs for every tool, so check tool.name. Pitfall: returning {} also skips the tool, while False and None do not. Analogy: the till refuses a refund over the limit, whatever the clerk was told. Likely question: "Why not raise an exception?" Because the model can read an error dict and recover; an exception ends the turn. Next: redaction and metering.
