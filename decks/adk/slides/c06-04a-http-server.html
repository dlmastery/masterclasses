from mcp.server.mcpserver import MCPServer
mcp = MCPServer("claims-handbook-server")
POLICIES = {
    "glass": "Glass repair: no deductible on comprehensive policies.",
    "rental": "Rental car covered up to 30 days at $40 per day.",
    "towing": "Towing covered up to 50 miles per incident.",
}
@mcp.tool()
def search_policy(topic: str) -> str:
    """Search the claims handbook. topic: glass, rental or towing."""
    return POLICIES.get(topic.lower(), f"No policy for '{topic}'.")
# list_topics(): same pattern, returns sorted(POLICIES)
if __name__ == "__main__":
    # mcp 2.x: host and port go to run(); the path defaults to /mcp
    mcp.run(transport="streamable-http", host="127.0.0.1", port=3000)

This is step 3 of the Acme claims desk: the claims handbook runs as its own MCP server over streamable HTTP, in terminal 2. Step 1: the tool looks the same as on stdio; the decorator, the docstring and the type hints define it. Step 2: the difference is the transport. In mcp 2.x, host and port go to run(), not to the MCPServer constructor, and the endpoint path defaults to /mcp, so the agent URL must end in /mcp. Step 3: a stdio server is a child process of one agent and dies with it; an HTTP server is a network service that many agents share, here the claims desk, a triage agent and an audit agent, and it keeps running when an agent stops. Think of the stdio server as a cook inside one restaurant, and the HTTP server as a supplier across the street that many restaurants use. A likely question: "When do I choose HTTP?" When several agents or teams share the tools, when the server needs its own scaling or deploy cycle, or when it runs in another language or host.
