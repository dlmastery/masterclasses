The last telemetry gotchas share one pattern: nothing errors, the numbers just stop. Press once: if Phoenix or Langfuse installs a global TracerProvider before ADK, ADK's own set call is "a no-op and results in a warning", so ADK spans never appear; register one provider and add the extra span processors to it. Press again: with MCP SDK 2.x, MCP calls go untraced, because the instrumentor is built for httpx 1.x; know this gap before you debug an MCP tool from traces. Press again: 2.2.0 sent cloud.resource.id instead of cloud.resource_id, so dashboards keyed on the right name read zero until 2.4.0 fixed it. The defence for all three is the alert at the bottom: spans are ingested, but the metric is zero. Analogy: a smoke detector with a dead battery is silent too; test it on purpose. Likely question: "How do I test the alert?" Send one synthetic query per deploy and check that both counters move. The counter values are illustrative.
