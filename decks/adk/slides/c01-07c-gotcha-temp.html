Agent rejects temperature=0, and Gemini 3 wants 1.0 anyway

refund_agent/agent.py
root_agent = Agent(
    name="refund_agent", model="gemini-3.5-flash",
    temperature=0,          # not an Agent field
    # ...
)
output · pydantic ValidationError
temperature is a GenerateContentConfig field.
Pass generate_content_config=
  types.GenerateContentConfig(temperature=...)
  instead.
refund_agent/agent.py
from google.genai import types

root_agent = Agent(
    name="refund_agent", model="gemini-3.5-flash",
    generate_content_config=types.GenerateContentConfig(
        temperature=1.0),   # the Gemini 3 default
    # ...
)

"Changing the temperature (setting it below 1.0) may lead to unexpected behavior, such as looping or degraded performance."

Docs Gemini 3 developer guide
Step 1: many first agents copy temperature=0 from older tutorials and pass it straight to Agent. Step 2: ADK rejects it with a pydantic ValidationError: "temperature is a GenerateContentConfig field. Pass generate_content_config=types.GenerateContentConfig(temperature=...) instead." Step 3: sampling settings belong in generate_content_config. Step 4: on Gemini 3 do not lower the temperature at all: the Gemini 3 developer guide says that setting it below 1.0 "may lead to unexpected behavior, such as looping or degraded performance". That links straight back to the last gotcha: a lower temperature can cause the loop that hits the call cap. Analogy: the agent is the driver, the GenerateContentConfig is the engine map; you tune the engine in its own menu. Likely question: "How do I make answers deterministic, then?" Put the decision in tools and callbacks, which are deterministic code, and test the trajectory, not the wording. Next: two October papers on tool descriptions.
