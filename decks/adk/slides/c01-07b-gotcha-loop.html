The third first-run error comes from the runner. Step 1: the symptom is LlmCallsLimitExceededError with the text "Max number of llm calls limit of `500` exceeded": the model called a tool again and again in one run, often because the tool returned a vague error. Step 2: the default cap is 500 LLM calls per run, so a loop burns 500 calls before it stops. Step 3: set RunConfig(max_llm_calls=20) on run_async, or the ADK_MAX_LLM_CALLS environment variable, so a loop fails fast and cheap at 20; then read the logged tool calls to find the loop. The excerpt is in labs/adk/lab1-refund-tools/run_capped.py. Analogy: the call cap is a circuit breaker; it protects the bill, it does not fix the wiring. Likely question: "Is 20 enough?"
