Score hard rules in code, and only meaning with a judge

  • The $500 rule is a code metric.
  • Judges score meaning: pinned model, 5 samples.
  • A completion bit beside every rubric.
  • Rubrics state the procedure, not golden ids.
  • No reference metrics on simulated cases.

The first half of the checklist for the Acme refund eval gate: what to score. Hard rules such as the 500 dollar ceiling go into a code metric, because judges plateau at 77 to 82 percent on hard tool-calling cases. Use the judge only for meaning, with a pinned model and five samples, because a pinned judge still flips about 40 percent of close calls. Put a judge-free completion bit beside every rubric, because 57.5 percent of "satisfied" simulated chats had failed. Write rubrics that describe the procedure, not the golden values: the CARGO paper, arXiv 2609.30471, found a reference-based judge failed every correct answer about an entity that differed from the golden one. And keep reference metrics off simulated cases, which have no golden turns; ADK fails with "expected_invocations is needed by this metric." Analogy: use a ruler for lengths and a person for taste, never the other way round. A likely question: "Does this mean one metric per rule?" Yes: small, named metrics make a red run easy to read.
