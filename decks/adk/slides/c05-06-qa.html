Interview drill: control what the model sees and remembers

Name four context failure modes. How does a graph limit poisoning?
Poisoning, distraction, confusion and clash (Breunig). In a Workflow graph each node sees only its node_input, and include_contents='none' gives a sub-agent no caller history. So a bad fact stays inside one node and does not spread to every later call.
When do you use preload_memory, and when load_memory?
preload_memory searches on every turn: predictable, but it costs tokens and latency each turn. load_memory is a tool, so the model searches only when it needs past context. Neither one writes memory: call add_session_to_memory, usually in after_agent_callback.
Why can the current time in the system instruction raise cost about 10x?
It changes the prefix on every call, so the KV/context cache never hits. Manus pays $0.30 per MTok for cached input and $3 for uncached input. Put stable text in static_instruction and dynamic data in the tail of the context.
Skill, rule, tool or sub-agent: what is the difference?
A rule is always-on guidance. A skill is an on-demand folder of know-how, loaded by progressive disclosure. A tool is one callable function. A sub-agent is a separate context with its own prompt, tools and model, and it returns a summary.

Ask each question and give the class ten seconds before you reveal the answer. Q1 tests vocabulary plus a mechanism: name the four failure modes, then say how architecture, not prompting, limits poisoning. Q2 is a cost-versus-recall trade-off; a strong answer also says that the Runner never writes memory by itself. Q3 is a favourite numbers question: one changing byte in the prefix turns every call into a cache miss, and cached input is 10x cheaper on Claude Sonnet in Manus's numbers. Q4 checks that the student does not mix up the four ways to add capability; a good extra point is that a sub-agent buys isolation at the cost of more total tokens. Analogy for Q4: a rule is a company policy, a skill is a manual on the shelf, a tool is a machine, and a sub-agent is a colleague you send a task to.
