class Review(BaseModel):
  grade: Literal["compliant", "needs_fix"]
  feedback: str = Field(
      description="What to change to meet the policy.")

write_copy = Agent(
    name="write_copy", model="gemini-3.5-flash", output_key="draft",
    instruction="Write a 2-sentence ad for: {brief}. "
                "Previous draft (may be empty): {draft?} "
                "Feedback to apply (may be empty): {feedback?}")

review_copy = Agent(
    name="review_copy", model="gemini-3.5-flash",
    output_schema=Review, output_key="review",
    instruction="Policy: no guaranteed returns, no 'risk-free', must "
                "say 'Capital at risk.' Grade this ad: {draft}")

This is the evaluator-optimizer pattern for Acme's ad copy on a unit-linked savings policy, and the first LLM step of the lab: copy_review needs a .env with GOOGLE_GENAI_USE_ENTERPRISE=FALSE and a GOOGLE_API_KEY from Google AI Studio; on Vertex AI set it to TRUE with your project and location instead. Do not use the old name GOOGLE_GENAI_USE_VERTEXAI: it still works but raises a DeprecationWarning. Walk the bands: Review is the grader's contract, a closed grade plus feedback. write_copy writes its text to state under draft through output_key; the question mark in {draft?} and {feedback?} makes a state placeholder optional, so it renders empty on the first pass, while {brief} without it would raise if the key were missing. On a retry the writer sees its previous draft and the feedback, so it revises instead of starting over. review_copy has output_schema=Review, so the next node gets a typed object, not prose. Think of a junior copywriter and a compliance officer passing one folder back and forth. A likely question: "Why not one agent that writes and checks itself?" A separate grader with a fixed schema is easier to test and cannot talk itself into a pass. Next: the gate that bounds the loop.
