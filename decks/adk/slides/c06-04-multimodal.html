Every modality is a Part: keep the bytes in artifacts and pass references

types.Part holds one payload: text · inline_data (bytes + mime_type) · file_data (Files API URI, gs://, HTTPS, YouTube) · function_response (can carry images on Gemini 3+) · thought + thought_signature.

Inline under ~20 MB is always safe. Files API above 100 MB per request (PDF 50 MB): 2 GB per file, 20 GB per project, 48 h, free. On Agent Platform, use gs:// URIs.

from google.adk import Agent
from google.adk.tools import ToolContext, load_artifacts
from google.genai import Client, types

async def generate_image(prompt: str, tool_context: ToolContext):
  """Generates an image based on the prompt."""
  response = Client().models.generate_images(
      model="imagen-3.0-generate-002",  # retired: port to Nano Banana
      prompt=prompt, config={"number_of_images": 1})
  image_bytes = response.generated_images[0].image.image_bytes
  part = types.Part.from_bytes(data=image_bytes,
                               mime_type="image/png")
  await tool_context.save_artifact("image.png", part)  # -> version 0
  return {"status": "success", "filename": "image.png"}

root_agent = Agent(name="root_agent",
                   tools=[generate_image, load_artifacts])
Pitfall: base64 media in history is resent every turn. Also, on Agent Runtime AdkApp defaults to InMemoryArtifactService. Pass an artifact_service_builder for GCS.

Model churn: Imagen 4 and Veo 3.1 are shut down on the Gemini API (Veo on 2026-10-22). Use gemini-nano-banana-2.1 for images and gemini-omni-1.1-flash for video. Read model IDs from env vars.

Everything the model sees is a list of Parts, and each Part carries one payload: text, inline bytes, a file reference, a function call or response, or a thought. Step 1: on the left the image bytes stay in the history, so each of the five turns sends the image again; at high resolution that is 1,120 tokens per turn, 5,600 in total. On the right the tool saves the bytes as an artifact, returns only a small pointer, and the event records artifact_delta with the version. Step 2: on turn 3 the model asks for the file, and load_artifacts attaches it to that one request only, so the total is 1,120. Step 3: media_resolution sets the token cost per item; click the buttons to compare, and note that PDFs stop gaining quality at medium. Analogy: an artifact is a coat check; you keep the small ticket, not the coat. Likely question: "Why not keep the image in session state?" State is small JSON that is written into every event; binaries belong in the artifact service, and SaveFilesAsArtifactsPlugin moves user uploads there for you.
