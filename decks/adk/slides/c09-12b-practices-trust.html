Run each eval three times and test the gate itself

  • Run ≥ 3 times. Accept by paired bootstrap.
  • Trust one run.
  • Check the config path and the case count.
  • Keep a known-bad case per gate.
  • Pin agent, judge and harness. 43 → 72 solved by harness alone.

        num_runs=3)   # default is 2

The second half of the checklist: how often to run, and how to trust the gate itself. adk eval has no repeat flag in 2.13.0, so run the golden set from pytest with AgentEvaluator and num_runs 3; the default is 2. Accept a change only by a paired bootstrap, as the production shopping-assistant paper arXiv 2609.32092 does: resample the same cases from the old and new runs many times and check that the confidence interval of the score change stays above zero. Never trust one run, because close calls flip about 40 percent of the time. Then test the gate: check the config path, count the cases, keep a known-bad case that must fail, and pin the agent model, the judge model and the harness version, because changing only the harness took the same model from 43 to 72 solved SWE-bench tasks in arXiv 2608.26218. Analogy: a smoke alarm is only useful if you test it with smoke. A likely question: "Is three runs enough?" For a gate, yes, as a floor; for a leaderboard-style comparison of close agents, you need far more.
