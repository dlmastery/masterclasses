def route_ticket(node_input: Triage):
  routes = list(node_input.labels)
  if node_input.priority == "p1" and "outage" not in routes:
    routes.append("outage")              # p1 always pages on-call
  yield Event(output=node_input.model_dump(), route=routes)

route_ticket is plain Python, and that is the point: the model labels, the code decides. Step 1: suppose classify returned only the billing label but priority p1. The rule "p1 always pages on-call" adds outage to the routes. Because it is a function, you can unit-test this rule and it costs no tokens. Step 2: the route is a list, so every matching branch runs; here billing and page_oncall run in the same run. The same Event carries the Triage payload as output, which page_oncall receives as node_input. Step 3: a thank-you ticket is labelled other, which has no key in the edge map, so DEFAULT_ROUTE sends it to the human queue. DEFAULT runs only when no key matches: if the labels were other and billing, billing would run and the default would not. Analogy: the nurse writes the label, and the hospital rule book picks the ward. A likely question: "Why not let the LLM return the route directly?" Then a casing slip like "Billing" ends the branch with only a log line, and you cannot unit-test the rule.
