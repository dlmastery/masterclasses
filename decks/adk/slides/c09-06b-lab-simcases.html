Step thirteen: turn the scenarios into eval cases. adk eval_set create makes an empty set called refund_sim, stored as refund_agent/refund_sim.evalset.json, and add_eval_case reads scenarios.json plus session_input.json and adds one case per scenario. The case id is the first 8 hex characters of a SHA-256 of the scenario, and duplicates are skipped, so if you edit a scenario's text you get a new case and the old one stays in the set: delete it, or recreate the set. The message format comes from cli_tools_click.py; the ids shown are illustrative. Analogy: a library that files each book by a fingerprint of its text; change one word and it is a new book on the shelf. A likely question: "Can ADK write the scenarios for me?" Yes, adk eval_set generate_eval_cases can, but it needs the Agent Platform API and application default credentials.
