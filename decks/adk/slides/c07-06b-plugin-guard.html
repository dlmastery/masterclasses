RefundGuardPlugin blocks any refund over $500 before the tool runs

labs/adk/lab7-acme-refunds/refund_guard.py · excerpt
class RefundGuardPlugin(BasePlugin):
    def __init__(self, max_amount: float = 500.0):
        super().__init__(name="refund_guard")
        self.max_amount = max_amount

    async def before_tool_callback(
        self, *, tool: BaseTool, tool_args: dict[str, Any],
        tool_context: ToolContext,
    ) -> Optional[dict]:
        amount = float(tool_args.get("amount", 0) or 0)
        if amount > self.max_amount:   # a returned dict skips the tool
            return {"status": "blocked", "reason":
                    f"{amount} exceeds limit {self.max_amount}"}
        return None

Plugin hooks take keyword-only arguments: tool_args, not args.

A returned dict skips the tool and becomes its result.

None lets the call through: $79 reaches the tool.

RefundGuardPlugin is the same rule as the callback, moved up one level. Focus one: the plugin's before_tool_callback is async and takes keyword-only arguments: tool, tool_args and tool_context. Note tool_args, not args: copying an agent callback signature into a plugin is a common bug. Focus two: above 500 dollars the hook returns a blocked dict; a returned dict skips the tool and becomes its result, so partner_refunds gets "640.0 exceeds limit 500.0" and the money never moves. Focus three: returning None lets the call through, so the 79 dollar refund on A-100 reaches issue_refund. The imports, BasePlugin, BaseTool, ToolContext, Any and Optional, are in the full file in the lab folder. Think of a guard at the building door instead of a lock on one office. A likely question: "Why read amount with or 0?" The model can send null or omit the argument; float(None) would raise, and a crash in a guard is worse than a clear block.
