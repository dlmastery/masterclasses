Interview drill: run an agent in production on Google Cloud

Agent Runtime, Cloud Run or GKE?
Agent Runtime for managed sessions, Memory Bank, Agent Identity, A2A and publishing to Gemini Enterprise with the least ops. Cloud Run for a custom FastAPI surface and revision traffic splitting. GKE for GPUs or self-hosted models. Cloud Run and GKE can still use managed Sessions and Memory Bank through agentengine:// URIs.
How do you canary a new agent version safely?
Deploy with --no-traffic --tag. Run the eval suite against the tag URL. Shift 1 → 5 → 25 → 100% with session-sticky routing. Watch error rate, p99, tokens per invocation and judge score. Roll back with --to-revisions PREV=100. Never shadow with live write tools.
Name three agent SLIs that a web SRE does not track.
Tokens per invocation, LLM calls per invocation (the loop signature) and an online judge or task-success score. A fourth: tool error rate by tool_origin (LOCAL, MCP, SUB_AGENT, A2A), which blames an upstream MCP server.
What in ADK 2.13 can silently break your monitoring?
OTel GenAI v2 became the default, and the call_llm span was removed. Dashboards and alerts keyed on call_llm go blank, so detection itself fails. Update them to generate_content, or set ADK_TELEMETRY_SCHEMA_VERSION_OPT_IN=otel_semconv_1_36.

Give students ten seconds per question before you reveal the answer. Question 1 tests the hosting trade-off; strong candidates add that hosting and state are separable, because Cloud Run and GKE can use managed Sessions and Memory Bank through agentengine:// URIs. Question 2 tests progressive delivery for stateful, side-effecting software: the tag URL lets you run evals on the live candidate, session-sticky routing stops one conversation from seeing two prompt versions, and shadow traffic needs stubbed tools. Question 3 tests whether the candidate knows that a loop returns HTTP 200 and shows up only in tokens and LLM calls. Question 4 is a recent-release trap: the 2.13 telemetry change can turn the monitoring off without any error. Analogy for question 2: a new drug goes to a small trial group first, with stop rules written before the trial starts. Likely follow-up: "How do you roll back on Agent Runtime?" Use blue/green: deploy a second resource and switch the client or the gateway to the new resource ID, then switch back to roll back.
