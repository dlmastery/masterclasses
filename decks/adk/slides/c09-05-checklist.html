Ship only when the checklist holds: simple design, owned context, verified steps, measured runs

Design

  • Written as a workflow first. An eval justifies each agent loop.
  • One agent with tools before multi-agent.
  • Prototype on the most capable model. Then downshift per step with evals.

Instructions

  • Right altitude. Structured (XML or Markdown). Critical items first.
  • Few canonical examples. No contradictions. Current date stated.
  • Prompts versioned and reviewed: “a prompt change is a deploy”.

Tools

  • Few, namespaced tools, shaped around workflows.
  • Readable, paginated returns. Actionable errors.
  • Every tool risk-rated. High risk → confirmation.

State and context

  • Event-sourced and resumable.
  • Scoped state: temp:, session, user:, app:. Artifacts for binaries.
  • Static prefix first. Caching and compaction configured.

Reliability

  • Bounded retries with backoff. A failover model.
  • max_llm_calls and timeouts set.
  • Idempotent tools. No broad except.

Security

  • Rule of Two per session, or HITL.
  • Identity from trusted context, never from model arguments.
  • Layered guardrails. Dependencies pinned.

Evals and ops

  • 20–50 real-failure tasks, outcome-graded, pass^k reported.
  • Capability and regression suites kept apart.
  • OTel tracing, dashboards, eval-gated CI/CD with canary.
  • Pinned model IDs: aliases like gemini-flash-latest drift.

Multimodal

  • Minimum resolution per item.
  • Files API IDs or artifacts inside loops, not base64.
  • Text inside media is untrusted input.

This is the handout slide: it condenses the consolidated vendor guidance from Anthropic, OpenAI, Google and others into eight groups. Steps 1 to 4 reveal two groups each; ask the room which line their last project broke. Stress three lines: write it as a workflow first, a prompt change is a deploy, and identity comes from trusted context, never from model arguments. Step 5 adds the Gemini specifics, which are easy interview points: temperature 1.0 on Gemini 3, newer models ignore sampling knobs, and thinking_level plus thinking_budget returns HTTP 400. Step 6 flips the three failure cards to show their fixes. Analogy: a pilot's pre-flight checklist; experts still use it, because the cost of one missed line is high. Likely question: "Do I need all of this for a prototype?" No; Design and Evals are the minimum, and you add the rest before real users and real side effects.
