def lookup_policy(policy_number: str) -> dict:
    """Return coverage for a policy number like POL-448120."""
    return {"status": "success", "policy_number": policy_number,
            "collision_deductible_usd": 500,
            "coverage": ["collision", "glass", "liability"]}

class AuditPlugin(BasePlugin):
    def __init__(self) -> None:
        super().__init__(name="audit")
    async def before_tool_callback(
            self, *, tool: BaseTool, tool_args: dict[str, Any],
            tool_context: ToolContext) -> Optional[dict]:
        log = tool_context.state.get("audit_log", [])
        entry = f"{tool.name}({tool_args})"
        tool_context.state["audit_log"] = log + [entry]
        return None                     # None: the tool runs

A plugin is a class with hooks. The App registers it once for every agent.

lookup_policy returns a dict. The model reads the deductible: 500.

Plugin hooks are keyword-only. This hook appends one audit_log entry.

Return None: the tool runs. Return a dict: it replaces the tool result.

Step 1 extracted the claim. Now a second agent, claims_assistant, answers coverage questions, and the App in agents/claims_api/agent.py adds an audit plugin. The two agents are joined in a later chapter, so for now the user types the policy number. Click 1: the tool returns a plain dict; the model reads collision_deductible_usd 500. Click 2: the plugin hook is keyword-only, and it uses tool_args, not args as an agent callback does; it appends one audit entry to state before every tool call, in every agent of the App. Click 3: returning None lets the tool run; returning a dict would skip the tool and use that dict as the result. Analogy: the plugin is the security desk in the lobby: every visitor signs the book, whichever floor they go to. A likely question: "Plugin or agent callback?" Use a plugin for rules that must cover every agent; plugins run before agent callbacks, and the first non-None result wins.
