user_content: the turn the eval replays.

final_response: the reference answer for the judge.

tool_uses: the expected tools, in order.

session_input: the app, the user and the start state.

Step five: the recorded chats are now a golden evalset, and this is the file you keep in git. Each case stores four things: the user turn to replay, the reference answer for the judge, the expected tool calls in order, and the session the run starts from. The slide shows case 2, large_refund_escalates for A-2040; case 1, small_refund for A-1001, has the same keys with lookup_order and then issue_refund for 79 dollars. Click through and watch each part of the chat fly into its slot. Analogy: the evalset is the answer key of an exam, written once and reused for every build. A likely question: "Can I use camelCase keys?" Yes: the eval models accept snake_case and camelCase, but they forbid unknown keys, so a typo such as tool_use fails loudly.
