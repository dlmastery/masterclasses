This is the codelab "Getting Started with MCP and A2A with ADK": three services on Cloud Run. The travel agent keeps a local weather sub-agent and calls a remote currency agent over A2A; the currency agent calls a FastMCP server that reads the Frankfurter API. Step 1: the client fetches the Agent Card from the well-known path; RemoteA2aAgent does this for you. Step 2: SendMessage creates a Task, and the task moves from submitted to working. Step 3: inside the remote agent, McpToolset sends call_tool over Streamable HTTP, and the task completes. Step 4: the remote agent returns an Artifact made of Parts, and ADK turns it into events in the root session. Analogy: MCP is a power socket with a known shape; A2A is a contractor who takes a job and returns a deliverable. Likely question: "Gemini Enterprise and A2A v1.0?" Gemini Enterprise registers A2A v0.3 agents, so v1.0 servers use the compatibility packages.
