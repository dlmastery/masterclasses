Gotcha MCP at runtime

When a toolset fails to load, the agent keeps talking without it

SymptomNo exception. The agent answers without its tools. CauseServer crash, a print() on stdout, a URL without /mcp, or a start slower than timeout. FixAlert on the log line. Run a smoke test at startup.

Before 2.10 / 2.11, a dead session came back as a normal result: Session terminated. Alert on that string too.

The third MCP failure is the expensive one, because nothing turns red. Step 1: the claims server exits, the toolset cannot load, and ADK logs one line: "Agent claims_desk will run without the tools from toolset McpToolset (prefix 'claims'), which failed to load". The agent keeps running and tells the adjuster "I can't access claims". Step 2: the usual causes are a server crash, a print on stdout, a URL without /mcp, or a server that starts slower than the timeout. Step 3: you own the alert: match that log line in your logging system, and run a startup smoke test, which is the next slide. Step 4: in versions before 2.10 and 2.11, after a server restart or a scale-to-zero, ADK kept the dead session and returned "MCP tool execution failed: Session terminated" as a normal tool result, so alert on that error string too, not only on exceptions. Think of a phone line that goes dead while the operator keeps talking politely to the caller. A likely question: "Why does ADK not just raise?" One broken toolset should not take down an agent that has other working tools, so the choice is deliberate.
