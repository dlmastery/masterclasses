from google.adk import Workflow

root_agent = Workflow(name="acme_desk", edges=[
    ("START", intake, classify, pick),
    (pick, {"refund": refund, "question": answer}),
    (refund, audit), (answer, audit)])

A tuple of N nodes is a chain. "START" is a reserved name, valid only in a chain.

A dict maps each route label to a node. A label with no key runs nothing; Lab 3 adds a default.

Two pairs join both branches at audit.

Run it from the parent folder. Only events with message= print.

The last lines of the file wire everything together, and the graph below lights up the part of the graph that each entry creates. Press once: a tuple of N nodes is a chain; START, intake, classify and pick run in that order. "START" is a reserved name, and the string form works only inside a chain tuple; elsewhere import START from google.adk.workflow. Press again: a pair of a node and a dict is a route map; each key is a route label and each value is the node that runs. A label with no key runs nothing and raises no error; the log only says "The branch will end." That is why Ticket uses a Literal, and why Lab 3 adds DEFAULT_ROUTE and a test for it. Press again: two plain pairs, refund to audit and answer to audit, join the branches. Last press: run it from the parent folder of acme_desk; the quoted text is the first user message. Only events with message= print, and function nodes print under the workflow name, so you see one line. The output is illustrative. Likely question: "Does order inside the list matter?" No; the entries describe edges, not steps.
