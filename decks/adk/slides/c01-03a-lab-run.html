Audit the trajectory, not only the answer. A right answer can hide a wrong process.

trajectory · one turn · illustrative
user "Can I return order A-1002? I just changed my mind."
function_call lookup_order(order_id="A-1002") → category "electronics", 41 days
function_call check_refund_eligibility(order_id="A-1002", reason="changed_mind") → eligible: false, window_days: 30 41 > 30
final answer "…our policy allows change-of-mind returns within 30 days, so it is not eligible."
Run every command from the folder that contains refund_agent, not from inside it, because ADK imports the folder as a Python package. The one-shot form takes the query as a positional argument; without it adk run is interactive; --in_memory --jsonl gives a clean, scriptable run. Walk the trajectory on the right: the user message, lookup_order, then check_refund_eligibility, where 41 days is more than the 30-day window, and only then the final answer, which quotes the rule from the tool result. Analogy: the trajectory is the receipt for the answer; the answer is the total, the tool calls are the line items you audit. Likely question: "Why not just test the final text?" Because a correct answer can hide a wrong process; the CXBench paper on the runner slides puts a number on that. Next: the same events in adk web, including an error.
