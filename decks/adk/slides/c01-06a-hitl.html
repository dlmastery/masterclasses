from google.adk.tools import FunctionTool, ToolContext

APPROVAL_THRESHOLD_USD = 200.0

def needs_approval(order_id: str, amount_usd: float,
                   tool_context: ToolContext) -> bool:
    """Same parameters as issue_refund. ..."""
    return amount_usd > APPROVAL_THRESHOLD_USD

root_agent = Agent(
    # ... name, model, instruction, callbacks as before
    tools=[lookup_order, check_refund_eligibility,
           FunctionTool(issue_refund,
                        require_confirmation=needs_approval)],
)

The cap from the last build is a hard ceiling at $1,500. Between $200 and $1,500 Acme wants a person to decide. Step 1: an instruction such as "ask a supervisor before any refund over $200" is only a request to the model; nothing stops the call, so all three refunds ran. Step 2: require_confirmation takes a bool or a predicate; ADK calls needs_approval with the tool's own arguments, unfiltered, so the predicate must take the same parameter names, including tool_context, or Python raises a TypeError about an unexpected keyword argument. Step 3: wrap issue_refund in FunctionTool; $80 is issued at once, $250 and $1,299 wait. The issue_refund body writes refunds_issued to state, so approved refunds are auditable; it is in labs/adk/lab1-refund-guardrails. Analogy: the predicate is the till that calls the manager for any refund over the limit. Likely question: "Can the model skip the gate?" No: the gate is in FunctionTool, not in the prompt.
