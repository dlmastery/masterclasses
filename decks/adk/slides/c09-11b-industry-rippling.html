Case study Rippling on LangChain
Rippling, in a vendor case study from June 2026, layers its agent evals like a pyramid. The base is offline tests with mocks on every commit. Above it, 300 to 400 integration queries run after merge in a full sandbox. About ten scenarios block a deploy. At the top, evals run continuously in production, several times a day. Step two closes the loop: failing production traces go back to the base, an agent proposes a fix, the evals rerun, and a human merges. The table maps the same layers onto the Acme refund gate we built: the golden set on every commit, the simulated set after merge, the 500 dollar metric as the deploy blocker, and production failures as new golden cases. The numbers are Rippling's own and come from a vendor post, so read them as a shape, not a benchmark. Analogy: a test pyramid for code, with a feedback pipe from the top back to the base. A likely question: "Why only ten blocking scenarios?" A deploy gate must be fast and trusted; the broad suites inform, the few hard cases block.
