from google.adk.agents import LlmAgent
# ORDERS (the table) and INSTRUCTION (the policy): see the file

def lookup_order(order_id: str) -> dict:
    """Return days since purchase, amount (USD) and category."""
    return ORDERS.get(order_id, {"error": f"unknown order {order_id}"})

refund_agent = LlmAgent(
    name="refund_agent",
    model="gemini-3.5-flash",
    description=("Checks refund eligibility for an order id "
                 "under Acme policy."),
    instruction=INSTRUCTION,   # 30/14-day windows, $500 cap
    tools=[lookup_order],
)

One agent definition. Steps 1, 2 and 5 import it.

This is the one file the whole lab shares. ORDERS holds three test orders, shown in the table: A-100 is a 79 dollar apparel order at day 12, A-200 is a 640 dollar electronics order at day 45, and A-300 is a 120 dollar apparel order at day 42; the full dictionary is in labs/adk/lab7-acme-refunds/refund_core.py. lookup_order is a plain function tool: its docstring becomes the tool description, and an unknown id returns an error dict instead of raising, so the model can recover. refund_agent carries the policy in its instruction: apparel 30 days, electronics 14 days, refunds over 500 dollars need a manager. The MCP server, the A2A server and the skill agent all import from this module, so you keep one copy. Think of refund_core as the kitchen, and MCP and A2A as two serving hatches. A likely question: "Why is the policy in the instruction and not in code?" It is here only to start; step 4 moves it into a Skill, and step 6 enforces the 500 dollar cap in code.
