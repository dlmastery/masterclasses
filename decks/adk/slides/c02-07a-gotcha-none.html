Symptom first: the downstream claims code crashes with KeyError 'incident_date'. Click 1, the cause: the email in Lab 2 had no year, so the model returned null; with output_key and output_schema, ADK stores model_dump with exclude_none=True, so a null field is not stored as None, it is absent from the dict. Click 2, the fix: read optional keys with .get, which returns None. Click 3: or rebuild the typed object with ClaimIntake.model_validate, which fills the default None again and gives you attribute access. Analogy: the claim form has no box for a missing date, so the clerk leaves the box out instead of writing "none". A likely question: "Can I turn exclude_none off?" Not through output_key; if you need every key, validate the dict back into the model as shown.
