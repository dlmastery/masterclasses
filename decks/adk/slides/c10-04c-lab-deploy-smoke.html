Symptom403 Forbidden after --no-allow-unauthenticated. CauseYou sent an access token. FixSend an identity token. Grant the caller roles/run.invoker.
A deploy is not done until a real request comes back. Press once: a private Cloud Run service checks an identity token, so the script asks gcloud for one. Press again: the first curl creates session s1 for employee E-1001 under the app name hr_agent. Press again: run_sse sends one message with state_delta, so the guard from step 1 sees the caller's id; the reply on the right is illustrative. Press again: the most common failure is 403 Forbidden, because people paste the access token from print-access-token; Cloud Run wants print-identity-token and the caller needs roles/run.invoker. Agent Runtime is the opposite: its REST :query endpoint takes an access token, and smoke.sh shows that call with async_create_session. Analogy: an identity token is your staff badge; an access token is a key to one cupboard. Likely question: "Do I need an identity token on GKE?" Not by default: the ClusterIP service is reachable only inside the cluster, for example through kubectl port-forward.
