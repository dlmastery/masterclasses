Contain the server process, and make every failure loud

  • stdio servers in a container with one mount. 16.4% launder file access.
  • allow_private_network_access=True in production.
  • Pin google-adk, mcp and server versions.
  • Errors say "<cause>. Call <tool>". Recovery 45% → 84%.
  • Smoke-test get_tools(). Alert on "will run without the tools".
  • print() in a stdio server. stdout carries JSON-RPC.
The second half of the review list is about the process around the tools. Check 1: run stdio servers in a container with one mounted directory, because 16.4% of triaged servers reach the filesystem beyond their label, and never set allow_private_network_access=True in production, because it opens the metadata endpoint too. Check 2: pin google-adk, mcp and the server versions, since the 2.x SDK rename shows how a minor upgrade breaks server code. Check 3: write errors as "cause, then the tool to call", which lifted recovery from 45% to 84% in arXiv 2609.35381. Check 4: smoke-test get_tools() at startup and alert on the "will run without the tools" log line, and never print to stdout in a stdio server. The picture shows the layers from the outside in: the container, the server's own checks, the confirmation gate, and the filter with its prefix, around the model; the alerts watch all of them. Think of an onion: an attacker who gets through one layer still meets the next. A likely question: "Which layer would you add first?" tool_filter, because it is one line and it shrinks everything after it.
