Gotcha Evals

A wrong config path or zero cases still gives a green run

Symptomrefund_policy_score is missing from the output. CauseA typo in the config path. ADK logs only Using default criteria. Fixtest -f the config first.
SymptomA green pipeline on a failing eval. CauseExit 0 before 2.13.0, and | tee hides the exit code. Fixpipefail, then count the cases that ran.
Issue #6951 zero cases passed
labs/adk/lab9-refund-eval/ci/eval_gate.sh · excerpt
set -euo pipefail
export PYTHONPATH=$PWD
CFG=refund_agent/test_config.json
test -f "$CFG" || { echo "missing $CFG"; exit 1; }

adk eval refund_agent refund_agent/refund.evalset.json \
  --config_file_path="$CFG" --print_detailed_results | tee eval.log
N=$(grep -c '^Eval Id:' eval.log || true)
test "$N" -eq 2 || { echo "ran $N of 2 cases"; exit 1; }
grep -q 'Metric: refund_policy_score' eval.log || exit 1
Two failures that look like success: the pipeline is green, so nobody looks. First: a typo in the config path is not an error. ADK logs "No config file supplied or file not found. Using default criteria." and scores with the two defaults, so the 500 dollar rule never runs; the gate script checks that the file exists first. Second: before 2.13.0 adk eval always exited 0, and a pipe into tee hides the exit code unless pipefail is on, so the script sets pipefail and also counts the cases that ran; update that number when you add cases. On the pytest path, before 2.10.0 AgentEvaluator also passed an evalset with zero cases, issue 6951; 2.13.0 raises "No eval cases were evaluated". The last line checks that our own metric really ran. Analogy: test the smoke alarm with smoke, not by looking at the green light. A likely question: "Is the case count not brittle?" Yes, a little, and that is the point: adding a case should be a conscious change to the gate.
