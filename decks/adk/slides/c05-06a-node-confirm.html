Swap the hand-written gate for one require_confirmation decorator

labs/adk/lab5a-refund-approval/refund_confirm/agent.py · excerpt
AUTO_APPROVE_LIMIT = 500.0
def intake(node_input: str):     # "A-2040 820"
  order_id, amount = node_input.split()[:2]
  yield Event(state={"order_id": order_id, "amount": float(amount)})
# The predicate gets `amount` by name from state. Return a real bool.
@node(require_confirmation=lambda amount: amount > AUTO_APPROVE_LIMIT)
def issue_refund(order_id: str, amount: float):  # args = state keys
  key = f"refund-{order_id}"                     # idempotency key
  yield Event(message=f"REFUNDED ${amount:.2f} on {order_id} "
                      f"(key {key})")
root_agent = Workflow(name="refund_confirm",
                      edges=[("START", intake, issue_refund)])
Trade-off: yes or no only. No draft, no revise loop, no partial amount.
This build slide replaces the hand-written manager_gate from Lab 5A with one decorator on issue_refund. The first click collapses the gate node into a pause badge on issue_refund: the graph is now START, intake, issue_refund. The second click is the predicate: lambda amount: amount > AUTO_APPROVE_LIMIT uses the same 500-dollar constant as the old gate, and amount is bound by name from the state key that intake wrote; for 820 it returns True, so the node pauses before its body runs. The third click is the honest part: the line count drops from 19 to one decorator because the decorator is a yes/no gate. The draft, the revise loop and the partial amount go away, so keep the RequestInput gate with ManagerDecision when a manager approves 700 instead of 820 or adds a note. It is like a door with a built-in badge reader instead of a guard who stands in front of it. This needs google-adk 2.12 or newer; the lab is tested against 2.13.0 source. A likely question: "Can the predicate see other state?" It gets the node's bound args by name, plus ctx, node_input and any state key with a matching name. Next: what the reply must look like.
