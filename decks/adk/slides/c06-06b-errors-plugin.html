For servers you cannot edit, a plugin drops the human-only step

labs/adk/lab6-acme-claims-desk/claims_agent/agent_errors.py
import re
from google.adk.plugins.base_plugin import BasePlugin
HUMAN_STEP = re.compile(r"\b(Run|Open|Edit) [^.]*\.\s*")  # human-only
class AgentErrorPlugin(BasePlugin):
    def __init__(self):
        super().__init__(name="agent_errors")
    async def after_tool_callback(
            self, *, tool, tool_args, tool_context, result):
        text = str(result)
        if "error" not in text.lower():
            return None                     # normal results pass
        cleaned = HUMAN_STEP.sub("", text)  # keep the cause
        return {"result": cleaned} if cleaned != text else None
# register once: App(..., plugins=[AgentErrorPlugin()])
Our own server now writes agent-style errors, but third-party MCP servers will not. A plugin fixes their text in one place for every tool. Step 1: a regular expression finds human-only steps, sentences that start with Run, Open or Edit. Step 2: after_tool_callback runs after every tool call; normal results pass through untouched, so the plugin only touches errors. Step 3: it deletes the human-only sentence and keeps the cause; a non-None return replaces the result the model reads. The same paper measured cause-only errors at 82% recovery, against 45% with the terminal step. Step 4: register the plugin once on the App, and it covers every agent and tool in the app; the lab keeps that App block as an option at the end of agent.py. Think of an interpreter who leaves out the parts of a message that only apply to someone else. A likely question: "Why a regex and not a model call?" A regex is deterministic and free; the paper also tested a one-sentence prompt that deletes the step, with the same 82%, if your errors are too varied for a pattern.
