Why the flag exists: a child can be interrupted mid-run.

Run 1: two children finish. line-3 stops, e.g. on a crash.

On resume, ADK re-runs the parent from the top.

Finished children return cached outputs. Only line-3 runs again.

Keep the parent thin. Put side effects in the children.

Three bugs bite the orchestrator from the Acme expense audit; this is the first: a parent that calls ctx.run_node without rerun_on_resume=True gets the ValueError on the left. Read the error on the left: it says a node must have rerun_on_resume=True, because dynamically scheduled nodes might be interrupted and the workflow re-runs the parent to collect the child's response. The animation shows why. In run 1 two children finish and the third is interrupted, for example by a crash or by a request for human input. On resume, ADK re-runs the parent from the top; the finished ctx.run_node calls are replayed from history and return their cached outputs, and only the unfinished child runs again. So the fix is one decorator argument, on every parent, including nested ones, and a design rule: keep the parent thin, because its own code runs again on each resume; put database writes and emails in child nodes, which are cached. Think of a project manager who re-reads the whole checklist every morning, but does not redo the ticked items. A likely question: "Does a static graph need this?" No; it is about parents that schedule nodes at run time.
