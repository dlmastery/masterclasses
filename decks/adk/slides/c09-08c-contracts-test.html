import asyncio
from types import SimpleNamespace
from refund_agent.agent import OutcomeContractPlugin

def test_negative_amount_becomes_error():
    bad = {"status": "success", "order_id": "A-1001", "amount": -79.0}
    out = asyncio.run(OutcomeContractPlugin().after_tool_callback(
        tool=SimpleNamespace(name="lookup_order"), tool_args={},
        tool_context=None, result=bad))
    assert out["status"] == "error"
    assert out["recovery_tools"] == ["escalate_to_human"]

Wire the plugin into an App in agent.py: adk eval, adk web and adk api_server look for app before root_agent there, so the eval gate now runs with the contract on. Passing plugins to a Runner directly is deprecated in 2.x; the warning says to use the app argument. Then test the contract without a broken API: call after_tool_callback directly with the bad dict, a SimpleNamespace that has only a name stands in for the tool, and assert that the result is an error with escalate_to_human as the recovery tool. The lab file has a second test that a good amount, 79.0, returns None. The pytest output is illustrative. Analogy: you test a fuse with a test current, not by setting the house on fire. A likely question: "Does the plugin fix the value?" No: it only makes the failure loud and names the next tool; the model still decides, so keep the eval gate next to it.
