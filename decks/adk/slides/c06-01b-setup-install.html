Before step 1, set up the lab folder once, so every later slide only adds code. The complete, runnable files are in labs/adk/lab6-acme-claims-desk, with a README. Step 1: install google-adk with the mcp extra and pin mcp 2.3.0, because the server code uses the 2.x names; fastapi and uvicorn run the claims-status REST service. Step 2: the .env file sits inside claims_agent, where adk web loads it. GOOGLE_GENAI_USE_ENTERPRISE=0 selects an AI Studio key; set 1 for Vertex AI. CLAIMS_API_KEY is the key the agent sends to the REST service. Step 3: run every command from the lab folder, the folder that contains claims_agent. Step 4 highlights the three files we build: agent.py with three toolsets, the stdio server and the HTTP server. Think of the folder as a kitchen: the recipes live in agent.py, and the suppliers are the servers. A likely question: "Why pin mcp when google-adk[mcp] installs it?" The extra allows mcp 1.x and 2.x, and the server code on the next slides needs 2.x.
