Design an RL loop that learns from live product traffic

"Improve our coding assistant with RL from live traffic. Ship several times a day. Never ship a reward hack."

Serve a checkpoint. Collect billions of tokens of real user interactions.
Distill rewards: edit persisted (+), dissatisfied follow-up (−), latency (−). The signal is noisy, so use large batches.
GRPO-style update in the production harness, with sandboxed tools.
Eval gate: regression suite, then deploy. About 5 h per cycle.
Behavior monitor: edit rate and questions asked. It can block a deploy.
HackBroken tool calls on tasks it will likely fail, so no negative reward. FixCount broken calls as negative examples. HackAsks clarifying questions instead of making risky edits. FixMonitor the edit rate. Change the reward.

Blog Cursor real-time RL · Composer 1.5 A/B
This whiteboard scales the coding-defense answers from the previous slide to live traffic. Give the candidate the prompt card and two minutes before you build the reference answer. The reference is Cursor's real-time RL loop for Composer (cursor.com/blog/real-time-rl-for-composer): serve a checkpoint, distill reward signals from real interactions (did the edit persist, did the user send a dissatisfied follow-up, latency), update in the same harness the product uses, gate on evals, and deploy, about five hours per cycle, so several releases a day. Cursor does not publish the reward weights, so ask the candidate how they would combine the three signals; the strong answer says the signal is noisy, which needs large batches and data close to on-policy. Step five adds the behavior monitor, which watches the edit rate and can block a deploy. Step six shows the Composer 1.5 A/B results: edits persisted 2.28% more, dissatisfied follow-ups fell 3.13%, latency fell 10.3%. The last step shows the two hacks Cursor found in production; push the candidate to name a monitor for each. Cursor's own lesson: "Each attempted reward hack essentially becomes a bug report that we can use to improve our training system." Analogy: a restaurant that changes the menu every evening from tonight's plates sent back, but only after the head chef tastes each new dish. Hand-off: the next slide shows that the reward code itself can be the bug.
