lab4_rewards.py · correctness-gated brevity reward
import re
BOX_RE = re.compile(r"\boxed\{([^{}]*)\}")

def _is_correct(text, gold):
    m = BOX_RE.findall(text)
    return bool(m) and abs(float(m[-1]) - float(gold)) < 0.01
# TRL 1.16 passes completion_ids, trainer_state, log_metric
def gated_brevity_reward(completions, completion_ids, solution,
        trainer_state=None, log_metric=None,
        target_tokens=120, warmup_steps=50, **kwargs):
    ramp = min(1.0, trainer_state.global_step / warmup_steps)
    out, gated = [], 0
    for c, ids, gold in zip(completions, completion_ids, solution):
        if not _is_correct(c[0]["content"], gold):
            out.append(0.0); gated += 1; continue
        out.append(ramp * max(0.0, 1 - len(ids) / (2 * target_tokens)))
    log_metric("brevity/gated_frac", gated / len(out))
    log_metric("brevity/ramp", ramp)
    return out

This is the correctness-gated brevity reward from the reward-hacking slides, in the claims-payout run. TRL 1.16 calls every reward function with completion_ids, trainer_state and log_metric as keyword arguments, so this function plugs straight into reward_funcs next to accuracy_reward. Show the code and the output first, and ask why two correct answers get zero brevity credit. Step 1 is the answer: in a raw regex, backslash-b is a word boundary, so the pattern wants "oxed" after a boundary and never matches a real \boxed{8500}; every answer is gated as wrong. Step 2 shows the fix and an assert that tests the regex on one real model-style string. Step 3 runs the self-test again: only the wrong \boxed{1} is gated, and the short correct answer earns 0.42 (half of 1 − 40/240, because step 25 is half the warm-up). Analogy: a ticket scanner that rejects every ticket looks like a very strict guard until you test it with one real ticket. Likely follow-up: "Is there a twin bug?" Yes: in a normal, non-raw Python string, backslash-b is a backspace byte, and the lab's claims_data SYSTEM prompt held exactly that until it became a raw string. So use raw strings for prompts, patterns and test strings, and alert when one reward channel sits at a constant value. Next chapter: the data those rewards and verifiers are trained on.
