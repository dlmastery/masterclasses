One case: a refund assistant on Qwen3-0.6B + LoRA. Find its silent bugs, then serve it to 200 tenants.

This chapter follows one case: a refund assistant on Qwen3-0.6B with a LoRA adapter, trained on the 2,992 Bitext REFUND rows, and then served as one tenant of a multi-tenant adapter service. The chapter is about the bugs that do not raise an error. The animation shows the two ideas we drill. First, the loss mask on a chat transcript: system and user tokens get label -100, which is PyTorch's ignore_index, so they get no loss; only the assistant tokens, including the end-of-turn token, get loss. Second, LoRA: the weight W stays frozen, and LoRA learns a low-rank update B times A that is added to W. B is d by r, A is r by k, and r is 16 here. B starts at zero, so at step 0 the model equals the base model, and only B and A receive gradients. An analogy: SFT is a teacher who grades only the answer lines of an exam, never the question lines. The template and mask checks run on a laptop CPU; the training runs need one GPU with at least 12 GB. A likely question: "Why must the end-of-turn token be inside the trained span?" Because otherwise the model never learns to stop. Next: debug the refund training script itself.
