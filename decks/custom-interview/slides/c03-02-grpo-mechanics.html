Interview · GRPO mechanics

GRPO learns only from groups that disagree

Why does GRPO need no critic, and what does that cost?
The group mean is the baseline, so there is no value model. Cost: G samples per prompt, and a same-score group gives zero gradient.
Reward is noisy and many answers hit the length cap. What do you read?
completions/clipped_ratio. A cut-off answer scores 0. Above ~10%, raise max_completion_length or mask cut-off answers.
GRPO or rejection-sampling fine-tuning (RFT), on the same prompts and verifier?
GRPO: up to +10.9 pts over tuned RFT. Iterated RFT closes only ~30% of that gap. But RL sharpens: pass@20 can fall.
RFT = sample, keep the verified-correct answers, SFT on them. pass@k = at least 1 of k samples is correct.

from trl import GRPOConfig, GRPOTrainer
from trl.rewards import accuracy_reward
from claims_data import claims_dataset  # lab 2 data

args = GRPOConfig(output_dir="qwen-claims-grpo",
    num_generations=8,               # G per prompt
    per_device_train_batch_size=8,   # 8 x 4 = 32
    gradient_accumulation_steps=4,   # = 4 groups of 8
    max_completion_length=256,       # default 512
    mask_truncated_completions=True) # default False
GRPOTrainer(model="Qwen/Qwen2.5-0.5B-Instruct",
    args=args, reward_funcs=[accuracy_reward],
    train_dataset=claims_dataset(2000, seed=7)).train()
Ask each question, wait for an answer, then reveal the model answer. The code is the core of lab2_grpo_claims.py, the claims-payout run from the chapter opener, scored by accuracy_reward on a boxed answer. The full lab file also adds LoRA, bf16 loading, a soft length penalty and an eval split. Question one tests the group baseline and its blind spot: a group where all 8 answers score the same has zero advantage, so it costs compute and teaches nothing. The picture shows frac_reward_zero_std, and the fix: probe the base model 8 times per prompt and keep prompts with a pass rate from 0.08 to below 0.90, which is the ThinkingBox rule. Question two tests metric reading: a cut-off answer looks wrong to the verifier, so read clipped_ratio before you blame the reward. The batch must also hold whole groups: 8 per device times 4 accumulation steps is 32 completions, 4 groups of 8, otherwise TRL raises "generation_batch_size must be divisible by num_generations". Question three is the "is it RL or data?" debate: on the same prompts and verifier, GRPO beat tuned RFT by up to 10.9 points, and iterated RFT recovered only 3.2 of those points. Separately, in ThinkingBox pass@1 went from 51.7 to 60.8 while pass@20 fell from 89.4 to 88.0, so RL made the model more reliable, not more capable. Analogy: GRPO grades on the curve inside one exam room; if everyone gets the same mark, nobody learns where they stand.
