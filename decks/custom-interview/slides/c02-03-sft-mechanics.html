Most silent SFT bugs live in the chat template and the loss mask

After SFT the model never stops generating. Why?
The tokenizer's EOS is not the template's end-of-turn token, so the stop token gets no loss. Example: Qwen3-0.6B-Base has EOS <|endoftext|>, but turns end with <|im_end|>.
eos_token="<|im_end|>"assert end in ids[-2:]
What does assistant_only_loss=True need?
Generation markers in the chat template: {% generation %} … {% endgeneration %} around each assistant reply. TRL builds the loss mask from them.

check_eos.py
# pip install trl==1.16.0 transformers==5.20.2 datasets
from datasets import Dataset
from trl import SFTConfig, SFTTrainer
M = "Qwen/Qwen3-0.6B-Base"     # eos_token: <|endoftext|>
msgs = [{"role": "user", "content": "Refund my order."},
        {"role": "assistant", "content": "I can help."}]
args = SFTConfig(output_dir="refund-lora",
                 eos_token="<|im_end|>")   # the fix
tr = SFTTrainer(model=M, args=args,
    train_dataset=Dataset.from_list([{"messages": msgs}]))
ids, tok = tr.train_dataset[0]["input_ids"], tr.processing_class
end = tok.convert_tokens_to_ids("<|im_end|>")
assert end in ids[-2:]   # a turn ends "<|im_end|>\n"
print("ok")               # without the fix: AssertionError
check_mask.py · runs on CPU
# pip install trl==1.16.0 transformers==5.20.2
from transformers import AutoTokenizer
from trl import get_training_chat_template
tok = AutoTokenizer.from_pretrained("Qwen/Qwen3-0.6B")
U = {"role": "user", "content": "Refund my order."}
A = {"role": "assistant", "content": "I can help."}
out = tok.apply_chat_template([U, A], tokenize=True,
    chat_template=get_training_chat_template(tok),  # markers
    return_dict=True, return_assistant_tokens_mask=True)
pairs = zip(out["input_ids"], out["assistant_masks"])
kept = [t for t, m in pairs if m]
assert kept, "mask is empty: every label would be -100"
assert U["content"] not in tok.decode(kept)
print(repr(tok.decode(kept)))  # ends 'I can help.<|im_end|>\n'
Ask each question, pause, then reveal the answer. Both bugs train to the end with no error, so the only defence is a cheap check before the GPU run; the right side shows that check for each question, on the same two chat turns. Question 1: if the tokenizer's EOS is not the template's end-of-turn token, the stop token never gets loss and the model never learns to stop. Qwen3-0.6B-Base ships eos_token <|endoftext|>, while its template ends turns with <|im_end|>, so set SFTConfig(eos_token="<|im_end|>"). The instruct checkpoint Qwen3-0.6B already ships eos <|im_end|>, so it does not show this bug. The check looks at the last two ids because the Qwen template writes a newline after <|im_end|>. Question 2: the assistant mask comes from {% generation %} markers in the Jinja template. get_training_chat_template is a public TRL 1.16.0 function; it returns a patched template for known families such as qwen3, or None when the template is already training-ready. TRL 1.16.0 does not patch Gemma 4; there you get "ValueError: The chat template is not training-compatible (missing prefix-preservation or {% generation %} markers) and patching is not supported for this template." For Gemma 4, use prompt-completion data instead. -100 is PyTorch's ignore_index: a token with that label gets no loss. Analogy: a smoke detector with no battery stays quiet, so you test it on purpose. Likely follow-up: "How do you catch this in CI?" Run both asserts on every dataset and template change.
