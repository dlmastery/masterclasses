Gotcha PEFT targets on a hybrid model

A DPO loss stuck at ln 2 means the policy never moved

A DPO-LoRA run on Nemotron-Nano-9B-v2 finishes 25/25 steps. Loss is 0.6931 at every step. Why?
DPO loss = −log σ(β · margin). The margin compares policy and reference log-ratios. At step 0 the margin is 0, so the loss is ln 2 = 0.6931. A flat ln 2 means the margin never changed.
Reported cause: PEFT's default targets match attention projections only. That is 4 of 56 layers. PEFT raises only when nothing matches (#3658).
Fix: name the Mamba and MLP modules, and assert coverage. Also check that gradients reach the adapter.

# pip install peft==0.21.2 transformers==5.20.2 accelerate==1.15.0
from accelerate import init_empty_weights
from peft import LoraConfig, get_peft_model
from transformers import AutoConfig, AutoModelForCausalLM
cfg = AutoConfig.from_pretrained("nvidia/NVIDIA-Nemotron-Nano-9B-v2",
                                 trust_remote_code=True)
with init_empty_weights():  # meta device: no weights loaded
    model = AutoModelForCausalLM.from_config(cfg, trust_remote_code=True)
lora = LoraConfig(task_type="CAUSAL_LM", target_modules=[
    "in_proj", "out_proj",                    # Mamba (M)
    "up_proj", "down_proj",                   # MLP (-)
    "q_proj", "k_proj", "v_proj", "o_proj"])  # attention (*)
m = get_peft_model(model, lora)
layers = {int(n.split("layers.")[1].split(".")[0])
          for n, _ in m.named_parameters() if "lora_A" in n}
assert len(layers) == cfg.num_hidden_layers, f"{len(layers)} of 56"
Ask the question and let the candidate reason from the number. First, the DPO loss: it is minus log sigmoid of beta times the margin, and the margin compares how much more the policy prefers the chosen answer than the reference does. At step 0 the policy equals the reference, so the margin is 0 and the loss is ln 2, 0.6931. A loss that stays at exactly ln 2 for 25 steps means the margin never moved. In the reported run (PEFT issue 3554), the cause was adapter coverage: Nemotron-Nano-9B-v2 is a hybrid with 56 layers, 27 Mamba layers, 25 MLP layers and only 4 attention layers, at indices 14, 21, 30 and 39 of the hybrid_override_pattern. PEFT's default targets are the attention projections, so only those 4 layers got an adapter, and the model scored 0 of 164 on HumanEval. Be precise: partial coverage makes learning weak, it does not by itself freeze the loss. A loss pinned at exactly ln 2 also asks you to check that gradients reach the adapter, and that the reference is not the same object as the policy. The fix lists the Mamba projections in_proj and out_proj, the MLP projections up_proj and down_proj, and the attention projections, or uses target_modules="all-linear". The check builds the model on the meta device, so it runs on a laptop without the 9B download. Analogy: you wired 4 of 56 rooms and wonder why the house stays dark.
