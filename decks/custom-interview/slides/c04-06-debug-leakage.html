lab7_leakage_splits.py · 400 customers × 15 events
import numpy as np
import pandas as pd
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.model_selection import KFold, cross_val_score

rng = np.random.default_rng(0)
n_customers, per_customer = 400, 15
customer = np.repeat(np.arange(n_customers), per_customer)
fraudster = rng.random(n_customers) < 0.15
profile = rng.normal(size=(n_customers, 5))
profile[fraudster, 0] += 0.8                    # weak, real signal
fingerprint, is_fraudster = profile[customer], fraudster[customer]
noise = rng.normal(size=(len(customer), 5))
df = pd.DataFrame(np.hstack([fingerprint + 0.3 * noise, noise[:, :2]]),
                  columns=[f"f{i}" for i in range(7)])
df["customer_id"] = customer
df["event_day"] = rng.integers(0, 365, len(df))
y = (is_fraudster & (rng.random(len(df)) < 0.8)).astype(int)

X = df.drop(columns=["customer_id", "event_day"])
model = HistGradientBoostingClassifier(max_iter=200, random_state=0)
auc = cross_val_score(model, X, y, cv=KFold(5, shuffle=True, random_state=0),
                      scoring="roc_auc")
print(f"ROC-AUC {auc.mean():.3f} +/- {auc.std():.3f}")

lab7_leakage_splits.py · fix
from sklearn.model_selection import GroupKFold
auc = cross_val_score(
    model, X, y, groups=df["customer_id"], scoring="roc_auc",
    cv=GroupKFold(n_splits=5, shuffle=True, random_state=0))

Show the code and the 0.886 first, and ask the candidate why production disappoints. The bug is on the cross_val_score line: KFold shuffles rows, and each of the 400 customers has 15 events with a stable fingerprint, so the same customer sits in train and test and the model memorizes customers instead of fraud. Pass groups equal to customer_id and use GroupKFold with shuffle: the captured run drops to 0.602 plus or minus 0.075, and only that number generalizes to new customers. Analogy: a teacher who grades a student on questions the student has already seen measures memory, not skill. The group key is a business decision, so write it into the data contract, and add the time-split assert from the lab to CI because chargebacks arrive late. Likely follow-up: "When do you combine group and time splits?" When the model will meet new customers in the future, use a time cut-off with a label-delay gap and exclude the training customers.
