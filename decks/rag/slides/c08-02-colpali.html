colqwen_search.py · sentence-transformers v6

# pip install -U "sentence-transformers[image]"
from sentence_transformers import MultiVectorEncoder

model = MultiVectorEncoder("vidore/colqwen2.5-v0.2")
BASE = ("https://huggingface.co/datasets/"
        "sentence-transformers/example-documents/resolve/main/")
pages = [BASE + "doc1.jpg", BASE + "doc2.jpg"]   # page images

# many patch vectors per page image, 128 dims each
doc_emb = model.encode_document(pages)
# one vector per query token
q_emb = model.encode_query(
    ["Total outlay is maximum in which year?"])
# MaxSim: max over patches, then sum over query tokens
scores = model.similarity(q_emb, doc_emb)

ColPali (Faysse et al., ICLR 2025) skips OCR, layout parsing and chunking. It renders each PDF page as an image, and PaliGemma-3B gives about 1,000 patch vectors of 128 dims per page. The query becomes about 20 token vectors. Step 1 fills the token-by-patch similarity matrix; step 2 keeps the best patch per token; step 3 sums those maxima into the page score. This is ColBERT MaxSim applied to pixels. Step 4 shows the similarity map: it tells you where on the page the match is, which is good for debugging and for showing evidence. The Hugging Face blog reports that ColPali beats pipelines in which Claude Sonnet captions every visual element. Step 5 is the cost: multi-vector storage is about 40 times a dense vector until you use PLAID-style indexes and token pooling. Analogy: a dense vector is a one-line summary of the page; multi-vector keeps a sticky note on every patch. Likely question: "Why not just use one multimodal vector?" Answer: cheaper and fits any vector DB, but you lose token-to-patch detail on dense pages; a common design is single-vector recall plus ColPali reranking.
