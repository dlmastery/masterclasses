Gotcha Rerankers

Rerankers return positions and raw logits, not IDs or probabilities

rank() and rerank() return positions in the list you sent. Map them to IDs.

MiniLM-L6 returns logits. Add a Sigmoid, then tune any cut-off on labelled data.

langchain-qdrant sends lambda_mult as Qdrant's diversity. Pass 1 - 0.9.

Model card ms-marco-MiniLM-L6-v2 Issue langchain#39052 (open)
Three reranker bugs that pass every unit test and only show up in the scorecard. First: CrossEncoder.rank, Cohere and Voyage all return the position in the list you sent, so if you return h["corpus_id"] you hand the evaluator ints 0-17 (the 18 candidates) and every metric falls to near the floor run; map through cand_ids. Second: ms-marco-MiniLM-L6-v2 ships with an Identity activation, so the scores are logits from about -11 to +11, and a 0.5 cut-off on a logit is about 0.62 after a sigmoid, not a 50 percent threshold; pass activation_fn=torch.nn.Sigmoid() if you need 0-1, and tune any "no answer" cut-off on labelled data for each model version, because Cohere itself says a 0.9 is not twice as relevant as a 0.45. Third: langchain-qdrant passes lambda_mult straight into Qdrant's diversity, so 0.9 "mostly relevance" becomes mostly diversity; issue 39052 is still open, so pass 1 minus your value or call query_points with models.Mmr yourself. Analogy: the reranker gives you seat numbers and a raw thermometer reading, not passenger names and a percentage. Likely question: "Is a Cohere 0.9 a probability?" No; it is normalised to 0-1, but it is still a ranking signal. Hand-off: with the code bugs fixed, the next slide asks whether hybrid fusion and reranking help on every query.
