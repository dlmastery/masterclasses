Rank first, then let the agent reason over the ranked list

BM25 Wins at Scale: A Scaling Study of RAG Paradigms

A file-system agent (an LLM that browses files with ls and grep) wins on small corpora. BM25 wins from ~10M tokens.
Keep BM25 next to vectors. Hand the agent a ranked list.
lab6/rank_first.py · bm25s 0.3.15 · Lab 6 store
import bm25s
from lab6_multihop_register import PASSAGES, store
IDS = [i for i, _ in PASSAGES]
bm25 = bm25s.BM25(k1=1.2, b=0.75)
bm25.index(bm25s.tokenize([t for _, t in PASSAGES], stopwords="en"))
def rrf(rankings, k=60):                     # Lab 4: fuse ranks, not scores
    fused = {}
    for ranking in rankings:
        for rank, doc_id in enumerate(ranking, start=1):
            fused[doc_id] = fused.get(doc_id, 0.0) + 1 / (k + rank)
    return sorted(fused, key=fused.get, reverse=True)
def ranked(q: str, k: int = 4) -> list[str]:   # the agent starts from this list
    toks = bm25s.tokenize(q, stopwords="en")
    docs, _ = bm25.retrieve(toks, corpus=IDS, k=min(k, len(IDS)))
    dense = [d.metadata["id"] for d in store.similarity_search(q, k=k)]
    return rrf([list(docs[0]), dense])[:k]
print(ranked("Which jacket does Kestrel Textiles make?"))

The main point comes from BM25 Wins at Scale (arXiv 2607.26497): an agent should reason over a ranked list, not replace ranking. The paper grows one enterprise corpus, EnterpriseRAG-Bench, through 28 nested tiers from 1.7 million to 601 million tokens. A file-system agent, an LLM that browses the documents with ls and grep tools, leads on the smallest tiers; at about 10 million tokens BM25 overtakes it and leads every larger tier, ending near 20 points ahead, while the agent spends 39 times the query tokens. The line shapes in the chart are schematic; the crossover, the margin and the cost ratio are the paper's numbers. The paper also measures dense retrieval, which is efficient but less accurate, and graph RAG, which hits construction-cost walls before deployment scale; I left those lines out to keep one comparison. The code applies the lesson to the Acme desk: index the Lab 6 passages with bm25s, fuse BM25 and dense ranks with the Lab 4 RRF, and let hop() start from that list. Two more papers point the same way. 2608.01913: accuracy follows cumulative gold recall@25, the share of gold passages seen in the top 25 results so far, at r = 0.99, and 77.5 to 93.6 percent of search episodes, where an episode is one search call and its results, add no new evidence; so log new evidence per step and pivot on a repeated query. 2609.14412, Question's Gambit: split the first search into clues, retrieve per clue, union and rerank; accuracy goes from 83.1 to 90.5 percent with the retriever unchanged. Analogy: a librarian hands you the ten best books first; you do not walk every shelf. Likely question: "Does this mean agents are useless at scale?" No; the agent still does the reasoning, but it starts from ranked discovery. Next: let the agent write its searches as code.
