When is GraphRAG worth its indexing cost?
When users ask corpus-wide sensemaking questions over a stable corpus: indexing costs about 1000x vector RAG, and global search wins 72–83% on comprehensiveness. For specific facts, use hybrid search + a reranker. For data that changes daily, use LazyGraphRAG (index = vector cost) or LightRAG (graph union updates).
Explain how HippoRAG 2 uses Personalized PageRank.
Offline, OpenIE triples make a KG of phrase and passage nodes, with synonym edges. Online, the query gets top-5 triples; an LLM filter keeps the good ones. Kept phrases and all passages (× 0.05) are the seeds. PPR spreads activation over the graph, and passages rank by their score. Result: associative multi-hop recall, 59.8 avg F1 vs 57.0 for dense.
Why do GraphRAG papers and HippoRAG disagree on LightRAG?
They use different metrics. GraphRAG-family papers use LLM-judge win rates on comprehensiveness and diversity: LightRAG is about 50% vs GraphRAG. HippoRAG 2 uses F1 on factual QA: LightRAG gets 6.6. Pick the metric that matches your task, and always include a strong dense baseline.
Text-to-SQL on a 1,000-column warehouse: your design?
Retrieve the schema, not documents: embed DDL + column docs and link only the relevant tables. Retrieve similar (question, SQL) pairs as few-shot examples. Execute, and send errors back for self-correction. Use a read-only role with row-level security. Why: on Spider 2.0, an o1-preview agent solves only 21.3%.
Ask the room each question first and give them thirty seconds before you reveal the answer. Question one tests cost judgement: an interviewer wants to hear "stable corpus, global questions" and a cheaper option for changing data. Question two tests mechanism: seeds, spreading activation, ranking passages; the analogy is a smell of smoke that spreads from the fire along the corridors. Question three is a favourite trap: the same system looks strong or weak depending on the metric, so name the metric before you name a winner. Question four is a design question; strong answers mention schema retrieval, an execution feedback loop and security. Likely follow-up: "How would you evaluate it?" Execution accuracy on a golden set of questions with known SQL results.
