# part 1 (step 1) stays; this main() replaces the main() of part 2 (step 2)
async def evidence_for(rag: LightRAG, q: str) -> dict:
    data = await rag.aquery_data(q, param=QueryParam(mode="mix"))
    d = data["data"]
    return {
        "entities": [e["entity_name"] for e in d["entities"]][:8],
        "references": {r["reference_id"]: r["file_path"] for r in d["references"]},
    }

async def main():
    rag = LightRAG(working_dir=WORKING_DIR, llm_model_func=llm_model_func,
                   llm_model_name=MODEL, embedding_func=embedding_func)
    await rag.initialize_storages()               # reuses ./claims_kg from step 2, no ainsert
    try:
        q = "Which Elm St hail claims must the SIU review together, and who handled them?"
        ev = await evidence_for(rag, q)
        print("entities:", ev["entities"])
        for ref_id, path in ev["references"].items():
            print("ref", ref_id, "->", path)
    finally:
        await rag.finalize_storages()

asyncio.run(main())

This is step 3 of the Harbor Mutual lab: we stop asking LightRAG for a finished answer and take its evidence instead. First, aquery_data runs the same mix retrieval but calls no LLM, so it returns entities, relationships, chunks and references as data. Second, evidence_for keeps the top 8 entity names, which your own agent, for example the Chapter 7 requirement register or an ADK workflow node, uses for its reasoning step. Third, the reference map turns reference ids into file paths, so the final answer cites policy/hail-guidelines.txt and the two claim files. Analogy: you ask the records clerk for the folders and the index cards, not for the clerk's opinion. Likely question: "Why not just use aquery?" Because your agent then controls the prompt, the verifier and the citations, and EffiRAG (arXiv 2609.18099) shows that answering from the source text beat LightRAG-hybrid on 93 of 120 questions at 57% lower cost.
