Latency budget

Embed query → ANN search → rerank → LLM prefill (grows with context) → decode.

Cost budget

Tokens in context → reranker calls → agent loops: agents use ~4x, multi-agent systems ~15x the tokens of chat.

Freshness promise

Source changes → index lags → cache keeps the old answer. Zombie chunks answer from deleted or changed documents.

Production, managed RAG and best practices

Every answer spends time, tokens and trust. This chapter covers tracing and caching, incremental indexing, managed RAG services, a best-practice checklist and open challenges.

A demo answers one question. A product answers a million questions, and each answer spends three budgets: time, money and trust in freshness. Press three times: each gauge fills segment by segment and the needle passes its budget mark. The segment widths are illustrative, not measurements; the order is the point. Latency: prefill grows with the context, so the number of chunks you send drives time. Cost: tokens in context and agent loops dominate; Anthropic reports about 4x the tokens of chat for agents and about 15x for multi-agent systems. Freshness: a "zombie chunk" is a chunk whose source document was edited or deleted, but the chunk still answers. Analogy: a restaurant menu on the web that still shows last year's prices. Likely question: "Which budget breaks first?" Usually latency on long contexts and cost on agent loops; freshness breaks silently, so you need an SLO for it.
