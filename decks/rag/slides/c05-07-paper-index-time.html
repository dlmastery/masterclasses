UNREAL: Unifying Retrieval and Long-Context with a Single Model

One frozen LLM selects evidence from a 21M-chunk index and from inside a long prompt. Long context and RAG become one selection step.
"Long context or RAG?" has a third answer: retrieve inside the long context and drop distractors first.
These three papers move work out of the query path. Step 1: HyPE asks an LLM once, at index time, for the questions each chunk answers, so q06 matches the question "purchase or delivery date?" and the paper reports up to 42 points more context precision with no LLM call per query. Step 2: "RAG Deserves an Index" compiles quote-verified claims at ingest; it reached 85.2% at about 2.2k reader tokens against 72.5% at 16.3k for the best chunking, and only a contextual-chunk hybrid plus rerank stack kept pace, at about 21 times the tokens. Step 3: NVIDIA's UNREAL uses one frozen LLM to select evidence both from a 21M-chunk index and from inside a long prompt, so long context and RAG become the same selection step. Analogy: a library that writes the index cards when a book arrives, not when a reader asks. Likely question: "Is HyPE the same as HyDE?" No: HyDE writes a fake answer per query at query time; HyPE writes questions per chunk once, at ingest. Next: Chapter 6 (Lab 5) puts the choice of retrieval path behind a router in an ADK workflow.
