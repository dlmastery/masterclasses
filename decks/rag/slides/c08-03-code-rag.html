cAST chunks along the AST: split large nodes, merge small siblings under a size budget. +4.3 Recall@5 on RepoEval, +2.67 Pass@1 on SWE-bench.

Cursor: re-index only what changed

  1. A Merkle tree of file hashes finds the changed files. 50,000 files give about 3.2 MB of hashes.
  2. One changed file changes every hash up to the root. Compare roots, then walk down.
  3. Split changed files into syntactic chunks. Embed them asynchronously. Cache embeddings by chunk content.
  4. A simhash seeds a new user's index from a teammate's (92% average similarity). Content proofs return only files the client has.

Code breaks three assumptions of text RAG: the user often searches for an exact name, the structure is a syntax tree, and the corpus changes every few minutes. cAST (Findings of EMNLP 2025) chunks along the AST and gains 4.3 Recall@5 on RepoEval. Steps 1 to 3 follow Cursor's January 2026 blog: a Merkle tree finds the changed files, only their syntactic chunks are re-embedded, and embeddings are cached by content, so a teammate's clone seeds yours through a simhash. Step 4 shows the result: p99 time to first query fell from 4.03 hours to 21 seconds. Step 5 is the 2026 debate: a May 2026 study found grep usually beat vector retrieval inside coding-agent harnesses, but the harness mattered a lot, so the practical answer is a hybrid toolset.
