lab5_it_triage.py · step 4: the IT branch
import asyncio, os, re
from google.adk import Agent
from google.adk.runners import InMemoryRunner
from google.adk.tools.google_search_agent_tool import GoogleSearchAgentTool, create_google_search_agent
MODEL = os.getenv("MODEL", "gemini-3.8-flash")
KNOWN_ISSUES = {
    "KI-311": "Okta SSO login loop after a password reset. Fix: clear the stale session cookie "
              "and re-sync the SAML clock skew. Queue: identity. Severity P2.",
    "KI-207": "Claim PDF upload fails for files over 20 MB. Fix: compress or split the PDF. "
              "Queue: claims-tools. Severity P3.",
}
def search_known_issues(query: str) -> dict:
    """Searches Northwind's internal known-issues knowledge base.
    Args:
      query: Keywords from the ticket, e.g. error text and product area.
    Returns:
      A dict with 'results': a list of {'id', 'text'} for matching known issues."""
    words = set(re.findall(r"[a-z0-9]+", query.lower()))
    hits = [{"id": k, "text": v} for k, v in KNOWN_ISSUES.items()
            if len(words & set(re.findall(r"[a-z0-9]+", v.lower()))) >= 2]
    return {"status": "ok", "results": hits}            # [] is an answer, not an error
web_search = GoogleSearchAgentTool(create_google_search_agent(MODEL))   # tool name: google_search_agent
it_triage = Agent(name="it_triage", model=MODEL, tools=[search_known_issues, web_search],
    instruction="""You triage Northwind IT tickets. Ticket: {question?}
1. ALWAYS call search_known_issues first.
2. Call google_search_agent ONLY if no internal issue matches (e.g. a vendor outage).
3. Reply exactly: Severity: P1-P4 | Queue: ... | Why: ... with citations [KI-xxx] or the web page title.""")
async def main():
    runner = InMemoryRunner(agent=it_triage, app_name="it_triage")
    for i, t in enumerate(["I'm stuck in an Okta login loop since my password reset",
                           "Zoom will not start for anyone in the office, is Zoom down today?"]):
        for e in await runner.run_debug(t, session_id=f"t{i}", quiet=True):
            if e.author == "it_triage" and e.content and e.content.parts and e.content.parts[0].text:
                print("ANSWER:", e.content.parts[0].text)
            if e.grounding_metadata and e.grounding_metadata.grounding_chunks:
                for c in e.grounding_metadata.grounding_chunks:
                    if c.web: print("  web source:", c.web.title)
if __name__ == "__main__": asyncio.run(main())   # import-safe for lab5_helpdesk.py

This is step 4 of Lab 5, the last lab step before the build: the IT branch gets a real triage agent, and the Workflow route map now says "it_support": it_triage instead of it_agent. Step 1: search_known_issues is a plain Python function; ADK builds the tool declaration from its signature and Google-style docstring, and it returns an explicit empty list when nothing matches, so the model sees "no match", not an error. Step 2: google_search is a Gemini built-in that cannot share a request with function tools, so GoogleSearchAgentTool wraps it in a search-only sub-agent and carries the grounding metadata back up. Think of a librarian who checks the in-house binder first and phones the outside reference desk only when the binder is silent. Step 4: the code prints web.title from the grounding chunks, and production UIs must also render the Search suggestions. The {question?} placeholder gives it the ticket from state when it runs as a Workflow node, and renders empty when you run this file alone. Likely question: "Why not put google_search straight into the tools list?" Because the docs say it can only be used by itself; the wrapper also gives you one sub-agent that you can rate-limit, log and switch off per tenant. That completes the three branches; the next slide makes the HR branch retry a weak search.
