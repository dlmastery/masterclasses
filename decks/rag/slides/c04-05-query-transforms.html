def hyde_search(question, llm, embed, index, k=5):
    fake_doc = llm("Write a short passage that answers the question.\n"
                   f"Question: {question}\nPassage:")
    vec = embed(fake_doc)            # embed the answer-shaped text
    return index.search(vec, k)      # real docs near the hypothetical one

Query transforms fix a vocabulary gap between how users ask and how documents are written. Multi-query and RAG-Fusion write several rewrites and merge the hits, HyDE embeds a fake answer because answers look more like documents than questions do, step-back asks for the general principle first, and decomposition splits a multi-hop question into steps, which leads into agentic RAG in the next chapter. Self-query turns words into a metadata filter, but the security rule is strict: tenant and ACL filters come from your auth system, never from the model. The "Advanced RAG Techniques" codelab runs HyDE and step-back on Cloud SQL with pgvector, and its whole HyDE prompt is one line: "Write a concise, hypothetical answer to the question." Analogy: a librarian rephrases your question before searching the catalogue. Likely question: "Should I always add RAG-Fusion?" No; the 2026 industry study saw recall gains vanish after reranking and truncation, so every transform costs an LLM call and must earn its place on an end-to-end metric.
