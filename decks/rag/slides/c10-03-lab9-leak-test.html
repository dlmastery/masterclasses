# part 1 (step 1) defines DOCS, USERS, col, acl_where(), search() and q
def post_filter_search(user: str, query: str, k: int = 3):   # the WRONG pattern
    res = col.query(query_texts=[query], n_results=k)
    return [(i, d) for i, d, m in zip(res["ids"][0], res["distances"][0], res["metadatas"][0])
            if set(m["allowed_groups"]) & set(USERS[user])]

print("post-filter maria:", post_filter_search("maria_callcenter", q))

# leak test: the assertion your CI runs for every user x every golden query
for u, groups in USERS.items():
    for doc_id, _ in search(u, q, k=5):
        allowed = next(d[2] for d in DOCS if d[0] == doc_id)
        assert set(allowed) & set(groups), f"LEAK: {u} got {doc_id}"
print("ACL leak test passed")

This is the second half of the same script. First, the wrong pattern: post_filter_search asks Chroma for the global top-3 and only then removes what Maria may not see. For the fraud question the top-3 are siu-02, adj-07 and siu-05, so Maria gets an empty list, although faq-01 is allowed and sits at rank 4; that is starvation, and at real scale TurboVec measured post-filter Recall@10 of only 0.09 to 0.19. Analogy: a librarian who picks three books from the locked room and then tells you that you may not have them. The leak test below uses the correct search() and asserts, for every user and every returned document, that the user shares a group with the document; run it for every golden query in CI next to the Lab 8 quality gate. A likely question is "do I need this if Chroma already filters?": yes, because the filter must also cover BM25, the reranker input and the semantic cache, and the test proves every path.
