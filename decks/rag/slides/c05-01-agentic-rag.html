Agentic RAG patterns

Classic RAG is one fixed pass. The pipeline retrieves once, also when the question does not need it. Nothing checks the retrieved evidence before the model uses it.

Agentic RAG is a policy. An LLM decides whether to retrieve, where (vector DB, SQL, web, API, MCP server), what to query (rewrite, decompose), if the evidence is good enough (grade, reflect) and when to stop.

Agentic RAG works by “embedding autonomous AI agents into the RAG pipeline.”

Paper Agentic Retrieval-Augmented Generation: A Survey on Agentic RAG (Singh et al., arXiv 2501.09136, v4 Apr 2026)
Classic RAG is a straight line: query, retriever, LLM, answer. It retrieves on every question and it never checks what it found. Press once to name these two faults, then press again and watch the line bend into a loop. The loop has three decisions: retrieve or not, which source, and is the evidence good enough; a failed check sends the agent back to rewrite or to switch the source. Analogy: classic RAG is a vending machine, agentic RAG is a librarian who asks a follow-up question and checks a second shelf. Likely question: "Is agentic RAG always better?" No. It costs more tokens and more latency, so the next slide starts with the simplest workflow that works.
