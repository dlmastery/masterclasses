Interview: multimodal, code and memory retrieval

You must index 10M scanned pages. ColPali or parse-then-text?
ColPali wins on table and chart pages, but it stores about 40x more than one dense vector (311.5 MB vs 7.5 MB on 4,874 passages). Compress with PLAID and token pooling (78.8 MB). Or use a single-vector multimodal embedder for recall and ColPali to rerank the top pages.
Why can grep beat a vector index for a coding agent?
Exact identifiers, always fresh, no index to sync. A 2026 study found grep usually more accurate across Claude Code, Codex and Gemini CLI, but the harness changed the result. Keep embeddings for concept queries such as "where is the auth logic?".
The user says "I moved to Berlin." Design the memory update.
Extract the fact. Find conflicting memories for this user_id. Invalidate the old city with a validity window (Graphiti) or choose UPDATE (Mem0). Keep the history, so "where did I live last year?" still works. Never write outside the user's scope.
Single-vector vs multi-vector retrieval: what is the trade-off?
One vector per item is cheap and fits any vector DB. Gemini Embedding 2 also crosses modalities. Multi-vector keeps token-level detail (about 1,000 patch vectors per page) and wins on dense pages, at a higher cost in storage and compute.
