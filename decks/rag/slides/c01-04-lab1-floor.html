# evalkit.py (continued): QUERIES and the four metric functions are defined above
def evaluate(name: str, search, ks=(1, 3, 5)) -> dict:
    """search(query_text) -> ranked list of chunk ids, best first."""
    rows = {f"R@{k}": 0.0 for k in ks} | {"MRR@10": 0.0, "nDCG@5": 0.0}
    misses = []
    for qid, (text, gold) in QUERIES.items():
        ranked = search(text)
        for k in ks:
            rows[f"R@{k}"] += recall_at_k(ranked, gold, k)
        rows["MRR@10"] += mrr(ranked, gold)
        rows["nDCG@5"] += ndcg_at_k(ranked, gold, 5)
        if not hit_at_k(ranked, gold, 5):
            misses.append(qid)
    n = len(QUERIES)
    rows = {m: round(v / n, 3) for m, v in rows.items()}
    print(f"{name:<22}", "  ".join(f"{m}={v:.3f}" for m, v in rows.items()), "| miss@5:", misses)
    return rows

The harness takes any function that maps query text to a ranked list of chunk ids, so BM25, hybrid search, rerankers and Qdrant all plug in later without a change, and the numbers stay comparable. The floor run passes a retriever that ignores the query and returns the corpus in order; this output is the one in the course that was really executed, on the standard library and Python 3.12. It scores recall at 5 of 0.333 and MRR of 0.197, and it misses 10 of 15 queries in the top 5. Analogy: the floor is the price of a random guess on a multiple-choice exam; any student who studied must beat it. If a real retriever lands near these numbers, check the ID mapping before you blame the model, because integer positions never match string ids like c04. A likely question is "why not just use ranx?": you can, as a cross-check, but compare against mrr at 10, because plain mrr in ranx reads the whole run.
