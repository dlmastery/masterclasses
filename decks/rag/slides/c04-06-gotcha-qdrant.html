Gotcha Qdrant 1.20

Qdrant fuses with k=2 by default, and a short prefetch returns nothing

client = QdrantClient(url="http://localhost:6333")       # integration tests: never only ":memory:"
assert client.info().version.startswith("1.20"), "client and server minor versions differ"

# model, BGE_QUERY, create_collection and upsert: unchanged from Lab 4 step 2
def qdrant_hybrid(query: str, limit: int = 10, offset: int = 0, k_rrf: int = 60) -> list[str]:
    q_vec = model.encode_query(query, prompt=BGE_QUERY, normalize_embeddings=True).tolist()
    depth = limit + offset + 10                          # each prefetch >= limit + offset
    res = client.query_points(
        collection_name="northwind_kb",
        prefetch=[models.Prefetch(query=models.TextQuery(text=query), using="text", limit=depth),
                  models.Prefetch(query=q_vec, using="dense", limit=depth)],
        query=models.RrfQuery(rrf=models.Rrf(k=k_rrf, weights=[3.0, 1.0])),  # weights: server >= 1.17
        limit=limit, offset=offset)
    return [p.payload["chunk_id"] for p in res.points]
1 · The fusion constant SymptomYou switch engines and the rankings change. One list's top hit dominates. Causehybrid/fusion.py: DEFAULT_RANKING_CONSTANT_K = 2. The paper uses 60. With k=2, rank 1 scores 1/3 and rank 10 scores 1/12. With k=60 the curve is flat, so agreement between lists wins. FixPin Rrf(k=60) or your tuned k in code and in config review.
2 · The prefetch depth SymptomAn empty result, although both prefetches return points. CauseQdrant docs: the prefetch limit must be at least limit + offset of the main query, otherwise you can get an empty result. FixSet each prefetch limit ≥ limit + offset.
3 · Client and server versions (qdrant#8436) SymptomWeighted RRF fails: 400 - {"status":{"error":"Format error in JSON body: Expected some form of vector, id, or a type of query at line... CauseServer 1.13.2, client 1.17.x. Weighted RRF needs server v1.17.0+. Local ":memory:" mode also differs: it ignores a top-level query_filter on fusion with prefetches (#1372). FixPin client minor = server minor. Check client.info().version at startup. Run integration tests on qdrant/qdrant at the prod version.

Three Qdrant defaults change hybrid results without any error, so check them before you trust a benchmark. First, Qdrant's RRF constant is 2, not the 60 from the paper: with k=2 the top hit of one list wins, as the worked example shows, where chunk A is first in BM25 only and still beats chunk B, which is fifth in both lists. Second, every prefetch must return at least limit plus offset points, or the main query can come back empty. Think of the prefetch as a funnel: if it is narrower than the bucket you want to fill, you get nothing out. Third, pin the client and server to the same minor version and test against a real server in Docker, because weighted RRF needs server 1.17 and local mode behaves differently. A likely question is whether k=60 is always right: no, tune k on your labelled set, but write the value down explicitly.
