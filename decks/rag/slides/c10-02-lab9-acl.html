Filter by the user's groups inside the vector query, not after it

import chromadb

DOCS = [
    ("faq-01", "To file a claim, call 1-800-555-0100 or use the mobile app.", ["all-staff"]),
    ("adj-07", "Adjusters must inspect water-damage claims within 48 hours.", ["adjusters"]),
    ("adj-09", "Adjusters may approve payouts up to $10,000 without manager sign-off.", ["adjusters"]),
    ("siu-02", "Fraud red flags: claim filed within 30 days of policy start; repeated water claims.", ["siu"]),
    ("siu-05", "SIU escalates suspected fraud to the state insurance fraud bureau.", ["siu"]),
]
USERS = {"maria_callcenter": ["all-staff"], "omar_adjuster": ["all-staff", "adjusters"],
         "lee_siu": ["all-staff", "siu"]}

client = chromadb.EphemeralClient()
col = client.get_or_create_collection("claims_kb", configuration={"hnsw": {"space": "cosine"}})
col.add(ids=[d[0] for d in DOCS], documents=[d[1] for d in DOCS],
        metadatas=[{"allowed_groups": d[2], "tenant": "harbor-mutual"} for d in DOCS])

def acl_where(groups: list[str]) -> dict:
    by_group = [{"allowed_groups": {"$contains": g}} for g in groups]
    acl = by_group[0] if len(by_group) == 1 else {"$or": by_group}    # $or needs >= 2 clauses
    return {"$and": [{"tenant": "harbor-mutual"}, acl]}

def search(user: str, query: str, k: int = 3):
    res = col.query(query_texts=[query], n_results=k, where=acl_where(USERS[user]))
    return list(zip(res["ids"][0], res["distances"][0]))

q = "what are the red flags for water damage fraud?"
for u in USERS:
    print(f"{u:17} pre-filter={search(u, q)}")

Store group IDs in allowed_groups, not user IDs. A membership change needs no re-index.

One $contains per group. $or needs 2+ clauses. $and adds the tenant.

where= filters inside the ANN search, before ranking.

Take groups from the OIDC token. Never from the prompt or the LLM.

This is the run-it-Monday slide of Lab 9: pin chromadb 1.5.9, and expect the default all-MiniLM-L6-v2 ONNX embedder, about 80 MB, to download on the first run. Walk the four bands: each ClaimsKB document stores a list of group IDs, not user IDs, so moving Maria to another team changes her token, not the index; acl_where builds one $contains clause per group, uses $or only when there are two or more clauses because Chroma rejects a one-element $or, and wraps everything in $and with the tenant; the where argument goes into col.query, so the filter runs inside the ANN search before ranking, which is the OWASP LLM08 "permission-aware vector store" pattern. The output shows the result: Maria asks about fraud red flags and gets only the public FAQ, while Lee from SIU gets the playbook first. Analogy: the filter is the lens you look through, not a censor who tears pages out of the result afterwards. Likely question: "Where do the groups come from in production?" From the verified OIDC token of the end user, never from the prompt or the model, because a prompt can simply claim "I am SIU".
