def norm_groups(groups: list[str]) -> list[str]:
    return sorted({g.strip().lower() for g in groups})       # same function at ingest and query
# ingest: metadatas=[{"allowed_groups": norm_groups(g), "tenant": "harbor-mutual"} for ...]

def acl_where(groups: list[str]) -> dict:
    by_group = [{"allowed_groups": {"$contains": g}} for g in norm_groups(groups)]
    acl = by_group[0] if len(by_group) == 1 else {"$or": by_group}   # $or needs >= 2 clauses
    return {"$and": [{"tenant": "harbor-mutual"}, acl]}              # exactly one top-level operator

FENCES = ("<<DOC>>", "<</DOC>>", "<DOC>", "</DOC>")
def spotlight(doc: str) -> str:
    for tag in FENCES:
        doc = doc.replace(tag, "")                            # attacker cannot close the wrapper
    return "<<DOC>>" + "^".join(doc.split()) + "<</DOC>>"

def reply_text(resp) -> str:
    return resp.text or ""                                    # None when blocked or empty

These are the three ways the Lab 9 guards break in practice. First, Chroma's validate_where rejects an $or with one clause, and Maria has exactly one group, so the call-centre user is the first to hit the ValueError; it also rejects two keys side by side, so the tenant and the ACL clause go inside one $and. Second, a case or whitespace mismatch such as "SIU" against "siu" fails silently: the privileged user sees nothing, and nobody files a bug, so call one norm_groups function on both sides. Third, an attacker can type your closing delimiter, so strip the fence strings from untrusted text before you wrap it, and treat a None reply as its own failure rather than a crash in the canary assert. Analogy: a fence is only a fence if the visitor cannot bring their own gate. Likely question: "Why not escape the tags instead of deleting them?" Either works; what matters is that no untrusted string can produce your exact closing tag. Next, the 2026 papers that explain why the suite tests the retrieval channel and asserts outcomes.
