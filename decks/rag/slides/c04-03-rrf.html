Reciprocal Rank Fusion merges ranked lists by rank only, with k = 60

RRFscore(d) = Σ 1 / (k + rank_r(d)) over all rankers r. Only ranks count, so BM25 (unbounded) and cosine (−1..1) need no calibration.

Pilot MAP: k=0 .2072 · k=60 .2145 · k=500 .2098. "k = 60 was fixed during a pilot investigation and not altered." RRF beats Condorcet, CombMNZ and the best single system by 4–5% on average.

Qdrant: set each prefetch limit ≥ the main limit + offset. If you do not, the result can come back empty.
Paper Cormack, Clarke, Büttcher, SIGIR 2009 Docs Qdrant hybrid queries
rrf.py

def rrf(rankings: list[list[str]], k: int = 60) -> list[tuple[str, float]]:
    scores: dict[str, float] = {}
    for ranking in rankings:
        for rank, doc_id in enumerate(ranking, start=1):
            scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (k + rank)
    return sorted(scores.items(), key=lambda x: x[1], reverse=True)

bm25 = ["A", "C", "E"]; dense = ["D", "B", "A"]
print(rrf([bm25, dense])[0])   # ('A', 0.03226...)

RRF is the default way to merge a BM25 list and a dense list. Each list gives a document 1 over (60 plus its rank), and the scores add up. Walk the worked example: A is rank 1 in BM25 and rank 3 in dense, so it gets 0.0164 plus 0.0159, which is 0.0323; B is only in the dense list at rank 2, so it gets 0.0161; A wins because both lists agree on it. Then show the pilot table: k from 0 to 500 barely moves MAP, so you almost never tune k. Analogy: two judges rank the same contestants; you add up placings, not their raw scores, because one judge scores out of 10 and the other out of 100. Likely question: "When is score fusion better?" When the scores are calibrated and you have labels to tune alpha; otherwise RRF is the safe default, and Qdrant v1.17 adds weights if one list is more reliable.
