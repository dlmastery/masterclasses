import os
import numpy as np
from lightrag.llm.gemini import gemini_embed
from lightrag.utils import wrap_embedding_func_with_attrs

MODEL = os.getenv("MODEL", "gemini-3.8-flash")       # demo: gemini-2.0-flash (shut down)
EMBED, DIM = "gemini-embedding-001", 1536            # demo: models/text-embedding-004

@wrap_embedding_func_with_attrs(embedding_dim=DIM, send_dimensions=True,
                                max_token_size=2048, model_name=EMBED)
async def embedding_func(texts: list[str], embedding_dim: int | None = None,
                         context: str = "document") -> np.ndarray:  # demo: texts only -> TypeError
    return await gemini_embed.func(texts, model=EMBED, embedding_dim=embedding_dim, context=context)

os.environ.setdefault("GEMINI_API_KEY", os.environ.get("GOOGLE_API_KEY", ""))  # LightRAG reads GEMINI_API_KEY
WORKING_DIR = f"./claims_kg_{EMBED}_{DIM}"           # new dir per embedder + dim
os.makedirs(WORKING_DIR, exist_ok=True)

Copy-paste from the official LightRAG Gemini example fails today, and this slide shows the three reasons in the order you hit them. First the model: gemini-2.0-flash is shut down, so read model ids from config. Second the decorator: send_dimensions=True makes EmbeddingFunc inject embedding_dim, and the demo function only takes texts; we inferred the TypeError from the source and did not run it. Third the environment and the index: LightRAG's Gemini binding reads GEMINI_API_KEY or LLM_BINDING_API_KEY, not GOOGLE_API_KEY, and a working_dir built with one embedder and dimension breaks when you change either. Analogy: the working_dir is a filing cabinet sized for 1536-wide folders; you cannot push 768-wide ones into it, so you buy a new cabinet. Likely question: "Can I switch to gemini-embedding-2 later?" Yes, but in a new directory with a full re-index, because its vectors are not compatible with gemini-embedding-001. Next: three recent papers on what a graph and an image index really cost.
