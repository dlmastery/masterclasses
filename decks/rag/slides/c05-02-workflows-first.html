A workflow first, an agent only when needed

A workflow is a fixed code path with LLM steps. An agent chooses its own path. When you know the path, use a workflow: it is cheaper to test, trace and cap.

Survey taxonomy: 4 dimensions (agent cardinality, control structure, autonomy, knowledge representation) · 4 agentic patterns (reflection, planning, tool use, multi-agent collaboration) · 7 families (router, multi-agent, hierarchical, corrective, adaptive, graph-based such as Agent-G and GeAR, Agentic Document Workflows). The 5 workflow patterns above come from Anthropic's “Building effective agents”.

The survey by Singh et al. (arXiv 2501.09136, v4 April 2026) sorts agentic RAG by four dimensions and seven architecture families, but the practical lesson is simpler. Each of the five workflow patterns from Anthropic's "Building effective agents" maps to one RAG job: chaining is rewrite, retrieve, answer; routing picks the source; parallelization fans out queries and fuses them with RRF; orchestrator-workers is deep research; evaluator-optimizer is the grade-and-rewrite loop. A workflow is a fixed code path, so you can test it, trace it and put a cap on it. Use an autonomous agent only when one pass fails on real queries. Then show the cost: an agent uses about 4 times the tokens of chat, and a multi-agent system about 15 times (Anthropic, June 2025). Analogy: a workflow is a recipe, an agent is a chef who improvises; use the recipe until it fails. Likely question: "Where is the line between the two?" If code decides the next step, it is a workflow; if the model decides, it is an agent.
