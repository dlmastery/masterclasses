Best practices

Retrieval rules: decide fusion per corpus, rerank 30-50, pin defaults

Do

  • Normalise IDs (E-4012, SKUs) on corpus and query. bm25s drops the 1-letter "E".
  • Choose fusion per corpus; keep dense-only as an option. 2610.30612
  • Pin the RRF k in code. Qdrant default 2, paper 60.
  • Fetch depth 20+ per retriever before fusion. Prefetch < limit + offset returns nothing.
  • Rerank 30-50 candidates when the LLM reads 10. 2609.27213
  • Replace MiniLM with Ettin-17M/32M; use bf16 + FlashAttention-2. NanoBEIR 0.6825 vs 0.6369.
  • Rank with reranker scores; tune cut-offs per model. MiniLM gives logits.
  • Score answers, not only MRR. Hit@10 +14 pts, answers +3.8 (2610.01324).

Don't

  • Add raw BM25 and cosine scores. The scales differ.
  • Trust only ":memory:" tests. Local Qdrant differs (#1372).

# retrieval_config.py -- one reviewed config + the Ettin reranker
from sentence_transformers import CrossEncoder
from kb import TEXT
from lab3_hybrid import hybrid_search

RETRIEVAL = {                     # reviewed like code
    "fusion": "rrf",              # per corpus: Fusion Tax check
    "rrf_k": 60,                  # Qdrant default is 2
    "depth": 20,                  # per retriever, before fusion
    "rerank_candidates": 40,      # 30-50 when the LLM reads 10
    "keep": 10,
    "reranker": "cross-encoder/ettin-reranker-32m-v1",
}
reranker = CrossEncoder(RETRIEVAL["reranker"])   # HF Ettin blog, 2026-05-19

def retrieve(query: str, cfg: dict = RETRIEVAL) -> list[str]:
    cand_ids = hybrid_search(query, depth=cfg["depth"], k_rrf=cfg["rrf_k"])
    cand_ids = cand_ids[:cfg["rerank_candidates"]]
    hits = reranker.rank(query, [TEXT[i] for i in cand_ids], top_k=cfg["keep"])
    return [cand_ids[h["corpus_id"]] for h in hits]  # positions -> business ids

These rules are the whole chapter in one reviewed config file. Steps 1 and 2 cover fusion: normalise codes so BM25 can see them, pick fusion per corpus because the Fusion Tax paper shows hybrid still hurts 8 to 21 percent of queries, and pin k because Qdrant's default is 2 while the paper uses 60. Step 3 covers reranking: BoundaryMORPH shows that a small rerank budget only re-checks the obvious top hits, so rerank 30 to 50 when the LLM reads 10, and the Ettin models from Hugging Face are both faster and better than MiniLM, as the throughput bars show. Step 4: reranker scores are for ranking, and the clinical-notes paper lifted Hit@10 from 46.6 to 60.6 percent while answer correctness moved only from 44.8 to 48.6, so measure the answer. Analogy: the config file is the recipe card; if a value is not written down, the next cook changes it without noticing. Likely question: "Why 40 candidates on an 18-chunk corpus?" Here the slice simply returns all 18; the value is for the production corpus, where the reranker budget must cover more than the 10 chunks the LLM reads. Hand-off: Chapter 5 keeps retrieve() on top of hybrid_search() and fixes the queries that still miss, such as q11 and q06.
