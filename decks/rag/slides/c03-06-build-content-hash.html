import hashlib
import chromadb
from sentence_transformers import SentenceTransformer
chunker, doc = ...   # omitted: Lab 2 HybridChunker (Qwen3 tokenizer, 512) + DoclingDocument
MODEL, DIM = "Qwen/Qwen3-Embedding-0.6B", 256
model = SentenceTransformer(MODEL, device="cpu", truncate_dim=DIM)
col = chromadb.PersistentClient(path="./chroma_claims").get_or_create_collection(
    name=f"claims_qwen3_{DIM}", embedding_function=None,
    configuration={"hnsw": {"space": "cosine"}}, metadata={"embedding_model": MODEL, "dim": DIM})
fresh = {}
for ch in chunker.chunk(dl_doc=doc):
    text = chunker.contextualize(chunk=ch)
    cid = hashlib.sha256(f"{MODEL}|{DIM}|{text}".encode()).hexdigest()[:32]
    pages = sorted({p.page_no for it in ch.meta.doc_items for p in it.prov})
    fresh[cid] = (text, {"source": doc.origin.filename, "first_page": pages[0] if pages else -1,
                         "heading": (ch.meta.headings or [""])[-1]})
existing = set(col.get(where={"source": doc.origin.filename}, include=[])["ids"])
to_add = [cid for cid in fresh if cid not in existing]
to_delete = sorted(existing - fresh.keys())
if to_add:
    v = model.encode_document([fresh[c][0] for c in to_add], normalize_embeddings=True)
    col.upsert(ids=to_add, embeddings=v, documents=[fresh[c][0] for c in to_add],
               metadatas=[fresh[c][1] for c in to_add])
if to_delete:
    col.delete(ids=to_delete)
print(f"chunks={len(fresh)} reused={len(fresh) - len(to_add)} embedded={len(to_add)} "
      f"deleted={len(to_delete)} total_in_index={col.count()}")

Chunk Recomputation under Real Document Revisions

120 real revision pairs: fixed-size chunking re-embeds 57-68%, recursive 38-56%, content-defined 43-54%. Recall differs by <2 pts.
Log reused / embedded / deleted. reused=0 on a small edit = boundary drift.
Hash only the text, and a model upgrade keeps the old vectors. Put MODEL and DIM in the hash.
This build adds day-2 ingestion to the Northwind Mutual index: the claims policy changes, and we must not pay to embed it all again. Step 1 shows the naive sync: drop the collection, re-chunk, and embed all 42 chunks with the positional ids of Lab 2, so one edit changes every id. Steps 2 and 3: the id is a SHA-256 of model, dimension and chunk text, so an unchanged chunk keeps its id, and a model or dimension change gives new ids and a new collection name automatically; then the set difference gives 5 chunks to embed and 4 old chunks to delete. Analogy: a library that re-prints only the pages with new text, and removes the old pages from the shelf. Step 4 and 5: the second run makes 5 embed calls instead of 42, and the October paper on real Wikipedia revisions shows that the chunker choice decides how much you re-embed, with under 2 points of recall difference. Likely question: "Why Qwen3 and not Gemini here?" The claims policy stays on-prem, as in step 2, and Lab 2 chunked with the Qwen3 tokenizer at 512 tokens, so no chunk is cut at embed time. The same id diff works on the claim_chunks table in pgvector. Hand-off: the next two slides list the silent defaults that broke these steps in real projects.
