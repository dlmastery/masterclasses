# lab2_bm25.py -- BM25 baseline for the Northwind support KB
import re
import bm25s
import Stemmer
from kb import IDS, TEXT
from evalkit import evaluate

stemmer = Stemmer.Stemmer("english")
# Keep codes like "E-4012" / "P-220" as ONE token: the default pattern \b\w\w+\b drops the 1-letter "E".
CODE = re.compile(r"\b([A-Z])-(\d{2,5})\b", re.IGNORECASE)   # also catches "e-4012"
def normalise(text: str) -> str:
    return CODE.sub(r"\1\2", text)                    # "E-4012" -> "E4012"

corpus_tokens = bm25s.tokenize([normalise(TEXT[i]) for i in IDS], stopwords="en",
                               stemmer=stemmer, show_progress=False)
retriever = bm25s.BM25(k1=1.2, b=0.75)                # Lucene k1; the bm25s default is k1=1.5
retriever.index(corpus_tokens, show_progress=False)

def bm25_search(query: str, k: int = 10) -> list[str]:
    q_tokens = bm25s.tokenize(normalise(query), stopwords="en", stemmer=stemmer, show_progress=False)
    k = min(k, len(IDS))                               # bm25s raises ValueError if k > corpus size
    docs, scores = retriever.retrieve(q_tokens, corpus=IDS, k=k, show_progress=False)
    return [d for d, s in zip(docs[0], scores[0]) if s > 0]   # drop zero-score padding

if __name__ == "__main__":
    print(bm25_search("customer sees E-4012 at checkout")[:3])
    evaluate("BM25 (bm25s)", bm25_search)
    retriever.save("northwind_bm25", corpus=IDS)

Glue codes: E-4012 becomes E4012. Apply it to the corpus and to the query.

Same stemmer and stopwords="en" on both sides. Pin k1=1.2: the bm25s default is 1.5.

Cap k at 18 chunks. corpus=IDS gives string ids. Drop zero-score padding rows.

Score with the same evaluate(). Reload with BM25.load(..., load_corpus=True).

Codes (q02, q15) and "monogrammed" (q04) win. Paraphrases miss: dense retrieval, chapter 4.

This is the last step of Lab 1: the first real retriever goes into the same evaluate() harness as the floor run. Walk the four focus bands: glue error codes before tokenising, use the same stemmer and stopwords on corpus and query, cap k at the corpus size and ask for string ids, then score and save. On the scorecard, BM25 lifts recall@5 from 0.333 to 0.767 and MRR@10 from 0.197 to 0.680; the floor row was executed, the BM25 row is illustrative, so teach the pattern, not the third decimal. Analogy: BM25 is a librarian who matches the exact words on the spine; "customs fees" never finds the book called "import duties". Likely question: "Why not drop BM25 and go dense only?" Because BM25 is the one that finds bare codes such as P-220, and the BM25 Wins at Scale paper (arXiv 2607.26497) shows it overtakes a file-system agent above about 10M corpus tokens at a fraction of the query tokens.
