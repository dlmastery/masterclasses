# lab5_st_claims.py
import json
import numpy as np
from sentence_transformers import SentenceTransformer, quantize_embeddings

chunks = [json.loads(line) for line in open("out/claims_chunks.jsonl", encoding="utf-8")]
texts = [c["text"] for c in chunks]

model = SentenceTransformer("Qwen/Qwen3-Embedding-0.6B", device="cpu", truncate_dim=256)
print("prompts:", list(model.prompts), "| dim:", model.get_embedding_dimension(),
      "| max_seq_length:", model.max_seq_length)
model.max_seq_length = 1024          # cap memory; chunks are <=512 tokens anyway

doc_emb = model.encode_document(texts, batch_size=16, normalize_embeddings=True,
                                show_progress_bar=True)
queries = ["Is water damage from a burst pipe covered?", "How long do I have to report a claim?"]
q_emb = model.encode_query(queries, normalize_embeddings=True)

scores = model.similarity(q_emb, doc_emb)            # cosine (from model config)
for qi, q in enumerate(queries):
    top = np.argsort(-scores[qi].numpy())[:3]
    print(f"\nQ: {q}")
    for j in top:
        print(f"  {scores[qi, j]:.3f} p{chunks[j]['pages']} {chunks[j]['headings'][-1:]} ")

int8_docs = quantize_embeddings(doc_emb, precision="int8", calibration_embeddings=doc_emb)
print("\nfloat32 bytes:", doc_emb.nbytes, "| int8 bytes:", int8_docs.nbytes)
np.save("out/claims_qwen256.npy", doc_emb.astype(np.float32))
truncate_dim=256 keeps 256 of 1,024 dims, then normalises.
Config allows 32,768 tokens. Chunks are ≤ 512: cap at 1,024.
encode_query adds the Instruct prompt. Plain encode() drops it.
int8 stores 4x less. Calibrate on a representative sample.
Mean quality hides per-query neighbour loss. Test 256-d on hard queries. arXiv 2610.17742 Neighborhood loss under PCA truncation

This lab embeds the same claims chunks from Lab 2, but on our own machines, so no policy text leaves the network. Walk the four focus steps: truncate_dim cuts the 1,024-dimension Qwen3 vector to its first 256 dimensions, max_seq_length caps memory, encode_query and encode_document apply the model's own prompts, and int8 quantization cuts storage by four. Matryoshka truncation is like a nested set of dolls: the first 256 numbers are a complete, smaller vector by training, not by accident. Stress that plain encode() for queries silently drops the "Instruct:" prompt and costs recall with no error. A likely question is "how much recall do I lose at 256 dimensions?"; the answer is to measure it on your hard queries, because arXiv 2610.17742 shows that the mean hides large per-query loss. Hand-off: the script saves out/claims_qwen256.npy; step 3 asks how to search 256-d vectors like these fast without losing neighbours.
