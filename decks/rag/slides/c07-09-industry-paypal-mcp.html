import json
from langchain_core.documents import Document
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_google_genai import GoogleGenerativeAIEmbeddings
catalog = json.load(open("mcp_tools.json"))   # name + description
emb = GoogleGenerativeAIEmbeddings(model="gemini-embedding-001")
index = InMemoryVectorStore(emb)
index.add_documents([Document(f"{t['name']}: {t['description']}",
                              metadata={"schema": t}) for t in catalog])
def tool_search(query: str, k: int = 5) -> list[dict]:
    hits = index.similarity_search(query, k=k)  # + BM25, rrf() at scale
    return [d.metadata["schema"] for d in hits]

arXiv 2608.23992 SCOUT: Hybrid Semantic Tool Discovery for Enterprise MCP Gateway (PayPal) · Shopify production-ready agentic systems
Our compliance desk now talks to many MCP servers, and PayPal's SCOUT gateway paper (arXiv 2608.23992, "Hybrid Semantic Tool Discovery for Enterprise MCP Gateway", 25 August 2026) shows what happens at 2,000+ tools from 200+ servers: the tool schemas alone take 70.1 percent of the context before the analyst's question arrives, and prompt caching makes that cheaper but frees no space. The gateway exposes only two meta-tools. tool_search runs the Chapter 4 hybrid recipe, BM25 plus dense fused with RRF, over a tool catalog and returns the top-k schemas, so tool tokens fall from 140.2k to 1.3k. execute_tool is the single chokepoint for auth, policy and logging, a catalog pipeline keeps the index fresh, and clients need no change. A sharp student will notice that 140.2k at 70.1 percent implies a 200k window, and 1.3k of 200k is 0.65 percent, not 0.8; the paper reports 0.8 percent, probably against the total request size, so quote the token counts rather than the percentages. The code sketch indexes each tool's name and description as a document in the same InMemoryVectorStore as Lab 6 and returns the stored schemas; at scale, add BM25 and the rrf() from rank_first.py. If hop() had to choose among many search tools, this is where it would look them up. Shopify Sidekick reports a tool ladder: 0 to 20 tools are fine, 20 to 50 blur, and past 50 the system becomes hard to reason about; treat that as their report, not a law, and measure selection accuracy yourself, because the SCOUT abstract reports none against full exposure. Anthropic's Tool Search Tool points the same way, with about 85 percent fewer tool-definition tokens. Analogy: a shop assistant who fetches the three right items from the stock room, instead of piling the whole catalogue on the counter. Likely question: "Does accuracy drop when the model sees fewer tools?" Run your own tool-selection eval before and after.
