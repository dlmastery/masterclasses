# Agent, Event, MODEL and Verdict come from step 1
answerer = Agent(name="answerer", model=MODEL, output_key="draft",
                 instruction="Answer: {question}\nUse ONLY this evidence and "
                             "cite ids like [PTO-2026]:\n{evidence}")

verifier = Agent(name="verifier", model=MODEL, output_schema=Verdict,
                 output_key="verdict",
                 instruction="Evidence:\n{evidence}\n\nDraft:\n{draft}\n\n"
                             "Check each claim of the draft against the evidence.")

def gate(node_input: Verdict, draft: str):
    if node_input.supported:
        yield Event(message=f"VERIFIED: {draft}")
    else:
        yield Event(message="Opened HR ticket; could not verify: "
                            f"{node_input.unsupported_claims}")

This is step 3 of Lab 5: the three nodes that the HR-chain edge from step 2 names after retrieve_hr. The answerer writes its text to state["draft"] through output_key, and its {question} and {evidence} placeholders read state. The verifier is a separate agent that sees only {evidence} and {draft}, because a workflow node defaults to include_contents='none', and it returns a Verdict; gate reads that Verdict as node_input and the draft by parameter name, so only verified text reaches the employee, which is the check_identity pattern of the agent_in_workflow sample. In the last step the draft carries a planted claim, "and 3 more days with manager approval", that no evidence sentence supports, so the gate stays shut and an HR ticket opens. Analogy: the answerer writes the memo, the verifier is the colleague who reads only the memo and the policy page, never the chat. Likely question: "Why not let the answerer check itself?" A separate agent, ideally on a different model, does not share the writer's blind spots; arXiv 2609.35774 found a post-generation completeness check (d = +0.48) beats agentic search tweaks, and 2607.24010 says to log how often the router picks each branch, because router quality changes with the traffic mix.
