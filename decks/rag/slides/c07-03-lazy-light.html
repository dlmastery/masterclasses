LazyGraphRAG and LightRAG cut graph cost by deferring LLM work or using one call

LazyGraphRAG: no LLM at index time

It "requires no prior summarization of the source data". Index: a noun-phrase co-occurrence graph; graph statistics make communities.

Query: 3–5 subqueries → best-first ranking → LLM relevance tests, breadth-first → deepen → stop at the budget → map-reduce claims.

5,590 AP articles, LLM judge. At 4% of GraphRAG global query cost, it beats all methods on local and global queries. Ships in Microsoft Discovery (Azure).

from lightrag import LightRAG, QueryParam
from lightrag.llm.openai import gpt_4o_mini_complete, openai_embed

rag = LightRAG(working_dir="./rag_storage", embedding_func=openai_embed,
               llm_model_func=gpt_4o_mini_complete)
await rag.initialize_storages()        # inside async def main()
await rag.ainsert(f.read())            # incremental: graph union
for mode in ["naive", "local", "global", "hybrid", "mix"]:
    print(mode, await rag.aquery("What are the top themes in this story?",
                                 param=QueryParam(mode=mode)))
await rag.finalize_storages()

Both systems attack the same problem: full GraphRAG spends LLM calls at index time on every chunk and every community. LazyGraphRAG moves that work to query time: the index is cheap NLP co-occurrence, the same cost as vector RAG and 0.1% of GraphRAG, and the LLM only tests chunks that look promising, until a budget runs out. That budget is the one knob: Z100_Lite costs the same as an 8k vector RAG call, and more budget gives more quality. LightRAG keeps an LLM-built graph but drops community reports: one LLM call makes low-level keywords that hit entity nodes and high-level keywords that hit relation edges, and an update is a graph union. Analogy: GraphRAG pre-cooks every meal; LazyGraphRAG cooks to order; LightRAG keeps a well-labelled pantry. Likely question: "Is LightRAG better than GraphRAG?" On LLM-judge win rates it is about even, near 50%, at a small fraction of the query tokens; the next slide shows that F1 tells a different story.
