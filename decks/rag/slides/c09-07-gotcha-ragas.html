Gotcha ragas 0.4.3

Failed rows raise your faithfulness score: report coverage with it

shopco_eval/gate_value.py · NaN-safe faithfulness for the release gate
import asyncio, math
# faith = Faithfulness(llm=judge): built in Lab 8, step 1

def gate_value(results) -> tuple[float, float]:
    vals = [r.value for r in results]
    coverage = sum(not math.isnan(v) for v in vals) / len(vals)
    assert coverage >= 0.95, f"only {coverage:.1%} rows scored: the judge broke, not the bot"
    strict = sum(0.0 if math.isnan(v) else v for v in vals) / len(vals)   # NaN counts as 0
    return strict, coverage

async def score_answered(run: list[dict], gold: dict, faith) -> tuple[float, float]:
    answered = [r for r in run if r["response"].strip()]  # "" -> ValueError
    results = await asyncio.gather(*(           # ascore, never score(), inside a loop
        faith.ascore(user_input=gold[r["id"]]["question"], response=r["response"],
                     retrieved_contexts=r["retrieved_contexts"])
        for r in answered))
    return gate_value(results)

This is the ragas gotcha that makes a broken run look like a better bot. With raise_exceptions=False, every judge error becomes NaN, and safe_nanmean drops those rows from the denominator, so in the animation System B loses its two weak rows and its headline rises from 0.375 to 0.75 while it is really the worse system. The fix in gate_value is two numbers: coverage, asserted at 0.95 or more to match the gate's 5 percent NaN limit, and a strict score that counts NaN as 0; with both, B shows 50 percent coverage and 0.375. Analogy: a class average that only counts the students who handed in their exam always looks good. The other two cards are the errors you hit when you wire this into the ShopCo gate: an empty abstention is not a response, and score() inside an event loop must become ascore(). A likely question is "should we leave ragas?": not right away, but pin 0.4.3, keep this wrapper in your own repo, and do not wait on upstream fixes.
