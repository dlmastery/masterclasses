Gotcha Embeddings

Embedding traps: one vector per batch, no norm, silent truncation

northwind_index/embed_checks.py · three asserts at write time
import json
import numpy as np
from google import genai
from google.genai import types
from sentence_transformers import SentenceTransformer
client = genai.Client()                                           # GEMINI_API_KEY
texts = ["Refund not received", "Duplicate premium charge", "Claim PDF upload fails"]

res = client.models.embed_content(model="gemini-embedding-2",       # no task_type
    contents=[types.Content(parts=[types.Part.from_text(text=t)]) for t in texts],
    config=types.EmbedContentConfig(output_dimensionality=768))     # 2 auto-normalises
assert len(res.embeddings) == len(texts), "inputs were aggregated into one vector"

resp_001 = client.models.embed_content(model="gemini-embedding-001", contents=texts,
    config=types.EmbedContentConfig(task_type="RETRIEVAL_DOCUMENT", output_dimensionality=768))
v = np.asarray([e.values for e in resp_001.embeddings], dtype=np.float32)
v /= np.linalg.norm(v, axis=1, keepdims=True)                       # 001 below 3072 dims
assert np.allclose(np.linalg.norm(v, axis=1), 1.0, atol=1e-3)

model = SentenceTransformer("Qwen/Qwen3-Embedding-0.6B", truncate_dim=256)
model.max_seq_length = 1024                                         # the Lab 3 step 2 cap
chunks = [json.loads(l)["text"] for l in open("out/claims_chunks.jsonl", encoding="utf-8")]
too_long = [i for i, c in enumerate(chunks)
            if len(model.tokenizer(c, add_special_tokens=True)["input_ids"]) > model.max_seq_length]
assert not too_long, f"{len(too_long)} chunks will be truncated"

CauseGemini docs: Adding multiple inputs directly to the contents parameter produces one aggregated embedding for all inputs. FixOne types.Content per input. Assert the count. No task_type: use prefixes (task: search result | query: …).

FixNormalise and assert unit norm at write time. gemini-embedding-001 and gemini-embedding-2 vectors are not compatible: re-embed everything.

Three embedding bugs that raise no error and quietly damage the Northwind Mutual index. First: gemini-embedding-2 aggregates a plain list of strings into one vector, so wrap each ticket in its own types.Content and assert that the count of vectors equals the count of inputs. Second: gemini-embedding-001 below 3072 dimensions is not normalised, so dot product is not cosine until you divide by the norm; and never mix 001 and 2 vectors in one index. Third: Sentence Transformers truncates at max_seq_length with no warning, so the tail of a long claims chunk becomes unsearchable; count tokens at ingest and keep the truncated percentage at zero. Analogy: a scale that always reads a number, even when nothing is on it, so you must check it with a known weight. Likely question: "Why not simply trust the library defaults?" Because each default here is correct for one model and wrong for the next, and three asserts cost microseconds. Hand-off: the vectors are now correct; the next slide checks the index settings that store and search them.
