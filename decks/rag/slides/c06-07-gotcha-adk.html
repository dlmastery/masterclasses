Gotcha google-adk 2.13.0 · Workflow state and models

ADK fails on missing state keys, and its default model is unlisted

SymptomKeyError: Context variable not found: `evidence` in agent 'answerer'. CauseA route reaches the agent before the state key exists (_instructions_utils.py). FixWrite the key earlier, or make it optional: {evidence?}, as {feedback?} in the workflows/loop sample.
SymptomWorkflowDataError: Missing value for parameter "draft" of function "gate". It was not found in state and has no default value. CauseFunction-node parameters bind from state by name. The answerer has no output_key="draft", or the name is misspelled. FixMatch output_key to the parameter name, or give the parameter a default.
SymptomAn agent with no model= calls an ID the models page does not list. google_search + a function tool in one agent: HTTP 400 INVALID_ARGUMENT. CauseLlmAgent.DEFAULT_MODEL = 'gemini-3.5-flash' (llm_agent.py L289). The page lists 3.5 Flash-Lite and 3.8 Flash. 2.0 Flash is shut down. FixAlways pass model= from config. Use GoogleSearchAgentTool or a single_turn sub-agent for search.
lab5_helpdesk.py + lab5_it_triage.py · the three fixes
import os
from google.adk import Agent, Event
from google.adk.tools.google_search_agent_tool import (
    GoogleSearchAgentTool, create_google_search_agent)
# Verdict, retrieve_hr, verifier and the edges: unchanged from steps 1-3 and the build

MODEL = os.getenv("MODEL", "gemini-3.8-flash")     # not DEFAULT_MODEL 'gemini-3.5-flash'
web_search = GoogleSearchAgentTool(create_google_search_agent(MODEL))   # search alone

answerer = Agent(name="answerer", model=MODEL, output_key="draft",   # matches gate(draft)
                 instruction="Answer: {question}\nUse ONLY this evidence and "
                             "cite ids like [PTO-2026]:\n{evidence?}")

def gate(node_input: Verdict, draft: str = ""):    # default: no WorkflowDataError
    if node_input.supported and draft:
        yield Event(message=f"VERIFIED: {draft}")
    else:
        yield Event(message="Opened HR ticket; could not verify: "
                            f"{node_input.unsupported_claims}")

{evidence?} renders empty when a route skips retrieve_hr.

output_key equals the parameter name, and the default stops the crash.

Set model= from config. Keep google_search in its own agent.

Three errors that every team hits in the first hour with ADK 2.13 workflows. First, an agent instruction like {evidence} is a hard dependency on session state: if a route reaches the answerer before retrieve_hr has written the key, ADK raises "Context variable not found"; write the key earlier, or add a question mark, the same syntax the workflows/loop sample uses for {feedback?}. Second, function-node parameters bind from state by name, so gate(draft) needs an upstream output_key="draft"; a typo gives WorkflowDataError, and a default value keeps the gate safe because it still refuses an empty draft. Third, ADK 2.13.0 ships DEFAULT_MODEL 'gemini-3.5-flash', an ID the Gemini models page does not list, so always pass model from config, and never put google_search next to a function tool in one agent, which gives HTTP 400. Analogy: state keys are function arguments that the type checker cannot see, so you test the routes, not only the happy path. Likely question: "Why not make every placeholder optional?" Because then a missing evidence key silently produces an answer with no evidence; use the question mark only on routes where an empty value is correct, and keep the verifier gate.
