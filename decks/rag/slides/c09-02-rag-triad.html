Score retrieval, grounding and answer relevance separately: the RAG triad

TruLens RAG triad: one metric per edge

Groundedness splits the answer into claims and looks for evidence for each claim. TruLens 2.16.0 traces on OpenTelemetry.

Docs TruLens, RAG Triad

Retrieval metrics need relevance labels

  • Recall@k: relevant chunks in the top-k. Main RAG metric.
  • Precision@k: relevant chunks in the top-k, divided by k.
  • MRR: mean of 1/rank of the first relevant hit.
  • nDCG@10: graded and rank-discounted. MTEB/BEIR headline.
  • Hit rate / Match@k: any relevant chunk in the top-k.

Faithfulness = supported claims / all claims. Here 3 of 4 claims have evidence: 0.75.

Context Precision@K is rank-aware: swap a relevant and an irrelevant chunk and ContextUtilization drops from ≈1.0 to ≈0.5. No LLM: IDBasedContextPrecision (2/4 = 0.5). Cheap judge: FaithfulnesswithHHEM (HHEM-2.1-Open, CPU).

faithfulness.py · ragas 0.4.3 collections API

from openai import AsyncOpenAI
from ragas.llms import llm_factory
from ragas.metrics.collections import Faithfulness

llm = llm_factory("gpt-4o-mini", client=AsyncOpenAI())
faith = Faithfulness(llm=llm)
result = await faith.ascore(
    user_input="When was the first super bowl?",
    response="The first superbowl was held on Jan 15, 1967",
    retrieved_contexts=[
        "The First AFL–NFL World Championship Game was an "
        "American football game played on January 15, 1967, "
        "at the LA Memorial Coliseum."])
print(result.value)          # 1.0

Build the triangle edge by edge. Step 1: context relevance compares the query with the retrieved chunks. Step 2: groundedness compares the answer with the chunks. Step 3: answer relevance compares the answer with the query. Step 4: the answer splits into four claims. Three find evidence and stick; "sold out" finds none and bounces, so faithfulness is 3/4 = 0.75. Steps 5 and 6 walk through the RAGAS collections API: make the judge LLM, make the metric, call ascore. Analogy: a fact-checker who highlights each sentence of an article and looks for a source for it. Likely question: "Why not one overall score?" Because a low score must tell you which component to fix: the retriever or the prompt and model.
