Design RAG for 50M documents, p95 under 1 second, with per-user ACLs.
Run hybrid BM25 + ANN (HNSW or DiskANN; MRL 768 dims + int8). Apply the ACL pre-filter inside both queries with the end user's identity. Fuse with RRF. Rerank the top-100 with a small, fast reranker. Cache the static prompt prefix. Stream the output. Give each span a latency budget and trace it.
Build your own pipeline, or use File Search / RAG Engine?
Use managed for speed, citations and low ops. Build DIY when you need custom chunking, hybrid weights, rerankers, ACL logic or a non-Google stack. Measure both on the same golden set before you decide.
How do you migrate to a new embedding model with zero downtime?
Blue/green. Build the new index in parallel. Compare both indexes on the golden set. Switch reads when the new index wins. Keep the old index for rollback. Never mix vectors from two models in one index.
What are the risks of a semantic cache?
Cross-user leakage: partition by user or tenant. False hits: tune the threshold; at 0.5 a "Nice" question hit the "Paris" answer (RedisVL docs). Stale answers: set a TTL and invalidate entries by doc_id when a document changes.
Ask the students to answer each question aloud before you reveal the model answer. Q1 is a classic system-design question. A strong answer names the budget per span, puts the ACL filter inside the ANN and BM25 queries (not after generation), and keeps the reranker small because it runs on every query. Q2 tests judgment, not loyalty to a vendor: the right answer is "measure both on the same golden set". Q3 tests whether the candidate knows that vectors from two models live in different spaces. Analogy: you cannot compare a GPS coordinate with a street address; you must re-encode everything. Q4 has three distinct risks; a strong candidate names all three and a fix for each. Likely follow-up: "How do you pick the threshold?" Use a labelled set of paraphrase and non-paraphrase pairs and an optimizer such as RedisVL CacheThresholdOptimizer.
