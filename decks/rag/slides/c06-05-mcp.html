MCP spec 2026-07-28 (prior revision 2025-11-25)

  • Stateless: no initialize handshake; version and capabilities ride in _meta.
  • Servers MUST implement server/discover.
  • No Mcp-Session-Id in Streamable HTTP.
  • subscriptions/listen replaces the GET stream.
  • Multi Round-Trip Requests replace server-side sampling and elicitation.
  • tools/list carries ttlMs and cacheScope, in a fixed order. Roots, Sampling, Logging: deprecated.
kb_agent.py · ADK McpToolset

from google.adk.agents import LlmAgent
from google.adk.tools.mcp_tool import McpToolset
from google.adk.tools.mcp_tool.mcp_session_manager import (
    StreamableHTTPConnectionParams)

kb = McpToolset(
    connection_params=StreamableHTTPConnectionParams(
        url="https://kb.example.com/mcp", timeout=5),
    tool_filter=["search", "fetch"],  # retrieval surface only
)
root_agent = LlmAgent(model="gemini-flash-latest",
    name="kb_agent", tools=[kb],
    instruction="Search the KB. Cite the fetched docs.")
A retrieval server is now a stateless, cacheable HTTP service. A search cursor travels as an explicit handle in the tool arguments.

MCP turns a corpus into a tool server. ADK, LangGraph, Claude, ChatGPT and Gemini Deep Research all call the same search and fetch tools, so you write no glue per framework. OpenAI deep research accepts an mcp tool only if the server implements search and fetch and require_approval is "never"; that makes search plus fetch a de facto retrieval contract. The 2026-07-28 spec removes the initialize handshake and the session id, so each request stands alone, and tools/list is cacheable and comes in a fixed order, which helps prompt caching. Analogy: a USB-C port for knowledge; any laptop plugs into any drive. In ADK, use tool_filter to expose only search and fetch, not every tool on the server. Likely question: "Is MCP output safe to put in the prompt?" No. Tool output is untrusted input; chapter 9 covers indirect prompt injection.
