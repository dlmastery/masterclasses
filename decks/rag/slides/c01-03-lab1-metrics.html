# evalkit.py -- retrieval metrics on a labelled set (no dependencies)
import math
from kb import QUERIES

def recall_at_k(ranked: list[str], gold: set[str], k: int) -> float:
    return len(set(ranked[:k]) & gold) / len(gold)

def hit_at_k(ranked: list[str], gold: set[str], k: int) -> float:
    return 1.0 if set(ranked[:k]) & gold else 0.0

def mrr(ranked: list[str], gold: set[str], k: int = 10) -> float:
    for rank, doc_id in enumerate(ranked[:k], start=1):
        if doc_id in gold:
            return 1.0 / rank
    return 0.0

def ndcg_at_k(ranked: list[str], gold: set[str], k: int) -> float:
    dcg = sum(1.0 / math.log2(r + 1) for r, d in enumerate(ranked[:k], start=1) if d in gold)
    ideal = sum(1.0 / math.log2(r + 1) for r in range(1, min(len(gold), k) + 1))
    return dcg / ideal

recall@k = share of the gold chunks in the top k. hit@k = at least one.
MRR = 1 / rank of the first gold chunk: how far the LLM reads down.
nDCG = discounted gains ÷ the ideal order with min(len(gold), k) slots.

Anthropic's "1 − failure rate@20" is hit@20, not recall@20. Post Anthropic: Introducing Contextual Retrieval
These four functions are the whole metric layer of evalkit.py, and every later lab calls them through the same harness. Walk one query in the REPL: q11 asks about the loyalty return window and the refund date, so it has two gold chunks, c04 and c02, and our example retriever ranks c04, c09, c02. Recall at 1 is 0.5 because we found one of the two gold chunks; hit at 1 is 1 because at least one appeared, and that hit number is what Anthropic reports as one minus the failure rate at 20, so never compare it with someone else's recall. MRR is 1 because the first gold chunk sits at rank 1, and nDCG at 3 is 1.5 divided by the ideal 1.631, which gives 0.920. Analogy: recall asks "did you bring all the ingredients", MRR asks "how deep in the bag was the first one". A likely question is "which metric should I report?": report recall at k for the k your prompt uses, plus MRR, and always say which one you mean.
