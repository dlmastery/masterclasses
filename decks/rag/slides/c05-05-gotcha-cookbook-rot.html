Cookbook Enhancing RAG with Contextual Retrieval Docs Prompt caching
The Contextual Retrieval cookbook is the right recipe, but its notebook cell rots on the current SDK, so engineers who paste it lose an afternoon. First, anthropic 2.3.0 has no temperature parameter, and API version 2026-10-21 rejects temperature, top_p and top_k with a 400 on every model; effort is the control that remains, and low is enough for a one-line chunk context. Second, Haiku 5.5 thinks by default, so content[0] can be a thinking block: always pick the first block whose type is text. Third, prompt caching fails silently: below 512 tokens on Haiku 5.5, or 4,096 on the cookbook's Haiku 4.5, or when chunks of one document are more than five minutes apart, you just pay full price, so log an alert when a real document never writes or reads the cache. Analogy: a recipe that still says "gas mark 4" in a kitchen with an induction hob. Likely question: "Why not pin the old SDK?" You can for a week, but the old API version is the one that goes away, so fix the call. Next: Build 3, the third fix, returns the whole policy parent.
