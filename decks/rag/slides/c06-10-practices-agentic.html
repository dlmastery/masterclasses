Best practices

Agentic RAG rules: budgets in code, isolated verifiers, empty results

Do

  • Keep the attempt budget in state plus a route. Prompts do not stop loops.
  • Let retrieval return "(no results)". Else the grader never sees failure.
  • Verify with another agent and model on {evidence} + {draft} only.
  • Set model ids from config; pin google-adk==2.13.0. DEFAULT_MODEL is unlisted.
  • KB first, web second, web in GoogleSearchAgentTool. Switch off per tenant.
  • Add abstain and related-mismatch routes. Top-1 50.48% → 79.05% (2610.22652).
  • Log route usage and harm rate. 2607.24010
  • Add loops only where routes earn latency. ~90 s vs ~8-9 s (2610.14428).

Don't

  • Mix google_search with File Search or RAG Engine in one request. HTTP 400.
  • Let the generator decide when to stop. 2609.16453

# helpdesk_config.py -- one reviewed place for every budget and model id
import os

MODEL = os.getenv("MODEL", "gemini-3.8-flash")
VERIFIER_MODEL = os.getenv("VERIFIER_MODEL", "gemini-4-argon")  # != MODEL
MAX_ATTEMPTS = int(os.getenv("MAX_ATTEMPTS", "3"))   # then abstain
RETRIEVE_MIN_OVERLAP = 2  # below this, retrieve_hr returns "(no results)"
WEB_FALLBACK_TENANTS = {"northwind-it"}  # may use the web sub-agent
ROUTES = ("hr_policy", "it_support", "out_of_scope")

def log_route(route: str, counts: dict[str, int]) -> None:
    assert route in ROUTES, route
    counts[route] = counts.get(route, 0) + 1  # realized usage, weekly review
This slide turns Lab 5 into rules you can check in a code review, and every rule lands as a badge on the helpdesk graph. Step 1: the attempt budget and the "(no results)" floor live in code, because a model can ignore a limit that exists only in its prompt, and a retriever that always returns something never lets the grader say "nothing found". Step 2: the verifier is a separate agent on a separate model that sees only evidence and draft, and every model id comes from config, because ADK 2.13.0's default model is not on the Gemini models page. Steps 3 and 4: web search sits behind its own sub-agent that you can switch off per tenant, there are explicit escape routes, and you log how often each route fires, because the July paper shows router rankings change with the traffic mix. Analogy: the config file is the cockpit checklist; the pilot does not decide fuel limits mid-flight. Likely question: "Why not just use a skills agent like Airbnb?" You can, when the work tolerates it: their agent matched human procedure 99.2% of the time, but each case took about 90 seconds against 8 to 9 for the fixed pipeline.
