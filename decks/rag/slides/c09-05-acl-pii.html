Filter by the end user's permissions inside the query, before ranking, and redact PII at ingestion

Embeddings drop the source document's ACL. Top-k returns what is similar, not what this user may see. The retriever becomes a confused deputy.

Docs OWASP LLM08: “permission-aware vector stores”
  1. Index time: copy the source ACL onto every chunk as metadata. Use group ids. Deny overrides grant.
  2. Query time: pass the end user's identity, not a service account. Filter inside the vector and BM25 queries, before ranking and fusion.
  3. Re-sync chunk ACLs when permissions change.
  4. Partition semantic caches and memories the same way.
Post-filtering can return fewer than k results and leaks through counts. Never let an LLM write tenant or ACL filters.

PII: redact or pseudonymize at ingest, before embedding, because embeddings can be inverted (OWASP LLM08). Redact again at output. Right-to-erasure deletes must reach vector stores, caches and traces.

Products: OpenSearch and Elasticsearch document-level security. Glean and Microsoft 365 Copilot advertise permission-trimmed retrieval. Red-team: user A asks for user B's data; PII probes; poisoning canaries.

Docs Presidio, Getting started (text)
Two users send the same query. Step 1: without a filter, both lists contain "HR salaries", so user B from sales sees a document he may not open. Step 2: the permission filter moves inside the retriever query. B's restricted chunk is removed before ranking, and the list still has k = 4 results; a post-filter would show only 3 and leak through the count. Step 3: the same leak through a semantic cache: B's similar question hits A's cached answer, until the cache is partitioned by user. Steps 4 and 5: the filter in code, then Presidio removes PII before embedding. Analogy: a library that shows every book title in the catalogue but keeps the restricted shelf locked; the catalogue must be filtered too. Likely question: "Can the LLM decide which filter to apply?" No. Identity and ACL filters come from the authenticated session, never from model output.
