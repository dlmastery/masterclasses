Gotcha langgraph 1.2.17

LangGraph now allows 10,007 steps: set recursion_limit and a counter

lab6/lab6_guards.py · langchain 1.4.7 · langgraph 1.2.17
from typing import Literal
from langgraph.graph import StateGraph, START, END
from langchain.chat_models import init_chat_model          # langchain==1.4.7 (Lab 6 pins)
# importing Lab 6 builds its 6-passage store; hop() and answer() keep Lab 6's llm
from lab6_multihop_register import Plan, State, hop, answer
# without the "google_genai:" prefix, a gemini-* name infers google_vertexai
llm = init_chat_model("google_genai:gemini-3.8-flash")      # used by plan() below
def plan(s: State):
    p = llm.with_structured_output(Plan).invoke(
        f"Decompose into single-fact sub-questions: {s['question']}")
    subqs = p.subquestions or [s["question"]]                # avoids StopIteration in hop()
    return {"register": [{"q": q, "a": None, "src": None, "tries": 0} for q in subqs], "hops": 0}
def next_step(s: State) -> Literal["hop", "answer"]:
    still_open = any(r["a"] is None for r in s["register"])
    under_cap = s.get("hops", 0) < 2 * len(s["register"])       # optional key: use .get
    return "hop" if still_open and under_cap else "answer"
g = StateGraph(State); g.add_node(plan); g.add_node(hop); g.add_node(answer)
g.add_edge(START, "plan"); g.add_edge("plan", "hop")
g.add_conditional_edges("hop", next_step, ["hop", "answer"]); g.add_edge("answer", END)
app = g.compile()
q = ("Who must approve a return of the jacket made by the supplier "
     "that failed the March 2026 audit?")
out = app.invoke({"question": q}, {"recursion_limit": 20})       # default is now 10007

In langgraph 1.2.17 the default recursion limit is 10007, read from LANGGRAPH_DEFAULT_RECURSION_LIMIT in _internal/_config.py, not 25. So Lab 6's hop loop without its counter does not fail fast when a row never resolves: it can burn thousands of LLM calls first. With a limit you get an error such as "langgraph.errors.GraphRecursionError: Recursion limit of 20 reached without hitting a stop condition. You can increase the limit by setting the recursion_limit config key." Treat the hops counter as the real guard and the recursion limit as the safety net: the cap is 2 times the register length, and recursion_limit 20 sits above the worst case of 10 steps. The chart in panel 1 is on a log scale; 25 and 10,007 are about 400 times apart. The second trap is init_chat_model with a bare Gemini name: it infers google_vertexai and warns "Inferred model_provider='google_vertexai' from ... This default will change to 'google_genai' in the next major release." Pass the google_genai prefix, or use ChatGoogleGenerativeAI as Lab 6 does. The guard file needs langchain 1.4.7, which the Lab 6 install line already pins; the new llm applies to plan() only, because hop() and answer() keep Lab 6's ChatGoogleGenerativeAI, which already talks to the Gemini API. Importing the Lab 6 module also builds its store, which costs six embedding calls. The third trap is an empty plan: next() finds no open row and raises StopIteration; and TypedDict with total=False never fills missing keys, so s["hops"] raises KeyError: 'hops' if a node reads it before plan() wrote it. Fall back to the question and read optional keys with get. Analogy: a fuse in the wall is the safety net, but you still switch off the heater when the room is warm.
