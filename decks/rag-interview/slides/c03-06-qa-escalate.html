Interview · escalation and abstention

Escalate to long context only when the answer is uncertain

When do you escalate from RAG to the full long context?
Only on high answer entropy: 97.4% of long-context accuracy with 70.7% fewer tokens.
In a multi-turn chat, which query do you retrieve with?
One standalone query that merges every turn's constraints. Sharded turns lose up to 21%.
gated_search() returns “insufficient”. What does the caller do?
Abstain or ask. Generators answer 40–99% of such questions, even when told to abstain.
respond.py · the caller of gated_search()
from gated_search import gated_search           # previous slide
ENT_MAX = 0.5                                   # placeholder: fit on the labelled set
# llm: your Gemini wrapper with standalone(), read(), read_long(), log_miss()
def respond(turns: list[str], llm) -> str:
    q = llm.standalone(turns)                   # merge every turn's constraints
    ids, status = gated_search(q)
    if status == "insufficient":
        llm.log_miss(q)                         # grow the labelled set
        return "I can't find that. Which order or error code?"
    answer, entropy = llm.read(q, ids)          # 8 chunks + answer entropy
    if entropy < ENT_MAX:
        return answer                           # most queries stop here
    return llm.read_long(q)                     # escalate: full documents

This slide is the expensive end of the router from the previous slide. Q1: long context is the costly branch, so gate it on uncertainty. The EDAR paper routes on answer entropy and kept 97.4% of long-context accuracy with 70.7% fewer tokens; it ships no code, so present it as a pattern, and fit ENT_MAX on your labelled set. Q2: in multi-turn chat, users spread constraints across turns ("zipper broke", "the 40L pack", "bought 3 years ago"). Retrieving with the last turn alone misses the warranty chunk; the paper measured up to a 21% relative drop for sharded queries, so merge the turns into one standalone query first. Q3: RINSE found that even when told to abstain, generators answered 40.0-99.3% of insufficient-evidence questions, so the caller must branch before the reader: abstain with a clear message or ask a clarifying question, and log the query so it joins the labelled set. Analogy: a pilot who cannot see the runway goes around; landing anyway is the failure. Likely follow-up: "Is abstaining bad for the user?" Track the abstain rate next to accuracy; a rising rate is a content gap to fix, not a model bug. Next: put normalise, hybrid, rerank and the gate together on one whiteboard.
