Choose RAG for facts, tuning for behaviour, and check recall first

When do you choose RAG over fine-tuning or one long prompt?
Facts → RAG. Behaviour → fine-tune. A small, static, one-ACL corpus fits one cached prompt. Only RAG filters per user at query time.
Your RAG bot gives wrong answers. What do you check first?
Recall@k on a golden set. No gold chunk in the top-k: no fix downstream. Then split retrieval failures from reasoning failures.
Can an agent with grep and file tools replace the index?
Not at scale. BM25 overtakes a file-system agent above ~10M corpus tokens. Rank first, then let the agent reason.

def recall_at_k(ranked, gold, k):   # share of gold ids in top k
    return len(set(ranked[:k]) & gold) / len(gold)

def hit_at_k(ranked, gold, k):      # 1.0 if any gold id in top k
    return float(bool(set(ranked[:k]) & gold))

Read each question aloud and give the room ten seconds before you reveal the answer. Pause after each reveal. Q1 is the most common screening question. Test the cascade in order: a small, static corpus with one access-control list fits one cached prompt (Claude Haiku 5.5 caches prompts of 512 tokens or more); fresh, private or cited facts go to RAG, because only retrieval can filter by user permissions at query time; behaviour, format and style go to fine-tuning. Analogy: fine-tuning teaches the doctor how to talk; retrieval hands the doctor today's lab results. Q2 tests whether the candidate measures retrieval before touching the prompt. Recall@k is the share of gold chunks in the top k; hit@k only asks whether at least one gold chunk is there, and arXiv 2610.26951 shows that retrieval finds any relevant chunk far more reliably than all of them. arXiv 2609.33778 covers the other half: the evidence is retrieved, but the reasoning goes wrong. Q3 is the 2026 question: agents do not remove the index, they reason over its ranked output. Likely follow-up: "How big must the golden set be?" Start with real user questions, label every chunk that holds the answer, version the set, and grow it until a change of one query does not move the metric. Hand-off: the next drill asks why the gold chunk was missing in the first place, which is usually chunking.
