Interview · query rewriting and sufficiency

Gate before you rewrite: a cheap score signal picks the weak queries

Should every Northwind query get an LLM rewrite or HyDE (embed an LLM-written fake answer)?
No. A score gate rewrites under 40% of queries. HyDE adds 57.5 invented terms per query.
How do you know the evidence is sufficient before you generate?
Read the reranker's score shape (QPP). It flags weak evidence at AUROC 0.856 in 2 ms.
How do you set GATE and SPREAD?
Sweep both on the labelled queries. Keep the lowest rewrite rate that holds R@5.
weak() · the score-shape signal, no LLM call
GATE, SPREAD = 0.55, 0.02     # placeholders: fit on labels
def weak(r) -> bool:          # r: [(chunk_id, score)], best first
    if len(r) < 2:
        return True
    top1, top5 = r[0][1], r[min(4, len(r) - 1)][1]
    return top1 < GATE or top1 - top5 < SPREAD   # low or flat

import torch
from sentence_transformers import CrossEncoder
from kb import TEXT
from lab3_hybrid import hybrid_search, rrf
from lab7_query_transform import rewrite          # Gemini 3.8 Flash, cached
ce = CrossEncoder("cross-encoder/ettin-reranker-32m-v1", activation_fn=torch.nn.Sigmoid())
def rerank(q: str, ids: list[str]) -> list[tuple[str, float]]:
    hits = ce.rank(q, [TEXT[i] for i in ids], top_k=8)
    return [(ids[h["corpus_id"]], h["score"]) for h in hits]   # 0..1 scores
def gated_search(q: str) -> tuple[list[str], str]:
    r = rerank(q, hybrid_search(q, depth=75)[:30])
    if not weak(r):                                # weak(): left panel
        return [i for i, _ in r], "direct"         # most queries stop here
    qs = [q] + rewrite(q).paraphrases              # keep the original query
    lists = [hybrid_search(x, depth=75) for x in qs]
    r = rerank(q, rrf(lists, k=60, weights=[2.0] + [1.0] * (len(qs) - 1))[:30])
    return [i for i, _ in r], ("insufficient" if weak(r) else "rewritten")

The theme of this slide is adaptive compute: run the cheap path first and spend an LLM call only on a signal. Q1: HyDE means the LLM writes a hypothetical answer and you embed that. A strong candidate says one rewriter is at best on par with a strong hybrid plus reranker baseline; a union of rewriters gave +12.5 HIT@10 (51.70 vs 39.22), and a score-gated router rewrote fewer than 40% of queries. HyDE also injects about 57.5 unsupported terms per query (SAFE-QE paper). Industry agrees: Snap gates its LLM query path to about 10% of users, for about 90% lower LLM cost and +27.6% conversion in a two-week A/B (arXiv 2607.23121). Q2: QPP means query performance prediction; here it reads the shape of the reranker scores, which is free. AUROC 0.856 means that for a random sufficient and a random insufficient query, the signal ranks the sufficient one higher 86% of the time; a local LLM judge got 0.649. Q3: GATE and SPREAD are placeholders; sweep them on the labelled queries and log the rewrite rate. The dot diagram is illustrative: 3 of 10 queries go to the rewrite path. Analogy: a hospital triage desk sends only the unclear cases to the specialist. Likely follow-up: "Why keep the original query in the fusion?"
