Prompt
Design the vector layer for a B2B SaaS: 10,000 tenants (a few huge, most tiny), per-user permissions, and an embedding-model upgrade next quarter.
  1. Identity: groups claim from the OIDC token. Store groups, not users.
  2. Isolation: big tenants get a partition; small tenants share the default.
  3. ACL: filter inside the search, in the vector and BM25 legs.Recall loss = stale index + filters that cut graph paths.
  4. Versioning: dual-read = query v1 and v2, serve v1, compare recall.
  5. CI: leak test per user × golden query; rowcount == LIMIT.
Red flags: service-account identity; a post-filter after ranking; one index for every tenant.

Read the prompt aloud and ask for the identity source before the candidate draws any index. Step 1: the groups claim comes from the authenticated token, never from the prompt. Store group ids on the chunks, so a membership change touches the identity provider and no vector is re-indexed. Step 2: the pgvector README recommends PARTITION BY LIST (tenant_id) for multi-tenancy. Huge tenants get their own partition; small tenants share the DEFAULT partition. A tenant whose recall@10 falls below its target (its SLO, service-level objective) moves to its own partition. Step 3: the ACL filter runs inside the search on every store, and in both legs of a hybrid search (BM25 keywords plus vectors) before fusion. The paper 2610.15130 splits the recall loss into staleness (new rows and ACL changes not yet merged into the index) and filtered navigability (a strict filter cuts the graph paths, so the walk cannot reach the matching rows; the 4-of-10 result on the filter slide). Step 4: dual-read sends each query to v1 and v2, serves v1, and logs v2 recall on the golden set; flip when v2 is equal or better. Notion's p50 fell from 70–100 ms to 50–70 ms with 60% lower search spend after its move to turbopuffer, with the embedder upgrade in the same migration. Step 5: the leak test runs in CI against every store and asserts that no row from another tenant or group comes back. Likely follow-up: "What happens when a user leaves a group?" The identity provider changes one membership; no vector is re-indexed.
