Ask each question, let the candidate answer, then reveal the model answer. Q1 has three distinct risks, and a strong candidate gives a fix for each. Cross-tenant leak: partition entries by tenant and filter on it. False hit: tune distance_threshold, a cosine distance from 0 to 2 where lower is stricter; the lab uses 0.08, stricter than the RedisVL default 0.1, picked on labelled paraphrase and non-paraphrase pairs (RedisVL ships CacheThresholdOptimizer). Stale answer: set a TTL and invalidate by doc_id when a document changes. policy_version is the version of the ACL and fee policy, so a permission change makes old entries unreachable. Q2 tests judgment, not vendor loyalty: File Search costs $0.15 per 1M tokens to index, storage and query embeddings are free, files are capped at 100 MB, and a store should stay under 20 GB. It cannot share a request with other built-in grounding tools such as Google Search or URL Context, but on Gemini 3 and later it can sit next to your own function tools. Citations come back as file_citation annotations; in google-genai 2.33.0 the start_index is in bytes, so insert citation marks from right to left. Close with "measure both on the same golden set". Q3: deterministic recall@5 first, canary abstention with zero tolerance, faithfulness with a NaN-rate check, then a paired bootstrap against the baseline. BLOCK means a hard check failed; REJECT means the paired test shows a regression; INCONCLUSIVE means there is not enough evidence, so collect more rows. A beta-binomial gate treats the pass rate as uncertain and needs enough samples; in AGO it still let 22.2 to 35.1% of unsafe changes through, against 29.3 to 41.8% for a naive gate, so the gate reduces risk but does not remove it. Analogy: an eval gate is airport security with a separate lane for bags that need a second look. Next: put the cache, the ACL pre-filter and the eval gate into one 50M-document design.
