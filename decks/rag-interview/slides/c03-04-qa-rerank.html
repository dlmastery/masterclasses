Rerankers reorder candidates; they cannot find what you missed

Northwind reranks all 150 hybrid candidates and keeps 8. What does it cost, and how do you cut it?
One forward pass per pair. Cap 150 → 30 pairs: 5× less compute.
Reranking raised Hit@10 a lot, but answers barely improved. Why?
It only reorders. Hit@10 +14 pts, answers only +3.8. Measure answers per stage.
A new ranker wins pairwise preference. Ship it?
Not yet. Its MRR fell 0.576 → 0.306. Gate on MRR and cost.

Hit@k any gold chunk in the top k · R@k share of gold chunks in the top k · MRR 1 / rank of the first gold chunk

from sentence_transformers import CrossEncoder
from kb import TEXT                        # chunk_id -> text
from evalkit import evaluate               # prints R@1/3/5, MRR@10, nDCG@5
from lab3_hybrid import hybrid_search
ce = CrossEncoder("cross-encoder/ettin-reranker-32m-v1")   # replaces MiniLM
def rerank_search(query: str, candidates: int = 30, keep: int = 8) -> list[str]:
    cand_ids = hybrid_search(query, depth=75)[:candidates]   # 30 pairs, not 150
    hits = ce.rank(query, [TEXT[i] for i in cand_ids], top_k=keep, batch_size=32)
    return [cand_ids[h["corpus_id"]] for h in hits]
evaluate("hybrid + Ettin-32M", rerank_search)  # ship on MRR@10 + answer accuracy + p95 ms
Q1 tests whether the candidate counts forward passes: one cross-encoder pass per query-chunk pair. On an H100 in bf16, Ettin-17M scores 7,517 pairs per second and Ettin-1B 928, so 150 pairs cost about 20 ms and 162 ms of compute; on a CPU, 267 and 2.1 pairs per second, so about 0.56 s and 71 s. Capping at 30 pairs cuts all of these by 5×. The code ships Ettin-32M, which Hugging Face recommends with 17M as the MiniLM replacement (NanoBEIR 0.6825 vs MiniLM-L12 0.6369); its speed sits between the two measured sizes, so time it on your own GPU. Two more cost levers: score short child chunks (small chunks that link to a parent section), not whole documents, and spend extra reranking only near the top-k cut-off (BoundaryMORPH, arXiv 2609.27213). Managed options: Google's ranking API runs under 100 ms; an LLM reranker takes 1-2 s. Q2 is the stage-attribution trap: on clinical notes, reranking lifted Hit@10 from 46.6% to 60.6% but answer correctness only from 44.8% to 48.6%; the paper reports Hit@10, while for Northwind you measure R@5 and the reader's real window of 8. Q3: on NevIR, a negation test set, one ranker raised pairwise preference (picking the right one of two documents) from 52.30% to 56.62% while MRR fell from 0.5764 to 0.3055. Zero-shot LLM rerankers also tie: Glean's Jev gave identical scores to about 37 of 41 candidates. Analogy: a reranker is a sorting table, not a bigger net. Likely follow-up: "Your Ettin reranker drops MRR on negation queries. What now?" Add a negation slice to the labelled set and gate the release on it.
