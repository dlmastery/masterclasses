Interview · hybrid search

Hybrid search: fuse ranks, pin the defaults, watch the fusion tax

Why RRF instead of averaging Northwind's BM25 and cosine scores?
The scales differ. RRF uses ranks only: Σ 1/(k + rank), k = 60. Then tune one weight on labels.
Can hybrid search be worse than dense alone?
Yes, on 8–21% of queries. Print the per-query “got worse” list, not only the mean.
You moved hybrid into Qdrant and BM25 into bm25s. Quality changed. What do you check?
Silent defaults. Qdrant's k is 2: pin k = 61 (= paper 60). bm25s drops the “E” in E-4012: normalise codes.

pin_defaults.py · qdrant-client==1.20.0 · bm25s==0.3.15
import re
import bm25s
from qdrant_client import QdrantClient, models
from kb import IDS, TEXT
CODE = re.compile(r"\b([A-Z]{1,4})-(\d{2,6})\b", re.I)  # extend to your code grammar
def normalise(text: str) -> str:                       # at index AND query time
    return CODE.sub(r"\1\2", text)                     # E-4012 -> E4012
corpus_tokens = bm25s.tokenize([normalise(TEXT[i]) for i in IDS], stopwords="en")
client = QdrantClient(url="http://localhost:6333")
def qdrant_hybrid(q: str, q_vec: list[float]) -> list[str]:
    res = client.query_points(
        collection_name="northwind_kb",                # built in lab4_qdrant.py
        prefetch=[models.Prefetch(query=models.TextQuery(text=normalise(q)),
                                  using="text", limit=75),
                  models.Prefetch(query=q_vec, using="dense", limit=75)],
        query=models.RrfQuery(rrf=models.Rrf(k=61)),  # 1/(rank+k-1): 61 == paper 60
        limit=30)
    return [p.payload["chunk_id"] for p in res.points]

Ask each question, wait 20 seconds, then reveal the answer. Q1: BM25 is unbounded and cosine is −1..1, so a strong answer fuses ranks with RRF, k = 60, and walks the c12 example: in both lists beats rank 2 in one list. With labels, tune one static weight w first (weighted RRF: w for BM25, 1 − w for dense, grid-searched on the labelled set); the Thomson Reuters study (arXiv 2610.24341) found optimal weights form intervals, and 74 of 128 per-query methods beat plain RRF, so a static weight is the cheap first step. Q2 is the counter-intuitive 2026 result: the Fusion Tax paper finds the best fusion still ranks relevant documents below dense-only on 8-21% of queries, and RRF wins only when the two retrievers are balanced; the histogram is a sketch, the range is the paper's. Q3 tests production habits: qdrant-client fusion.py sets DEFAULT_RANKING_CONSTANT_K = 2 and scores 1/(rank + k − 1), so k = 61 reproduces the paper's k = 60; bm25s's default pattern \b\w\w+\b drops the one-letter "E" in "E-4012", so normalise codes with one function at index and query time. Weaviate has the same class of trap: its hybrid alpha default depends on the client, so set it explicitly. Analogy: two judges score on different scales, so compare their rankings, not their points. Likely follow-up: "When would you drop hybrid?" When dense clearly leads on your labelled set and the hurt list is long. Next: a reranker that returns almost nothing.
