refund_graph.py · counter, feedback, fallback, safety net
# as before: imports, llm, store, retrieve(), q, g with linear edges
# State gains two keys: unsupported: list[str], tries: int
class Verdict(BaseModel): unsupported: list[str] = []
def generate(s):
    bad = s.get("unsupported") or []          # failures fed back
    p = f"Use ONLY:\n{s['context']}\nAvoid: {bad}\nQ: {s['question']}"
    n = s.get("tries", 0) + 1                  # tries counted here
    return {"answer": llm.invoke(p).text, "tries": n}
def verify(s):
    p = f"List unsupported sentences.\n{s['context']}\n{s['answer']}"
    v = llm.with_structured_output(Verdict).invoke(p)
    return {"unsupported": v.unsupported}
def after_verify(s):
    if not s["unsupported"]: return "publish"
    return "generate" if s["tries"] < 2 else "fallback"
g.add_node("publish", lambda s: {})       # no-op: answer is in state
g.add_node("fallback", lambda s: {"answer": "A specialist will reply."})
g.add_conditional_edges("verify", after_verify)
for n in ("publish", "fallback"): g.add_edge(n, END)
print(g.compile().invoke(q, {"recursion_limit": 25})["answer"])

Show the code and ask the room to find the bug before you advance. Click 1 runs it: the output streams, the step counter climbs, and the run dies at 10007 steps; each round is one generate call and one verify call, so about 5,000 rounds cost about 10,000 paid LLM calls. Finding 1: the verify to generate edge has no counter and no fallback. Finding 2: generate never sees which sentences failed, so it gets the same prompt, writes the same draft, and verify says NO forever. Finding 3: in LangGraph 1.2.17 the default recursion limit is 10007, not 25; source: langgraph/_internal/_config.py, getenv("LANGGRAPH_DEFAULT_RECURSION_LIMIT", "10007"). The fix puts a tries counter in state (it is counted in generate, so after two drafts tries is 2 and after_verify routes to fallback), sends the unsupported sentences back into the prompt, and passes recursion_limit 25 as the safety net. The publish node returns an empty dict on purpose: the answer is already in state. Analogy: the counter is the guard at the door, and the recursion limit is the fire alarm, so you need both. A likely follow-up: why not just set the limit? Because the limit raises an error with no answer, while the counter ends in a fallback the customer can use.
