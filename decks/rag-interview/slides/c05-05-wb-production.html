Prompt

Design enterprise RAG over 50M documents from Drive, Jira and email. p95 time-to-first-token under 1 s, per-user permissions, nightly updates, a weekly release cadence.

  1. One permission-aware index, not federation: Dropbox Dash measured federated agent queries at up to 45 s.
  2. Hybrid BM25 + ANN (HNSW or DiskANN); 768-dim int8 vectors, 4x smaller. ACL pre-filter in both.
  3. RRF (reciprocal rank fusion) of both ranks, then a small reranker: top 100 in, top 10 out.
  4. Tenant-partitioned cache: a hit returns at once. Cached prompt prefix.
  5. Ingest by content hash; embedding_version per vector; blue/green upgrades.
  6. Eval gate in CI blocks the deploy: recall@5, canaries, judge NaN rate.

Read the prompt aloud and let the candidate draw before you reveal each step. This is the classic system-design question: a strong answer builds one permission-aware index instead of federating live API calls, because Dropbox measured federated agent queries at up to 45 seconds (Dropbox tech blog, January 2026, on Dash). Listen for three things: a latency budget per span, the ACL filter inside both the BM25 and the ANN queries with the end user's identity, and a small reranker, because it runs on every query. MRL (Matryoshka) embeddings let you cut vectors to 768 dimensions, and int8 makes each vector 4x smaller than float32, so the 50M vectors fit in RAM. The waterfall is an example budget, not a measurement. Each bar is a target p95 for that span, and p95 values do not add up: the p95 of a sum is not the sum of the p95s, and tail latencies stack. So keep about 80 ms of headroom for network and queueing; that leaves roughly 640 ms for the model's first token. A cache hit skips the rest of the path and returns in about 30 ms. The eval gate sits in the release lane: it runs in CI before a deploy, not on a live request. The reference latencies use different percentiles and different stages, so do not compare them directly. Analogy: the budget is a train timetable, and every station gets a fixed number of minutes or the train is late. Likely follow-up: "How do you migrate the embedding model with zero downtime?" Build the new index blue/green, compare both on the golden set, switch reads in one step and keep the old index for rollback. Next: the eval gate in step 6 has a bug that hides a broken judge.
