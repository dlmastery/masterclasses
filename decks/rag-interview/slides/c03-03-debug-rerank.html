from sentence_transformers import CrossEncoder
from kb import TEXT                       # chunk_id -> text
from lab3_hybrid import hybrid_search     # query -> ranked chunk_ids
reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L6-v2", max_length=512)
def rerank_search(query: str, candidates: int = 30, keep: int = 5) -> list[str]:
    cand_ids = hybrid_search(query)[:candidates]
    hits = reranker.rank(query, [TEXT[i] for i in cand_ids], top_k=keep)
    return [h["corpus_id"] for h in hits if h["score"] > 0.5]
print(rerank_search("zipper broke on my pack after 3 years"))

Show the code and the output, and ask the room for two bugs on one line before you reveal anything. The first click is context only: rank() scores the 30 pairs and returns 5 dicts, best first. Bug one: corpus_id is the position in the list you passed, so the function returns 3 instead of "c09" and every string comparison in the evaluator fails. Bug two: ms-marco-MiniLM-L6-v2 stores an Identity activation in its config.json, so the scores are raw logits from about −11 to +11, and a 0.5 threshold throws away 4 of the 5 top-ranked hits. After the fix, the reranker moves c09 from position 3 in the hybrid list to rank 1, so MRR@10 rises from 0.770 to 0.860 while R@5 stays at 0.933: a reranker only reorders. Analogy: the reranker hands back seat numbers from your own guest list, not names, and it scores on a scale you did not choose. The same position-index trap exists in the Cohere and Voyage rerank APIs. A likely follow-up: "How do you set a no-answer cut-off?" Pass a sigmoid or use a calibrated model, tune the threshold on labelled data, and re-tune after every model upgrade.
