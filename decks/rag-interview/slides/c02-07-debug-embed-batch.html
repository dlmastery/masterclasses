import chromadb
from google import genai
from google.genai import types
client = genai.Client()                                # reads GEMINI_API_KEY
col = chromadb.PersistentClient(path="kb").get_or_create_collection(

    "TKT-1077": "Claim PDF upload fails: files over 20 MB are rejected.",
    "TKT-1103": "Refund not received: refunds post 5-7 business days after approval.",
    "TKT-1150": "Duplicate premium charge: void the second authorization.",
}

    model="gemini-embedding-2",
    contents=texts,
    config=types.EmbedContentConfig(output_dimensionality=768))
for tid, emb in zip(ids, resp.embeddings):
    col.upsert(ids=[tid], embeddings=[emb.values], documents=[TICKETS[tid]])

# index_tickets.py -- embed resolved Northwind tickets into Chroma
import chromadb
from google import genai
from google.genai import types
client = genai.Client()                                # reads GEMINI_API_KEY
col = chromadb.PersistentClient(path="kb").get_or_create_collection(
    "tickets", embedding_function=None)   # we pass Gemini vectors ourselves
TICKETS = {
    "TKT-1042": "Login loop after Okta SSO: clear the stale session cookie.",
    "TKT-1077": "Claim PDF upload fails: files over 20 MB are rejected.",
    "TKT-1103": "Refund not received: refunds post 5-7 business days after approval.",
    "TKT-1150": "Duplicate premium charge: void the second authorization.",
}
ids, texts = list(TICKETS), list(TICKETS.values())
resp = client.models.embed_content(                    # still one API call
    model="gemini-embedding-2",
    contents=[types.Content(parts=[types.Part.from_text(text=t)]) for t in texts],
    config=types.EmbedContentConfig(output_dimensionality=768))
assert len(resp.embeddings) == len(texts)
for tid, emb in zip(ids, resp.embeddings, strict=True):   # Python 3.10+
    col.upsert(ids=[tid], embeddings=[emb.values], documents=[TICKETS[tid]])
print("indexed", col.count())

Prompt. The script indexes 4 tickets and prints indexed 1. No exception. Find the bug.
Line 17: a list of strings in contents gives one aggregated vector.
Line 19: zip() stops at the shorter list. Three tickets drop.
SymptomOne vector comes back for four strings. zip() stops after the first pair, so 3 tickets drop with no error. Causegemini-embedding-2: a list of strings in contents gives one aggregated embedding (Gemini API docs). gemini-embedding-001 returns one vector per string. FixWrap each input in its own Content (still one call). Assert the count. Use zip(strict=True).
Issue llama_index #21658 Docs Gemini API: Embeddings
Show the code and the output, and ask the room why four tickets give one row with no error. The first clue is line 17: for gemini-embedding-2, the Gemini API docs say that a plain list of strings in contents produces one aggregated embedding for all inputs, so resp.embeddings has length 1. gemini-embedding-001 behaves differently: a list of strings gives one vector per string, so the same code works on 001 and breaks after the upgrade. The second clue is line 19: zip() stops at the shorter list, so TKT-1042 gets the merged vector and the other three tickets disappear silently. The fix wraps each text in its own types.Content (still one API call with four inputs), asserts that the vector count equals the input count, and uses zip(strict=True) on Python 3.10 or later. With strict=True the original bug becomes loud: ValueError: zip() argument 2 is shorter than argument 1. The collection has embedding_function=None, so every later query must pass query_embeddings from the same Gemini model. Analogy: you hand a clerk four letters and get back one envelope, and nobody counts the envelopes.
