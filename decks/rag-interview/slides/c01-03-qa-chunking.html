Sweep 2-3 sizes in embedder tokens on the golden set. Pick by recall@k. Cut at real headings.
Why can you afford Contextual Retrieval on every chunk, and how does it fail silently?
Prompt caching: the document is the cached prefix. Under 512 tokens on Haiku 5.5, nothing is cached and no error is returned.
A one-line edit re-embeds half the document. Why, and what is the fix?
Boundary drift: fixed-size chunks re-embed 57-68% per revision. Cut at headings. Key chunks by sha256.

Heading paths, not LLM context. Real heading paths beat LLM-contextualised fixed windows: +0.022 nDCG@10 (2610.10170).

Docling's chunker.contextualize() prepends this heading path. It makes no LLM call. nDCG@10 = ranking quality of the top 10, from 0 to 1.

Contextual Retrieval = an LLM writes 1-2 sentences of context for each chunk. The whole document is the cached prefix.

contextual.py · anthropic==2.3.0 · claude-haiku-5-5
def situate(client, doc: str, ask: str) -> str:   # client = anthropic.Anthropic()
    content = [{"type": "text", "text": doc,              # same for every chunk
                "cache_control": {"type": "ephemeral"}},   # cache breakpoint
               {"type": "text", "text": ask}]              # changes per chunk
    resp = client.messages.create(model="claude-haiku-5-5", max_tokens=300,
                                  messages=[{"role": "user", "content": content}])
    u = resp.usage                              # both stay 0 when doc < 512 tokens
    print(u.cache_creation_input_tokens, u.cache_read_input_tokens)
    return next(b.text for b in resp.content if b.type == "text")

Why the fix works: heading cuts follow structure, not offsets. Later chunks keep their text, so they keep their hash.

Content-defined chunking: a rolling hash of the text sets the cuts (43-54% re-embedded).

Ask each question and give the room ten seconds before you reveal the answer. The interviewer listens for three phrases: "measure on a golden set", "tokens, not characters" and "update cost". Q1: there is no universal size; sweep two or three sizes in the embedder's own tokens and pick by recall@k. Real heading paths are a cheap, deterministic win, and the placebo control in arXiv 2610.10170 shows that the gain comes from the heading text, not from extra tokens; the same paper found that two-stage section routing hurts. Also say that parser, chunker and embedder interact (arXiv 2609.31660), so test them together. Q2: separate the two ideas. Docling's contextualize() only prepends the heading path. Anthropic-style Contextual Retrieval makes one LLM call per chunk, and prompt caching makes it affordable: the document block carries cache_control, so chunks 2 to n read it from cache. The silent failure is the trap: a document under 512 tokens on Haiku 5.5 (4,096 on Haiku 4.5) is never cached, and both usage counters stay 0. Q3: analogy: fixed windows are like page breaks in a word processor, so one inserted line moves every later break, which is why 9 of 12 windows change on the strip. Likely follow-up: "How do you keep parent and child chunks in sync?" Re-chunk the document, delete its old children by document id, then upsert.
