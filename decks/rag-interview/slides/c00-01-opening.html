Click 0. This deck is a drill: read each question aloud, answer it out loud, then press for the model answer. The worked example is a real 2026 result: hybrid search lost to dense-only search on many queries. Think of a code review: the bug is the question, the root cause is the mechanism, the metric is the number, the patch is the fix, and the reviewer's next comment is the probe. Click 1, Question (the bug). Restate the question as a measurable claim: which metric (recall@10), which corpus, compared with which baseline (dense-only). Click 2, Mechanism (the root cause). RRF gives each document the sum of 1/(k_rrf + rank) over the lists. A document at #1 in a bad BM25 list gets the same boost as #1 in a good dense list: RRF ignores how good each list is. The table shows it: A is #1 in dense, but C and B pass it at k_rrf=2 and at k_rrf=60. A small k_rrf makes the top ranks dominate; a large k_rrf flattens the curve, so agreement between lists dominates. k_rrf is the RRF smoothing constant, not the recall@10 cutoff. Click 3, Number (the metric). The Fusion Tax paper (arXiv 2610.30612) used RRF with k_rrf=60. RRF hurt 15-33% of queries against dense-only. The best method, dense-weighted score interpolation, still hurt 8-21%. Start with 20-50 labelled queries, the same rule of thumb Anthropic gives for starter agent evals. To build the harness, see the RAG deck Labs 1 and 3 (evalkit.py, lab3_hybrid.py). Click 4, Fix (the patch). Measure dense-only against hybrid per corpus on the golden set. Keep hybrid only where it wins, or weight toward dense. A separate trap: Qdrant's RRF uses k_rrf=2 by default, not 60. Set k in models.Rrf (Qdrant 1.16 and later) so your numbers are comparable. Other fix types (a filter that leaves too few candidates, a judge that returns NaN) come in later chapters. Click 5, the model answer. It uses all four moves in two sentences. Click 6, the probe (the reviewer's comment). The paper found that a per-query router never beat one static policy on held-out corpora, so keep one winner per corpus.
