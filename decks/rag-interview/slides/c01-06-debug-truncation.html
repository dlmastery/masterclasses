from sentence_transformers import SentenceTransformer
from langchain_text_splitters import RecursiveCharacterTextSplitter
model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")
tok, limit = model.tokenizer, model.max_seq_length   # 256 here
splitter = RecursiveCharacterTextSplitter.from_huggingface_tokenizer(
    tok, chunk_size=240, chunk_overlap=0)  # 256 - 2 special - margin
chunks = splitter.split_text(open("adjuster_manual.md").read())
n_tok = lambda c: len(tok(c)["input_ids"])   # incl. [CLS], [SEP]
cut = [i for i, c in enumerate(chunks) if n_tok(c) > limit]
pct = 100 * len(cut) / len(chunks)
print(len(chunks), f"chunks truncated: {pct:.1f}%")
assert not cut, f"{len(cut)} chunks will be truncated"
vecs = model.encode(chunks, normalize_embeddings=True)

Show the code and the output, then give the room thirty seconds to find the bug. The splitter counts characters, but the embedder counts tokens: all-MiniLM-L6-v2 keeps only 256 tokens, and a 2,000-character chunk is much longer than that, so the appeal rule at character 1,600 is never embedded. This is documented behaviour, not a library bug: Sentence Transformers always passes a max length with truncation on, so transformers prints no warning; issue 4060 is still open. The fix sizes chunks with the embedder's own tokenizer: 240 leaves room for the two special tokens plus a small margin, and the assert checks it. Overlap is optional; it is counted inside chunk_size, so you can add it back. Read model.max_seq_length for every embedder you use, because it differs per model. The chunk numbers change after the fix because the splits changed. Analogy: a scanner that reads only the first page of every letter you feed it. Likely follow-up, "Can I just raise max_seq_length?": no, a model gives poor embeddings for inputs longer than the ones it was trained on; pick an embedder with a longer window and still chunk in its own tokens.
