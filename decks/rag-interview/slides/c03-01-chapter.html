The code builds on the Northwind retrieval labs: kb.py · evalkit.py · lab2_bm25.py · lab3_hybrid.py · lab7_query_transform.py (export GEMINI_API_KEY).

This chapter covers the most-asked RAG design area in 2026 interviews: hybrid search, reranking and query rewriting. The funnel shows the standard shape: BM25 finds exact words and dense search finds meaning; each sends its top 75, so RRF gets up to 150 candidates, fewer unique chunks when the two lists overlap. RRF (Reciprocal Rank Fusion) merges by rank, k is a smoothing constant, and we truncate to the top 30. A cross-encoder reads the query and each chunk together, reorders the 30, and 8 reach the reader. Analogy: a hiring funnel where each round is cheaper to skip than to run, so every round must prove its value. The theme of every drill: a stage can raise the mean and still make single queries worse, so a strong candidate prints the per-query "got worse" list. Every drill uses one running case, Northwind outdoor-gear support search, with error codes such as E-4012, and the code reuses the lab files kb.py, evalkit.py, lab2_bm25.py, lab3_hybrid.py and lab7_query_transform.py. Likely question: "Do I always need all three stages?" No; measure each stage on a labelled set and keep only the ones that help. Next: hybrid search and RRF.
