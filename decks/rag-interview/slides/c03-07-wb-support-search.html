Prompt

Design retrieval for Northwind's support bot. Queries mix exact codes ("E-4012 at checkout") and paraphrases ("box came crushed"). Budget: p95 under 300 ms. Show how you would know it works.
  1. Normalise IDs at index and query time.
  2. BM25 ‖ dense, top 75 each, ACL filter in both.
  3. RRF with k=60 pinned. Keep the top 30.
  4. Rerank 30 pairs. Gate, then 8 chunks to the reader.
  5. Weak queries only: rewrite, retry once.
  6. p95 budget: 142 of 300 ms. Weak path: own SLO.
  7. Eval tap per stage: R@5, MRR@10, “got worse” list.

Read the prompt aloud and let the candidate draw before each reveal. The main line runs left to right and top to bottom: normalise, BM25 and dense in parallel (top 75 each, with the ACL filter inside both retriever queries, so a filtered user still gets k results and nothing leaks into the reranker), RRF with k pinned, then the cross-encoder, the gate and the reader. Child chunks are small chunks that link to a parent section; the reranker scores the small ones. The gate sits before the reader: only weak queries branch down to the rewriter and loop back once. The budget is an example, not a measurement: normalise 1 ms, BM25 and dense 60 ms in parallel, RRF 1 ms, rerank 80 ms, which covers tokenising, transfer and queueing; Ettin-17M computes 30 pairs in about 4 ms on an H100 and Ettin-1B in about 32 ms, so our Ettin-32M sits between them, and Google's ranking API runs under 100 ms. The weak path adds an LLM rewrite and a second retrieval, so it does not fit the 300 ms p95: give it its own SLO and track the share of weak queries. For a real-world anchor, Atlassian Rovo cut retrieval p90 from 125 to 60 ms on turbopuffer. The interviewer wants stage-by-stage measurement: R@5 and MRR@10 on the labelled set after every stage, plus the list of queries each stage made worse; the chips are the lab numbers with the MiniLM baseline. Likely follow-up: "Why does the weak path not just get a bigger reranker?" A reranker cannot find what retrieval missed, so the retry changes the query instead. This closes the chapter.
