from uuid import uuid4
from google.adk import Context, Event
from google.adk.events import RequestInput
from google.adk.workflow import node
# intake wrote state {"order_id", "amount"}; nodes get
# them by parameter name (parameter_binding="state")
@node(rerun_on_resume=True)
def manager_gate(ctx: Context, amount: float):
  if amount <= 500.0:  # auto-approve
    yield Event(route="approved")
    return
  iid = f"refund_approval_{uuid4()}"
  answer = ctx.resume_inputs.get(iid)
  if answer is None:
    yield RequestInput(interrupt_id=iid,
                       message=f"Approve ${amount:.2f}? yes/no")
    return
  ok = str(answer).lower() == "yes"
  yield Event(route="approved" if ok else "rejected")
# intake, issue_refund, notify_rejected, edges: unchanged

Show the code and the two adk run calls, and ask why the yes never lands. Point at the line numbers. The hint is lines 7-8: with rerun_on_resume=True the node runs again from the top when the answer arrives, so every line before the lookup runs a second time. The answer is lines 12-13: uuid4() gives a fresh interrupt id on that second run, so ctx.resume_inputs.get(iid) looks for an id that nobody answered and the node yields a new RequestInput. Fix it with an id derived from ctx.invocation_id and ctx.run_id. The CLI resumes the paused invocation, so invocation_id stays the same; run_id changes per loop pass. The RequestInput docstring says reusing an id is supported but unique ids per loop pass are recommended, so the rule is unique per pass, stable across reruns. Lines 5-6 answer a common question: function nodes get order_id and amount from state by parameter name. The workflow has no LLM node, so no API key is needed: pip install google-adk==2.13.0, a refund_approval folder with agent.py and an __init__.py that imports it. Analogy: a ticket desk that prints a new ticket number each time you come back, so your call is never answered. Likely follow-up: the default rerun_on_resume=False is the hand-off pattern, where the reply simply becomes the node's output and this bug cannot happen.
