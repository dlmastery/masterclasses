Model Armor is a Google Cloud service, not a class: it needs a project and a template.
This chapter treats every tool in two ways: as an interface that the model must choose correctly, and as an attack surface. At first the loop shows refund_agent calling its four tools; billing is marked "MCP or A2A?" because that is the first protocol question. Click 1: the issue_refund wire turns red, because a refund moves money and cannot be undone. Click 2: a before_tool_callback lands on that wire, and the calls stop there: deterministic code, not the prompt, decides. Analogy: the model is a new clerk who reads the labels on the drawers, and the callback is the lock on the cash drawer. Likely student question: "Why not write 'ask before refunding' in the system prompt?" Because a prompt is advice that injected text can override; the security Q&A gives the numbers. The chapter follows one scenario: refund_agent and its tools, the A2A billing agent, policy in code and injection containment, then an MCP tool platform for 40 teams, then a debug drill. All code uses google-adk 2.13.0.
