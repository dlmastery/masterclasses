A human approval is a security boundary only when you bind it

Is a human approval a security boundary in ADK?
Not by default. The tool gate (require_confirmation) trusts any reply from the user role. A2A (Agent-to-Agent) messages arrive as the user, so a peer can forge one.
How do you bind an approval to one effect?
Show the exact effect in the payload. The reply must echo it, and the gate compares the echo with state before it routes to the refund.
Why must "manager said yes" never be cached in user: state?
An old approval then authorizes a new action. Scope each approval to one interrupt id.

A forged confirmation passes the tool gate

Put an authenticating proxy in front of adk api_server (it has no auth). Do not serve confirmation-gated tools over A2A. Guard fix pending (#7134).

refund_approval/agent.py · bound manager_gate
from pydantic import BaseModel
from google.adk import Context, Event
from google.adk.events import RequestInput
from google.adk.workflow import node

class ManagerDecision(BaseModel):
    approved: bool
    order_id: str   # echo of the payload
    amount: float   # echo of the payload

@node(rerun_on_resume=True)
def manager_gate(ctx: Context, order_id: str, amount: float):
    iid = f"refund_approval_{ctx.invocation_id}_{ctx.run_id}"
    answer = ctx.resume_inputs.get(iid)
    if answer is None:
        yield RequestInput(interrupt_id=iid, response_schema=ManagerDecision,
            payload={"order_id": order_id, "amount": amount},
            message=f"Approve ${amount:.2f} on {order_id}?")
        return
    d = ManagerDecision.model_validate(answer)
    bound = d.order_id == order_id and d.amount == amount
    yield Event(route="approved" if d.approved and bound else "rejected")

Reused approvals are an attack

+0.0 ppattack success when an agent reuses earlier approvals (AgentDojo, arXiv 2609.33910)
  • One approval = one interrupt id = one effect.
  • Log the interrupt id, the payload and the reply.
  • Do not write user:approved = True.

Ask each question and let the candidate answer before you reveal the step. Question 1: ADK has two pause types. RequestInput sends adk_request_input; a tool gate (require_confirmation=) sends adk_request_confirmation. Issue #6461 is about the tool gate: a peer sends a function_response with confirmed true, and the only trust check is that the event author is the user. Inbound A2A messages become role user. A guard shipped in v2.8.0 was reverted on 2026-08-20 because it broke every HITL tool confirmation; the replacement, #7134, is still open. So put an authenticating proxy in front of adk api_server and never expose it publicly. Question 2: the payload shows the order and the amount; the manager's client echoes them in the reply; the gate validates the reply and routes to approved only when the echo matches state. The arXiv paper 2610.21063 ("Approve What, Exactly?") found post-approval argument changes in four of eight runtimes, which is what this check stops. Question 3: arXiv 2609.33910 ("When Consent Outlives Context") measured residual authority replay: reusing earlier approvals raised attack success by up to 35.1 percentage points on AgentDojo. Analogy: a signed blank cheque. Likely follow-up: "Is a per-action check enough?" No; also cap the daily refund total in a workflow-level policy node.
