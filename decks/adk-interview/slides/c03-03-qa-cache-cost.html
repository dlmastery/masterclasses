hr_cache.py
import asyncio, pathlib
from google.adk import Agent, Runner
from google.adk.agents.context_cache_config import ContextCacheConfig
from google.adk.apps.app import App
from google.adk.sessions import InMemorySessionService
from google.genai import types

HANDBOOK = pathlib.Path("handbook.md").read_text(encoding="utf-8")
agent = Agent(name="hr_policy_agent", model="gemini-3.5-flash",
    static_instruction=HANDBOOK,                    # stable prefix, first
    instruction="Employee: {user:employee_name}.")  # dynamic, after it
app = App(name="hr_app", root_agent=agent,
    context_cache_config=ContextCacheConfig(
        min_tokens=4096, ttl_seconds=900))  # default TTL 1800; 900 for short chats

async def main() -> None:
    svc = InMemorySessionService()
    runner = Runner(app=app, session_service=svc)
    await svc.create_session(app_name="hr_app", user_id="emp-17", session_id="s1",
                             state={"user:employee_name": "Priya"})
    for q in ["How many PTO days do I get?", "Can I carry them over?",
              "What about parental leave?"]:
        msg = types.Content(role="user", parts=[types.Part(text=q)])
        async for ev in runner.run_async(user_id="emp-17", session_id="s1", new_message=msg):
            if ev.is_final_response() and ev.usage_metadata:
                u = ev.usage_metadata
                print(f"{q[:28]:28} prompt={u.prompt_token_count} cached={u.cached_content_token_count}")
asyncio.run(main())

Ask each question and wait for the candidate before you reveal the answer. Q1, click 1: a context cache matches an identical prefix, so a timestamp in front of the handbook makes every call a miss; watch the time row move below the handbook, and calls 2 to 4 turn into hits. Call 1 is always a miss because ADK creates the cache after the first call, and Gemini 3 needs at least 4096 tokens of prefix (2048 on Gemini 2.5). Q2, click 2: this is the proof; the ContextCacheConfig defaults are ttl_seconds=1800 and cache_intervals=10, and extra="forbid" makes a misspelled field an error. Q3, click 3: read each meter before you blame the price. TurnCost (arXiv 2610.15093) found that 98.6% of input tokens came from the prefix cache and that turn count explained 84% of cost variance, so turns/session is the first term to check. Uber grew weekly agentic requests 9.4 times while cost per session fell 52%, with cheaper subagents, compaction at 400K tokens and a cache TTL of 1 hour instead of 5 minutes. The 6 to 13 turns case is a worked example, not a measured result. Likely follow-up: "Is a cheaper model always cheaper?" No: measure cost per successful outcome, because retries can raise it.
