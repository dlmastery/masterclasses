27from typing import Literal
from google.adk import Agent, Context, Event, Workflow
from pydantic import BaseModel
MAX_ROUNDS = 3
class Review(BaseModel):
  grade: Literal["compliant", "needs_fix"]
  feedback: str
def brief(node_input: str):
  yield Event(state={"brief": node_input, "feedback": "", "round": 0})
write_copy = Agent(name="write_copy", output_key="draft",
  instruction="Write a 2-sentence ad for: {brief}. Fix: {feedback?}")
review_copy = Agent(name="review_copy", output_key="review",
  output_schema=Review,
  instruction="Must say 'Capital at risk.' Grade this ad: {draft}")
def gate(ctx: Context, node_input: Review):
  if node_input.grade == "compliant":
    yield Event(route="done")
  elif ctx.state["round"] >= MAX_ROUNDS:
    yield Event(route="escalate")
  else:
    yield Event(state={"feedback": node_input.feedback}, route="retry")
# publish and escalate get draft from ctx.state["draft"] by name
def publish(draft: str): yield Event(message=f"PUBLISHED: {draft}")
def escalate(draft: str): yield Event(message=f"To Legal: {draft}")
root_agent = Workflow(name="copy_review", edges=[
  ("START", brief, write_copy, review_copy, gate),
  (gate, {"retry": write_copy, "done": publish, "escalate": escalate})])

Show the code and the symptom, and give the room one minute to find the line. Step 2 asks about the elif on line 18. Step 3: line 9 sets round to 0 once, in the brief node; line 18 reads it on every pass, but no line writes it again, so 0 >= 3 is never true and the only exit left is a compliant grade that never comes. The tile "gate runs" comes from the trace (gate@250 in node_path), not from state: that gap between 250 and 0 is the clue. Expect someone to say "set max_iterations": there is none on graph cycles. LoopAgent had it; a Workflow cycle is bounded only by your own counter, because validation rejects only unconditional cycles and a routed back-edge is legal. The default cap of 500 LLM calls per run (override it with the ADK_MAX_LLM_CALLS environment variable) stopped this run, but that cap is a cost backstop, not a design. There is a second cause: write_copy is never told the "Capital at risk." rule, so the critic keeps failing it; put the rule in the writer's instruction and keep the counter as the backstop. publish and escalate get the draft by parameter name from ctx.state, which is the Python default binding. Analogy: a guard who checks the visitor count but never clicks the counter. Likely follow-up: how would you catch this in tests? Use a critic stub that always says needs_fix and assert that the run ends in escalate after 3 rounds; log the round count so evals can measure rounds-to-compliant.
