orchestrator.py · the fan-out (google-adk 2.13.0)
import asyncio
from google.adk import Agent
from google.adk.apps.app import App
from google.adk.runners import InMemoryRunner
from google.genai import types

answerer = Agent(name="dor_answerer", model="gemini-3.5-flash",
    static_instruction="Answer ONE question from retrieved facts.")
runner = InMemoryRunner(app=App(name="dor", root_agent=answerer))
sem = asyncio.Semaphore(5)             # at most 5 questions in flight

async def answer(q: str) -> tuple[str, str]:
    async with sem:                    # a fresh session per question
        s = await runner.session_service.create_session(app_name="dor", user_id="dor")
        msg = types.Content(role="user", parts=[types.Part(text=q)])
        async for ev in runner.run_async(user_id="dor", session_id=s.id, new_message=msg):
            if ev.is_final_response() and ev.content and ev.content.parts:
                return q, "".join(p.text or "" for p in ev.content.parts)
        return q, "UNKNOWN"

The reference answer is the Palo Alto Networks Document of Record design on ADK and Vertex AI Agent Engine (Google's managed runtime for deployed agents), from the Google Cloud blog of 2026-01-14. Click 1: their first version sent all 140 questions through one agent context and hit "Out of Memory" errors; in general a growing prompt also overflows the context window and lowers answer quality. Click 2: the orchestrator keeps the dossier and sends questions to two ADK agent endpoints in batches of five; the second lesson is that the orchestrator and the agent in one GKE cluster gave frequent pod crashes, so the agent moved to Agent Engine. Click 3: each agent scores its answer by the share of claims grounded in the retrieved facts, the orchestrator keeps the better one, and a verification step labels it low, medium or high. The blog does not say how agents A and B differ. Click 4: write-back is asynchronous through Pub/Sub. Click 6 shows our own version of the fan-out, a semaphore of five with a fresh session per question; it is a design inspired by the case, not their code. The blog gives about 2.5 hours per dossier before optimization and no number after it. Likely follow-up: "Does a second agent double the cost?" Yes, roughly, so tie it back to the cost equation: you pay for quality with requests per turn.
