Agent architecture and graph workflows

In an ADK 2.0 Workflow, nodes are agents or Python functions and edges are code. Interviewers test where you draw that line.

workflow vs agent vs multi-agent routes, joins and loops dynamic nodes and agent modes google-adk 2.13.0
This chapter drills one boundary: code owns the flow, and the model owns only the judgment. On the first frame the whole chain is visible: START hands the ticket text to classify, the only LLM node (coral zone), and classify returns a Triage object that a plain Python function, route_ticket, turns into a route (amber zone). On the click the two exits appear: route_ticket emits the "page" route for an outage or any p1 ticket, so it goes to page_oncall, and a label with no edge (such as "other") falls to DEFAULT_ROUTE and the human queue. Triage is a Pydantic object with the labels and a priority. The four chips are our agenda: architecture choice, routes and joins, loops, then dynamic nodes and agent modes, all tested against google-adk 2.13.0. Analogy: the LLM is the triage nurse who reads the symptoms, but the hospital protocol decides which ward the patient goes to. Likely student question: "Then why use an LLM at all?" Because free text needs judgment; the next slide gives the evidence for how little of the path should be free.
