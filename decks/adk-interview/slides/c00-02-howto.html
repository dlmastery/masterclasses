How to use this deck

Say your answer out loud before you click

Self-study: press → to show the next answer. Press N for the speaker notes.

Three drill types

AQ&A

Three questions per slide. Each answer is one click.

e.g. "What happens to an unmatched route?"

BWhiteboard

A design prompt. Then the reference design builds step by step.

e.g. "Triage 10,000 tickets a day"

CDebug this

Buggy code and a symptom. Find the bad line before the answer step.

e.g. "The loop ran until the call cap"

Use the deck as a drill, not as a reading. On a Q&A slide, say your answer before you click, then compare it with the model answer. On a whiteboard slide, sketch the design first, then watch the reference design build. On a debug slide, find the bad line before the answer step shows it. Each chapter mixes all three drill types and has one whiteboard. A worked example of a one-minute answer, for "what happens to an unmatched route?": mechanism, the routed node emits a label that has no edge; failure mode, the branch ends with one log warning and no error; number, zero exceptions raised; fix, add DEFAULT_ROUTE to human_queue and use a Literal schema. Analogy: answer like a bug report. A likely student question is "how long should an answer be?": about one minute, with one number in it.
