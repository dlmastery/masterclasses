Policy belongs in deterministic code, not in the system prompt

Where does the allow or deny decision for a refund live?
In code. A before_tool_callback compares the amount with a cap that trusted code set. It returns a dict, so the tool does not run. A prompt is only advice.
deterministic origin checks: 1.6-2.6% attack success
Why must the user identity come from trusted state, not a tool argument?
Injected text can change the arguments that the model writes. Read the caller from session state and block a mismatch.

refund_agent/agent.py · google-adk 2.13.0
from google.adk import Agent
from refund_agent.tools import issue_refund

def refund_cap(tool, args, tool_context):   # agent level: args
    cap = tool_context.state.get("app:refund_cap_usd", 100)
    amount = args.get("amount_usd", 0)
    if tool.name == "issue_refund" and amount > cap:
        msg = f"Refunds over ${cap} are blocked in chat."
        return {"status": "error", "error_message": msg}
    return None                      # None = run the tool
agent = Agent(name="refund_agent", model="gemini-3.5-flash",
              tools=[issue_refund],
              before_tool_callback=refund_cap)

app: keys are shared by every session of the app. Ops set them, not the model: create_session(..., state={"app:refund_cap_usd": 100}).

refund_agent/guard.py · google-adk 2.13.0
from google.adk.apps import App
from google.adk.plugins import BasePlugin
from refund_agent.agent import agent
class RefundGuardPlugin(BasePlugin):
    async def before_tool_callback(
            self, *, tool, tool_args, tool_context):
        # trusted: your server wrote it into session state
        caller = tool_context.state.get("customer_id")
        asked = tool_args.get("customer_id")    # model-written
        if tool.name == "get_order" and asked != caller:
            msg = "You can only view your own orders."
            return {"status": "error", "error_message": msg}
        return None
app = App(name="refund_agent", root_agent=agent,
          plugins=[RefundGuardPlugin(name="refund_guard")])

Your server sets customer_id from the login token at create_session. No tool lets the model write it.

Contain injection with scoped tools; use models only as a screen

A ticket tells your reader agent to call issue_refund. Contain it.

Why not let an LLM judge approve each tool call?
