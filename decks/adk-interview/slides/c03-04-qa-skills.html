hr_app/agent.py · the skill as a sub-agent
import pathlib
from google.adk import Agent
from google.adk.skills import load_skill_from_dir
from google.adk.tools import AgentTool
from google.adk.tools.skill_toolset import SkillToolset

HERE = pathlib.Path(__file__).parent
pto = load_skill_from_dir(HERE / "skills" / "pto-policy")

# inline would be: tools=[SkillToolset(skills=[pto])] on root_agent
# sub-agent: a fresh context that returns only its answer
pto_agent = Agent(
    name="pto_specialist", model="gemini-3.5-flash",
    description="Input: a PTO question. Returns: days and section.",
    instruction="Answer only from the pto-policy skill.",
    tools=[SkillToolset(skills=[pto])])
root_agent = Agent(
    name="hr_policy_agent", model="gemini-3.5-flash",
    instruction="Call pto_specialist for PTO questions.",
    tools=[AgentTool(agent=pto_agent)])
Ask each question and let the candidate answer before you click. Q1: a rule is not an ADK class; it is text in instruction or static_instruction. The key word for skills is progressive disclosure: the model first sees only names and descriptions, then loads the body and the reference files when a request matches. Q2, click 2: in SkillsBench (arXiv 2610.18522), loaded-skill recall fell from 73.6% to 27.4% with 1,000 distractor skills, and the zero-load rate, where the model loads no skill at all, rose from 9.3% to 51.6%; a preselection step kept recall at 73.9%. ADK has no built-in preselection: rank the skills yourself (retrieval or a cheap model) and pass only the top-k into SkillToolset(skills=...), or give SkillToolset a registry so the model uses search_skills. A related trap: two skills for the same job make one skill take over; rule compliance fell from 93-99% to 61-62% (arXiv 2610.25064), and one combined worked example fixes most of it. Q3, clicks 3 and 4: loose skills tie or win inline; contract skills win as sub-agents, most for small models, at a higher token cost (arXiv 2609.09233). If you keep many skills inline, SkillLifecycleConfig(default_mode=SkillLifecycleMode.BOUNDED, max_active_skills=3) caps active skills; the cap runs without a flag, but evicted skill text leaves the request, and unload_skill is offered, only with ADK_ENABLE_SKILL_LIFECYCLE=1. Likely follow-up: "Why did my skill fail to load?" The folder name must equal the name in SKILL.md.
