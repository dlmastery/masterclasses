Dynamic nodes and agent modes: three production traps

Static graph, or a dynamic node that calls ctx.run_node?
Static when you can draw the flow; dynamic when the fan-out size is known only at runtime.Set max_parallel_workers: the Python default is unlimited.
Your orchestrator calls ctx.run_node and raises a ValueError. What is missing?
@node(rerun_on_resume=True): on resume, the parent re-runs from the top.Finished children replay from history. Keep side effects in children.
You port a SequentialAgent to a Workflow, and billing forgets the ticket text. Why?
A Workflow node defaults to single_turn, with include_contents="none".billing gets only the classify output.Fix: include_contents="default", or put the ticket in state and read {ticket}.

invoice_audit/agent.py · static graph, capped worker
from google.adk import Event, Workflow
from google.adk.workflow import node
def split_lines(node_input: str):
  return [l.strip() for l in node_input.split(";") if l.strip()]
@node(parallel_worker=True, max_parallel_workers=4)  # default: unlimited
def check_line(node_input: str):
  return float(node_input.rsplit("$", 1)[1]) <= 250.0
def summarize(node_input: list):
  yield Event(message=f"{sum(node_input)} of {len(node_input)} lines OK")
root_agent = Workflow(name="invoice_audit",
    edges=[("START", split_lines, check_line, summarize)])
invoice_audit/agent.py · dynamic fan-out
import asyncio
from google.adk import Agent, Context, Event
from google.adk.workflow import node
auditor = Agent(name="auditor", instruction="Audit the line in the message.")
@node(rerun_on_resume=True)         # required for any ctx.run_node caller
async def orchestrate(ctx: Context, node_input: str):
  lines = [l.strip() for l in node_input.split(";") if l.strip()]
  raw = await asyncio.gather(*[
    ctx.run_node(auditor, node_input=l, use_sub_branch=True)  # isolate runs
    for l in lines])
  yield Event(output=raw)

This slide comes after the debug drill on purpose: static cycles are done, and now the graph changes at runtime. Q1: use a static graph when you can draw the flow, because the graph checks edge schemas at construction time and adk web draws it; use a dynamic @node with ctx.run_node when the number of branches is known only at runtime. For a map over a list, a parallel_worker node runs once per item, and the diagram shows the cap: 4 run, 2 wait. In Python max_parallel_workers defaults to None, which means unlimited, while TypeScript defaults to 8. Q2: a node that calls ctx.run_node must set rerun_on_resume=True, or it raises "ValueError: A node must have rerun_on_resume=True"; on resume the parent re-runs from the top and finished children replay their cached outputs, so the orchestrator must stay thin and side effects belong in children. use_sub_branch=True keeps parallel children from seeing each other's events. Q3: inside a Workflow an LlmAgent node with no mode resolves to single_turn, and the Workflow sets include_contents="none" unless you set it yourself (checked in the v2.13.0 source, _workflow_graph_utils.py L163-168), so billing gets only the Triage JSON. Fix it with include_contents="default", or, more robust across versions, write the ticket to state and read {ticket} in the instruction, as the triage intake does. The three modes: single_turn is the node default, task chats with the user until it has a typed result, and chat never finishes a node, so it is legal only right after START; validation rejects chat after any other node. Analogy: a single_turn node is a contractor who gets a work order, not the whole email thread. Likely question: "Why not give every node the full history?" Cost and leakage: parallel single_turn workers should see only their own branch.
