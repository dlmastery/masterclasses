Evals, observability and production

Expect questions on pass^k (all k runs of a case must pass), judge trust, silent telemetry breaks and safe upgrades.

adk eval AgentEvaluator user simulation OpenTelemetry adk deploy
This chapter drills one claim: an agent is production-ready only when a gate can fail it. Step 0 shows build 3, a regression: the eval gate turns red and adk eval exits 1. Since 2.13.0 adk eval exits 1 on any failed case; before 2.13.0 the exit code did not reflect failures (CHANGELOG 2.13.0), so old CI pipelines passed silently. Steps 1 and 2 show build 4, the fix: exit 0, then the canary, then production when the agent SLIs stay normal. Step 3 closes the loop: a failing production trace comes back as a new eval case. Analogy: a smoke detector that never beeps is not a safe house, it is a broken detector. Likely student question: "Is one eval run enough?" No, the next slide shows why you run each case several times and report pass^k.
