Calibrate your own judge

  1. Sample real conversations. Get labels from 3 or more experts.
  2. Compute Cohen's κ, judge vs humans (sklearn.metrics.cohen_kappa_score).
  3. Tune the judge prompt until κ is near the human-vs-human κ.
Read each question aloud and let the students answer before you reveal the model answer. Q1 is the number to know: the same three 75% trials give 98% for pass@3 and only 42% for pass^3, and a support customer sees pass^k, because each customer gets one attempt. Be precise about ADK: AgentEvaluator.evaluate(num_runs=3) runs each case 3 times but compares the mean score with the threshold, so one bad run can hide; since 2.13.0 adk eval exits 1 on a failed case, so three separate adk eval runs that must all exit 0 give a real pass^3 gate. For Q2, add the CXBench result: 55.5% of runs were false passes with the right outcome but a non-compliant process, and only 13.8% passed both (arXiv 2610.25954), so outcome checks alone are not enough. For Q3, also say that you keep a known-good and a known-bad fixture in every gate, because ADK's safety_v1 metric silently resolved to safety_v3, which scores in the opposite direction (issue #7258, pinned in 2.10.0). Analogy: a judge is a thermometer, so you check it against a known temperature before you trust the reading. Likely student question: "Why not run 10 times?" You can, but each run costs a full agent pass; pick k from the number of attempts your users really get.
