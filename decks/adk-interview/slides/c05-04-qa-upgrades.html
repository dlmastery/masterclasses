$ adk deploy cloud_run --project=$PROJECT --region=$REGION \
    --service_name=refund-agent refund_agent \
    -- --set-env-vars=ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false
Only adk deploy agent_engine --otel_to_cloud sets it to false for you.

Read each question and let the candidate answer before you reveal the step. For question 1, the key word is "silent": 2.13.0 defaults to OTel GenAI semconv 1.44 and removes the call_llm span, so the dashboard shows zero while traffic is normal. Set ADK_TELEMETRY_SCHEMA_VERSION_OPT_IN=otel_semconv_1_36 through the gcloud flags after "--" while you move the dashboards. For question 2, ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS defaults to true, so message content goes into spans; only agent_engine with --otel_to_cloud turns it off for you. The MCP point comes from the maintainer on issue #6532: the OTel instrumentor is built for httpx 1.x, so under MCP SDK 2.x MCP calls go untraced rather than breaking. For question 3, pin google-adk, mcp and a2a-sdk, and litellm if you use it, in the same file locally and in the image; version skew in the cloud gave "'LlmAgent' object has no attribute 'mode'" (issue #6156). Analogy: the factory renamed a part number, so the stock counter says zero while the shelves are full. A likely follow-up: "What do you alert on?" Alert when spans arrive but a dashboard metric is zero, and run one synthetic canary query per deployment.
