Multimodal, code and memory

The retrieval loop stays the same. The index changes.

This chapter extends retrieval past plain text. Step 1 shows page images and video: a PDF page is often a picture, so we either parse it to text, caption it, or embed the image itself. Step 2 adds code, where exact names and freshness matter more than semantic similarity. Step 3 adds memory, which is retrieval over the user's own history instead of a shared corpus. Analogy: one librarian, four kinds of shelves, each with its own catalogue. Likely question: "Do I need a separate system for each modality?" Answer: often one retriever API with different indexes behind it.
