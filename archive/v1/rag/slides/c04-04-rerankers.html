Anthropic: retrieve 150, rerank, keep 20. Cost is one API round-trip or one GPU pass per pair. Cap the candidates. Keep docs ≤ max_tokens_per_doc (Cohere default 4096).

rerank.py

import cohere
co = cohere.ClientV2()
resp = co.rerank(
    model="rerank-v5.0-pro",        # or rerank-v5.0-fast, rerank-v3.5
    query="What is the capital of the United States?",
    documents=["Carson City is the capital city of Nevada.",
               "Washington, D.C. is the capital of the United States.",
               "Capital gains are profits from the sale of an asset."],
    top_n=2,
    relevant_spans={"mode": "enabled", "threshold": 0.1,
                    "max_spans": 3},   # v5+ only: spans behind the score
)
for r in resp.results:
    print(r.index, r.relevance_score)

Show the interaction spectrum one grid at a time. A bi-encoder makes one vector for the query and one for the document, so the only interaction is one cosine; it is fast because documents are encoded offline, but it loses detail. Late interaction keeps a vector per token: each query token takes its best match in the document (MaxSim) and the maxima add up. A cross-encoder reads the query and the document together with full attention, so it is the most accurate and also needs one forward pass per pair, which is why we only run it on about 150 candidates and keep 20. Analogy: the bi-encoder reads the book titles, ColBERT reads the index at the back, and the cross-encoder reads the chapter with your question in mind. Likely question: "Why not use a cross-encoder for the first stage?" Because you cannot precompute anything, so a million documents means a million forward passes per query.
