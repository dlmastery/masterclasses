rag_tool.py · google-adk 2.13.0

import os
from google.adk.agents import Agent
from google.adk.tools.agent_tool import AgentTool
from google.adk.tools.retrieval.vertex_ai_rag_retrieval import (
    VertexAiRagRetrieval)
from vertexai.preview import rag

ask_vertex_retrieval = VertexAiRagRetrieval(
    name="retrieve_rag_documentation",
    description="Retrieve documentation from the RAG corpus.",
    rag_resources=[rag.RagResource(
        rag_corpus=os.environ.get("RAG_CORPUS"))],
    similarity_top_k=10, vector_distance_threshold=0.6)

kb_agent = Agent(model="gemini-flash-latest", name="rag_agent",
    instruction="Fetch docs with the tool, then answer from them.",
    tools=[ask_vertex_retrieval])     # the tool stays alone here
kb_tool = AgentTool(agent=kb_agent)  # mixes with other tools

from google.adk.agents import LlmAgent, LoopAgent, SequentialAgent
from google.adk.tools.tool_context import ToolContext

def exit_loop(tool_context: ToolContext):
    """Call only when the evidence is sufficient."""
    tool_context.actions.escalate = True   # stops the LoopAgent
    return {}
grader = LlmAgent(name="Grader", model="gemini-2.5-flash",
    include_contents="none", output_key="critique",
    instruction="Judge if {evidence} fully answers {question}. "
                "Reply 'SUFFICIENT' or list gaps.")
researcher = LlmAgent(name="Researcher", model="gemini-2.5-flash",
    output_key="evidence", tools=[exit_loop, kb_tool, web_tool],
    instruction="If {critique} is 'SUFFICIENT' call exit_loop; "
                "else search to fill the gaps.")
loop = LoopAgent(name="CorrectiveLoop",
    sub_agents=[grader, researcher], max_iterations=4)

Built-in RAG and search tools work only alone in an agent. Wrap each in a sub-agent; call it with AgentTool.
Start with the tool. VertexAiRagRetrieval reads a RAG Engine corpus; the ADK docs now call it Knowledge Engine, the cloud docs still say RAG Engine. The model decides whether to call the tool, so this is agentic RAG in about 20 lines. The docs say the built-in retrieval tool and google_search can only be used by themselves in one agent, so wrap each in a sub-agent and expose it with AgentTool; then one researcher can use both, which is a multi-source router. The loop is a LoopAgent with max_iterations=4: the grader writes "critique" to session state, the researcher writes "evidence", and exit_loop sets escalate=True to leave the loop early; the SequentialAgent then runs the writer. Analogy: an editor and a reporter who pass one shared notebook until the editor says "sufficient", with a hard limit of four rounds. Interview angle: workflow agents make the loop testable and capped, because the control flow is code, not a prompt.
