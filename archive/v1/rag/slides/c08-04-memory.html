from google import adk
from google.adk.agents import Agent
from google.adk.memory import VertexAiMemoryBankService
from google.adk.tools import preload_memory

memory_service = VertexAiMemoryBankService(
    project="PROJECT_ID", location="LOCATION",
    agent_engine_id="AGENT_ENGINE_ID")
async def auto_save(callback_context):
    await callback_context.add_session_to_memory()

agent = Agent(model=MODEL, name="Generic_QA_Agent",
    instruction="Answer the user's questions",
    tools=[preload_memory],      # or load_memory: agent decides
    after_agent_callback=auto_save)
runner = adk.Runner(agent=agent, app_name="app",
    session_service=session_service,
    memory_service=memory_service)

preload_memory retrieves on every turn. load_memory is a tool the agent calls when it needs it. InMemoryMemoryService() is for prototypes.

RAG retrieves from a shared corpus. Memory retrieves from one user's own history. Steps 1 to 3 build the lifecycle: an LLM extracts candidate facts from the conversation, a consolidation step decides ADD, UPDATE, DELETE or NOOP against similar memories (this is Mem0's design), the store is scoped by user_id, and the agent retrieves and injects the top memories into the prompt. Step 4 is the Graphiti idea: when Alice moves from Acme to Google, the old edge is invalidated but kept, so the question about 2025 still has an answer. Steps 5 and 6 show the ADK version with Memory Bank: preload_memory retrieves every turn, and an after_agent_callback saves the session. Analogy: a good assistant keeps a notebook about you, crosses out old facts with a date, and never reads another client's notebook. Likely question: "Why not keep the whole history in the context window?" Answer: LongMemEval shows about a 30% accuracy drop over long interactions, and Mem0 reports over 90% token savings versus full context.
