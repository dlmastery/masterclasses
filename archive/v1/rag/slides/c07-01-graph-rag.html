Graph and structured RAG

Top-k similarity finds the chunks that look like the query. Two question shapes break it. Structure adds aggregation and traversal.

Global sensemaking

"What are the main themes across this 1M-token corpus?"

The answer is spread thin over all 100 chunks. The top-5 window (blue) sees 5% of the evidence. No single chunk holds the answer.

Multi-hop

"Which Stanford professor's student founded the company that acquired X?"

Only chunk C shares words with the query. Chunks A and B do not look like the query, so top-k never returns them.

Paper When to use Graphs in RAG (GraphRAG-Bench, ICLR 2026)
This chapter is about questions that plain top-k similarity cannot answer. First, global questions: the answer is a summary of the whole corpus, so every chunk is a little relevant and no five chunks are enough. Second, multi-hop questions: each hop is in a different chunk, and the middle chunks do not look like the question. Analogy: top-k is a search light; global questions need a map of the whole room, multi-hop questions need a rope from one object to the next. Structured RAG builds that map or that rope at index time: an entity graph, communities, a summary tree or a SQL schema. Then end with the caution: GraphRAG-Bench shows that graphs often lose to vanilla RAG, so measure before you adopt. Likely question: "Can I not just raise k?" Larger k adds cost and distractors and still misses chunks that are not similar to the query.
