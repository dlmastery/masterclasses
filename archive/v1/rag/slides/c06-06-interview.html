Multi-agent research costs about 15× the tokens of chat. When is it worth it?
Use it for broad questions that split into parallel parts, where token spend drives quality: token use explains 80% of BrowseComp variance. Do not use it for simple lookups. Cap the number of sub-agents and set a token budget.
Why does Search-R1 mask the retrieved tokens?
The loss must train decisions and reasoning: when to search, what to query, how to answer. The retrieved text is written by the environment, not the policy. Without the mask, the model learns to generate fake evidence.
Design a deep-research feature with a fixed budget.
Plan with a brief the user can edit. Run N capped sub-agents. Compress each lane to 1–2k tokens with URLs. Let a supervisor check for gaps. Write a cited report, then run a critic pass. Trace the token spend per lane.
What did the 2026-07-28 MCP spec change, and why does it help RAG?
Requests are stateless, and servers implement server/discover. There is no session id. tools/list is deterministic and cacheable. So a retrieval server scales like a plain HTTP service, and the tool list stays in the prompt cache.
