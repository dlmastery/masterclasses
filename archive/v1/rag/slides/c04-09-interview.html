Interview: hybrid search, reranking and long context

Why use RRF instead of averaging BM25 and cosine scores?
The scores have different scales and distributions: BM25 is unbounded, cosine is −1..1. RRF uses ranks only, so it needs no calibration. k = 60 is stable: pilot MAP was .2072 / .2145 / .2098 for k = 0 / 60 / 500. Use score fusion (Weaviate alpha, Qdrant DBSF) only when you can tune it on labels.
You retrieve 150 and rerank to 20. What is the latency budget, and how do you cut it?
The cost is one cross-encoder pass per pair, or one API round-trip. Cap the candidates. Truncate docs (Cohere max_tokens_per_doc, default 4096). Use a fast tier (rerank-v5.0-fast, rerank-3-lite). Batch the pairs on a GPU. Check that a smaller candidate set keeps recall.
Your context has 30 chunks and accuracy fell. Why?
Lost in the middle and context rot. GPT-3.5-Turbo with 30 docs and the answer in the middle scored 50.5%, below its closed-book 56.1%. Even one distractor hurts. Send fewer, reranked chunks. Put the best first and last, and remove near-duplicates.
When would you skip RAG?
When the corpus is under ~200k tokens, static, and has one permission level. Put it in the prompt with prompt caching: write 1.25× (5 min) or 2× (1 h), read 0.1×. Anthropic reports >2× lower latency and up to 90% lower cost. For large, changing or ACL'd corpora, retrieve.

For the reranker budget, the strong answer counts forward passes or round-trips and lists four ways to cut them, and it checks recall after each cut. For the 30-chunk question, name both effects and give the fix, with the striking number that 30 documents scored below no documents. For skipping RAG, give the size threshold, the static and single-permission conditions, and the cache price multipliers.
