Put the cheapest reliable verifier after every risky step, and turn every failure into a sensor

Doc Böckeler, Harness engineering for coding agent users, 2026-04-02 Doc Hashimoto, My AI Adoption Journey, 2026-02-05 Doc Building agents with the Claude Agent SDK Docs Antigravity: hooks

A harness is everything around the model. Guides steer the agent before it acts (feedforward). Sensors check its work after it acts (feedback). Each control is computational (code) or inferential (a model).

Sensorsfunction nodes (lint, tests, SQL dry run), RetryConfig, ToolCallIntegrityPlugincritic nodes, ClassifierNode, ModelArmorPlugin; AutoTracingPlugin for traces

ToolCallIntegrityPlugin (2.11) stamps each function call with "v1:" + HMAC-SHA256 and blocks tampered or replayed calls. It does not check tools that run as workflow nodes: the graph gives their arguments.

It is the idea that anytime you find an agent makes a mistake, you take the time to engineer a solution…

The Hashimoto loop in ADK: each production failure → adk eval_set add_eval_case → a CI gate with adk eval or AgentEvaluator.evaluate. If the same failure comes back, the build fails.

Use the lowest rung that catches the error. Anthropic's Agent SDK post uses the same order: rules, visual feedback, then LLM-as-judge ("not very robust").

Antigravity hooks (dev-time harness): SessionStart PreToolUse PostToolUse PreInvocation PostInvocation Stop.

.agents/hooks.json · sketch, illustrative scripts

{
  "verify-tests": {
    "enabled": true,
    "Stop": [{ "type": "command", "timeout": 120,
               "command": "python .agents/verify.py" }],
    "PreToolUse": [{ "matcher": "run_command",
      "hooks": [{ "command": "python .agents/guard.py" }] }]
  }
}

verify.py runs agents-cli eval run. On failure it prints {"decision": "continue", "reason": "3 eval cases failed"}.

  • PreToolUse prints deny, ask, force_ask or an argument overwrite.
  • Read-only verifier agent (permissionMode: plan): APPROVED / CONDITIONAL / BLOCKED.
  • No built-in PRM in ADK: wrap one as a guard node or a custom metric.
Start with the agent alone in the ring. Step 1: the guides fly in from the left; they shape the agent before it acts. Step 2: the sensors fly in from the right, computational on top and inferential below; read the table row with them. Step 3 is the most important idea of the slide: a red mistake appears in a production trace, becomes an eval case, and the eval case becomes a new sensor on the ring; that is Mitchell Hashimoto's definition of harness engineering. Step 4 shows the verifier ladder: always try the cheapest rung that can catch the error, because a schema check costs nothing and a human costs hours. Steps 5 and 6 show the same idea at development time in Antigravity: a Stop hook that refuses to let the coding agent stop while evals fail, a PreToolUse guard, and a read-only verifier agent. Analogy: a car has a steering wheel and a road map (guides) and also a speedometer, an ABS sensor and a crash test (sensors). Likely question: "Does ADK ship a process reward model?" No; you wrap one as a guard node or a custom metric.
