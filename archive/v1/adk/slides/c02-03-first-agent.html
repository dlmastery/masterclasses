travel_assistant/agent.py · three tool kinds

from google.adk.agents import Agent
from google.adk.tools import FunctionTool, google_search
from google.adk.tools.agent_tool import AgentTool
from google.adk.tools.langchain_tool import LangchainTool
from langchain_community.tools import WikipediaQueryRun
from langchain_community.utilities import WikipediaAPIWrapper
google_search_agent = Agent(
    name="google_search_agent", tools=[google_search])
wiki = WikipediaQueryRun(api_wrapper=WikipediaAPIWrapper(
    top_k_results=1, doc_content_chars_max=3000))
root_agent = Agent(
    name="root_agent",
    tools=[FunctionTool(get_fx_rate),     # plain def, calls an FX API
           AgentTool(agent=google_search_agent),
           LangchainTool(wiki)],
)

Codelab Building AI Agents with ADK: The Foundation
Step one replays the Foundation codelab: adk create asks for the model, the backend, the project and the region, then writes agent.py, __init__.py and .env. adk web starts the Dev UI on 127.0.0.1 port 8000 and keeps sessions in SQLite under .adk. Step two is the Empowering with Tools codelab: one agent with a custom FunctionTool, the built-in google_search inside its own sub-agent behind AgentTool, and a LangChain Wikipedia tool. Analogy: the docstring is the label on a drawer, and the model opens only the drawer whose label matches the question. Watch the pulses: an FX question reaches only get_fx_rate, and a history question reaches only the Wikipedia tool, which you confirm in the Events tab. If you set no model, LlmAgent falls back to gemini-3.5-flash, so pin the model from an environment variable. Likely interview question: "Why wrap google_search in AgentTool instead of a transfer?" With AgentTool the caller keeps control, because "Agent A retains control and continues to handle future user input"; the search agent also stays isolated from the other tools.
