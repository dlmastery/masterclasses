A graph is an agent.

Blog ADK for Go 2.0: build agent workflows as a graph Docs Welcome to ADK 2.0
Start with the one-sentence answer to the interview question "What is ADK 2.0?": it is a graph-based Workflow Runtime, and agents, tools and functions are all nodes, because BaseAgent now subclasses BaseNode. Follow the token. On the billing route, plain functions do the data-determined steps, and a RequestInput node waits for a human. On the general route, one Agent works alone inside a bounded LLM island. Google gives the reason in "Why we built ADK 2.0" (Google Developers Blog, 2026-07-01): "For production-grade reliability, you need full deterministic control over your application flow." Analogy: the graph is the railway track and the switches. The model is the driver who reads the signals at each station. Likely question: "Is this only LangGraph again?" Answer: explicit edges are a shared idea. In ADK, node input and output are typed, the graph is validated when you construct it, and HITL pause and resume come from the session event log. The node colours match the adk web graph view: amber RUNNING, violet WAITING, green COMPLETED.
