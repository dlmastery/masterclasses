Interview drill: design and debug an ADK 2.0 graph

How do you branch, and what happens to a route with no matching edge?
Yield Event(route=...) and map routes in a dict. An unmatched route ends the branch silently, with only a log warning. Add DEFAULT_ROUTE ("__DEFAULT__"). Constrain LLM routers with a Literal output schema, or use a ClassifierNode with a threshold.
Why can a graph cycle run forever, and how do you bound it?
Construction rejects only unconditional cycles. A conditional cycle has no max_iterations. Keep a round counter in ctx.state with a give_up route, or use a dynamic @node with a for bound. Backstop: max_llm_calls (default 500).
Graph workflow or dynamic workflow?
Graph for declarative flows: 10 construction rules check it, and adk web draws it. Dynamic (ctx.run_node, while, gather) for recursion and data-dependent loops. The parent needs rerun_on_resume=True. Deterministic child run ids are the checkpoint keys.
Two terminal nodes both produce output. What happens?
The run fails with WorkflowConfigurationError (“multiple terminal nodes produced output”), because the engine cannot choose the workflow output. Join them with a JoinNode. It emits one dict keyed by predecessor node name.

Give students thirty seconds per question before you reveal the answer. Question 1 tests the silent-stop failure and the three router grades. Question 2 is the most common graph bug in production: a critic that never approves, so the loop burns LLM calls until the 500-call backstop. Question 3 tests judgment: start with a graph because the engine checks it and adk web can draw it; move to a dynamic node only when the shape depends on data. Question 4 is a precise detail that shows real hands-on use. Analogy for the whole drill: a graph is a contract with the engine; every rule you break at design time is a rule the engine checks for you. Likely follow-up: "How would you test a router?"
