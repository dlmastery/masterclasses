Report every score per slice with n and a confidence interval, and compare models on paired items

Rules for a score you can trust

  • Report n and a 95% CI with every score. SE ≈ √(p(1−p)/n).
  • Use Wilson intervals for small n, or for p near 0 or 1: proportion_confint(method="wilson").
  • At n = 500 and p ≈ 0.8, each CI is about ±3.4 pts. The two CIs overlap. Use clustered SEs when questions share a passage or a conversation.
  • Report each slice with its n and CI. The aggregate hides slice regressions (Simpson’s paradox).
  • Compare models with paired differences on the same items. Pairing removes item-difficulty variance. Resample each answer k times to cut within-item variance.

Do a power analysis before you build the set

At α = 0.05 and power 0.8, the minimum detectable effect is ≈ 2.8 × SE(Δ). Unpaired, p = 0.8, n = 500 per arm: SE(Δ) ≈ 0.025, so you detect only ≈ 7-point deltas. Pairing shrinks this.

paired_bootstrap.py · from 07-eval-design §5

# Paired bootstrap on the same golden set
import numpy as np
rng = np.random.default_rng(0)
a = np.load("scores_A.npy")   # per-item scores, same order
b = np.load("scores_B.npy")
d = b - a
boots = np.array([
    rng.choice(d, size=len(d), replace=True).mean()
    for _ in range(10_000)])
lo, hi = np.percentile(boots, [2.5, 97.5])
print(f"delta={d.mean():+.3f}  95% CI [{lo:+.3f}, {hi:+.3f}]  "
      f"P(delta<=0)={np.mean(boots<=0):.3f}")

SciPy: scipy.stats.bootstrap((d,), np.mean, confidence_level=0.95, method="BCa"). For clustered items, resample the clusters (passages, conversations), not the items.

Many SOTA deltas sit inside the noise. Most reports still omit CIs and clustering.

This slide turns a leaderboard into an experiment. Step 0 shows the usual story: B beats A by 1.1 points, so B ships. Step 1 adds the error bars at n of 500; the intervals overlap, so the ranking is not proven. Step 2 splits the score by slice: B wins four slices but loses the Spanish slice by ten points, and the global number hid it. Step 3 is the right test: subtract per item, resample the differences 10,000 times, and read the 95 percent band; here it still touches zero. Step 4 is the power check: unpaired, 500 items can only detect about 7 points. Analogy: two runners on different tracks cannot be compared to a tenth of a second; run them on the same track. Likely question: "Why not a t-test?" A paired t-test is fine for large n; the bootstrap needs no normal assumption and extends to clusters.
