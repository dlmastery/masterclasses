.github/workflows/eval.yml
name: eval-gate
on: [pull_request]
jobs:
  eval:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: {python-version: "3.11"}
      - run: pip install "google-adk[eval]==2.13.0"
      - working-directory: labs
        env:
          GOOGLE_GENAI_USE_ENTERPRISE: "FALSE"
          GOOGLE_API_KEY: ${{ secrets.GOOGLE_API_KEY }}
          PYTHONPATH: ${{ github.workspace }}/labs
        run: |
          adk eval refund_agent refund_agent/refund.evalset.json \
            --config_file_path=refund_agent/test_config.json
Step four: we run the evalset from the shell and look at the exit code, because the exit code is the only thing CI reads. Here we use the broken agent from step 3, the one without the 500 dollar sentence: one case fails, and since 2.13.0 adk eval exits 1 when any case fails or when no case ran, so the pipeline stops before deploy. Before 2.13.0 it printed the red result and still exited 0, so older pipelines deployed the failing agent; think of a smoke alarm that beeped but did not call anyone. The efficiency metrics such as token_usage_v1 are added automatically and show NOT_EVALUATED, so do not read them as failures. The workflow file is all CI needs: pinned install, the API key from a repository secret, PYTHONPATH set to labs, and the same adk eval command. A likely question is "how do I rerun flaky cases?": 2.13.0 has no repeat flag for adk eval, so the practices slide shows pytest with num_runs.
