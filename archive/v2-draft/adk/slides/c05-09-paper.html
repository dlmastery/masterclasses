Three papers from September and October say the same thing: a yes from a human is only as safe as the scope of that yes. The grid is the 2610.22987 result, not an Acme measurement: one tile is one percent of that paper's capability tests for coding agents, and the approval card on the right is our Acme example. Step 1: residual authority replay reuses an earlier approval for a new action and raises attack success by up to 35.1 percentage points on AgentDojo, a prompt-injection benchmark, so scope each approval to one interrupt_id and never write "approved" into user: state; a second order gets a new interrupt and a new pause. Step 2: in From Approval to Abuse, planted repo context got coding agents to request broad allow-rules in 58% of instances; those rules covered 56.9% of capability tests, and once a rule was approved 47 of 58 runs reached silent malicious completion. Step 3: effect binding means the tool checks the exact approved payload again when it runs, so an amount edited from 820 to 8,200 raises PermissionError; ADK does not do this for you, so write the approved order and amount to state in manager_gate and compare inside issue_refund. The same paper lists threshold splitting, two 490-dollar refunds that each stay under the 500-dollar gate, so also keep a running refunded_total in state and pause when the session sum passes the limit. Analogy: a signed cheque names the payee and the amount; a blank signed cheque is a standing rule. Next: how Temporal makes the same loop durable per call.
