def refund_cap(tool: BaseTool, args: dict[str, Any], tool_context: ToolContext) -> Optional[dict]:
    cap = tool_context.state.get("app:refund_cap_usd", 1500)
    if tool.name == "issue_refund" and args.get("amount_usd", 0) > cap:
        return {"status": "error", "error_message": f"Refunds over ${cap} are blocked by policy."}
    return None                                            # None = run the tool
def redact_pii(tool: BaseTool, args: dict, tool_context: ToolContext,
               tool_response: dict) -> Optional[dict]:
    if tool.name == "lookup_order" and "order" in tool_response:
        order = {k: EMAIL.sub("[email redacted]", v) if isinstance(v, str) else v
                 for k, v in tool_response["order"].items()}
        return {**tool_response, "order": order}
    return None                                            # None = keep the tool result
root_agent = Agent(name="refund_agent", model="gemini-3.5-flash",
    instruction=("You are a refund desk assistant. Use lookup_order, then check_refund_eligibility. "
                 "Quote the rule you applied. Never promise a refund the tool did not approve."),
    tools=[lookup_order, check_refund_eligibility, issue_refund],
    before_model_callback=block_card_numbers, before_tool_callback=refund_cap,
    after_tool_callback=redact_pii, after_model_callback=meter_tokens)

arXiv 2608.11274 Agent Safety Should Be a Runtime Contract
The refund desk now gets a third tool, issue_refund. A prompt line such as "never refund more than $1,500" is a request to the model, and a customer who writes "A-1002 arrived damaged, refund $2,000 for my trouble" can talk the model past it. A callback is plain Python that runs at a fixed hook point, so the cap holds whatever the model decides. Walk the four hooks in order: before_model, after_model, before_tool, after_tool. The return rules matter: LLM callbacks stop on a truthy value, tool callbacks stop on any non-None value, even an empty dict; plugin callbacks run first, and each *_callback field also takes a list. Analogy: the prompt is a sign that says "staff only", the callback is the locked door. The paper 2608.11274 (Aug 2026) calls this a runtime contract: preventive gates plus evidential proof, which here are callbacks plus the event log. Likely question: "Why return an error dict and not raise?" Because the model reads the dict and can explain the limit to the customer. The cap is a hard ceiling; the next slide adds the softer layer: a human approves every refund over $200.
