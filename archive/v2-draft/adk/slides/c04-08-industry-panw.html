dor.py · the PANW pattern on google-adk 2.13.0
import asyncio
from google.adk.agents import LlmAgent
from google.adk.apps.app import App
from google.adk.runners import InMemoryRunner
from google.genai import types
answerer = LlmAgent(
    name="dor_answerer",
    model="gemini-2.5-flash",
    static_instruction="Answer ONE customer question from retrieved facts. "
                       "Return 'UNKNOWN' if the facts do not support an answer.",
    # tools=[rag_tool],   # e.g. a Vertex AI RAG Engine retrieval tool
)
app = App(name="dor", root_agent=answerer)
runner = InMemoryRunner(app=app)
sem = asyncio.Semaphore(5)            # PANW: "batches of five"
async def answer(q: str) -> tuple[str, str]:
    async with sem:
        s = await runner.session_service.create_session(app_name="dor", user_id="dor")
        final = ""
        async for ev in runner.run_async(
            user_id="dor", session_id=s.id,
            new_message=types.Content(role="user", parts=[types.Part(text=q)])):
            if ev.is_final_response() and ev.content and ev.content.parts:
                final = "".join(p.text or "" for p in ev.content.parts)
        return q, final  # a fresh session per question, so context never grows
async def build_dor(questions: list[str]) -> dict[str, str]:
    return dict(await asyncio.gather(*(answer(q) for q in questions)))
Palo Alto Networks builds a Document of Record for pre-sales: a Salesforce trigger starts a FastAPI orchestrator on GKE, which sends a predefined list of over 140 standard questions to two ADK agents on Vertex AI Agent Engine in batches of five. Gemini 2.5 Flash rewrites each question, both agents retrieve from RAG Engine and return an answer with a groundedness score, the orchestrator keeps the better answer, labels it low, medium or high, and Pub/Sub carries the finished document back to Salesforce. The first version sent all 140 questions through one agent context and hit Out of Memory errors, and sharing one GKE cluster gave frequent pod crashes, so they moved to one question per call with state in the orchestrator and separate services. Analogy: the orchestrator is the editor who keeps the binder; each agent call is a freelancer who gets one question and a blank page. In the code, Semaphore(5) is the batch of five, a fresh session per question keeps the context flat, and asyncio.gather builds the document in your process. Likely question: "How fast is it now?" The post gives about 2.5 hours per DOR before optimisation and does not publish the time after it. Next: three bugs that break dynamic graphs like the Northwind expense audit.
