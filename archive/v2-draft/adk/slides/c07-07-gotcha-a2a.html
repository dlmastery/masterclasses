An agent card is a promise, and ADK does not check the promise for you. The first gotcha: to_a2a writes protocol, host and port into the card, with a default port of 8000, so the client loads the card and then follows it to an empty port while uvicorn listens on 8001. The httpx ConnectError is the symptom; the fix is to pass the port you really serve on. The second gotcha appears when you deploy: RemoteA2aAgent accepts plain http only on a loopback host, and otherwise refuses the card with "Agent card URL must use https, or http on a loopback host". Write the public URL into the card, https on 443; on Cloud Run the container still listens on $PORT, which is 8080 by default, so do not try to bind 443. In the code the two to_a2a lines are alternatives: the laptop line and the Cloud Run line. Analogy: the card is a business card, and a wrong phone number on it sends every caller to an empty office. A likely question: "Can I skip to_a2a's card and write my own?" Yes, pass a hand-written agent_card=, but the same rule holds: the URL must match how you serve it.
