Gotcha MCP

MCP fails three ways: missing extra, renamed SDK, silent toolset loss

1 · the import fails SymptomImportError: cannot import name 'McpToolset' from 'google.adk.tools.mcp_tool' Causemcp is not installed. tools/mcp_tool/__init__.py catches the real ImportError and logs it only at debug level. Fixpip install "google-adk[mcp]==2.13.0"
2 · v1 server code on mcp 2.3.0 SymptomModuleNotFoundError: No module named 'mcp.server.fastmcp'. This is mcp 2.x, where FastMCP was renamed to MCPServer (from mcp.server.mcpserver import MCPServer)...
TypeError: MCPServer.__init__() got an unexpected keyword argument 'port' CauseThe SDK renamed FastMCP. In 2.x, host and port go to run(), not the constructor. FixMCPServer("x") + run(transport=..., host=..., port=...), or pin mcp<2.
3 · the toolset is lost, with no exception SymptomThe agent says "I can't access claims". The log shows Agent claims_desk will run without the tools from toolset McpToolset (prefix 'claims'), which failed to load: ... CauseServer crash, a print() on stdout, a URL without /mcp, or a startup slower than timeout. FixAlert on that log line. Run a startup smoke test.
Before 2.10 / 2.11: after a server restart or scale-to-zero, ADK kept the dead session and returned {'error': 'MCP tool execution failed: Session terminated'} as a normal result. Alert on the error string, not only on exceptions.
smoke_test.py · google-adk 2.13.0 · mcp 2.3.0
import asyncio
from claims_agent.agent import claims_tools
EXPECTED = {"get_claim", "approve_claim", "login"}
async def main() -> None:
    try:
        tools = await claims_tools.get_tools()
    except Exception as exc:  # crash, stdout print, bad /mcp path, timeout
        raise SystemExit(f"FAIL toolset did not load: {exc!r}")
    names = {t.name.removeprefix("claims_") for t in tools}
    if names != EXPECTED:
        raise SystemExit(f"FAIL expected {EXPECTED}, got {names}")
    print("OK", sorted(names))
asyncio.run(main())

These three MCP failures cost the most debugging time on the Northwind claims desk. The first two are loud: a missing mcp extra gives an opaque ImportError because ADK hides the real one at debug level, and v1 server code on mcp 2.3.0 fails because FastMCP is now MCPServer and host and port moved to run(). The third is silent: when the toolset cannot load, ADK logs one line and the agent keeps answering without its tools, so nothing turns red until you alert on that line. Run the smoke test before traffic, and in older versions also alert on the Session terminated error string, because it came back as a normal tool result. Think of it as a phone line that goes dead while the operator keeps talking politely to the caller. A likely question: "Why does ADK not just raise?" One broken toolset should not take down an agent that has other working tools, so the choice is deliberate, and you own the alert. Next, three recent papers on MCP security and tool selection.
