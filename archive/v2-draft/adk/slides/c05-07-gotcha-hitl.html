These three bugs hit the Acme refund gate after the lab works on your laptop; the slide shows each bug first and then its fix. First, the interrupt id must be the same on every rerun of a rerun_on_resume node. With uuid4 the id changes on each rerun, so resume_inputs.get never matches and the manager is asked again; the animation shows the lookup missing, while the id built from invocation_id and run_id hits the stored answer on the first resume. Second, replies are JSON-parsed when possible, so the word approve stays a string and ManagerDecision.model_validate raises ValidationError; response_schema "does not reshape the reply", so accept a string and parse it yourself, and remember that this simple parser turns anything except approve into a reject and loses notes and partial amounts, so ask for JSON when you need those. Third, issue 7010, still open, is about the tool-level FunctionTool predicate: ADK uses cast(bool, ...), which does nothing at runtime, so a predicate that returns None is falsy and an 820-dollar refund runs with no prompt; return a real bool on every path, and write the predicate of the node-level decorator from the last slide the same way. The double-star underscore parameter takes the other tool arguments, so the predicate only names the one it needs. Think of the interrupt id as a cloakroom ticket: if you print a new ticket every time you come back, you never get your coat. A likely question: "Why not just reuse one fixed string?" Reuse is supported, but the docstring still recommends unique ids per loop pass, which the revise loop in Lab 5 step 1 needs. Next: the same kind of traps on the payout side, in retry and resume.
