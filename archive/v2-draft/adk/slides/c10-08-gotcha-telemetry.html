Tracing is on in the Contoso HR assistant, and three defaults now work against us. First, ADK copies message content into spans unless ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS is false, and only the Agent Runtime deploy with --otel_to_cloud sets that for you, so on Cloud Run and GKE you set it yourself. Second, the animation shows what the 2.13.0 upgrade does to a dashboard: the call_llm panel drains to zero with no error, because semconv 1.44 removed that span, and the panel rebuilt on generate_content fills instead. Think of it as a street that the city renamed: the traffic is still there, but your map no longer finds it. Third, ADK 2.13.0 caps opentelemetry-sdk at 1.44, so pinning the latest 1.45.1 breaks the install. A likely question: "How do I notice a silent zero?" Run a synthetic canary query per deploy and alert when spans are ingested but the dashboard metric is zero.
