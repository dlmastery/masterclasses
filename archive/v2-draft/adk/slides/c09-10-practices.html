8 rules and 2 traps for an eval gate that blocks bad deploys

1 · What to score

  • The $500 rule is a code metric. Judges plateau at 77-82%. 2608.26623
  • Judges for meaning only: pinned model, num_samples 5.
  • A completion bit beside each rubric. 57.5% of "satisfied" chats failed. 2609.12191
  • Rubrics state the procedure, not golden ids. Golden-id judges fail correct answers. 2609.30471
  • Reference metrics on simulated cases. expected_invocations is needed
Sources (arXiv): 2608.26623 AgentJudgeBench · 2609.12191 GAUGE · 2609.30471 CARGO · 2609.32092 production eval · 2609.33044 Pinned and Still Unstable · 2608.26218 Same Model, Different Harness

2 · How often

  • Run ≥ 3 times. Paired bootstrap: resample case pairs, CI on the delta. 2609.32092
  • Trust one run. Close calls flip ~40%. 2609.33044
labs/test_refund.py · pip install pytest pytest-asyncio · cd labs && pytest -q
import pytest
from google.adk.evaluation.agent_evaluator import AgentEvaluator

@pytest.mark.asyncio
async def test_refund_golden():
    await AgentEvaluator.evaluate(
        agent_module="refund_agent",
        eval_dataset_file_path_or_dir="refund_agent/refund.evalset.json",
        num_runs=3)   # default 2; adk eval has no repeat flag in 2.13.0

3 · How to trust the gate

  • In CI, test -f the config and assert the case count.
  • Known-good and known-bad case per gate. #7258 flipped a metric.
  • Pin models, log the harness. New harness alone: 43 → 72 solved. 2608.26218
This is the checklist for the whole Acme refund eval gate, in three groups: what to score, how often, and how to trust the gate itself. Hard rules such as the 500 dollar ceiling go into a code metric, because judges plateau at 77 to 82 percent on hard tool-calling cases; every simulated rubric gets a judge-free completion bit, because 57.5 percent of "satisfied" simulated chats had failed; and rubrics describe the procedure, because the CARGO paper found a reference-based judge failed every correct answer about an entity that differed from the golden one. Run each eval at least three times with pytest and num_runs, and accept a change only by a paired bootstrap: resample the same cases from the old and new runs many times and check that the confidence interval of the score change stays above zero. A single run is not enough: a pinned judge flips about 40 percent of close calls. Then test the gate: check the config path, count the cases, keep a known-bad case that must fail, and pin the agent model, the judge model and the harness version, because changing only the harness took the same model from 43 to 72 solved SWE-bench tasks. Analogy: a smoke alarm is only useful if you test it with smoke. A likely question is "Why IN_ORDER and not EXACT?": the agent may make an extra lookup, but it must look up the order before it escalates.
