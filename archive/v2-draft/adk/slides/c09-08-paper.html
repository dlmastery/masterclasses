from google.adk.evaluation.eval_case import get_all_tool_calls
from google.adk.evaluation.evaluator import EvalStatus, EvaluationResult
DONE = {"escalate_to_human", "issue_refund"}   # a terminal tool was called

def completion_bit(eval_metric, actual_invocations, expected_invocations,
                   conversation_scenario):
    done = any(call.name in DONE for inv in actual_invocations
               for call in get_all_tool_calls(inv.intermediate_data))
    return EvaluationResult(overall_score=1.0 if done else 0.0,
        overall_eval_status=EvalStatus.PASSED if done else EvalStatus.FAILED)
Three papers from August and September say the same thing: an LLM judge is a noisy instrument, not ground truth. GAUGE ran 25 agents with simulated customers on tau-squared-bench and SimulatorArena: of the chats a judge rated satisfied, 57.5% had failed the customer's task, and on close pairs, meaning two agents with similar scores, the judge and the real reward disagreed 31% of the time. AgentJudgeBench shows six judges stuck at 77 to 82% on hard tool-calling cases, and structured rubrics buy at most 6.5 points. Pinned and Still Unstable shows a pinned temperature-0 judge flips about 5% of verdicts on a rerun and about 40% on close calls. The Monday change is a judge-free completion bit: a code metric that passes only if the agent called a terminal tool, escalate_to_human or issue_refund. Completion is not correctness, so keep refund_policy_score and the rubric next to it. Analogy: a polite customer saying "thanks" is not the same as the parcel arriving. A likely question is "Why not just a better judge?": the ceiling and the flip rate hold across judges, so the completion bit must not depend on any judge.
