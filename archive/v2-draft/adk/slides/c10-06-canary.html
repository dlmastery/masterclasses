The before line is the default: adk deploy cloud_run creates a new revision and it takes all the traffic at once. The after path uses plain Cloud Run revisions: deploy with --no-traffic and a tag, which gives the candidate its own URL, then point agents-cli eval run --url at that URL so the evals hit the real deployed revision before any user does. Shift 5%, then 25%, then 100%, and hold each step while error rate, p99 latency, tokens per invocation and the judge score stay steady. Tokens per invocation is the agent-specific gauge: a loop does not raise errors, it burns tokens, so a jump past 1.5x baseline is the rollback trigger, and the rollback is one update-traffic command. Analogy: a new chef cooks for one table before the whole room. Likely question: "What about Agent Runtime?" No traffic split was found there, so use blue/green with a second resource; and never shadow-test a candidate with live write tools, because a shadow call to a refund or HR write tool is a real write.
