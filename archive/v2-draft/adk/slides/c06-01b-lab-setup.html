Before step 1, set up the folder once, so every later slide only adds code. Install google-adk with the mcp extra and pin mcp 2.3.0, because the server code uses the 2.x names; fastapi and uvicorn run the claims-status REST service. The .env file sits inside claims_agent, where adk web loads it: GOOGLE_GENAI_USE_ENTERPRISE=0 selects an AI Studio key from aistudio.google.com, and CLAIMS_API_KEY is the key the agent sends to the REST service. Run every command from the northwind folder, the folder that contains claims_agent. You need three terminals: the REST service on 8081, the handbook MCP server on 3000, and adk web on 8000, where you pick claims_agent in the app list. The claims MCP server has no terminal, because McpToolset starts it as a child process over stdio. Think of it like a kitchen: two suppliers deliver from outside, and one cook works inside the restaurant. On Windows, use WSL, or the cmd forms on the slide. A likely question: "Why must terminals 1 and 2 start first?" agent.py fetches the OpenAPI spec when it is imported, and the HTTP toolset connects when the agent first runs.
