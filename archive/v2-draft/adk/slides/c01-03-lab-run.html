Run every command from the folder that contains refund_agent, not from inside it, because ADK imports the folder as a Python package. Walk the trajectory on the right: the user message, lookup_order, then check_refund_eligibility, and only then the final answer, which quotes the 30-day rule from the tool result. Think of the trajectory as the receipt for the answer: the answer is the total, the tool calls are the line items you audit. Then open adk web and show the same calls in the Events tab, and point out that a missing argument comes back to the model as an error dict, so the model can retry. A likely question is "why not just read the final text?": because a correct answer can hide a wrong process, and the next slide logs the trajectory from Python.
