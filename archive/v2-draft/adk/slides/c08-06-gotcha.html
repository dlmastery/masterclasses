Gotcha Context cache

cached=None on every turn: a timestamp moved the prefix

Symptomcached=None on every turn, also on turns 2 and 3. CauseA timestamp or {state} sits in static_instruction, or the prefix is under 4,096 tokens. FixKeep static_instruction byte-stable; put dynamic text in instruction.
handbook_app.py · fixed · google-adk==2.13.0
from google.adk import Agent
from google.adk.agents.context_cache_config import ContextCacheConfig
from google.adk.apps import App
from google.genai import types
HANDBOOK = open("handbook.md", encoding="utf-8").read()  # never changes
agent = Agent(name="handbook_agent", model="gemini-3.5-flash",
    static_instruction=types.Content(          # byte-stable prefix
        role="user",
        parts=[types.Part(text=HANDBOOK)]),
    instruction="Customer: {customer_name}. Now: {now}.")  # dynamic
app = App(name="bluefin_support", root_agent=agent,
    context_cache_config=ContextCacheConfig(
        min_tokens=4096, ttl_seconds=900))
# {customer_name} and {now} come from session state

The first Bluefin failure looks like "the cache does nothing": cached=None on every turn, not only on turn 1. The animation shows why: a timestamp inside static_instruction makes the prefix different on every turn, so the cache key changes and every request misses. Move the timestamp into instruction, which ADK sends as user content after the prefix, and the prefix stays the same, so turns 2 and 3 hit; turn 1 still misses, because caching starts on turn 2, so a single-turn eval never shows a hit. Think of the cache like a photocopy master: write the date on the master and you need a new master every time. The other cause is size: the prefix must reach 4,096 tokens on Gemini 3 and 2,048 on Gemini 2.5. A likely question: "Where does {now} come from?" Write it into session state before each turn, the same way {customer_name} is set when the session is created.
Gotcha Compaction and memory

Compaction needs a full pair; memory is not persistent by default

SymptomValueError: token_threshold and event_retention_size must be set together. CauseHalf a trigger pair. FixSet both fields; import from google.adk.apps.app.
SymptomValueError: Cannot add session to memory: memory service is not available. CauseA hand-built Runner has no memory_service. FixPass memory_service=VertexAiMemoryBankService(...).
SymptomMemories vanish after adk web restarts. CauseWithout --memory_service_uri, adk web uses InMemoryMemoryService. FixStart it with --memory_service_uri="agentengine://$AGENT_ENGINE_ID".

Two more Bluefin failures look like "the feature does nothing". First, compaction triggers come in pairs: token_threshold with event_retention_size, or compaction_interval with overlap_size, and half a pair raises a ValueError when the App is built. EventsCompactionConfig is exported from google.adk.apps.app; importing it from the package google.adk.apps raises ImportError, because that package exports only App and ResumabilityConfig. Second, memory: a Runner that you build by hand has no memory service, so add_session_to_memory raises "memory service is not available". adk web is different: without --memory_service_uri it falls back to InMemoryMemoryService, so the callback works but every memory disappears when the server restarts. Think of it as a notebook on the desk versus a filing cabinet: the in-memory service is the notebook that goes in the bin every night. A likely question is "does deleting the session forget the customer?": no, issue 7109 showed that memories survive delete_session, so call delete_memory, new in 2.13, in the erasure path. If create_bank.py fails with "The installed Agent Platform SDK exposes Client.agent_engines rather than Client.runtimes", install google-cloud-agentplatform 2.2 or later, as on the memory lab slide. Next, recent papers show that compaction itself can become a trust problem.
