Least privilege for MCP and REST tools in ten checks

0 / 10

1 · Tool surface

  • tool_filter on every toolset. New server tools need review.
  • tool_name_prefix per server. Merged namespaces: 154 hallucinated calls.
  • require_confirmation on money, delete, send. The server checks auth too.

2 · Identity and isolation

  • Identity in headers via header_provider. Never in the prompt.
  • stdio servers in a container, one mount. 16.4% launder filesystem access.
  • allow_private_network_access=True in prod. It lifts the SSRF guard.

3 · Operations

  • Pin google-adk, mcp and server versions.
  • Errors say "<cause>. Call <tool> …". Recovery 45% → 84%.
  • Smoke-test get_tools(). Alert on "will run without the tools".
  • print() in a stdio server. stdout carries JSON-RPC.
allow_private_network_access=True is for a dev or internal API on 127.0.0.1 only.

# pinned: google-adk==2.13.0, mcp==2.3.0
import pathlib
import sys
from google.adk.agents.readonly_context import ReadonlyContext
from google.adk.tools.mcp_tool import (
    McpToolset, StdioConnectionParams, StreamableHTTPConnectionParams)
from mcp import StdioServerParameters
SERVER = pathlib.Path(__file__).parent / "claims_server.py"

def payout_needs_human(**kwargs) -> bool:
    return float(kwargs.get("approved_amount", 0)) > 1000
def tenant_headers(ctx: ReadonlyContext) -> dict[str, str]:
    return {"X-Tenant-ID": ctx.state.get("user:tenant", "northwind")}

claims_tools = McpToolset(
    connection_params=StdioConnectionParams(
        server_params=StdioServerParameters(
            command=sys.executable, args=[str(SERVER)]),
        timeout=10.0),
    tool_filter=["get_claim", "approve_claim", "login"],
    tool_name_prefix="claims",
    require_confirmation=payout_needs_human)
handbook_tools = McpToolset(
    connection_params=StreamableHTTPConnectionParams(
        url="http://127.0.0.1:3000/mcp"),
    tool_filter=["search_policy", "list_topics"],
    tool_name_prefix="handbook",
    header_provider=tenant_headers,
    tool_list_cache_ttl_seconds=300)
This slide is the review list for every toolset the Northwind claims desk mounts, grouped as tool surface, identity and isolation, and operations. The surface checks decide what the model can see and do: a filter, a prefix per server so merged namespaces cannot collide, and a confirmation rule on money, delete and send tools, while the server keeps its own authorisation because other MCP clients can call it. The isolation checks come from the papers in this chapter: 16.4% of triaged servers exposed filesystem access they did not advertise, so a container with one mount is the real boundary. Think of it like a building pass: the badge lists the doors you may open, but each door still has its own lock. A likely question: "Why not just trust require_confirmation?" Because a human approves the call, not what the server process can reach on the host.
