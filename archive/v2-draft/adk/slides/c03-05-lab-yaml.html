agent.py logic + schema · unit tests
# no root_agent: the loader uses root_agent.yaml
from typing import Literal
from google.adk import Event
from pydantic import BaseModel
class Triage(BaseModel):
  label: Literal["billing", "outage", "other"]
def intake(node_input: str):
  yield Event(state={"ticket": node_input})
def route_ticket(node_input: Triage):
  yield Event(route=node_input.label)
def page_oncall():
  yield Event(message="PAGED on-call.")
def human_queue():
  yield Event(message="Routed to the human L1 queue.")
This is the last step of the Acme support desk lab: the triage router from the previous slide, now as reviewable YAML. To keep the YAML short, Triage has one label and three routes, with no how_to branch and no priority rule. The folder holds three YAML files and agent.py: root_agent.yaml for the topology, classify.yaml and billing.yaml for the two prompts. Press through and watch each YAML reference light up its node: START and .agent.intake, then classify.yaml, then .agent.route_ticket, then the three route keys. Every Triage.label value has its own key, including other, so no label can go unmatched. The Python constant DEFAULT_ROUTE is the string "__DEFAULT__", but no official YAML sample uses that key yet, so this lab maps each label explicitly. The function nodes yield their Event, the same as in Python step 3; return Event(...) also works. Think of the YAML as the wiring diagram on the wall and agent.py as the parts bin. Two errors to expect: run from inside the folder and you get ModuleNotFoundError; name route_ticket before an earlier edge defines it and you get "ValueError: Unknown node 'route_ticket'. A node has to be defined by an earlier edge before another edge can name it." A likely question is "can we let users upload YAML?" No: name: references import arbitrary Python objects, so load YAML only from trusted sources. Next: many teams still have 1.x pipelines, so we port one to a Workflow.
