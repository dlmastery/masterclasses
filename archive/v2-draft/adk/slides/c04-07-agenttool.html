from google.adk.agents import LlmAgent
from google.adk.code_executors import BuiltInCodeExecutor
from google.adk.tools import AgentTool, google_search
search_agent = LlmAgent(
    name="price_search",
    model="gemini-3.5-flash",
    description="Finds current retail prices for a product on the public web.",
    instruction="Search the web. Return a list of {retailer, price_usd, url}. Cite every url.",
    tools=[google_search],
)
calc_agent = LlmAgent(
    name="price_math",
    model="gemini-3.5-flash",
    description="Runs Python to compute statistics over a list of prices.",
    instruction="Write and run Python. Print mean, min, max and spread. Never guess numbers.",
    code_executor=BuiltInCodeExecutor(),   # runs in Gemini's sandbox, not locally
)
root_agent = LlmAgent(
    name="pricing_analyst",
    model="gemini-3.5-flash",
    instruction=(
        "1) Use price_search to collect prices. 2) Pass the numbers to price_math. "
        "3) Report the table, the stats, and the source urls."
    ),
    tools=[AgentTool(agent=search_agent), AgentTool(agent=calc_agent)],
)

Northwind's back office wants competitor premiums, and the first try puts google_search and a function tool on one Gemini 2.x agent, which the API rejects with 400 INVALID_ARGUMENT: Tool use with function calling is unsupported. The fix wraps each built-in in its own LlmAgent: price_search holds only google_search, price_math has a BuiltInCodeExecutor that runs in Gemini's sandbox, and the root pricing_analyst calls both through AgentTool, so control returns to the root instead of transferring away as with sub_agents. Watch the meter: each subagent fills its own context with pages and code, and only a short result list travels back, so the root context stays small. Analogy: the root is a manager who sends two analysts out and reads only their one-page memos. On Gemini 3 and later you may mix built-ins and function tools in one agent, and on older models GoogleSearchTool(bypass_multi_tools_limit=True) swaps in a sub-agent for you; since 2.13 the grounding is recorded on LLM spans, so you can audit the URLs. Likely question: "Why recompute the average in code?" Because arXiv 2609.37153 shows that plausible but wrong tool evidence cuts data-agent success by 26 to 39 points.
