This chapter takes one refund agent and makes it reusable in four ways, and the hero animation shows all four. First we expose it as a single MCP tool, so any MCP host can call it; then we expose the same agent over A2A with an agent card on port 8001, and a support triage agent owned by another team delegates refund tickets to it. Next the refund policy moves into an Agent Skill that the model loads only when a refund question arrives, and finally one plugin enforces the $500 cap on every agent in the App. Note the dashed links: refund_agent does not call the MCP tool or the card, it is exposed as them. Rule of thumb: with MCP the caller sees one tool and you own the contract; with A2A the caller sees an agent and the other team owns its prompt, state and lifecycle. Think of MCP as a power socket with a fixed shape, and A2A as calling another department. A likely question: "Why not always use A2A?" Because the A2A boundary also cuts session state and adds a trust boundary, which the gotcha and paper slides cover.
