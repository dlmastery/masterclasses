Start the server in the folder that holds agents/, and drive it with curl from a second terminal. First, list-apps shows claims_api: the server names each app after its folder. Second, create the session with a business key, claim-77; if you skip that, /run answers with a 404 "Session not found", unless you start the server with --auto_create_session. Third, /run returns the whole turn as a JSON list of Events. The request bodies use camelCase, and snake_case names such as app_name also work because the request model accepts both. Fourth, /run_sse sends one data line per event while the turn runs; with "streaming": true in the body you also get partial text chunks, so expect more lines. Last, GET the session: the audit_log that the AuditPlugin wrote is in its state, one entry per tool call. Analogy: /run is a letter that arrives when the turn is done; /run_sse is a phone call that you hear as it happens. On Windows, the single-quoted JSON bodies break in PowerShell, so use Git Bash or WSL. These are the same routes that adk deploy cloud_run serves, but put authentication in front of them.
