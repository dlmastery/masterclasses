# ClaimIntake and runner as in claim_intake.py (Lab 2, step 1)
intake_agent = Agent(name="claim_intake", model="gemini-3.5-flash",
    instruction="Extract a ClaimIntake from the email. Never guess a value.",
    output_schema=ClaimIntake,      # not generate_content_config
    output_key="claim")

        user_id="debug_user_id", session_id="debug_session_id")

Two mistakes with structured output, each shown as symptom first, then cause and fix. Step 0: the downstream claims code crashes with KeyError 'incident_date'. Step 1: the email from Lab 2 had no year, so the model returned null; with output_key and output_schema ADK stores model_dump with exclude_none, so a null field is not stored as None, it is absent. Read optional keys with .get, or rebuild the typed object with ClaimIntake.model_validate. Step 2: the second symptom is an error from ADK; the full text ends with "Move your schema to LlmAgent(output_schema=...)". Step 3: the cause is an old google-genai habit of putting response_schema into GenerateContentConfig; the schema belongs on the agent as output_schema. Analogy: the claim form has no box for a missing date, so the clerk leaves the box out instead of writing "none". A likely question: "Why does my trace show an extra set_model_response call when I add tools?" On an AI Studio key ADK cannot combine a schema and tools natively, so it adds a set_model_response tool and asks the model to answer through it. With GOOGLE_GENAI_USE_ENTERPRISE=1 (the Agent Platform backend, formerly Vertex AI) the call goes away. On AI Studio it still works; there is nothing to fix.
