import pathlib
from google.adk.agents import LlmAgent
from google.adk.code_executors import UnsafeLocalCodeExecutor
from google.adk.skills import load_skill_from_dir
from google.adk.tools.skill_toolset import SkillToolset
from refund_core import lookup_order    # A-300: $120, day 42

HERE = pathlib.Path(__file__).parent
skills = SkillToolset(
    skills=[load_skill_from_dir(HERE / "skills" / "refund-policy")],
    additional_tools=[lookup_order],          # supplies the function
    code_executor=UnsafeLocalCodeExecutor(),  # DEV ONLY: exec()
)
root_agent = LlmAgent(
    name="refund_skill_agent", model="gemini-3.5-flash",
    instruction="Use skills when they match the request.", tools=[skills])

Step 5 of the Acme refund team: agent.py turns the skill folder into four tools with SkillToolset. lookup_order comes from refund_core, where the new test order A-300 is a 120 dollar jacket bought 42 days ago. Walk the four levels in the animation. At first the model sees only the name and description from list_skills; load_skill adds the four steps and only then exposes lookup_order, because the frontmatter lists it in adk_additional_tools and additional_tools supplies the function. Then load_skill_resource reads policy.md, and run_skill_script runs prorate.py with the args as long options, which prints 72.0. Think of a manual on a shelf: the model reads the spine first and opens the chapter only when the question needs it. A likely question: "Can I run this in production?" Not with UnsafeLocalCodeExecutor: it runs scripts with exec() inside the agent process and script_timeout does not apply, so use a container or sandbox executor.
