refund_flow/agent.py · from step 1
def check_policy(ctx: Context, node_input: str) -> RefundCase:
  order = ORDERS[node_input]
  eligible = order["days_since_delivery"] <= 30          # 30-day policy
  ctx.state["refund_case"] = {"order_id": node_input, **order,
                              "eligible": eligible}
  return RefundCase(order_id=node_input, amount=order["amount"],
                    days_since_delivery=order["days_since_delivery"],
                    eligible=eligible)
write_reply = Agent(
    name="write_reply",
    model="gemini-3.5-flash",
    instruction=("You are a refunds agent. Case: {refund_case}. "
        "If eligible is true, confirm the refund amount. Otherwise explain "
        "the 30-day policy politely and offer store credit. Max 3 sentences."),
    output_key="reply_text",
)
def audit_log(reply_text: str):  # bound from ctx.state["reply_text"]
  yield Event(message=f"[audit] reply length={len(reply_text)} chars. "
                      "WORKFLOW COMPLETED.")
node_input: parse_request returns "A-1001". The edge gives it to check_policy.

State-bound parameter: reply_text gets the output_key value by name.

This slide runs the chain from the last slide and follows the data. Press through the three paths: the return value of parse_request rides the edge as node_input; check_policy writes refund_case into state, and the write_reply prompt reads it from there (the RefundCase that also rides the edge is not what the prompt template uses); and audit_log gets reply_text from state only because its parameter has the same name as the output_key. Think of a kitchen: the plate moves along the pass, and the order ticket hangs on the rail where every cook can read it. Step 4 is the plain run: adk run prints only message events, so check_policy shows no text, and the audit line is signed refund_flow, not audit_log, because function nodes sign as the Workflow; filter on node_info.path when you search traces. Step 5 runs A-1002 with --jsonl: every event appears, check_policy included, and @1 means the first run of that node. A likely question is why A-1002 gets store credit: it was delivered 41 days ago, the policy is 30 days, so eligible is false and the instruction says to offer store credit.
