refund_core.py
from google.adk.agents import LlmAgent

ORDERS = {
    "A-100": {"days_since_purchase": 12, "amount": 79.0, "category": "apparel"},
    "A-200": {"days_since_purchase": 45, "amount": 640.0, "category": "electronics"},
    "A-300": {"days_since_purchase": 42, "amount": 120.0, "category": "apparel"},
}

def lookup_order(order_id: str) -> dict:
    """Return days since purchase, amount (USD) and category for an order id."""
    return ORDERS.get(order_id, {"error": f"unknown order {order_id}"})

refund_agent = LlmAgent(
    name="refund_agent",
    model="gemini-3.5-flash",
    description="Checks refund eligibility for an order id under ACME policy.",
    instruction=("Policy: apparel 30 days, electronics 14 days, refunds over $500 "
                 "need a manager. Call lookup_order, then answer REFUNDABLE / "
                 "NOT_REFUNDABLE / NEEDS_MANAGER with one sentence of reasoning."),
    tools=[lookup_order],
)

Three test orders. Every step of the lab uses these same ids.
One agent definition. Steps 1 and 2 import it, so you keep one copy.
At step 3, terminals 2 and 3 run together. Terminal 1 is needed only for step 1.
Before step 1, set up one folder that the whole lab grows in. Install the pinned versions with the mcp and a2a extras, and export the two Gemini variables in every terminal, because the plain python and uvicorn processes do not read the agent folder's .env file the way adk web does. The key design choice is refund_core.py: lookup_order, the three test orders and refund_agent live in one module, and the MCP server and the A2A server both import it, so one agent is exposed two ways without a second copy. Each agent package for adk web needs an __init__.py with "from . import agent"; refund_service only needs an empty one so uvicorn can import it. Think of refund_core as the kitchen, and MCP and A2A as two serving hatches. A likely question: "Which processes must run?" Step 1 needs terminal 1; steps 2 and 3 need uvicorn on 8001 plus adk web on 8000; the skill steps need only adk web.
