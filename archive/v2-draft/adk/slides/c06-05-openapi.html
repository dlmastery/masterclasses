claim_tool.py · hand-written
import httpx
from google.adk.tools import FunctionTool
def get_claim_status(claim_id: str) -> dict:
    r = httpx.get(f"http://127.0.0.1:8081/claims/{claim_id}",
                  headers={"X-API-Key": "demo-key-123"})  # key in git
    return r.json()
claim_tool = FunctionTool(get_claim_status)

claims_agent/agent.py · adds claims_status
import os
import httpx
from google.adk.tools.openapi_tool.auth.auth_helpers import token_to_scheme_credential
from google.adk.tools.openapi_tool.openapi_spec_parser.openapi_toolset import (
    OpenAPIToolset)
spec = httpx.get("http://127.0.0.1:8081/openapi.json", timeout=5).json()
auth_scheme, auth_credential = token_to_scheme_credential(
    "apikey", "header", "X-API-Key", os.environ["CLAIMS_API_KEY"])  # no default
claims_status = OpenAPIToolset(
    spec_dict=spec,
    auth_scheme=auth_scheme,
    auth_credential=auth_credential,
    tool_filter=["get_claim_status"],   # snake_case(operationId)[:60]
    allow_private_network_access=True,  # 127.0.0.1: see the next slide
)
# root_agent: tools=[claims_tools, handbook_tools, claims_status]

One tool from the spec. The key never enters git.
Now claims_desk gets its third tool source, the claims-status REST service from terminal 1. It already publishes an OpenAPI spec, so do not hand-write an httpx tool with the key pasted into the source. Step 1 shows that BEFORE version: the key and the URL live in git. Step 2: OpenAPIToolset reads the spec, and token_to_scheme_credential turns the key from the CLAIMS_API_KEY environment variable into the X-API-Key header; os.environ with square brackets fails at startup when the key is missing, instead of falling back to a value in the code. Step 3: ADK makes one tool per operation and names it snake_case of the operationId, cut to 60 characters, so getClaimStatus becomes get_claim_status, and tool_filter must use that name; print the names from get_tools() when you are not sure. Step 4: agent.py downloads the spec when it is imported, so start claims_api before adk web; with a wrong key the tool returns the 401 as an execution error. Think of the spec as a menu with item numbers: the agent orders by the number, not by describing the dish. A likely question: "Why allow_private_network_access?" The API runs on 127.0.0.1, which the SSRF guard blocks by default; the next slide shows that guard.
