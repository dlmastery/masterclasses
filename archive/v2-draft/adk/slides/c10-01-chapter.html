Guardrails, deploy and AgentOps

Take the Contoso HR assistant to production: guard plugins, Model Armor, clean traces, three deploy targets, a canary, Gemini Enterprise.

Codelab Build a Secure Agent with Model Armor and Identity Codelab Stateful Data Science Agent on Agent Runtime Docs Cloud Run rollouts, rollbacks and traffic migration tested on google-adk 2.13.0 [gcp, otel] · google-cloud-agentplatform 2.6.0 · google-agents-cli 1.11.0
This chapter takes the Contoso People Team HR assistant from a laptop to production, and every station on the track is one lab or build-up. We guard it with our own plugin and Model Armor, trace it without putting employee data into spans, deploy it to Agent Runtime, Cloud Run or GKE, canary the new revision, publish it to Gemini Enterprise, and observe it. Watch the red arc in the animation: when tokens per invocation go above 1.5 times the baseline, which is the signature of a loop, we roll back in one command and the loop starts again. Think of it as a pit lane in a race: the car goes out, the team watches the telemetry, and a bad lap brings it straight back in. A likely question: "Why not just use the Model Armor settings in the Gemini Enterprise console?" Because those settings do not protect ADK agents, so the guards must live in the agent code.
