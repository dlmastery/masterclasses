import asyncio
from google.adk import Event, Workflow
from google.adk.workflow import JoinNode
POLICIES = {"POL-77": {"active": True, "deductible": 500, "limit": 20000}}
INACTIVE = {"active": False, "deductible": 0, "limit": 0}
def parse_claim(node_input: str) -> dict:   # "POL-77 rear-end collision 4200"
  policy_id, *desc, amount = node_input.split()
  return {"policy_id": policy_id, "desc": " ".join(desc), "amount": float(amount)}
async def policy_check(node_input: dict) -> dict:
  await asyncio.sleep(0.3)                     # stands in for the policy DB
  return POLICIES.get(node_input["policy_id"], INACTIVE)
async def fraud_score(node_input: dict) -> float:
  await asyncio.sleep(0.5)                     # stands in for the fraud model
  return 0.82 if "total loss" in node_input["desc"] else 0.07
async def damage_estimate(node_input: dict) -> float:
  await asyncio.sleep(0.2)                     # stands in for the estimator
  return round(node_input["amount"] * 0.95, 2)
claim_checks/agent.py · part 2 of 2 · join, decide, graph
# {"policy_check": {...}, "fraud_score": 0.07, "damage_estimate": 3990.0}
def decide(node_input: dict):
  pol, fraud = node_input["policy_check"], node_input["fraud_score"]
  est = node_input["damage_estimate"]
  payout = max(0, min(est, pol["limit"]) - pol["deductible"])
  if not pol["active"] or payout == 0:
    verdict = "DENY: policy inactive or payout 0"
  elif fraud > 0.6:
    verdict = f"REFER to SIU (fraud score {fraud:.2f})"
  else:
    verdict = f"APPROVE payout ${payout:,.2f}"
  yield Event(output=verdict, message=verdict)
join_checks = JoinNode(name="join_checks")
root_agent = Workflow(name="claim_checks", max_concurrency=3,  # optional cap
    edges=[("START", parse_claim, (policy_check, fraud_score, damage_estimate),
            join_checks, decide)])

This is step 1 of the Northwind back-office lab: one claim, three independent checks, one decision. Make a folder claim_checks with an __init__.py that says "from . import agent" and this agent.py; the file has no model call, so it runs offline with no API key and no .env. Walk the four focus steps: parse_claim splits the claim text, the three async checks sleep 0.3, 0.5 and 0.2 seconds to stand in for a policy database, a fraud model and an estimator, JoinNode is the barrier that waits for all three, and the tuple inside the edges chain is what makes the fan-out. max_concurrency=3 on the Workflow is an optional cap on graph-scheduled nodes, not what creates the branches. Think of the JoinNode as the claims supervisor who signs only when all three reports are on the desk. A likely question: "How does decide know which value is which?" The join emits a dict keyed by predecessor node name, and a function node's name is its function name, so the keys are policy_check, fraud_score and damage_estimate, as in the comment on line 1 of part 2. decide yields an Event because adk run prints only message content; a plain return value prints nothing. payout is clamped at zero, so a claim under the deductible is denied instead of paying a negative amount.
