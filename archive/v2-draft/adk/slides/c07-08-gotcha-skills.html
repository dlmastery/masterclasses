All three errors come from the skill loader and the toolset, before the model sees the skill, and the first frame shows the broken folder. One: load_skill_from_dir compares the folder name with the frontmatter name; the full message is "ValueError: Skill name 'refund-policy' does not match directory name 'refund_policy'." Names must be lowercase kebab-case unless you turn on the experimental SNAKE_CASE_SKILL_NAME feature, with at most 64 characters, and the description at most 1024. Two: a skill with a script needs an executor; without one, run_skill_script returns an error dict, "Neither Environment nor CodeExecutor is configured. An environment or code executor is required to run scripts.", with error_code NO_CODE_EXECUTOR, and passing both code_executor and environment raises a ValueError. UnsafeLocalCodeExecutor is for a laptop only, because it runs exec() in your process and script_timeout does not apply; in production use ContainerCodeExecutor or GkeCodeExecutor. Three: adk_additional_tools must be a YAML list even for one tool. Analogy: a skill folder is a labelled drawer; if the label and the drawer disagree, the clerk refuses to open it. A likely question: "Why not run scripts locally in production?" Because exec() shares your process and its memory, and nothing stops a slow script.
