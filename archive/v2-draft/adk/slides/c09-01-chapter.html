Evals that block bad deploys

Build the Acme refund eval gate: golden cases, a code metric for the $500 rule, simulated customers, and a CI exit code.

Codelab Evaluating Agents with ADK Docs adk.dev Evaluate tested on google-adk 2.13.0 pip install "google-adk[eval]==2.13.0" Python 3.11+ · GOOGLE_API_KEY from AI Studio
This chapter builds one eval gate for the Acme Retail refund agent, Lab 9, and every check in it runs from the command line. You need Python 3.11 or newer and a GOOGLE_API_KEY from AI Studio; only the safety_v1 and multi_turn metrics need a Google Cloud project, and this lab does not use them. The gate scores three things: the trajectory, which means the right tools in the right order; the answer, which an LLM judge compares with a golden reference answer; and the business rule that issue_refund never goes above 500 dollars, which is plain code and scores only 1 or 0. IN_ORDER means the expected tools must appear in this order and extra calls are allowed; we define it properly in step 3. Click through the card: the extra issue_refund of 820 dollars passes the trajectory gate, sounds fine to the judge, and only the code metric stops it, so CI gets exit 1. Think of the three gates as airport security: the boarding pass check, the interview, and the metal detector, which does not care how polite you are. A likely question: "Why not ask the judge to check the 500 dollar rule too?" Because judges plateau around 77 to 82 percent on hard tool-calling cases, and a hard rule needs a check that is right every time.
