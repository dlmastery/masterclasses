from google.adk import Agent
from google.adk.tools import FunctionTool, ToolContext
# ORDERS, lookup_order, check_refund_eligibility, the four callbacks: unchanged
APPROVAL_THRESHOLD_USD = 200.0          # refund_cap still blocks anything over $1,500
def issue_refund(order_id: str, amount_usd: float, tool_context: ToolContext) -> dict:
    """Issue a refund to the original payment method. Irreversible."""
    issued = tool_context.state.get("refunds_issued", [])
    tool_context.state["refunds_issued"] = issued + [{"order_id": order_id, "amount_usd": amount_usd}]
    return {"status": "success", "refund_id": f"RF-{order_id}", "amount_usd": amount_usd}
def needs_approval(order_id: str, amount_usd: float, tool_context: ToolContext) -> bool:
    """Same parameters as issue_refund: ADK calls this with the tool's arguments."""
    return amount_usd > APPROVAL_THRESHOLD_USD
root_agent = Agent(name="refund_agent", model="gemini-3.5-flash",
    instruction=(
        "You are a refund desk assistant. Use lookup_order, then check_refund_eligibility. "
        "Quote the rule you applied. Never promise a refund the tool did not approve. "
        "Call issue_refund only for an eligible order. If the tool says the call "
        "was rejected, tell the customer a supervisor declined it."
    ),
    tools=[lookup_order, check_refund_eligibility,
           FunctionTool(issue_refund, require_confirmation=needs_approval)],
    before_model_callback=block_card_numbers, before_tool_callback=refund_cap,
    after_tool_callback=redact_pii, after_model_callback=meter_tokens)
A predicate that falls through returns None, and None skips the gate (issue #7010, open). Always return a real bool.

The cap from the last slide is a hard ceiling. Between $200 and $1,500 Acme wants a person to decide. An instruction such as "ask a supervisor before any refund over $200" is only a request to the model; nothing stops the call. require_confirmation moves the gate into the framework: ADK calls needs_approval with the tool's own arguments, so the predicate must take the same parameter names, including tool_context. Over $200, the first call returns the error dict "This tool call requires confirmation, please approve or reject.", adk run asks for yes, and anything else returns "This tool call is rejected." In your own client, watch event.long_running_tool_ids and reply with a FunctionResponse that has the same id and {"confirmed": true or false}. Analogy: the predicate is the till that calls the manager for any refund over the limit. Best practice: read the threshold from app: state so ops can change it without a deploy, and expect the question "Can the model skip the gate?" No: the gate is in FunctionTool, not in the prompt.
