from google.adk import Event, Workflow
from pydantic import BaseModel
class Triage(BaseModel):
  labels: list[str]          # free text: "Billing" is legal
  priority: str
def route_ticket(node_input: Triage):
  yield Event(output=node_input.model_dump(),

ticket_triage/agent.py · fix
from typing import Literal
from google.adk import Event, Workflow
from google.adk.workflow import DEFAULT_ROUTE
from pydantic import BaseModel
class Triage(BaseModel):
  labels: list[Literal["billing", "outage", "how_to", "other"]]
  priority: Literal["p1", "p2", "p3"]
def route_ticket(node_input: Triage):
  yield Event(output=node_input.model_dump(),
              route=list(node_input.labels))
# intake, classify, billing, page_oncall, how_to, human_queue: Lab 3 step 3
root_agent = Workflow(name="ticket_triage", edges=[
    ("START", intake, classify, route_ticket),
    (route_ticket, {"billing": billing, "outage": page_oncall,
                    "how_to": how_to, DEFAULT_ROUTE: human_queue}),
])

SymptomNo branch runs. No error. Only the log line above. CauseThe model wrote 'Billing'. The dict key is 'billing'. FixAdd a DEFAULT_ROUTE edge. Classify into a Literal set.
Workflow graphs can fail without a sound. Step 0 shows the BEFORE code: labels is a plain list of strings, so the model may write "Billing" with a capital B. Step 1: route_ticket emits route=['Billing']. The token tries each key, billing, outage and how_to, and matches none. Nothing raises; the branch ends and you get one WARNING log line: "Node 'route_ticket' has conditional/DEFAULT edges but none were matched by the emitted route(s): ['Billing']. The branch will end." Step 2: the first half of the fix is a DEFAULT_ROUTE edge, which catches any unmatched route and sends the ticket to the human queue. Step 3: the second half is a Literal schema, so the model can only emit legal labels: the token is now 'billing' and takes the billing edge. Analogy: an unmatched route is a letter with a wrong address that nobody returns. A likely question is "Why does the engine not raise?": it treats an unmatched route as a legal end of a branch, so you must make the fallback explicit. Next: two errors that do fail loudly.

These two errors are loud, which is good: you find them in a test, not in production. Step 1: change write_reply into a plain function typed node_input: dict, and the Workflow refuses to build. The error names the edge and both classes. Step 2: the fix is one line, the same Pydantic class on both ends of the edge (or drop one hint). Step 3: two branches of a list route both end with an output, here because page_oncall returns a dict, and a plain return value becomes the node output. The run raises WorkflowConfigurationError: at most one terminal output. Step 4: this is why Lab 3 step 3 works: page_oncall yields only a message, so billing gives the one terminal output. The other fix is a JoinNode before one final node. Two more errors you will meet: "from google.adk import START" raises ImportError, because the top-level package exports only Agent, Context, Event, Runner and Workflow (import START from google.adk.workflow, or use the string "START" in a chain tuple); and "WorkflowDataError: Missing value for parameter reply_txt" means a parameter name does not match the output_key. Analogy: a schema check is a plug that will not fit the socket. Next: an October paper on what the routing decision costs.
