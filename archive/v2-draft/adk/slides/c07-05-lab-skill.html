skills/refund-policy/scripts/prorate.py L3
import argparse
p = argparse.ArgumentParser()
p.add_argument("--amount", type=float, required=True)
p.add_argument("--days", type=int, required=True)
a = p.parse_args()
share = max(0.0, (60 - a.days) / 30)    # day 30: 1.0, day 60: 0.0
print(f"{round(a.amount * min(share, 1.0), 2)}")

L1: name and description. The model sees only these until it loads the skill.
adk_additional_tools is a YAML list. Loading the skill unlocks lookup_order.
L2: the body. It names the file to read and the script to run.
L3: files read or run on request. Partial refund = amount × (60 − days) / 30.
Step 4 of the Acme refund team: the policy that lived in the refund_agent instruction moves into an Agent Skill, which is just a folder. SKILL.md has YAML frontmatter and a body. The frontmatter name and description are level 1: they are all the model sees until it decides to load the skill. The metadata key adk_additional_tools lists lookup_order; it must be a YAML list, and the tool only reaches the model after the skill loads. The body is level 2: four steps that name the reference file and the script. policy.md and prorate.py are level 3: the model reads or runs them only when a step asks. Run the script by hand first, so you know the expected number: order A-300 is a 120 dollar jacket at day 42, so the share is 60 minus 42, over 30, which is 0.6, and the refund is 72.0. Think of a binder on a shelf: the spine is level 1, the table of contents is level 2, and the appendices are level 3. A likely question: "Must the folder name match name:?" Yes, the loader raises a ValueError otherwise; the gotcha slide shows it.
