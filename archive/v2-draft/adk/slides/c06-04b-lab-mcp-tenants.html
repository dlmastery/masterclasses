from google.adk.agents.readonly_context import ReadonlyContext
# McpToolset and StreamableHTTPConnectionParams: imported in step 3
def tenant_headers(ctx: ReadonlyContext) -> dict[str, str]:
    tenant = ctx.state.get("user:tenant")   # set at login, not by the model
    if not tenant:
        raise ValueError("no user:tenant in session state")  # fail closed
    return {"X-Tenant-ID": tenant}
handbook_tools = McpToolset(
    connection_params=StreamableHTTPConnectionParams(
        url="http://127.0.0.1:3000/mcp", timeout=5.0, sse_read_timeout=300.0),
    tool_filter=["search_policy", "list_topics"],
    tool_name_prefix="handbook",
    header_provider=tenant_headers,        # one pooled session per identity
    tool_list_cache_ttl_seconds=300,       # tools/list reused for 5 minutes
)

This is step 4 of the Northwind claims desk: several brokers share the handbook server, so each request must carry the broker's identity. A broker here is an insurance agency that uses the desk, one tenant. Step 1: tenant_headers reads user:tenant from session state. State with the user: prefix belongs to one user and survives across that user's sessions; your login code sets it, never the model. If it is missing, raise, so a request never falls back to another tenant's data. Step 2: header_provider sends it as X-Tenant-ID, and ADK pools one MCP session per header identity, so two brokers never share a session. Step 3: the tools/list cache is keyed the same way and lives 300 seconds; ADK does not subscribe to tools/list_changed, so a tool the server adds appears only after the entry expires, and even then the model sees it only if tool_filter lists it. A value of 0 raises ValueError, and None disables the cache. Step 4: create the session with its tenant through the REST API that adk api_server --with_ui serves, then open it in the UI. Think of a hotel key card: identity travels with the request, not in what the guest says, so a prompt injection cannot change the tenant. A likely question: "Why did my new server tool not appear?" The cache had not expired yet, or tool_filter does not list it. Next, the third tool source: the claims-status REST API.
