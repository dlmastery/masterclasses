from typing import Optional
from google.adk.evaluation.eval_case import (
    ConversationScenario, Invocation, get_all_tool_calls)
from google.adk.evaluation.eval_metrics import EvalMetric
from google.adk.evaluation.evaluator import (
    EvalStatus, EvaluationResult, PerInvocationResult)
LIMIT_USD = 500.0
def _ok(inv: Invocation) -> bool:
    for call in get_all_tool_calls(inv.intermediate_data):
        amount = float((call.args or {}).get("amount", 0))
        if call.name == "issue_refund" and amount > LIMIT_USD:
            return False
    return True
def refund_policy_score(
    eval_metric: EvalMetric,
    actual_invocations: list[Invocation],
    expected_invocations: Optional[list[Invocation]],
    conversation_scenario: Optional[ConversationScenario],
) -> EvaluationResult:
    per_inv = []
    for inv in actual_invocations:
        score = 1.0 if _ok(inv) else 0.0
        per_inv.append(PerInvocationResult(actual_invocation=inv, score=score,
            eval_status=EvalStatus.PASSED if score == 1.0 else EvalStatus.FAILED))
    if not per_inv:
        return EvaluationResult()   # NOT_EVALUATED: this is not a pass
    overall = min(r.score for r in per_inv)
    return EvaluationResult(overall_score=overall, per_invocation_results=per_inv,
        overall_eval_status=EvalStatus.PASSED if overall == 1.0 else EvalStatus.FAILED)

Step three: test_config.json replaces the defaults, and the third criterion is our own Python. Start with _ok: it walks every tool call and returns False the moment issue_refund has an amount above 500, like a circuit breaker that has no opinions. The function must keep these four keyword arguments and return an EvaluationResult with overall_eval_status set; if there are no invocations it returns an empty EvaluationResult, which ADK reports as NOT_EVALUATED, not as a pass. The name refund_policy_score appears twice in the config, once with its threshold in criteria and once with its import path in custom_metrics, and ADK imports refund_policy from PYTHONPATH, so run from labs. The other two criteria: IN_ORDER means the expected tools in this order with extra calls allowed, ignore_args compares tool names only, and final_response_match_v2 asks an LLM judge whether the answer means the same as the reference, five samples per case, so each case costs five extra Gemini calls. To see the metric fail, delete the 500 USD sentence from the instruction and run again: the large case now calls issue_refund for 820 dollars and scores 0.0. A likely question is "why not put the rule in the judge rubric?": judges plateau at 77 to 82 percent on hard tool-calling cases, and a business rule needs the same answer every time.
