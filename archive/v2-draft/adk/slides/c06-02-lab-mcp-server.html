claims_agent/claims_server.py · mcp 2.3.0
import logging, os, sys
from mcp.server.mcpserver import MCPServer
logging.basicConfig(stream=sys.stderr, level=logging.INFO)  # not stdout
mcp = MCPServer("claims-server")
CLAIMS = {"CLM-1001": {"status": "open", "amount": 1800.0}}
@mcp.tool()
def get_claim(claim_id: str) -> dict:
    """Return status and amount (USD) for a claim id like CLM-1001."""
    if claim_id not in CLAIMS:
        return {"status": "error", "message": f"Unknown claim {claim_id}."}
    return {"status": "ok", "claim_id": claim_id, **CLAIMS[claim_id]}
@mcp.tool()
def approve_claim(claim_id: str, approved_amount: float) -> dict:
    """Approve a claim and schedule a payout of approved_amount USD."""
    claim = CLAIMS.get(claim_id)
    if claim is None or approved_amount > claim["amount"]:  # server rule
        return {"status": "error", "message": "Unknown claim or amount too high."}
    claim["status"] = "approved"
    return {"status": "ok", "claim_id": claim_id, "paid": approved_amount}
@mcp.tool()
def purge_claim(claim_id: str) -> dict:
    """Permanently delete a claim record (admin role only)."""
    if os.environ.get("CLAIMS_ROLE") != "admin":  # server role check
        return {"status": "error", "message": "Needs the admin role."}
    return {"status": "ok", "purged": CLAIMS.pop(claim_id, None) is not None}
if __name__ == "__main__":
    mcp.run()  # transport defaults to "stdio"

This is step 1 of the Northwind claims desk lab: a small MCP server with three claim tools that the agent starts as a child process. Walk the five steps. Step 1, the import: mcp 2.x renamed FastMCP to MCPServer, so old tutorials fail with an import error. Step 2, logging goes to stderr, because over stdio the stdout pipe carries the JSON-RPC messages and nothing else. Step 3, the three tools: get_claim returns a structured error for an unknown id, approve_claim refuses an amount above the claim, and purge_claim refuses callers without the admin role, so the server keeps its own checks whatever the client does. Step 4, mcp.run() picks stdio by default; running the server alone with stdin closed shows import errors in the terminal, because the server starts, reads the end of its input and exits. Step 5, one print() on stdout breaks the stream, and the agent sees "Failed to create MCP session"; use logging instead. Think of stdout as a phone line that a fax machine uses: if you say one word into it, the fax fails. A likely question: "Why not just remove purge_claim from the server?" Other MCP clients may need it, so the server keeps it behind its role check, and each client filters what its model may see. On Windows, use WSL or the cmd form from the setup slide.
