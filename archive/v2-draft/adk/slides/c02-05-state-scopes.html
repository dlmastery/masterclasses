def get_policy(topic: str, tool_context: ToolContext) -> dict:
    tool_context.state["temp:last_topic"] = topic              # this turn only
    asked = tool_context.state.get("user:topics_asked", [])
    tool_context.state["user:topics_asked"] = asked + [topic]  # all chats of u-tom
    return {"status": "success", "policy": POLICIES[topic]}

Before: keys without a prefix live in one session. A new chat starts empty.

Seed app: and user: keys at create. app: is shared by every user.

Send per-turn context as state_delta. It is written through an event.

temp: lives for this turn. user: follows u-tom into every chat.

output_key writes last_answer: this chat only. {user:language?} renders '' if missing.

Session 2 gets app: and user: back. InMemory keeps them only while the process runs.

This build is a standalone FAQ agent, claims_faq_agent, under the same app_name claims_api and the same customer u-tom. Both code blocks are excerpts; the full file in the repo adds the imports, the POLICIES dict, the InMemoryRunner, svc = runner.session_service and the user message msg. Start with the before block: the keys have no prefix, so they belong to one session, and a new chat for the same customer starts with an empty dict. Then walk the after code: create_session seeds an app: key and a user: key; the state_delta on run_async writes the language through an event; the tool writes temp:last_topic for this turn and appends to user:topics_asked; output_key stores last_answer with no prefix. The InMemorySessionService keeps separate app and user dicts and merges them into every session it returns, which is why session 2 still knows Tom. temp: keys are trimmed before commit, so they are never stored. Warn the room: app: keys are shared by every user of the app, so never write customer data there. The instruction uses {user:language?}: the question mark makes the key optional, so a missing key renders as an empty string; the gotcha slide shows what happens without it. Analogy: app: is the office noticeboard, user: is the customer file, unprefixed keys are the notepad for this call, and temp: is a sticky note you throw away when you hang up. The in-memory service loses all of this when the process stops; the next slide fixes that with SQLite.
