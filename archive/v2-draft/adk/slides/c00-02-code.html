acme_desk/agent.py
from google.adk import Agent, Context, Event, Workflow
# + from typing import Literal; from pydantic import BaseModel
class Ticket(BaseModel):
  route: Literal["refund", "question"]
  order_id: str = ""
def intake(node_input: str):
  yield Event(state={"ticket": node_input})
classify = Agent(name="classify", output_schema=Ticket,
  instruction="Label refund or question; copy order id: {ticket}")
def pick(node_input: Ticket):
  yield Event(route=node_input.route,
              output=node_input.model_dump())
def refund(ctx: Context, node_input: dict):
  oid = node_input["order_id"]
  ctx.state["outcome"] = f"refund queued for {oid}"
answer = Agent(name="answer", output_key="outcome",
  instruction="Answer in 2 sentences: {ticket}")
def audit(outcome: str):      # read from ctx.state["outcome"]
  yield Event(message=f"[audit] {outcome}")
root_agent = Workflow(name="acme_desk", edges=[
  ("START", intake, classify, pick),
  (pick, {"refund": refund, "question": answer}),
  (refund, audit), (answer, audit)])
acme_desk/ run adk from its parent __init__.py from . import agent agent.py this file .env your key (next slide)
adk run acme_desk "Refund A-1001, broken"
classify is the only model call on the refund path. output_schema keeps the label in a closed set. {ticket} reads session.state.
pick is plain code. It sends the label out as the route.
refund writes outcome to state. answer writes the same key with output_key. audit reads it by parameter name.
The dict edge maps each route to a node. A label with no edge only logs a warning. Lab 3 adds DEFAULT_ROUTE.
output · illustrative
[acme_desk]: [audit] refund queued for A-1001
# pick and refund print nothing
This is the graph from the first slide as real code; Lab 3 builds it step by step, so do not teach the API yet: point at the four highlighted ideas only, and do the setup on the next slide before you type along. There is no model= argument: Agent uses gemini-3.5-flash, the 2.13.0 default; set model= to pin another Gemini model id. Press once: classify has output_schema=Ticket, so its reply must be one of two labels plus an order id, and {ticket} in the instruction is read from session.state, where intake wrote it. Press again: pick is a plain function; it yields an Event whose route is that label. Press again: refund writes outcome into session.state and returns nothing, which is allowed; on the question path, answer writes the same key through output_key; audit gets outcome because a function parameter that is not node_input or ctx is read from state by name, and a missing key raises WorkflowDataError. Press again: the edges list maps "refund" to refund and "question" to answer; a label with no matching edge runs nothing and only logs a warning, which is why the schema is a Literal and why Lab 3 adds DEFAULT_ROUTE as the safety net. Last press: the run prints one line, because function nodes print under the workflow name and only events with a message print. Analogy: classify fills in a form, and pick is the clerk who files it in the right tray. Likely question: "Why not let the model call refund as a tool?" Because then a prompt decides whether money moves; here code decides, and you can unit-test pick without a model.
