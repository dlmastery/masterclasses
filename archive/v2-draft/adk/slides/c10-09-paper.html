Origin checks in code beat injection detectors that do not transfer

origin_guard.py · simplified sketch of ROPE
SENSITIVE = {"send_email": ["to"], "transfer_funds": ["iban", "amount"]}

async def origin_guard(tool, args, tool_context):
    fields = SENSITIVE.get(tool.name, [])
    # filled by YOUR code from the user turn / CRM
    trusted = set(tool_context.state.get("user:trusted_values", []))
    for f in fields:
        if str(args.get(f)) not in trusted:
            return {"status": "blocked",  # returned dict skips the tool
                    "error": f"'{f}' did not originate from the user or a trusted record; "
                             "ask the user to confirm"}
    return None

Three papers from August to October point the same way: put the security decision in code, and treat classifiers as an extra filter. Step 1: a 14-vector test of multi-agent systems found that injection through tool output succeeded 43% of the time even with system-prompt guardrails, and that role-scoped tools plus boundary screening cut overall success from 31.2% to 4.2%. Steps 2 and 3: ROPE guards only the few parameters that move money or data, and admits a value only if it came from the user or a trusted record, so the attacker can reword the injection five times and the gate gives the same answer; that is where the 1.6 to 2.6% attack success comes from. Step 4: detectors picked by public benchmark scores do not transfer, and the BIPIA leader catches 2% of AgentDojo injections at 1% false positives. Analogy: a bank checks that the payee is on your saved list; it does not try to guess if the phone call sounds suspicious. A likely question is "So is Model Armor useless?": no, it is a second layer on prompts, replies and tool outputs, but measure its false-positive rate on your own Contoso tool outputs before you turn on blocking.
