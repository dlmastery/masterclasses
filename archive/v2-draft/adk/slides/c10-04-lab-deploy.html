Ship one agent to Agent Runtime, Cloud Run or GKE with adk deploy

pip install "google-adk[gcp]==2.13.0" needs gcloud CLI, billing; kubectl for GKE Codelab Stateful Data Science Agent on Agent Runtime
ship.sh · run in the parent of hr_agent/
gcloud auth application-default login
export PROJECT=my-proj REGION=us-central1 && gcloud config set project $PROJECT
# A) Agent Runtime: managed sessions + Memory Bank, traces without content
adk deploy agent_engine --project=$PROJECT --region=$REGION \
  --display_name="contoso-hr" --otel_to_cloud \
  --service_account=contoso-hr@$PROJECT.iam.gserviceaccount.com hr_agent
export AGENT_ENGINE_ID=1234567890              # printed by the first deploy
adk deploy agent_engine --project=$PROJECT --region=$REGION \
  --agent_engine_id=$AGENT_ENGINE_ID hr_agent  # later: update in place
# B) Cloud Run: private, one warm instance; flags after "--" go to gcloud
adk deploy cloud_run --project=$PROJECT --region=$REGION \
  --service_name=contoso-hr --session_service_uri="agentengine://$AGENT_ENGINE_ID" \
  hr_agent -- --no-allow-unauthenticated --min-instances=1
# C) GKE: ClusterIP by default, no public IP
adk deploy gke --project=$PROJECT --region=$REGION \
  --cluster_name=agents-prod --service_type=ClusterIP hr_agent
# also: --extra_packages (2.13), --validate-agent-import; --trace_to_cloud is deprecated

# smoke test Cloud Run: identity token, not access token

Pass --agent_engine_id on updates, or each deploy makes a new instance.
Keep it private. Without --session_service_uri, sessions die with the instance.
ClusterIP is the default. LoadBalancer gives a public IP.
Cloud Run wants an identity token and roles/run.invoker. An access token gets 403.
This is the last step of the Contoso HR lab: the same hr_agent folder goes to three targets with one CLI. On Agent Runtime, remember the agent_engine_id: without it every deploy creates a new instance, and your client keeps talking to the old one. On Cloud Run, everything after the double dash goes to gcloud run deploy, so we keep the service private, keep one warm instance, and store sessions in Agent Runtime instead of instance memory. GKE gives a ClusterIP service by default, so nothing is public until you choose a LoadBalancer. An analogy: the package is one shipping container, and the three targets are a managed port, a self-service dock and your own warehouse. A likely question is "which one do I pick?": Agent Runtime when you want managed sessions, Memory Bank and publishing to Gemini Enterprise; Cloud Run when you want the ADK FastAPI routes, revisions and your own database; GKE when you need GPUs or self-hosted models.
