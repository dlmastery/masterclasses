Step five: instead of a frozen conversation, an LLM plays the customer. The NOVICE persona knows its order is ORD-555 but says so only when the agent asks, which a fixed golden script cannot do, because the script breaks as soon as the agent asks a clarifying question. Think of it as a mystery shopper with a hidden brief: the conversation_plan holds the secret facts and the goal, and the simulator sends the finished tag when the goal is met. In this run the agent opened the ticket but also told the customer the 820 dollar refund was approved; models do not follow an instruction every time, and this is exactly the slip the rubric in the next step must catch. The two commands create the eval set refund_sim and add one case per scenario, with an id made from a hash of the scenario text, so if you edit a scenario, delete the old case or recreate the set. A likely question is "where does refund_sim live?": eval_set create writes refund_agent/refund_sim.evalset.json, and adk eval accepts either that id or a file path.
