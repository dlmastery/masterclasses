manager_gate · Lab 5 step 1
@node(rerun_on_resume=True)
def manager_gate(ctx: Context, amount: float, draft: str):
  if amount <= AUTO_APPROVE_LIMIT:
    yield Event(route="approved", state={"final_amount": amount})
    return
  iid = f"refund_approval_{ctx.invocation_id}_{ctx.run_id}"
  answer = ctx.resume_inputs.get(iid)
  if answer is None:
    yield RequestInput(interrupt_id=iid, response_schema=ManagerDecision,
                       payload={"amount": amount, "draft": draft},
                       message=f"Refund ${amount:.2f} needs approval.")
    return
  d = ManagerDecision.model_validate(answer)
  if not d.approved:
    yield Event(route="rejected")
  elif d.note:
    yield Event(state={"note": d.note}, route="revise")
  else:
    yield Event(state={"final_amount": d.amount or amount}, route="approved")

refund_approval/agent.py
from google.adk import Event, Workflow
from google.adk.workflow import node
AUTO_APPROVE_LIMIT = 500.0
def intake(node_input: str):                       # "A-2040 820"
  order_id, amount = node_input.split()[:2]
  yield Event(state={"order_id": order_id, "amount": float(amount)})

@node(require_confirmation=lambda amount: amount > AUTO_APPROVE_LIMIT)
def issue_refund(order_id: str, amount: float):    # args = state keys
  key = f"refund-{order_id}"                       # idempotency key
  yield Event(message=f"REFUNDED ${amount:.2f} on {order_id} (key {key})")

root_agent = Workflow(name="refund_approval",
                      edges=[("START", intake, issue_refund)])
We now replace the hand-written manager_gate from step 1 of the lab with one decorator on issue_refund. Be fair about the swap: the decorator is a yes/no gate, so the draft, the revise loop and the partial amount go away, which is why the line count drops. The predicate lambda amount: amount > AUTO_APPROVE_LIMIT uses the same 500-dollar constant as the old gate; amount is bound by name from the state key that intake wrote. When it returns True, the node pauses with a RequestInput whose interrupt id is wf_tool_confirmation plus the node path and whose schema is ToolConfirmation. The reply must be the dict {"confirmed": true}: from adk run you type the JSON object as the query, because the CLI JSON-parses the text, while a plain "yes" stays a string and raises WorkflowDataError, which the second lane shows for another case. A rejection does not run the body; the node output is {"error": "This tool call is rejected."}. It is like a door with a built-in badge reader instead of a guard who stands in front of it. A likely question: "Why keep the old gate at all?" Because ToolConfirmation is yes or no: when the manager approves 700 instead of 820 or adds a note, you still need the RequestInput gate with ManagerDecision.
