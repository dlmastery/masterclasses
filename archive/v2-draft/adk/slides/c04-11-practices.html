Pick the cheapest pattern that passes the eval, then stop

1Pick the shape agent → graph

  • Start with one agent and ≤ 20 tools (Shopify: boundaries blur at 20-50).
  • Move to a graph past two branching paths (I/O '26).
  • No central multi-agent for user support: worse in 12 of 13 τ²-bench cells.

2Bound the shape JoinNode · MAX_ROUNDS · run_node

  • Fan out only independent checks; each reads the original claim.
  • Every loop gets MAX_ROUNDS and an "escalate" exit.
  • Thin orchestrator; side effects in child nodes, replayed on resume.
  • Do not chain dependent LLM steps a function can do: pn decay.

3Hand off with care AgentTool · output_key

  • Pass policy facts as typed state: handoffs dropped 56-85%.
  • Narrow domain subagents, read-only vs writable tools (Spec: MSQ 20.8%).
  • Delegate only for many findings: a tier keeps ~0.57; two tiers win at 403.

from google.adk import Context, Event, Workflow
# Review, brief, write_copy, review_copy, publish, escalate: Lab 4 step 3
MAX_ROUNDS = 3

def gate(ctx: Context, node_input: Review):
  ctx.state["round"] = ctx.state["round"] + 1
  if node_input.grade == "compliant":
    yield Event(route="done")
  elif ctx.state["round"] >= MAX_ROUNDS:
    yield Event(route="escalate")
  else:
    yield Event(state={"feedback": node_input.feedback}, route="retry")

root_agent = Workflow(name="copy_review", edges=[
    ("START", brief, write_copy, review_copy, gate),
    (gate, {"retry": write_copy, "done": publish, "escalate": escalate}),
])

This slide turns the chapter into rules you can check in a design review. Group one picks the shape: start with one agent and at most 20 tools, the band Shopify found clear, move to a graph once there are more than two branching paths, and do not default to a central multi-agent system for user-facing support, because arXiv 2610.27655 found it worse than one agent in 12 of 13 tau2-bench cells. Group two bounds the shape: fan out only independent checks that each read the original claim, give every loop MAX_ROUNDS and an escalate exit like the gate on the right, keep the orchestrator thin because it re-runs from the top on resume, and replace dependent LLM steps with functions where you can. Group three is about handoffs: typed state keeps policy facts that free-text handoffs dropped 56 to 85 percent of the time, narrow domain subagents did best in MS-Eval, and for closed models delegation raised cost and lowered performance; delegation only pays when findings run into the hundreds. Analogy: each dependent LLM step is a coin that lands right 95 times in 100, and you need every coin in a row to land right. Likely question: "Does a bigger model fix the decay?" Per-step reliability rises with scale but stays below 1 (2609.01660), so the number of dependent steps still sets the ceiling.
