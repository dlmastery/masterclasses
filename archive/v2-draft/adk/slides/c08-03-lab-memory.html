# imports: asyncio, os, sys, types, Agent, Runner, preload_memory,
#   VertexAiMemoryBankService, InMemorySessionService
async def save_to_memory(callback_context) -> None:
    await callback_context.add_session_to_memory()
agent = Agent(name="support_agent", model="gemini-3.5-flash",
    instruction="Bluefin support. Use remembered preferences.",
    tools=[preload_memory], after_agent_callback=save_to_memory)
memory = VertexAiMemoryBankService(
    project=os.environ["GOOGLE_CLOUD_PROJECT"],
    location=os.environ["GOOGLE_CLOUD_LOCATION"],
    agent_engine_id=os.environ["AGENT_ENGINE_ID"])
runner = Runner(agent=agent, app_name="bluefin_support",
    session_service=InMemorySessionService(),
    memory_service=memory, auto_create_session=True)
async def wait_for_memory() -> None:   # day2 calls this first
    for _ in range(12):                # generation is asynchronous
        r = await memory.search_memory(app_name="bluefin_support",
                                       user_id="cust-42", query="SMS")
        if r.memories: return
        await asyncio.sleep(5)
# main(day): run_async(user_id="cust-42", session_id=day), print
after_agent_callback runs after every turn and sends the session so far to Memory Bank.
The bank lives in an Agent Runtime in your project, a billed resource. Create it once with agentplatform.Client(...).runtimes.create(); delete it when you finish.
Day 2 polls search_memory until the facts exist. Then preload_memory searches with the user turn and injects matches before the model call. tools=[load_memory] lets the model decide.
Scope is app_name + user_id. Erase with delete_memory (2.13), not delete_session.

This is step two of the Bluefin lab: the customer tells us once, on day one, that she is on the Family 4-line plan and wants SMS only, and on day two the agent already knows. Run the two python commands; adk web with --memory_service_uri="agentengine://$AGENT_ENGINE_ID" is the dev-UI alternative with no code change. create_bank.py is four lines: agentplatform.Client(project, location), then client.runtimes.create(), then print the id; pin google-cloud-agentplatform 2.2 or later, because an old SDK only has Client.agent_engines. Two lines do the work: after_agent_callback calls add_session_to_memory after every turn, and preload_memory searches with the new user turn and injects the matches into the system context before the model runs. Memory generation is asynchronous on the service, so day two polls search_memory for up to a minute before it asks. Think of Memory Bank as the notes a good call-centre agent writes after a call, which the next agent reads before picking up the phone. Memories are keyed by app_name plus user_id, so a new user id looks like a stranger. A likely question is "how do I honour a forget-me request?": delete_session does not touch memories, so call the new delete_memory API from 2.13. The Agent Runtime bills to your project, so delete it in the console when you finish. Next, step 3 takes the same customer, cust-42, onto a voice billing call with run_live.
