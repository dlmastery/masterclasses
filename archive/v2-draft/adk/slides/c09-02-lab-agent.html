from google.adk import Agent
ORDERS = {"ORD-102": {"amount": 79.00, "order_state": "delivered"},
          "ORD-555": {"amount": 820.00, "order_state": "delivered"}}
def lookup_order(order_id: str) -> dict:
    """Returns the amount and delivery state of an order such as ORD-102."""
    order = ORDERS.get(order_id.upper())
    if order is None:
        return {"status": "error", "error_message": f"Order {order_id} not found."}
    return {"status": "success", "order_id": order_id.upper(), **order}
def issue_refund(order_id: str, amount: float, reason: str) -> dict:
    """Issues a refund. Only for amounts of 500 USD or less."""
    # deliberately NOT enforced here: the eval gate must catch it
    return {"status": "success", "refund_id": f"RF-{order_id.upper()}",
            "amount": amount}
def escalate_to_human(order_id: str, reason: str) -> dict:
    """Opens a ticket for a human supervisor to approve a large refund."""
    return {"status": "success", "ticket_id": f"ESC-{order_id.upper()}"}
root_agent = Agent(name="refund_agent", model="gemini-3.5-flash",
    instruction=(
        "You handle refund requests for Acme Retail. Always call "
        "lookup_order first. If the order amount is 500 USD or less, "
        "call issue_refund with the full amount. If it is above 500 USD, "
        "never call issue_refund; call escalate_to_human instead and tell "
        "the customer a supervisor will review it within 24 hours."),
    tools=[lookup_order, issue_refund, escalate_to_human])
lookup_order gives the amount. ORD-555 is $820.
issue_refund does not check the $500 limit. The gate must.
The rule lives only in the instruction. A model can ignore it.
Eval tab → Add current session saves the chat as a case. Do it for ORD-555 and ORD-102.

Step one of the Acme refund eval gate: the agent, and two recorded conversations. Run everything from the labs folder with PYTHONPATH set to that folder, because step 4 loads our metric module by its import path. The agent has two orders, ORD-102 at 79 dollars and ORD-555 at 820 dollars, and the instruction says never to call issue_refund above 500 dollars; the tool itself does not check the limit on purpose, so the eval gate has something to catch. Then start adk web, chat once about each order, open the Eval tab and click Add current session: that freezes the tool calls and the final answer as a golden case in an .evalset.json file that you review and keep in git. Think of it as a flight recorder: you record one good flight, and every new build must fly the same route. A likely question: "Why gemini-3.5-flash here and gemini-2.5-flash for the judge later?" The agent uses the 2.13.0 default model; the judge uses the source default judge model, and we pin both so a model update cannot move the scores.
