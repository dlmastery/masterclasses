# part 2 of payouts/app.py: asyncio, json, sys, types, runner
# are imported and built in part 1 (step 3)

async def main(cmd: str, arg: str):
  if cmd == "start":
    await runner.session_service.create_session(app_name="payouts", user_id="ops", session_id="s1")
    msg, inv = types.Content(role="user", parts=[types.Part(text=arg)]), None
  else:
    pending = json.load(open("pending.json"))
    inv = pending["invocation_id"]
    msg = types.Content(role="user", parts=[types.Part(function_response=types.FunctionResponse(
        id=pending["interrupt_id"], name="adk_request_input", response={"result": arg}))])
  async for ev in runner.run_async(user_id="ops", session_id="s1", invocation_id=inv, new_message=msg):
    if ev.content and ev.content.parts and ev.content.parts[0].text:
      print(f"[{ev.author}] {ev.content.parts[0].text}")
    if ev.long_running_tool_ids:
      json.dump({"invocation_id": ev.invocation_id,
                 "interrupt_id": next(iter(ev.long_running_tool_ids))}, open("pending.json", "w"))
      print("PAUSED -> pending.json")
    if ev.output is not None and ev.node_info and "/pay@" in (ev.node_info.path or ""):  # the pay node
      print("OUTPUT:", ev.output)

if __name__ == "__main__":
  asyncio.run(main(sys.argv[1], sys.argv[2]))
Process 1: on long_running_tool_ids, save both ids and exit.
Process 2 sends {"result": "yes"}. The hand-off node outputs "yes" (not JSON, so a str) to pay.
Finished nodes fast-forward from history. Only analyst_review and pay run.
After a crash, call run_async(invocation_id=inv) with no new message. That needs ResumabilityConfig and a Runner: not adk web or adk run.

This is the last step of the payouts lab: two separate Python processes share one SQLite session. For a fresh run, delete payouts.db, pending.json and side_effects.log first, because start creates the session s1 again. Process 1 runs kyc_lookup, which writes one line to side_effects.log, then analyst_review pauses with a RequestInput; the driver saves the invocation id and the interrupt id to pending.json and the interpreter exits. Process 2 is a new interpreter: it sends a FunctionResponse named adk_request_input with response {"result": "yes"}, exactly what adk run sends. analyst_review uses the default hand-off pattern, so the reply becomes its output; the engine JSON-parses string results when it can, and "yes" is not JSON, so pay receives the str "yes". The workflow scans the recorded events, fast-forwards kyc_lookup from its stored output, and runs only analyst_review and pay, which retries twice before it succeeds. Step 4 is the crash case: ResumabilityConfig adds cross-call resume and checkpoint events in payouts.db, so after a crash you call run_async with only the invocation id and no new message; without ResumabilityConfig that call fails with "ValueError: Running an agent requires a new_message or a resumable app." The docs say this crash resume is not supported from adk web or the CLI, while answering a pause works everywhere. Try it: press Ctrl-C during attempt 2 and continue with the invocation id; kyc_lookup replays and the log still has one line, and the attempt counter starts again. Think of a film editor who jumps straight to the cut point instead of shooting the first scenes again. A likely question: "Then why do I still need an idempotency key?" Because resume is at-least-once: a crash between the charge and the persisted event re-runs pay, so the gateway must dedupe on the same key, payout- plus the invocation id.
