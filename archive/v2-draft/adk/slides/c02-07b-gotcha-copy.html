Gotcha Session state

get_session returns a copy, so write state through an event

SymptomYou set claim_status. The next get_session does not show it. Causeget_session returns a detached copy. Edits on it never reach the store. FixWrite through state_delta=, tool_context.state or callback_context.state.

# runner, sessions, uid = "u-tom", sid = "claim-77": as in claims_followup.py
s = await sessions.get_session(app_name="claims_api", user_id=uid, session_id=sid)
s.state["claim_status"] = "reviewed"         # edits the copy: lost

msg = types.UserContent(parts=[types.Part(text="Mark the claim reviewed.")])
async for _ in runner.run_async(user_id=uid, session_id=sid, new_message=msg,
                                state_delta={"claim_status": "reviewed"}):
    pass                                     # the delta rides on this turn

s = await sessions.get_session(app_name="claims_api", user_id=uid, session_id=sid)
print(s.state["claim_status"])

Every session service works this way: InMemory deep-copies, SQLite and Postgres build a new object from the rows.
Docs State Repo in_memory_session_service.py
This is the same claim-77 session from the SQLite slide. Step 0: someone marks the claim reviewed, and the next read does not show it. Step 1: get_session returns a detached object; the in-memory service deep-copies the session, and the SQLite service builds a new object from the rows in the file, so editing s.state changes only your copy. Step 2: state changes persist only when they travel inside an event: state_delta on run_async, tool_context.state in a tool, or callback_context.state in a callback. Here state_delta rides on a normal user turn, so the agent also replies. Step 3: read the session again and the value is there, because the event wrote it to claims_sessions.db. Analogy: get_session is a photocopy of the claim file; writing on the photocopy does not change the file in the cabinet. A likely question: "Can I write state without running the agent?" Not with these public calls; in this course every write goes through a turn, a tool or a callback.
